# 指挥者注意事项

本文只写推进 Cubbix 时容易出错的地方，规则以 `AGENTS.md` 为准。

## 公开仓库

合并前检查改动和整条分支历史，确认没有本机路径、其他私有项目名、设备或账号信息。便宜模型常把评审报告的路径写进文档，工作单里要明确禁止，合并前再用 `grep` 查一遍。工作单、调研和报告放仓库外，Issue 只写结论。

## 决策边界

- 实现、评审、合并由指挥者推进。
- 界面改动先出设计稿，经维护者确认后再实现。
- **发布 Release 必须由维护者确认**，因为它会让已安装的应用自动升级。更新签名和公证密钥由维护者掌管，只通过环境变量注入。
- 版本号和更新日志单独核对，发布后确认公开升级链路可用。

## 实现和验证

- 合并条件是本机 `./scripts/selftest.sh` 全部通过，不加 GitHub Actions。`TestJSONHiddenWebKit` 在高负载下可能偶发超时（#34），要重跑确认，不能直接忽略。
- 测试一律后台运行，不抢焦点，不切 Space，不把窗口推到前台。必须前台才能测的项写“未测”，由维护者验收。
- 涉及激活策略、主窗口、菜单栏、快捷键、输入法的改动，工作单必须写明以上规则。
- 通知用 `mygo.NewNotification()`，不要直接调用 UNUserNotificationCenter；后者没有申请授权，提示发不出来。
- 文案从一开始就放进语言资源，验收截图中英文各一份。
- 测试不要写死会增长的条目数，比如版本历史。

## 设计稿

- `design/cubbix.pen` 用 headless CLI 编辑，修改前后核对节点数和 diff，提交前跑 `python3 design/scripts/layout.py`。
- `brand/cubbix-logo.pen` 只读，不要用 CLI 改写。
- 不要让执行者读图片来还原设计，部分模型会卡住；用文字描述布局，或派能读图的模型。
