## 2. 拖动

### 2.1 从哪里可以拖

| 区域 | 行为 | 理由 |
| --- | --- | --- |
| 搜索行左端图标区：宽 `SizePaletteSearchHeight`（36）、高同样 36 的方块，`search` 图标在其中居中 | **可以拖** | 维护者建议的位置；它现在只是一个图标，点击没有语义，拿来做抓手不抢任何现有交互 |
| 面板四周 `Space8` 内边距、搜索行与分隔线／列表之间的 `Space8` 间隙 | **可以拖** | 就是「面板空白处」；这些位置现在按下没有任何副作用（没有处理器，等于落到最外层） |
| 输入框文字区 | 不拖，保持选文字与光标定位 | 文字选择是输入框的核心行为，抢占会毁掉命令面板的输入体验 |
| 命令行、动作行、分组标题、键帽、底部任何控件 | 不拖，保持点选 | 这些是按钮与列表 |
| 窗口四周 `SizePaletteShadowMargin`（32）的透明留白（方案 A 才有） | **可以拖**；在上面按下但不拖动就松手，当作「点面板外」收起面板 | 它是窗口的一部分，紧贴面板；这一圈的点击本来也落不到别的应用（§5.4 限制） |

三处「可以拖」在实现上是三类：

- 图标区是一个独立元素（`ui.Box` 包住 `search` 图标），挂拖动手柄，处理器返回 `true`。
- 面板空白（`Space8` 内边距、搜索行与分隔线／列表之间的间隙、分隔线本身）由**面板容器**（`palette_view.go` 约 22 行那个带 `Padding(t.Space8)` 的 `ui.Column`）上的同一个处理器接手：落在「搜索行」或「列表」这两块矩形里就返回 `false`，其余位置返回 `true` 并开始拖动。两块矩形取这两个元素上一帧的 `Element.Bounds()`（窗口 DIP），不和坐标常量硬编码。
- 窗口留白（面板矩形之外的一圈）由**根容器**上的同一个处理器接手（§5.4 的那个 `Padding(SizePaletteShadowMargin)` 根视图）：命中链上再没别的元素，所以它收到的按下都在面板外面，不用再判断、直接 `true`。

**为什么不能“什么都不判断、一律返回 true”**：`ui/input.go` 的 `pointerDown`（约 306-310 行）只要处理器 `return true` 就直接 `return`，后面的 `rt.pressed = target`、`target.editor.press(...)`（约 378-380 行）都不会执行。而 `TextInput` 只设 `flagEditable`（`ui/textinput.go` 约 27 行）、`ButtonBase` 只设 `flagClickable`（`ui/base.go` 约 25-29 行），两者都没有输入处理器，挡不住外层容器：按下输入框或列表行时，`rt.handler(chain)`（`ui/handler.go` 约 131-138 行）取的是命中链上最先有处理器的祖先，也就是这两个容器。所以非拖动区必须 `return false`，输入框才能选字、列表行才能点；`handler.go` 约 29-38 行的“接下 `InputPointerDown` 之后移动与抬起都送到它”也正是这个代价——只有真正接下的拖动才享受它。

**焦点**：命中链上没有可聚焦元素也没有 `KeepFocus` 时，`pointerDown`（`ui/input.go` 约 322-334 行）把 `rt.focused` 清 0，同一次事件末尾的 `updateTextInput`（约 984 行）跟着停用输入法，要到下一帧 `paletteView` 的 `input.Focus()`（`palette_view.go` 约 26 行）才恢复。因此图标区、面板容器、根容器三处都要 `.KeepFocus()`（`ui/element.go` 约 948-952 行）。副作用：面板内任何按下都不再改焦点，输入框始终持有键盘——与每帧 `input.Focus()` 的现状一致，列表的 ↑↓ 本来就由输入框的 `OnShortcut` 处理。

### 2.3 选定方案：自己跟踪指针

**拖动状态**放在 `paletteState` 里（新字段，主线程使用，与既有字段同一约定）：

```go
// paletteDrag 是一次手动拖动。按下时记录屏幕点与面板起点，移动时每帧重新
// 合成屏幕点再算位移。所有坐标都是屏幕坐标（DIP，原点在主显示器左上角）。
type paletteDrag struct {
	active       bool  // 已经越过起步死区
	pressScreenX int   // 按下时指针的屏幕坐标
	pressScreenY int
	panelX       int   // 按下时的面板左上角
	panelY       int
	displayID    int64 // 当前帧面板所在的显示器（每帧重算，不是按下时的）
	snapX        bool  // 本帧吸附到竖线
	snapY        int   // 本帧吸附到哪条横线：0 无、1 默认高度、2 屏幕垂直中心
	guides       bool  // 参考线浮层是否显示
	outsideClick bool  // 双击那一按：松手不当作「点面板外」
}
```

**为什么每帧都要重新合成屏幕点**：`InputEvent.X/Y` 是**元素局部**坐标（`ui/handler.go` 的 `deliver` 约 146 行把窗口坐标换成元素盒内坐标），不是屏幕坐标；而窗口 `setFrame:` 之后，下一次 `mouseDragged:` 取到的 `locationInWindow`（`internal/darwin/surface.go` 的 `location` 约 526 行）跟着新原点走。所以「按下时记一个 `ev.X`、之后算 `ev.X - pointerX`」会在移动窗口的第一帧塌成残余量，面板回跳。正确做法是每帧把指针还原成屏幕 DIP：

```go
// palettePointerScreen 把一次指针事件的元素局部坐标还原成屏幕 DIP。
// winX/winY 是 Window.Position()（本轮窗口位置），b 是收到事件的元素的
// Element.Bounds()（上一帧、窗口 DIP），ev.X/ev.Y 是它相对元素盒的位移。
func palettePointerScreen(b ui.Rect, winX, winY int, ev ui.InputEvent) palettePoint {
	return palettePoint{X: winX + int(b.X) + int(ev.X), Y: winY + int(b.Y) + int(ev.Y)}
}
```

三项都是点、都是 DIP：`rectToMac`（`internal/darwin/window.go` 约 1387 行）只按主屏高度翻转 Y，不乘 `backingScaleFactor`。

按下（`InputPointerDown`，`Button == 0`）：

1. `Clicks == 2` → 视作「恢复默认位置」（§4.4），**不**开始拖动，置 `outsideClick = true`（这一次松手不收起），直接返回。
2. `pressScreenX/pressScreenY = palettePointerScreen(元素 Bounds, Window.Position(), ev)`。
3. 记录 `panelX/panelY`（当前面板矩形左上角，见 §5.4 的换算）。
4. `displayID = mygo.Screen.DisplayMatching(面板矩形).ID`（只在按下时定一次，用于第一帧的参考线；之后每帧重算）。
5. `active = false`、`guides = false`、`snapX = false`、`snapY = 0`、`outsideClick = false`，记下「按下但未越过死区」的状态。

移动（`InputPointerMove`）：

1. 先还原屏幕点 `p = palettePointerScreen(元素 Bounds, Window.Position(), ev)`，再算 `dx = p.X - pressScreenX`、`dy = p.Y - pressScreenY`；**第一次**超过 3 DIP 才置 `active` 并显示参考线浮层（避免点一下就让参考线闪一下）。
2. 候选位置 `candidate = (panelX + dx, panelY + dy)`。
3. **每帧重算显示器**：`display = mygo.Screen.DisplayMatching(candidate 的面板矩形)`；`display.ID` 与上一帧不同时，按该显示器的 `WorkArea` 重设参考线浮层（位置、尺寸、三条线坐标）并 `Invalidate`，这样跨屏拖动不会被锁在按下那块屏的工作区里。
4. `guides = paletteGuides(display)`；若 `active` 且未按 `⌥`（`ev.Mods & ui.Alt == 0`）按 §3.3 吸附，否则原样。
5. 用刚算出的 `display` 的工作区夹回（§4.3），按 §5.4 换算成窗口位置后 `Window.SetPosition`（窗口尺寸不变，不必 `SetBounds`）。
6. 更新参考线的加粗状态并 `Invalidate` 参考线浮层（只在吸附状态或显示器变化时重画，避免每帧重画整屏）。

抬起（`InputPointerUp`，`Button == 0`）：

1. 隐藏参考线浮层，清 `active`。
2. 若越过死区（`active` 曾为真），按松手后的面板矩形所在显示器写入位置（§4.1）；`config.PalettePositions` 为 nil 时先 `make`。
3. 否则（没越过死区）：按下点在面板矩形**外**且 `outsideClick` 为假 → 当作「点面板外」，`hidePalette()`（§5.4）；按下点在面板内 → 普通点击，什么都不做。两种都不写配置。
4. **面板不收起（拖动时）**：拖动不触发 `OnBlur`，也不调用 `hidePalette`。

要点：

- 移动时**始终用「按下时的面板位置 + 累计位移」**算候选位置，不要用「当前面板位置 + 帧间位移」。否则吸附把面板拽回去之后，下一次位移会基于被吸附的位置继续累加，指针与面板会越拖越偏。
- 位移也只能是「两个屏幕点的差」，不能是「两个元素局部坐标的差」（见上面的 `palettePointerScreen`）。`Bounds()` 给的是上一帧的值，面板拖动中只平移不改布局，够用；若将来拖动中改了布局，就先 `requestFrame()` 再取。
- 一次移动最多调一次 `SetPosition`（`InputPointerMove` 本身就是按平台的指针事件频率来的，不再自行节流）。
- 拖动期间不碰 `Show`／`Focus`／`visibility`，面板保持 key window；`a.visibility(true)` 会把激活策略切成 `Regular` 并激活应用（003 §6.2 的「绝不能做的事」），拖动中更不能用。
- 拖动期间 `paletteState.query`、选中行、列表滚动都不变；`refreshPalette` 每帧重建行时不要重置拖动状态。

### 2.4 与 nonactivating Panel、key window、输入法

### 2.5 备选：用 `Element.DragWindow`

若实测手动跟踪的手感不如系统拖动（例如拖到窗口边缘或触控板快速甩动时），可退回系统拖动，代价是：

1. 拖动中面板跟手由 AppKit 负责，**吸附只能在松手时生效**：拖动中靠 `Window.OnMove`（`mygo@v0.6.2/window.go` 约 1530 行）读窗口位置并画参考线，松手时再 `SetPosition` 贴到参考线。
2. 双击恢复默认位置必须另外找入口，只能靠命令面板的命令（§4.4）。
3. 抓手上不能挂任何点击或焦点行为（§2.2 第 4 项）。
4. 需要把 `buildPaletteWindow` 的 `DisableMove: true` 改成 `false`，否则 `setMovable: false` 可能让系统拖动无效——**这一条未实测**，`performWindowDragWithEvent:` 在不可移动窗口上的行为需要本机确认。

结论：主选手动跟踪，`DragWindow` 留作实测后的退路；两条路径共用 §3 的参考线与吸附计算和 §4 的存储，差别只在「谁在动窗口」：退回系统拖动后，§2.3 的 `palettePointerScreen` 与每帧合成整段可以整块删掉（位置由 `OnMove` 给出），§4.3 的夹回与参考线重算不变。

## 3. 参考线与吸附

### 3.1 参考线清单

只画三条，全部相对**面板所在显示器的 `WorkArea`**（已排除菜单栏与 Dock，`mygo@v0.6.2/modules.go` 的 `Display`，约 194-205 行）：

| # | 参考线 | 位置 | 吸附对象 |
| --- | --- | --- | --- |
| 1 | 竖线（屏幕水平中心） | `x = WorkArea.X + WorkArea.Width / 2` | 面板水平中心 |
| 2 | 横线（默认高度） | `y = WorkArea.Y + SizePaletteTopOffset`（96） | 面板上边缘 |
| 3 | 横线（屏幕垂直中心） | `y = WorkArea.Y + WorkArea.Height / 2` | 面板垂直中心 |

三行的值都是**屏幕坐标**（`Display.WorkArea` 就是屏幕坐标，`mygo@v0.6.2/modules.go` 约 194-205 行）。参考线浮层的盒子是**窗口局部**坐标（`Absolute().Left/Top` 相对父元素 padding box，`ui/element.go` 约 834-847 行），画之前必须减掉 `WorkArea` 原点：否则主屏那条横线会下移一个菜单栏（`WorkArea.Y` 就是菜单栏高），`WorkArea.X != 0` 的副屏竖线会整体偏出（§3.5）。

为什么是这三条：

- 第 1 条就是「居中」，是维护者截图里最明确的一条，也是默认位置的水平解。
- 第 2 条是**默认位置的那条线**：默认位置由 `SizePaletteTopOffset` 决定，用户把面板拖走以后，想回到「刚打开的样子」就得能把上边缘贴回 96。
- 第 3 条给「屏幕正中」一个落点，代价只是一条线。
- 不再加「左右三分之一」「四角」之类的辅助线：面板宽 640，屏幕宽 1440 时左右三分之一离中心只有 240，线一多反而判断不了该吸哪条。

竖线只有一条、吸附的是面板中心，不吸附左右边缘：面板宽 640 而屏幕宽 1440～1728，左右边缘对齐中心线没有可用语义。

### 3.2 出现与消失

| 时机 | 行为 |
| --- | --- |
| 指针按下拖动区 | 不显示（避免点击时闪一下） |
| 位移首次超过 3 DIP | 显示参考线浮层；浮层覆盖当前帧面板所在显示器的 `WorkArea` |

| 拖动中显示器配置变化 | 收起参考线并结束本次拖动（不改位置，不写配置）——`OnDisplaysChanged` 已经在 `main.go` 的 `ready`（约 361 行）里，回调里加一条判断 |

### 3.3 吸附算法

纯函数，便于单测：

```go
// paletteGuides 返回面板所在显示器上的参考线，屏幕坐标。
type paletteGuides struct {
	CenterX     int // 竖线
	TopY        int // 默认高度横线
	MiddleY     int // 屏幕垂直中心横线
}

// snapPalette 把候选面板位置吸到最近的参考线上。
// width/height 是面板（不是窗口）尺寸，threshold 是 SizePaletteSnap。
// 返回值里 active 表示命中了哪条线，供参考线加粗。
func snapPalette(candidate palettePoint, size paletteSize, guides paletteGuides, threshold int) (palettePoint, paletteSnap)
```

规则：

1. **横向**：面板水平中心 `candidate.X + width/2` 与 `guides.CenterX` 的距离 `≤ threshold` 时，令 `X = guides.CenterX - width/2`。
2. **纵向**：两条横线各算一次距离，取更近的那条：
   - 面板上边缘与 `guides.TopY` 的距离；
   - 面板垂直中心 `candidate.Y + height/2` 与 `guides.MiddleY` 的距离。
   命中者决定吸附后的 `Y`；两条都在阈值内且距离相等时取「默认高度」那条（它是默认位置，语义更强）。
3. 阈值 `SizePaletteSnap = 8`。8 是「明显能感到吸附、又不会把面板从手底下拽走」的量级；拖动位移在这附近时指针与面板最多差 8。
4. 吸附后仍然要过一遍 §4.3 的夹回，避免贴边时吸附把面板推出工作区（例如工作区窄于 640 时中心线吸附与夹回冲突，夹回优先）。
5. 按住 `⌥`（`ev.Mods & ui.Alt != 0`）时**跳过吸附但照常画参考线**：用户想精确摆放时线还在，手不被打断。选 `⌥` 而不是 `⌘`／`⌃`：`⌘` 在拖动时容易误触系统手势，`⌃` 是右键语义；`⌥` 上唯一的冲突是命令面板自己的 `⌥.`，而那是组合键的另一半，单独按住 `⌥` 不触发任何东西。
6. 吸附只影响最终的窗口位置，不改 `candidate` 的累计基准（§2.3 的要点）。

### 3.5 参考线的画法与颜色

## 4. 记住位置

### 4.1 存什么

存「面板矩形左上角相对该显示器 `WorkArea` 原点的偏移」，按显示器 ID 分组：

```toml
[palette_positions]
[palette_positions.732561]
x = 400
y = 96
```

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 键 | `Display.ID` 的十进制字符串 | MyGo 的 `Display.ID` 在 macOS 上是 `NSScreenNumber`，即 `CGDirectDisplayID`（`mygo@v0.6.2/internal/darwin/system.go` 的 `Displays`，约 154-183 行）：一个运行时显示器编号，不是序列号，也不是显示器名，公开配置里不出现设备信息 |
| 值 | 相对偏移 `(x, y)` | 存绝对屏幕坐标会在「显示器换了摆放位置或主屏换了」之后失效；相对偏移跟着显示器走 |
| 只存面板矩形 | 不含 `SizePaletteShadowMargin` | 阴影留白属于实现细节（§5.4），改 Token 不该让用户的位置漂移 |

作者用 `go-toml v2.2.4` 试过 `map[string]struct{X, Y int}` 的编解码往返：生成的是 `[palette_positions.<id>]` 表，回读正确，键为负数字符串（`-42`）也没问题。所以配置字段按 `map[string]paletteSeat` 写即可。

**写入前必须先 `make`**：旧 `config.toml` 没有 `palette_positions` 一节，`loadConfig` 解出来是 nil map，直接赋值会 panic。所有写入（拖动松手、双击恢复、命令恢复）统一走一个小函数：

```go
// putPaletteSeat 记下某块显示器上的位置；旧配置里没有这个 map 时先建。
func (c *Config) putPaletteSeat(key string, seat paletteSeat) {
	if c.PalettePositions == nil {
		c.PalettePositions = map[string]paletteSeat{}
	}
	c.PalettePositions[key] = seat
}
```

删除那条用 `delete`（对 nil map 也安全），不必另写一个函数；删空后保留空 map 即可，不用把整个字段移除。

### 4.2 什么时候写

| 时机 | 写不写 |
| --- | --- |
| 拖动松手（越过 3 DIP 死区） | **写**：按松手时面板矩形所在显示器（`Screen.DisplayMatching`）记一条；map 为 nil 时先 `make`（§4.1） |
| 双击拖动区恢复默认 | **写**：删掉当前显示器的那条；那一次松手不当作「点面板外」，面板不收起 |
| 执行「恢复默认位置」命令（§4.4） | **写**：删掉当前显示器的那条 |
| 面板只是被打开、被 `placePalette` 夹回 | **不写**：避免每次显示都改配置，也避免显示器临时变化把用户的位置覆盖掉 |
| 拖动中显示器配置变化 | **不写**（§3.2） |

### 4.3 打开时怎么摆、怎么夹回

`placePalette`（`palette.go` 约 177 行）现在固定「鼠标所在屏幕居中 + `SizePaletteTopOffset`」。改为：

1. `display = mygo.Screen.DisplayNearestPoint(mygo.Screen.CursorScreenPoint())`（保持现状：在哪个屏幕按 ⌥. 就在哪个屏幕开）。
2. 面板尺寸为 `SizePaletteWidth × SizePaletteHeight`（不读窗口尺寸，窗口含阴影留白，见 §5.4）。
3. 若 `config.PalettePositions[key(display.ID)]` 存在 → `x = display.WorkArea.X + seat.X`、`y = display.WorkArea.Y + seat.Y`；否则用默认值：水平居中 + `SizePaletteTopOffset`，与现在的 `palettePosition`（`palette.go` 约 189-196 行）一致。
4. **夹回**：过 `paletteClamp`（拖动帧也用同一个，见下）。
5. 换成窗口位置（§5.4）后 `SetPosition`。

`paletteClamp` 的语义（**第 2 版改正**：第 1 版写「贴左上角」，实际只有纵向成立）：

```go
// paletteClamp 把面板矩形收进工作区；工作区容不下面板时该方向不动，
// 保留调用方给的位置（打开时那个位置已经是 palettePosition 的兜底）。
func paletteClamp(p palettePoint, size paletteSize, work mygo.Rectangle) palettePoint {
	if work.Width >= size.Width {
		p.X = clamp(p.X, work.X, work.X+work.Width-size.Width)
	}
	if work.Height >= size.Height {
		p.Y = clamp(p.Y, work.Y, work.Y+work.Height-size.Height)
	}
	return p
}
```

| 情况 | 横向 | 纵向 |
| --- | --- | --- |
| 工作区容得下面板 | 夹在 `[WorkArea.X, WorkArea.X + Width - w]` | 夹在 `[WorkArea.Y, WorkArea.Y + Height - h]` |
| 工作区比面板窄（竖屏小副屏） | 不动：打开时即 `palettePosition` 的「水平居中、两边等量溢出」，拖动时即指针给的位置 | 不动：打开时即 `palettePosition` 的「贴工作区顶」 |

打开时纵向的兜底仍是现状：`y = WorkArea.Y + SizePaletteTopOffset`，若 `y + height` 超出，`palettePosition` 已经把它改成 `max(WorkArea.Y, WorkArea.Y + Height - height)`，也就是工作区矮于面板时贴顶。所以「与现状同一策略」只在纵向成立；横向现状是**居中**（`(WorkArea.Width - width) / 2`），并非贴左，本文不改这个行为。

**拖动帧的夹回要用当前帧的显示器**：每帧先 `display = Screen.DisplayMatching(候选面板矩形)`，再拿这个 `display.WorkArea` 过 `paletteClamp`（§2.3 移动第 3、5 步）。按字面用按下时那个 `displayID` 的工作区，会把面板锁在按下那块屏里，与 §7.3 的「两个显示器之间拖动」直接矛盾。

触发夹回的场景：分辨率变小、Dock 变大、显示器旋转、把面板拖到副屏后拔掉副屏（此时 `DisplayMatching` 已经落到另一块屏，键找不到 → 用默认位置）、系统重启后 `Display.ID` 变化（同上，落回默认位置，不报错）。

**记录“显示器 ID 是否稳定”**：`CGDirectDisplayID` 在同一显示器、同一接口的连续开机之间通常是稳定的，但换接口、接扩展坞、某些显示器休眠重连后可能变。因此「找不到键 → 用默认位置」必须是**正常路径**，不能当成异常；用户最多重新拖一次。

### 4.4 恢复默认位置

两条入口，都指向同一个函数 `a.resetPalettePosition()`：

1. **命令面板里的一条命令**（必需）：在 `commands.go` 的 `systemCommands`（约 271 行）里加

   | 字段 | 值 |
   | --- | --- |
   | `ID` | `palette.position.reset` |
   | `Title` | `localizedTitle("PaletteResetPosition")`（「恢复默认位置」／"Reset position"） |
   | `Keywords` | `位置`、`归位`、`居中`、`position`、`weizhi`、`wz`、`center`、`reset` |
   | `Icon` | `move` 或已有的 `locate-fixed`（需按 Lucide 0.468.0 补资产；也可先用已有 `settings-2` 之外的任一合适图标，见 §8） |
   | `Available` | `nil`（恒可用） |
   | `Run` | `a.resetPalettePosition()` |

   `Run` 的行为：删掉**面板当前所在显示器**（不是鼠标所在显示器）的那条记录、`save()`、按默认位置重摆（面板此刻已经因为执行命令而收起，重摆只是把窗口挪好，下次打开就是默认位置）。

2. **双击拖动区**（定稿：做）：`InputPointerDown` 的 `Clicks == 2` 直接视作恢复默认位置（§2.3 第 1 步）。成本几乎为零，且 `DragWindow` 抢走了双击的系统语义（§2.2 第 5 项），不会有歧义。双击那一按不进拖动，它的松手也不按「点面板外」收起（`paletteDrag.outsideClick`）。

### 5.3 已定方案 A 与理由

维护者定稿：**外观按方案 A**。B 与 C 仅作背景保留（若实测手感或观感不达标再回头讨论）。

1. **维护者要的观感系统阴影给不了**：大而柔、偏下、不发灰，需要自己定偏移与模糊；系统阴影的形状由 macOS 决定。
2. **深浅两套数值一次写清**：8% 黑的外描边在浅色下几乎只是「收一下边」，70% 白的内高光负责「微微凸起」，阴影用纯黑低透明度、向下偏 8，看着是投影不是灰雾；深色把外描边换成低透明白，否则黑边在深色里消失。
3. **可回归**：所有数值都是 Token，`tokens.py --check` 能守住，改起来只改设计源。
4. **代价可控且有已知限制**：窗口变大到 704 × 464，四周 32 DIP 的透明留白会吃掉点击（点在这一圈不会传给下面的应用），拖动区反而变大；面板位置与配置都按面板矩形算，不受影响。留白挡点击是**已接受的限制**，点上去时面板的反应定在 §5.4。

若将来只想要系统阴影的观感，退回 B 的改动是「删掉 `DisableShadow: true` 与自绘阴影、只留一个 `InsetShadow` + 一个 Token」；C 只在同时要毛玻璃时考虑，且需重新验材质与描边的对比度。

### 6.4 设置页与高度公式

「快捷键」页（`a.page == 3`，`awake_view.go` 的 `awakeSettings`，约 470 行）从 5 行变 6 行，顺序：

| 行 | 左 | 右 |
| --- | --- | --- |
| 1 | 常亮开关 `R05ShortcutLabel` | 录制按钮（默认 ⌃⌥⌘K） |
| 2 | 新建 JSON 窗口 `JSONShortcutLabel` | 录制按钮（默认 ⌃⌥⌘J） |
| 3 | 命令面板 `PaletteShortcutLabel` | 录制按钮（默认 ⌥.） |
| 4 | **卡片面板 `PanelShortcutLabel`（新增）** | 录制按钮（默认 ⌃⌥⌘P） |
| 5 | 反馈方式 `FeedbackMode` | 三段分段控件（002） |
| 6 | 提示位置 `FeedbackPosition` | 五段分段控件（002） |

高度（`main.go` 的 `settingsHeight`，约 169 行，`page == 3` 分支）：

- 内容高 = `6 × SizeRowHeight + 5 × StrokeHairline` = `6 × 48 + 5 × 1` = **293**。
- 窗口高 = `max(SizeWindowMinHeight, 293 + 2 × Space24)` = `max(176, 341)` → 按 `Space4` 向上取整 = **344**。
- 带错误图标时再多 `Space8 + SizeIcon` = 24 → 317 + 48 = 365 → 取整 **368**。

**必须同时改 `settingsMinimumSize`**（约 190 行）：它现在只按关于页算（`settingsHeight(t, 1, true) + 2 × Space24 + SizeRowHeight` = 340），6 行的快捷键页带错误图标需要 368，否则内容会被窗口裁掉。改法：取旧值与 `settingsHeight(t, 3, true)` 的大者：

```go
func settingsMinimumSize() (int, int) {
	t := tokens(false, "zh-CN")
	height := settingsHeight(t, 3, true)
	height = max(height, settingsHeight(t, 1, true)+int(2*t.Space24+t.SizeRowHeight))
	return int(t.SizeWindowWidth), height
}
```

副作用：设置窗口的最小高度与默认高度从 340 涨到 368（用户自己拉大过的尺寸不受影响）。这是本次唯一影响设置窗口外观的数值变化，验收时看一眼四页都不裁切。

**跨规格同步**：002 §2.2 的「快捷键页 5 行 + 4 条分隔线 = 244，窗口 292」按 6 行改成「6 行 + 5 条分隔线 = 293，窗口 344」；003 §2.4 的 `rows = 5` 同样改成 6（003 写的是「合并后固定 5 行」，卡片面板这一行落地后就是 6 行）。

### 6.5 要不要走 002 的屏幕提示

**不提示**。002 的规则是「只有本次操作没有其它可见结果时才提示」（002 §1.1），卡片面板从无到有、从有到无本身就是结果，屏幕上立刻能看到，再弹一条「已展开」既重复又慢半拍。命令面板同理（003 §9）。`FeedbackMode` 的设置与实现完全不动。

| 10 | 在另一块屏按 ⌥.，用哪个位置 | **该屏记住的位置**（没有就默认）；只有拖动才会改变归属 |
