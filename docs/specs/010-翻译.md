## 1. 场景、频率与流程

### 1.1 使用场景

需求是把 Cubbix 当作基础翻译用：英文词/短语查中文为主，少数整句整段中英互译，偶尔听一个词的读音。据此把场景收敛成五类：

| # | 场景 | 输入形态 | 期望 | 频率 |
| --- | --- | --- | --- | --- |
| 1 | 读英文文档/代码注释时查一个词 | 单个英文单词（手选或划词） | 立刻看到中文释义，必要时看本机词典的英文原文 | 每天多次 |
| 2 | 读英文长句/段落时想确认意思 | 一句话到一段话 | 通顺的中文，边出边看 | 每周数次 |
| 3 | 写英文邮件/文档时把中文翻过去 | 中文句子 | 通顺的英文 | 每周数次 |
| 4 | 脚本/Agent 里批量翻译一段文本 | 任意文本 | 拿到结果文本（CLI） | 每周数次 |
| 5 | 想听一个词的读音 | 单个英文单词 | 系统语音念一遍 | 低频，可自动 |

频率整体不高（每天几次到十几次），所以取舍一律偏向「少占界面、少加状态」。这也是不做历史、不做多服务对比、不做生词本的原因（§8）。

### 1.2 主流程

```
⌃⌥⌘T
  ├─ 面板已开 → 关闭（与 ⌥. 同一条 toggle 语义；有译文时也关）
  └─ 面板未开
       ├─ 前台应用不是我方 → 读 AX 选中文字（≤ 200 ms 预算）
       │    ├─ 拿到非空文本 → openTranslateText(text)
       │    └─ 空 / 无权限 / 不支持 → openTranslateText("")，输入框聚焦
       └─ 前台应用是我方 → openTranslateText("")，输入框聚焦

openTranslateText(text) → submitTranslate()
  ├─ 原文判型：isSingleEnglishWord → 并发（词典查询 || 模型请求）
  │                              └ 否则 → 只发模型请求
  ├─ 方向：detectDirection；方向行只显示一行灰字，点它交换一次方向
  ├─ 模型未配置 → phase = notConfigured，译文块给「去设置」；单词时词典块仍可显示
  └─ 流式返回 → phase = streaming，逐段追加到译文块
       └─ 结束 → phase = done；单词且开关打开 → speakText(原文)

失焦（window.OnBlur）→ onTranslateBlur()
  ├─ 有结果（output 或 dictionary 非空）且输入框非空 → 保留，什么都不做
  └─ 否则 → hideTranslate()（先取消在途请求）
Esc / 再按 ⌃⌥⌘T / 点关闭按钮 → closeTranslate()（先取消在途请求，再关）
```

步骤与函数（接口细节见 §5.2）：快捷键回调 `a.toggleTranslate` → `a.captureSelection` → `a.openTranslateText` → `a.submitTranslate` → `streamTranslation`（worker goroutine）→ `mygo.RunOnMain` 追加 → `a.refreshTranslate`（`SetContentSize` + `Invalidate`）；失焦走 `a.onTranslateBlur`，关闭统一走 `a.closeTranslate`。

`openTranslateText` 是**面板侧唯一入口**：快捷键、命令面板、卡片面板都落到它，函数里做「互斥收起其它面板、填原文、提交、刷新」这一串；CLI 走独立的 `applyTranslateCLI`（只取文本、不开面板，见 §5.5）。

### 1.3 判型与方向

两条纯函数，全部可单测：

1. **是否单个英文单词** `isSingleEnglishWord(s)`：`strings.TrimSpace` 后必须匹配 `^[A-Za-z][A-Za-z'\u2019-]{0,47}$`，即字母开头、只含字母与连字符/撇号、长度 1–48、没有空格与数字。命中才查系统词典。
   - 词组（`take into account`）**不查词典**：实测 `DCSGetTermRangeInString` 只返回第一个词的区间（`{0,4}` → `take`），`out of the box` 返回整句区间 `{0,14}` 但释义头是 `box`（§2.2）。判型在前置位置完成，词典函数不会收到词组；即使误传，`DCSGetTermRangeInString` 返回区间未覆盖整个 term 时按「未命中」处理。
2. **译向** `detectDirection(s)`，按顺序判定，先命中先返回：
   - 含日文假名（平假名/片假名）或韩文谚文 → `source:"auto", target:"zh-Hans"`。这是「建议改 10」的落地：把日文/韩文强制到简体中文；提示词里再写一遍（§5.2）。
   - 含任意汉字（`unicode.Is(unicode.Han, r)`，≥ 1 个）→ `source:"zh-Hans", target:"en"`。**不再用「汉字占汉字+拉丁字母 ≥ 0.15」的比例阈值**：第 1 版那个规则把「用 Cubbix」（1 汉字 + 6 拉丁字母，汉字占汉字+拉丁字母约 0.14）判成译中文，与「输入中文就译成英文」和文中举例都相反。改完后「用 Cubbix」→ 译为英文，「Cubbix 的翻译」→ 译为英文，「hello 你好」→ 译为英文。
   - 其余（英文、法文、纯标点/数字、纯汉字日文）→ `source:"auto", target:"zh-Hans"`。
   - **已知偏差（已定，§8 第 17 行）**：纯汉字日文（如 `日本語`，没有假名可判）仍按「中文 → 英文」走。要消掉它只能引入语言识别，超出本模块范围；按评审「建议改 10」的结论写明接受，不再提问。
   - 判定结果只用于提示词与界面上那一行方向灰字，不写配置。点方向行的交换规则见 §3.3。

### 1.4 与既有入口的关系

- 与卡片面板（001）、命令面板（003）**互斥**：`openTranslateText` 前先 `a.hideMenubarPanel()` 与 `a.hidePalette()`；反向由 001/003 已有入口负责，不改它们的代码。三者同时最多一个可见。
- 浮窗**不激活应用**、**不切 Space**、**不写窗口位置**（008 的位置记忆只覆盖设置窗口与 JSON 窗口，翻译浮窗是固定位置，理由见 §3.1）。
- 不做屏幕提示（002）：面板本身就是反馈。CLI 的静音规则沿用 006（`a.quiet`）。
- 有译文时失焦保留，是刻意与命令面板（`palette.go` 的 `buildPaletteWindow` 里 `OnBlur` 的启动器语义）不同：对照原文时点回文档，结果不能消失（§8 第 2 行）。

### 2.1 读选中文字

**方案：AX 只读取，不模拟按键。**

调用链（平台调用在 `translate_selection_darwin.go`，`//go:build darwin`；超时与代次在 `translate_selection.go`）：

1. dlopen HIServices 子框架；`AXUIElement*` 在子框架里，直接 dlopen 子框架路径比 dlopen 伞形框架稳（实验即用该路径，符号全部解析成功）。
2. **自己建属性名 CFString**：`kAXSelectedTextAttribute`、`kAXFocusedUIElement`、`kAXFocusedApplication`、`AXRole` 都是头文件宏（`AXAttributeConstants.h` 里 `#define kAXSelectedTextAttribute CFSTR("AXSelectedText")`），**不是可 `dlsym` 的符号**。对 HIServices 做 `dlsym` 得到空指针，把空指针传给 `AXUIElementCopyAttributeValue` 会返回 `-25201`（`kAXErrorIllegalArgument`）。实现用 `CFStringCreateWithCString`（`kCFStringEncodingUTF8`）或等价方式自建 `CFStringRef`，用完 `CFRelease`；`kAXSelectedTextAttribute` = `CFSTR("AXSelectedText")`、`kAXFocusedUIElement` = `CFSTR("AXFocusedUIElement")`、`kAXFocusedApplication` = `CFSTR("AXFocusedApplication")`、`AXRole` = `CFSTR("AXRole")`。
3. `AXIsProcessTrusted()` 判权限。**不要**用 `AXIsProcessTrustedWithOptions` 带 prompt，它会在被调用的瞬间弹系统授权框；我们要么不弹，要么由用户点按钮后跳系统设置（§3.5）。复核实验里临时进程返回真且没有弹窗；**这只说明检测函数可用，不能当成 Cubbix 已授权**。
4. 取前台应用 pid：
   - 用 `NSWorkspace.frontmostApplication` 直接取 pid，再创建应用级 AX 元素。
   - **已复现的负面结果**：非 GUI 的命令行进程里，系统级元素的 `AXFocusedUIElement` 与 `AXFocusedApplication` 都返回 `-25204`（`kAXErrorCannotComplete`）。
   - 第二条路已经验证：`NSWorkspace` 的 `frontmostApplication` 在临时进程里**取到了 pid**，用该 pid 经 `AXUIElementCreateApplication` 再读焦点元素返回 `0`，`AXSelectedText` 返回 `0` 且长度为 0（没有打印文字）。第 1 版把这条标成「未实测」，本版按复核结论改成「已取到 pid 并据此读到焦点元素」。真实应用里选中文字的命中率仍归 §6.2。
   - 第 4 步评审接受这条直接链：前台 pid 本来就是 NSWorkspace 的职责，额外的系统级 AX 查询没有增加已验证的覆盖面，反而消耗 200 ms 预算。非 GUI 实验失败不能推论 GUI 必定失败；这里只是取消冗余的首选链，不宣称系统级不可用。pid 为空或是 Cubbix 自己时不读选中文字。
5. `AXUIElementCopyAttributeValue(focused, kAXSelectedTextAttribute, &value)`，把 `CFStringRef` 用 `CFStringGetLength` + `CFStringGetMaximumSizeForEncoding` + `CFStringGetCString(UTF-8)` 转成 Go 字符串，然后 `CFRelease`。
6. worker 的 context 为整条链设置 200 ms 截止时间；应用级元素和焦点元素在各自读取前分别用 `AXUIElementSetMessagingTimeout` 设置剩余秒数（`float32`），设置失败就退回空输入。SDK 明确元素超时只对该对象有效，因此不能只在应用级元素上设置。每次读之前检查截止时间，所有非空的 Copy 输出均释放，焦点元素与字符串分别核验 CF 类型。每个应用实例最多保留一个在途原生读取；超时结果不应用，迟到调用结束后释放对象和 worker，再允许新读取。

**返回值怎么归类**（复核实验实际见到的两种「无选中」形态都要当没有选中）：

| 结果 | 含义 | 处理 |
| --- | --- | --- |
| `0` 且字符串非空 | 有选中 | 直接翻译 |
| `0` 且字符串为空 | 支持该属性但没有选中（复核实验在文本框上见到） | 打开空输入框 |
| `-25212`（`kAXErrorNoValue`） | 该元素没有这个属性 | 打开空输入框 |
| `-25211`（`kAXErrorAPIDisabled`） | 没授权 | 打开空输入框 + 本次会话引导 |
| `-25204` / 其它 | 应用不响应或超时 | 打开空输入框，不重试 |
| `-25201`（`kAXErrorIllegalArgument`） | 属性名 CFString 没建对（实现 bug，不该出现） | 打开空输入框；单测用假 seam 覆盖，见 §6.1 |

另外三条约束：

- 读之前判 `AXIsProcessTrusted()`，为假直接跳过 AX，不产生任何错日志噪音。
- 前台应用是自己（pid 相同）时不读。
- 取到的文本按 `MaxTranslateInput = 4000` 个字符截断（超出时在面板里提示已截断，见 §3.2），避免把整篇文档灌进提示词。

**⌘C 兜底：已定不做。** 理由逐条（§8 第 7 行照此结论）：

1. 需要同样的辅助功能权限，权限这一层没有变松；它只多覆盖「实现了复制、但没实现 `AXSelectedText`」的应用。
2. 代价是剪贴板：要先读全部表示（`mygo.Clipboard.Read()`），再写回（`Write(data)`），中间这段时间里用户自己的剪贴板被占用；富对象往返保真度无法保证，这是会丢用户数据的那一类风险。
3. 合成事件（`CGEventPost`）在安全输入框里会被系统吞掉，在终端/编辑器里还可能触发应用自己的绑定。`CoreGraphics` 的 `CGEventPost` 符号能解析，仍然不采用。
4. 时序上要和用户的真实 ⌘C 抢，需要等剪贴板 `changeCount` 变化或超时，最坏 200–300 ms。

所以：**AX 失败就退回输入框**，并在面板里给一行可关闭的说明（§3.5）。本节不再提供 ⌘C 兜底的实现契约，`TestTranslateClipboardRestore` 也不写（§6.1）。

### 2.2 macOS 系统词典（Dictionary Services）

**接口**：`CoreServices.framework/Frameworks/DictionaryServices.framework` 的 `DCSGetTermRangeInString` / `DCSCopyTextDefinition`（头文件 `DictionaryServices.h`）。签名是纯 C，没有回调；前者按值返回 `CFRange`，后者按值接收 `CFRange` 并返回 `CFStringRef`。`CFRange` 的两个字段均为 `CFIndex`，在 macOS 的 64 位目标上用两个 `int64` 对应；purego v0.11.1 支持该结构体的传参与返回。

**复核后的实测结果**（`CGO_ENABLED=0`，purego v0.11.1；第 1 版与评审各自在仓库外临时目录完成，临时程序已删除）：

| 输入 | 用 `offset=0` 的自动区间 | 结论 |
| --- | --- | --- |
| `hello` / `serendipity` | 区间覆盖整个词 | 单词正常；`serendipity` 释义开头与文中引文一致 |
| `take into account` | 区间 `{0,4}` → 命中 `take` | 只拿到第一个词，不是词组；`take` 的释义是 16502 个 UTF-16 字符（第 1 版写的「16656 字节」是同一条的另一种计数） |
| `out of the box` | 区间 `{0,14}`（整句）→ 释义头却是 `box` | 即使区间覆盖整句，拿到的仍是单个词的释义 |
| 整串区间（最长 20000） | 返回空 | 不要把整串区间传给 `DCSCopyTextDefinition`，拿不到词组释义 |

释义是**一整段纯文本**：词头、音节点、音标、词性、义项、例句、词源全在一个字符串里，没有结构，读音用 `|` 与 `·` 分隔。**界面上只能按纯文本显示**，不做结构化解析。

**重复查询的内存结论（必须改 1）**：第 1 版的「同词二次查询内存爆到 GB 级」以及由此推出的「每词只能调用一次，否则进程被杀」全部删掉。评审在同一种调用上复核：

| 情形 | maximum resident set size |
| --- | --- |
| `serendipity` 连续调用 2 次 | 26787840 字节 |
| 按设计里的函数签名（`CGO_ENABLED=0`、purego v0.11.1）再查 8 次 | 30523392 字节 |
| `hello` 与 `Hello`、两个不同词、整串区间 | 都停在约 30 MB |

评审列出的那组 GB 级数字（10 GB、176 MB、409 MB、8.7 GB）在复核中都没有出现。原因没有继续追查（**推测**：第 1 版那次测量把不相关的进程/计数混进来了），但结论明确：**重复调用不是内存炸弹，也不是正确性问题**。

因此本版的硬约束只有一条：

- **只对单个英文单词查词典**，理由是「词组拿不到整条释义」（上面的表），**不是**内存。判型 `isSingleEnglishWord` 在调用前完成；`dictionaryDefinition` 内部再用「返回区间是否覆盖整个 term」做一次防御性判断，不覆盖就返回空。
- 进程级缓存（键 `strings.ToLower(strings.TrimSpace(term))`，有上限的 map，例如 64 条，只在内存、不落盘）**保留，但只是少打系统的优化**：命中缓存不二次调用；缓存被淘汰或未命中时重复调用系统接口是合法的。禁止把「每词只调一次」写成正确性条件或写进测试断言。
- **离线可用**：释义在毫秒级返回，说明走的是本地词典数据；系统里存在词典资产目录。没有断网验证，所以表述为「有本地资产、实测毫秒级返回」，不断言「拔网也一定行」（§6.2 归入维护者实测）。

### 2.3 钥匙串与 API Key

**不需要自己写 purego**：MyGo v0.6.2 已经公开 `mygo.Secrets`（`mygo@v0.6.2/secrets.go` 的 `SecretsModule.Set/Get/Delete`、`Service`、`ErrSecretNotFound`、`MaxSecretSize = 2560`），macOS 上就是登录钥匙串的 generic password，内部实现是 purego 调 `SecItemAdd` / `SecItemCopyMatching` / `SecItemUpdate` / `SecItemDelete`（`mygo@v0.6.2/internal/darwin/secrets.go` 的 `keychain`）。

采用它的三个理由：

1. 已经在本仓库的依赖里，不新增依赖，也不用自己维护 CFDictionary 的构造与释放。
2. `Secrets` 的注释写明：`Secrets.Get` 可以从任意 goroutine 调用并且可能阻塞（系统可能要求解锁或确认），主线程不被卡住——正是我们要的语义；`MaxSecretSize = 2560` 足够一般 API Key。
3. 服务名默认取应用标识符；`Secrets.Service("…")` 可指定，**不用指定**：同一个应用的配置与密钥放一起。

**把「别的程序读不到」这句改准（建议改 4）**：`mygo@v0.6.2/secrets.go` 的 `Secrets` 注释明确写了「同用户的其他程序仍可能读到，Linux 上不问」，并且「macOS 上换签名的构建会再要一次授权」。钥匙串提供的是系统级加密存放与按应用的隔离，不是绝对不可读。第 1 版那句绝对化表述删掉，方案仍然用 `mygo.Secrets`，文档里只写「存于系统钥匙串；同用户的其他程序仍可能读取，macOS 换签名构建会再次要求授权」。

约定：

- 键名固定 `translate-api-key`；`Get` 返回 `mygo.ErrSecretNotFound` 表示未设置。
- 读写都在 worker goroutine 上做，主线程只拿结果。
- **界面掩码（必须改 5）**：`mygo@v0.6.2/ui/textinput.go` 的 `Password` 已经存在，会把单行输入隐藏（`Password` 对多行无效，所以 Key 行必须用单行的 `ui.TextInput`，不能用 `TextArea`）。设置行调用 `ui.TextInput(...).Password()`；提交后立即清空输入框，保存成功后只留「已保存」与「替换」「清除」两个文字按钮；点「替换」才显示输入框，未保存时只显示输入框，不画状态点。**已保存的值永不回显明文，也永不写日志**。第 1 版「`ui` 没有密码掩码、需要自己画 `•`、v1 不做」整段删掉。
- 首次写入可能触发系统钥匙串授权框（未实测）；失败时 `settingsError` 用 `TranslateKeyError`，不清空已有值。
- 0600 配置文件作为**不采用**的备选：明文落盘且随备份/同步外流，与「公开仓库不存凭据」的纪律不匹配。
- **日志**：HTTP 失败只记资源键与状态码，例如 `log.Print("translate: status 401")`；**不要 `log.Print` 整个 `url.Error`**，它带地址（建议改 4）。不记 URL、Key、原文、译文、响应体。

### 2.4 系统语音

**两条路，先 AVSpeech，再 `say`。**

- **AVSpeechSynthesizer**：Objective-C 类。复核实验：dlopen `AVFAudio` 之后 `objc_getClass("AVSpeechSynthesizer")` 非空，`alloc` / `init` 成功；`objc_getClass("AVSpeechUtterance")`、`objc_getClass("AVSpeechSynthesisVoice")` 同样可解析（第 1 版实验还验证了不 dlopen 对应框架时 `NSSpeechSynthesizer`/`NSApplication` 取到 0，这条要写进实现注释）。调用方式：`alloc` + `init`，`utteranceWithString:`，`setVoice:`（`voiceWithLanguage:` 取当前语言），`speakUtterance:`，停止用 `stopSpeakingAtBoundary:`。
- **合成器生命周期（建议改 8）**：合成器在**主线程创建**，并保留到朗读结束才释放（用 `translateState.speaking` 与一个持有引用的字段管理），否则对象被回收后朗读会被截断；创建、`alloc`、`init`、`speakUtterance:` 任一步失败才退回 `say`。`speakUtterance:` 本身在复核实验里**没有调用**，出声与打断仍未实测。
- **`say` 兜底**：`say` 命令存在，`say -v '?'` 能列出音色。用 `exec.Command` 起子进程，`Process.Kill` 停止；不需要权限。两个都失败时，按钮的失败提示用 `TranslateSpeakFailed`（tooltip），不弹窗。

**未实测**：是否真的出声、能否在朗读中被打断、与系统「朗读所选内容」是否抢同一个通道、`say` 兜底是否被触发过，全部归入 §6.2。为不在无人值守时出声，**自动发音只在「面板正在前台显示 + 输入是单个英文单词 + 开关打开」三个条件同时成立时触发**，且每次打开最多一次。

### 2.5 MyGo 的浮窗、快捷键与输入

- **浮窗**：`WindowOptions.Panel = true`。`mygo@v0.6.2/window.go` 的字段注释明确写了：面板浮在所有应用窗口与全屏应用之上、在用户当前 Space、不进 Dock/切换器，且「显示或聚焦它会给它键盘但**不激活应用**，应用保持活动、并在面板隐藏后拿回键盘」。`mygo@v0.6.2/internal/darwin/window.go` 的 `createWindow` 对 `Panel` 加上 `styleNonactivatingPanel`、`setHidesOnDeactivate:` 为 0，以及加入所有 Space（含全屏）的 collection behavior；`window.Show` 在 `Panel` 为真时**不调** `activateIgnoringOtherApps:`。命令面板（`palette.go` 的 `buildPaletteWindow`）用的就是这套，可直接照抄窗口结构：`Frameless` + `Transparent` + `DisableShadow` + 自带阴影边距 + `OnBlur`。
  - `setHidesOnDeactivate:` 为 0 意味着 AppKit 不会因应用失焦自动藏起面板，正好配合 §3.8 的失焦规则：**由应用自己的 `OnBlur` 决定关不关**，不要再靠系统代劳。
- **已知限制（与 001/003 相同）**：设置窗口或 JSON 窗口可见时应用是 `ActivationPolicyRegular`（`main.go` 的 `visibility`），这时面板能否浮在别人的全屏 Space 上不作验收条件，实现时实测并记录。按「建议改 2」，**`showTranslate` 不调用 `visibility`**：那个函数在设置或 JSON 窗口可见时会把策略设成 `ActivationPolicyRegular`，MyGo 会随之激活应用，把用户从原来的应用/Space 拉回来；未配置时打开设置走 `a.show()`（§3.5）。
- **快捷键**：第 5 个槽位，走既有的 `registerSlot`（`awake_app.go`），自动获得「与其它槽位冲突检测、注册失败提示、录制时挂起/恢复、只注销自己持有的组合」这一整套（`awake_view.go` 的 `shortcutSlots`、`shortcutConflict`、`restoreShortcuts`）。**不能**绕过它自己调 `mygo.GlobalShortcut.Register`。现有函数按四个 target 写死，必须逐一加 translate 分支：`awake_view.go` 的 `shortcutSlots`、`shortcutSettingsRow`、`recordShortcut`、`slotError`、`clearSlotError`、`shortcutSlotEnabled`、`beginTileShortcutRecording`、`restoreShortcuts`，以及 `awake_app.go` 的 `setSlotError`。`recordShortcut` 的 `default` 分支**不得再兜底写 `AwakeShortcut`**：改成显式 `case "awake"`，未知 target 什么都不写，只把草稿交给录制状态机；`shortcutSlotEnabled("translate")` 返回模块开关，关闭时该行置灰；注册失败经 `setSlotError` 写入 `ShortcutUnavailable`。
- **输入**：`ui.TextArea`（`mygo@v0.6.2/ui/api_gen.go`）+ `OnTextKey`（`mygo@v0.6.2/ui/textinput.go`）。`OnTextKey` 的文档注释给的例子就是「Enter 发送、Shift+Enter 换行」，与本模块要的「改后回车重译」完全一致，不需要自己拦键。结果区译文用 `ui.Text(...).Selectable()`（`ui/textinput.go` 的 `Selectable`）让用户能选中、⌘C 复制。Key 行是单行 `ui.TextInput` + `Password()`（§2.3）。
- **动态尺寸**：`Window.SetContentSize`（`mygo@v0.6.2/window.go`），与卡片面板 `refreshMenubarPanel`（`menubar_panel.go`）同一手法。
- **命令面板的命令模型（必须改 2）**：`commands.go` 的 `command{…, Param, Run}` + `request{Command, Arg, Awake}`。第 1 版写「`翻译 <文本>` 直接可用」是错的：
  - `commands.go` 的 `splitCommandQuery` 先 `strings.ToLower(normalizeQuery(query))` 再切参数，切出来的 `Arg` 是**全小写**文本；
  - `palette.go` 的 `refreshPalette` 只在 `cmd.Param == paramAwake` 时把 `prefix.Arg` 写进 `request.Arg`，其它参数命令的 `Arg` 是空的；
  - 结果 `Run` 拿到的是空字符串或全小写，大小写和专名都丢了。
  - 修法：小写副本**只用于匹配**，原文从未经小写的查询里按同一段切（§5.4），并且 `paramText` 要单独写入 `request.Arg`。

### 2.6 默认快捷键的选取

已有占用：`⌃⌥⌘K`（常亮）、`⌃⌥⌘J`（JSON）、`⌃⌥⌘P`（卡片面板）、`⌥.`（命令面板）、`⌘,`（设置），都在 `config.go` 的 `defaultConfig` 与 `knownShortcutConflict`（`awake_view.go`）里。

| 候选 | 判断 | 结论 |
| --- | --- | --- |
| `⌃⌥⌘T` | 与前四个同族、同手指区，不在 `knownShortcutConflict` 的任何一组里；`⌃⌘T`、`⌥⌘T`、`⌃⇧⌘T` 是另一组键，不是 Apple 公开的系统全局组合 | **采用**（已定，§8 第 15 行） |
| `⌃⌥⌘Y` / `⌃⌥⌘G` | 同样空闲，但离 ⌃⌥⌘ 更远 | 备选 |
| `⌥T` / `⌃⌘T` | 与输入法、终端、IDE、浏览器常用组合冲突概率高 | 不用 |

取它之后**不改** `knownShortcutConflict`：那张表只放本应用已占用与已知系统占用的组合；用户若改成一个系统组合，录制器本来就会按 `ShortcutSystemConflict` 提示。`GlobalShortcutModule.Register` 没有四槽上限，第五个走 `registerSlot` 即可；某个应用若已占用这一组，现有注册失败显示 `ShortcutUnavailable`。本轮没有真正注册。

### 2.7 复核后可复现的最小实验

第 1 版与评审的实验都在仓库外的临时目录用 `CGO_ENABLED=0` 编译一个不依赖 MyGo 的程序（只用 purego v0.11.1），跑完删除；本版没有重跑。

```go

### 3.2 状态

`phase` 是唯一的主状态字段；界面只按它渲染，不允许出现两个字段互相矛盾。`tooLong`、`speaking`、`directionSwapped`、`dictionaryExpanded` 是**叠加标记**，不是 `phase`（必须改 8）：第 1 版把 `tooLong` 放进与 `loading` 互斥的 `translatePhase`，实现会只显示截断提示、不再进入流式；本版截断到 4000 后照常 `loading` → `streaming` → `done`。

| --- | --- | --- | --- | --- | --- |

### 3.3 结果排版与方向行

**已定（维护者决定 1）：模型的中文/英文译文在上，系统词典在下。** 本版把这条落成浮窗的主结构：译文块在上、词典块在下，单词时词典块可折叠、默认展开前几行。

理由：

1. 主诉是「英文单词短语查中文」。中文译文是要看的东西，词典是佐证与补充（本机启用的词典对英文词返回英文释义），把英文释义放上面等于让用户先读英文。
2. 词典返回极快（毫秒级），模型要几百毫秒到几秒。译文在上时用户第一眼看到的就是译文区（哪怕还在加载），词典只是下方的补充；译文逐段增长会把词典块往下推，所以用译文块预留最小高度 64（约 2 行）加词典块固定折叠/展开高度来减少跳动，不对每一行增量做全窗口重排。
3. 单词查询时，词典块仍然「先到先显示」：译文区显示加载骨架的那一刻，词典已经可以出现在下方，用户不会空等。模型失败时也一样：上方是失败文案，下方词典保留（§3.2）。

具体规则：

- 单词查询（`isSingleEnglishWord` 为真）：并发发起词典与模型；词典可能在 `loading` 阶段就画出来，顺序固定在译文块**下方**，与译文块用一条 `StrokeHairline` 分隔。译文块长高时词典块整体下移，但两块内部的排版不重排（§3.1 的高度公式）。
- 非单词：不查词典，结果区只有译文块，没有分隔线、没有词典块。
- 词典块默认展开前 `SizeTranslateDictionaryPreviewLines` 3 行，点 `chevron-down` 收起到只有头行，再点展开；展开时正文最大 `SizeTranslateDictionaryMax` 96，超出内部滚动。不做「展开全文」的第二层控件。
- 词典块不加额外标题颜色，头行只有 chevron + `TranslateDictionary` 一行小字；正文用 `ColorTextSecondary`，与译文块的 `ColorText` 区分。
- 单词查询若词典查不到，词典块整块不出现，不留空行、不留折叠头。

**方向行（一行灰字，可交换一次）：**

- 只显示一行 `FontSizeSmall` 12 `ColorTextSecondary` 灰字：`TranslateToChinese` = 「英 → 中」/「EN → ZH」，或 `TranslateToEnglish` = 「中 → 英」/「ZH → EN」。不写「译为中文」这类句子，不显示源语言代码、不显示模型名、不显示服务名。
- 点击该行只做一件事：**交换一次方向**（源与目标对调，显示换成另一行灰字）；再点一次交换回来。不弹下拉、不改设置、不写配置，只作用于本次提交；面板重新打开或重新输入时回到 `detectDirection` 的自动结果。用 `translateState.directionSwapped` 一个布尔量表达。
- tooltip 用 `TranslateSwapDirection`（「交换方向」/「Swap direction」），保证纯图标/纯文字行的可访问性；键盘焦点可到达（focus-visible 才画焦点框，`AGENTS.md`）。

### 3.4 设置页「翻译」模块

按 007 的信息架构，翻译是第 6 个模块，侧栏**插到 JSON 与「快捷键」之间**（建议改 7；不是接到「关于」后面）：

```
通用 / 常亮 / JSON / 翻译 / 快捷键 / 关于
```

页面骨架照 007 §2.2：头部卡片 + 分组 + 行。

| 分组 | 行 | 右控件 | 说明级别与文案 |
| --- | --- | --- | --- |
| 头部卡片 | 图标（第 1 步复用 `text-quote`，后续换 `languages`）；名称「翻译」；说明 `TranslatePageDesc` | 模块总开关 | 页面说明，不属于三级 |
| 设置 | 接口地址（`TranslateBaseURL`） | 单行输入（宽 240） | **①** 短句 `TranslateEndpointLocalHint`「本机地址可用 http」；完整规则 `TranslateBaseURLInfo` 挂在输入框 tooltip |
| 设置 | API Key（`TranslateAPIKey`） | 已保存时只显示「已保存」与「替换」「清除」；点「替换」后显示单行 `ui.TextInput(...).Password()`（宽 180），未保存时只显示输入框；回车保存后清空并收起，空提交不删除已有 Key | **②** `TranslateKeyHint`「存于系统钥匙串」，**放到第二行**（建议改 6） |

| 设置 | 单词自动发音（`TranslateAutoSpeak`） | 开关 | **①** `TranslateAutoSpeakHint`：只对单个英文单词生效 |
| 快捷键 | 翻译（`TranslateShortcutLabel`） | 录制器（复用 `shortcutSettingsRow`） | **③** 冲突原因沿用现有键 |

**接口地址规则（复核后定稿）**：

- **所有地址走同一个函数** `translateEndpoints(base string) (chat, models string, err error)`：`endpoint()` 与 `modelsEndpoint()` 只是它的两个包装。用户填写的 Base URL 先 `strings.TrimSpace` 并去掉尾部 `/`；路径若以 `/chat/completions` 结尾，先去掉这一段再当 Base；路径为空时补 `/v1`。聊天地址 = Base + `/chat/completions`，模型列表 = Base + `/models`，**两者共用同一个前缀**。
- 一律拒绝查询串与片段（也拒绝 userinfo 伪装）；`https` 放行；`http` 只放行回环主机 `127.0.0.0/8`、`localhost`（大小写不敏感）与 `[::1]`。IPv6 必须带方括号，按 `url.URL.Hostname()` 判断：不带方括号的写法得不到 `::1` 这个主机名，因而被拒绝。其它 scheme 与非回环 `http` 都拒绝。错误只用哨兵表达，不含地址、Key 或正文；不记 URL 错误详情。
- 不写任何具体网关产品名、端口号或私有地址，公开文档只说「本机网关」。
- 地址行的 ① 级灰字**只放短句** `TranslateEndpointLocalHint`（「本机地址可用 http」/ "http allowed for localhost"）；完整规则挂在输入框的 tooltip（`TranslateBaseURLInfo`）上。非回环 `http` 被拒绝时，**在测试连接或保存时**用行内错误提示（复用现有 `triangle-alert` + tooltip 样式）显示 `TranslateEndpointHTTPRejected`，不放在标题旁、不新增第二行；`rowHeight` 仍是 48，窗口高度不变。

**模型行（维护者要求）：**

- 「模型」是**可编辑输入 + 可选列表**：点 `chevron-down` 发 `GET <Base URL>/models`（地址校验与 `endpoint()` 同一套，带 `Authorization: Bearer <Key>`），解析 OpenAI 兼容的 `{"data":[{"id":"…"}]}`，把 `id` 列表铺成一个下拉供选择，选中即填入输入框。
- **拉列表失败不影响手填**：网络失败、401/403、非 2xx、`data` 为空、JSON 不可解析，都只把图标换成 `triangle-alert` + tooltip `TranslateModelFetchFailed`，输入框保持可编辑，不清空、不禁用、不重试循环；列表为空时用 `TranslateModelListEmpty`。
- 模型名允许带 `/`（如 `group/xxx`、`provider/model`），**不做格式限制**：不套正则、不按 `/` 切分、不去掉内部字符，只 `strings.TrimSpace` 后原样放进请求体的 `model` 字段。
- 「测试连接」用**一次最小请求同时验证地址、Key、模型三者**：`POST <Base URL>/chat/completions`，请求体带当前模型名、`messages` 为一句固定的极短文本（不用用户原文）、`max_tokens: 1`、`stream: false`，超时 10 s；2xx 且能解析出 `choices` 才算成功。401/403 → `TranslateAuthError`，404/400 指向模型 → `TranslateModelError`，连接失败 → `TranslateNetworkError`，超时 → `TranslateTimeout`，其它 → `TranslateServerError`。成功短暂换 `check`，2 s 后收起（同 007 的 `updateStatus` 手法）；不写成「已是最新」。**不记 URL、Key、请求体、响应体**。
- 两个图标按钮都在同一行里，不新增设置行，因此不抬高窗口高度。

**Key 行与其它规则：**

- `ui.TextInput` 单行 + `Password()`（§2.3）；已保存时只显示「已保存」与「替换」「清除」，不再显示状态点或输入框；未保存或正在替换时只显示输入框，回车保存。读写均在 worker 上，失败保留已有 Key 与已保存状态，用 `triangle-alert` + tooltip `TranslateKeyError`。

- 说明文字按 007 §3.1 的三级规则：① 标题旁灰字（控件窄）、② 标题下第二行（控件宽或句子长）、③ `info` + tooltip（多条规则/随状态变化）。本页 ①②③ 各用一两次，没有第 4 类。Key 行从 ① 升到 ② 是「建议改 6」；地址行的 ① 级只留短句，完整规则进输入框 tooltip，拒绝时在测试连接或保存时给行内错误，不堆在标题旁。

**高度核算（守住维护者已定的 444）**，按 `settings_view.go` 的 `rowHeight` / `cardHeight` / `sectionHeight` / `pageHeight` / `settingsHeight` 实算：

| 项 | 算式 | 值 |

### 3.5 无权限与未配置的引导（不弹窗）

- **没有辅助功能权限**：快捷键按下时不弹任何系统框，直接打开空输入框，结果区上方一行 12 号灰字 `TranslateSelectionDenied` + 文字按钮 `TranslateGrantAccess`。按钮打开系统辅助功能设置面板（`x-apple.systempreferences:…?Privacy_Accessibility`，一个 `open` 调用，不需要额外权限）。该行**每次应用启动最多出现一次**（内存布尔量），用户开始输入立即消失。
- 切到翻译设置页以及设置窗口重新获得焦点时重读 `AXIsProcessTrusted`，从系统设置返回后授权状态立即刷新；不读前台选中文字、不轮询、不调用带 prompt 的函数。
- 用户点了「去授权」之后，不再主动探测；下一次按快捷键时再 `AXIsProcessTrusted()` 一次即可。
- **未配置模型**：不弹窗、不改激活策略。面板里给一行 `TranslateNotConfigured` + 「打开翻译设置」按钮，点击 `a.selectSettingsPage(settingsTranslate); a.show()`（与命令面板的 `settings.*` 同一条路径），并先 `a.hideTranslate()`。**`showTranslate` 与这条路径都不调用 `main.go` 的 `visibility`**（建议改 2）：`visibility` 在设置或 JSON 窗口可见时会把策略设成 `ActivationPolicyRegular`，MyGo 会随之激活应用；打开设置直接走 `a.show()`。
- **开发构建的已知现象**：TCC 按签名与构建标识记录授权，重新构建后可能需要重新勾选（Apple 平台通例，**未实测**）。这一点写进实现注释，不进界面。

### 5.5 CLI 协议（必须改 3、4、建议改 9）

**新增 action，不改协议版本**：`translate` 是全新 action，旧 CLI 根本没有这个子命令，因此不会读到新的响应正文帧；`Response.Bytes` 缺省 0，其它 action 的响应格式一字不变。006 §3.3「加字段不升版本」继续成立。

```
→ {"v":1,"id":"…","op":"run","action":"translate","bytes":22,"to":"auto"}
Hello, this is a test.            ← 请求正文帧：恰好 bytes 个字节的原文，UTF-8，与 json.new 同一套定长帧
← {"v":1,"id":"…","ok":true,"code":"","message":"","bytes":30,
   "translate":{"source":"auto","target":"zh-Hans","model":"…","clipped":0},
   "state":{…}}
你好，这是一次测试。                ← 响应正文帧：恰好 bytes 个字节的译文，UTF-8，不额外加换行
```

**为什么必须走正文帧（必须改 3）**：`internal/cli/protocol.go` 的 `EncodeLine` 拒绝超过 `MaxLine`（4096）的一行，`internal/cli/client.go` 的 `readResponse` 用同一上限去读。4000 个汉字光 `message` 就超过这一行，第 1 版还把同一段再放进 `translate.text` 并带上完整 `state`，服务端 `EncodeLine` 必然失败。另外 `cli_server.go` 的 `writeResult` 只拷贝 `Response` 上**已声明**的字段，`internal/cli/protocol.go` 的 `Response.Result()` 也只构造那几个字段；只在 `Result` 上加 `Translate` 到不了客户端。因此本版两条一起做：

- 译文正文走**响应定长正文帧**（与请求正文帧对称），不进 JSON 行；`message` 置空（失败时仍是错误文案）；JSON 行里只放小的元数据与 `state`，始终小于 `MaxLine`。客户端新增 `readBodyFrame`（与 `cli_server.go` 的 `readFull` 同语义）；`internal/cli/client.go` 里没有现成的 `readFull`，不能只改服务端。
- `cli.Result`、`cli.Response` **都**加 `Bytes int` 与 `Translate *TranslateResult`，并修正 `Response.Result()` 把两个字段一起拷贝；`cli_server.go` 的 `handle` 构造 `Response` 时也要带上它们。
- `cli.TranslateResult` = `{source, target, model, clipped, text}`；**`text` 只在客户端本地回填**（`Client.Do` 读完正文帧后填入），服务端序列化时始终为空并用 `omitempty` 省略；`--json` 打印时 `translate.text` 就是回填后的译文。`Result.Translate` 里的 `model` 只放模型名，不放地址、Key、原文。
- 新增 `writeTranslationResult(conn, response, body)`：先 `writeResult` 写 JSON 行，再在同一连接写恰好 `response.Bytes` 字节的正文；写超时覆盖两段。响应正文上限 `MaxTranslateBody = 64 << 10`（64 KiB）：应用侧最多输出 4000 字符，UTF-8 最坏约 16 KiB，余量充足。客户端 `Client.Do` 在 `readResponse` 之后按 `Result.Bytes` 用 `readBodyFrame` 读正文并做 UTF-8 校验，超限直接报错。
- 备选方案「把翻译响应的行上限单独放宽、服务端编码与客户端读取一起改」也能成立，但需要同时改 `EncodeLine`、`readLine`、`readResponse` 三处并给 `state` 留足余量；本版选正文帧，因为它复用 006 已有的定长帧语义，改动面更小。

**阻塞语义与代次（必须改 4）**：`cli_server.go` 的 `applyCLIAsync` **不能**用来跑翻译。它只替换 `a.lidCompletion`，注释写明「动作和最终快照都在主线程」，并且只在合盖真的进入进行中时才延迟 `reply`；翻译挂上去要么提前返回，要么覆盖合盖的回调。本版做法：

- `cliServer` 增加独立的 `translateAsync func(context.Context, cli.Request, []byte, func(cli.Result, []byte))` 钩子，`startCLIServer` 里设为 `a.applyTranslateCLI`；`applyReqContext` 在 `s.dispatch` 里按 `req.Action == cli.ActionTranslate` 分到该钩子，**不经过 `s.applyAsync` / `applyCLIAsync`**，也不碰 `lidCompletion`。
- 第 2 步评审修正：各 CLI 请求用自己的 `context` 与 `reply` 隔离生命周期，取消取代应用级代次比较。共享 `a.translateCLIGeneration` 会让后到的 CLI 请求作废仍在执行的前一请求；CLI 调用没有浮窗内「新输入替换旧输入」的语义，所以并发请求应各自完成。worker 上跑 `clipTranslateInput`、`detectDirection`（或 `--to` 覆盖）、`streamTranslation`（收集增量、不建窗口、不刷 UI），完成后经 `mygo.RunOnMain` 组装 `cli.Result` 并调用 `reply(result, []byte(text))`。**客户端断连、服务端等待超时或应用退出时取消对应 context；取消后的迟到完成不再组装快照或回包，存活请求只回一次**。CLI 不涉及浮窗的取消、Esc 或 UI 状态机。
- `applyReqContext` 的 `outcome` 加 `body []byte`，`handle` 收到后走 `writeTranslationResult`。

                       [--to auto|zh|en] [--text STR | --file PATH | -]
```

参数解析与 `json new` 的 `--text/--file/-` 共用 `cmd/cubbix/args.go` 的 `readBody` 与 `cmd/cubbix/main.go` 的 `readBody`/`readStdin`；`checkOptions` 把 `--to` 加入 `translate` 的允许集合。

**为什么不复用 `json.new` 的 action**：`json.new` 的正文语义是「文档内容」，会额外触发窗口、剪贴板、文件路径等副作用；翻译只要文本进、文本出，混在一条 action 里会让 `applyCLI` 的分支既管窗口又管网络。

### 5.6 与 URL scheme 的关系（明确不做）

006 §2.2 立过一条规矩：「CLI 的**动作种类**＝URL 白名单」。翻译会打破这条，必须写清理由，并建议在 006 里改一句话：

1. **写不进去**：URL 要按编码搬运整段文字，长度、编码、换行都受 URL 限制，脚本会立刻撞墙。
2. **不该写进去**：URL 是任何应用与网页都能触发的通道。原文与译文属于用户内容，一旦进 URL 就会进浏览器历史、系统日志、其它应用的 URL 处理链。
3. **没有回程**：URL 没有响应体，译文拿不回来，只剩「弹个窗口」这一半功能，而这半功能用 `cubbix://palette` + 命令面板已经能做到。

因此：**`translate` 只在 CLI 与命令面板提供**。建议把 006 §2.2 那句改成「不需要返回值的动作集合与 URL 白名单一致；需要返回值的只读或计算型动作（`status`、`translate`）只在 CLI 上」。这条建议由评审决定要不要同时改 006 的正文（本 PR 不改 006）。

4. §5.5 的 `bytes == 0` 占位接上：CLI 无参数且标准输入是终端时发零长正文帧，服务端用同一条 AX 链取选中文字，没权限／没选中／超时都回 `TranslateNoSelection`（退出 4），不打开浮窗。显式空 `--text`、空管道仍是用法错误（退出 2）；帮助文案同步。
5. AX 全部调用收在 `selectionReader` 接口后面，单测用假实现覆盖有选中、空选中、读失败、超时、无权限、前台是自己；真实 AX 只在仓库外做只读实验。沿用第 1 步的偏离：未新增画板轮次与 Token，界面证据只放工作单目录。
