## 1. 场景、频率与流程

### 1.1 使用场景

维护者的原话是「用 Cubbix 替代 Easydict，只用其中最基础的翻译」。据此把场景收敛成两类：

| # | 场景 | 输入形态 | 期望 | 频率 |
| --- | --- | --- | --- | --- |
| 1 | 读英文文档/代码注释时查一个词 | 单个英文单词（手选或划词） | 立刻看到中文释义，必要时看系统词典的英文原文 | 每天多次 |
| 2 | 读英文长句/段落时想确认意思 | 一句话到一段话 | 通顺的中文，边出边看 | 每周数次 |
| 3 | 写英文邮件/文档时把中文翻过去 | 中文句子 | 通顺的英文 | 每周数次 |
| 4 | 脚本/Agent 里批量翻译一段文本 | 任意文本 | 拿到结果文本（CLI） | 每周数次 |
| 5 | 想听一个词的读音 | 单个英文单词 | 系统语音念一遍 | 低频，可自动 |

频率整体不高（每天几次到十几次），所以取舍一律偏向「少占界面、少加状态」。这也是不做历史、不做多服务对比、不做生词本的原因（§8 第 5 项）。

### 1.2 主流程

```
⌃⌥⌘T
  ├─ 面板已开 → 关闭（与 ⌥. 同一条 toggle 语义）
  └─ 面板未开
       ├─ 前台应用不是我方 → 读 AX 选中文字（≤ 200 ms 预算）
       │    ├─ 拿到非空文本 → showTranslate(s, text) → submitTranslate()
       │    └─ 空 / 无权限 / 不支持 → showTranslate(s, "")，输入框聚焦
       └─ 前台应用是我方 → showTranslate(s, "")，输入框聚焦

submitTranslate()
  ├─ 原文判型：isSingleEnglishWord → 并发（词典查询 || 模型请求）
  │                              └ 否则 → 只发模型请求
  ├─ 方向：detectDirection（含汉字 → 译为英文；否则 → 译为简体中文）
  ├─ 模型未配置 → phase = notConfigured，下方给「去设置」
  └─ 流式返回 → phase = streaming，逐段追加到译文区
       └─ 结束 → phase = done；单词且开关打开 → speakText(原文)
```

步骤与函数（接口细节见 §5.2）：快捷键回调 `a.toggleTranslate` → `a.captureSelection` → `a.openTranslateText` / `a.showTranslate` → `a.submitTranslate` → `streamTranslation`（worker goroutine）→ `mygo.RunOnMain` 追加 → `a.refreshTranslate`（`SetContentSize` + `Invalidate`）。

### 1.3 判型与方向

两条纯函数，全部可单测：

1. **是否单个英文单词** `isSingleEnglishWord(s)`：`strings.TrimSpace` 后必须匹配 `^[A-Za-z][A-Za-z'\u2019-]{0,47}$`，即字母开头、只含字母与连字符/撇号、长度 1–48、没有空格与数字。命中才查系统词典。
   - 词组（`take into account`）**不查词典**：本轮实测 `DCSGetTermRangeInString` 只返回第一个词的区间，`DCSCopyTextDefinition` 对整串区间直接查不到（§2.2）。工作单里「很短的词组也用词典」这一条按实测否掉，改成「单词查词典、词组走模型」，理由写在 §2.2。
2. **译向** `detectDirection(s)`：
   - 含汉字（Unicode `Han` 区：`unicode.Is(unicode.Han, r)`）且汉字数 ≥ 1，同时汉字占「汉字 + 拉丁字母」的比例 ≥ 0.15 → 源语言 `zh-Hans`，目标 `en`。阈值 0.15 用来让「Cubbix 的翻译」这类中英混排仍算中文，而「用 Cubbix」里只有一个词的中文短句不会被误判。
   - 其余情况（英文、日文、韩文、法文、符号）→ 源语言 `auto`，目标 `zh-Hans`。工作单要求「输入中文就译成英文，其他语言都译成简体中文」，这条规则就是它的实现；日文/韩文交给模型自己判断源语言。
   - 判定结果只用于提示词与界面上的一行小字（`译为英文` / `译为中文`），不写配置。

### 1.4 与既有入口的关系

- 与卡片面板（001）、命令面板（003）**互斥**：`showTranslate` 前先 `a.hideMenubarPanel()` 与 `a.hidePalette()`；反向由 001/003 已有入口负责，不改它们的代码。三者同时最多一个可见。
- 浮窗**不激活应用**、**不切 Space**、**不写窗口位置**（008 的位置记忆只覆盖设置窗口与 JSON 窗口，翻译浮窗是固定位置，理由见 §3.1）。
- 不做屏幕提示（002）：面板本身就是反馈。CLI 的静音规则沿用 006（`a.quiet`）。

### 2.1 读选中文字

**方案：AX 只读取，不模拟按键。**

调用链（全部在 `translate_ax_darwin.go`，`//go:build darwin`）：

1. `purego.Dlopen("/System/Library/Frameworks/ApplicationServices.framework/Frameworks/HIServices.framework/HIServices", …)`。`AXUIElement*` 在 HIServices 子框架里，直接 dlopen 子框架路径比 dlopen 伞形框架稳（本轮实验即用该路径，符号全部解析成功）。
2. `AXIsProcessTrusted()` 判权限。**不要**用 `AXIsProcessTrustedWithOptions` 带 prompt，它会在被调用的瞬间弹系统授权框；我们要么不弹，要么由用户点按钮后跳系统设置（§3.5）。
3. 取前台应用 pid：
   - 首选 `AXUIElementCreateSystemWide()` + `kAXFocusedApplication` + `AXUIElementGetPid`。
   - **本轮的负面结果要写清楚**：在非 GUI 的 CLI 进程里，系统级元素的 `AXFocusedUIElement` 与 `AXFocusedApplication` 都返回 `-25204`（`kAXErrorCannotComplete`），而同一次运行里，用前台应用 pid 建的元素 `AXFocusedUIElement` 返回 `0` 并拿到角色 `AXWebArea`。所以实现必须准备第二条路：用 pid 建元素。
   - pid 的来源：MyGo 没有公开「前台应用」API（`mygo@v0.6.2/app.go` 只有 `OnActivate` 之类的回调，没有 frontmost）。可行做法是 objc 调 `[NSWorkspace sharedWorkspace]` 的 `frontmostApplication`（purego 的 `objc` 子包支持消息发送，仓库外的实验里 `objc_getClass` 已经能取到 AppKit 的类）。这条路径**未实测**，实现时按「先系统级、失败再 NSWorkspace、再失败就当没选中」的顺序写，并把最终选择记进日志（不含文本）。
4. `AXUIElementCopyAttributeValue(focused, kAXSelectedTextAttribute, &value)`，把 `CFStringRef` 用 `CFStringGetLength` + `CFStringGetMaximumSizeForEncoding` + `CFStringGetCString(UTF-8)` 转成 Go 字符串，然后 `CFRelease`。

**返回值怎么归类**（本轮两个都实测到了，实现里必须都当「没有选中」）：

| 结果 | 含义 | 处理 |
| --- | --- | --- |
| `0` 且字符串非空 | 有选中 | 直接翻译 |
| `0` 且字符串为空 | 支持该属性但没有选中（本轮在 `AXTextField` 上实测到「err=0、长度 0」） | 打开空输入框 |
| `-25212`（`kAXErrorNoValue`） | 该元素没有这个属性（本轮在 `AXWebArea` 上实测） | 打开空输入框 |
| `-25211`（`kAXErrorAPIDisabled`） | 没授权 | 打开空输入框 + 本次会话引导 |
| `-25204` / 其它 | 应用不响应或超时 | 打开空输入框，不重试 |

另外三条约束：

- 读之前判 `AXIsProcessTrusted()`，为假直接跳过 AX，不产生任何错日志噪音。
- 前台应用是自己（pid 相同）时不读。
- 取到的文本按 `MaxTranslateInput = 4000` 个字符截断（超出时在面板里提示已截断），避免把整篇文档灌进提示词。

**要不要 ⌘C 兜底：建议不做（v1）。** 理由逐条：

1. 需要同样的辅助功能权限，权限这一层没有变松；它只多覆盖「实现了复制、但没实现 `AXSelectedText`」的应用。
2. 代价是剪贴板：要先读全部表示（`mygo.Clipboard.Read()` 能读全部已声明的表示），再写回（`Write(data)`），中间这段时间里用户自己的剪贴板被占用；富对象（图片、Promise、文件名列表）往返后保真度无法保证，这是会丢用户数据的那一类风险。
3. 合成事件（`CGEventPost`）在安全输入框里会被系统吞掉，在终端/编辑器里还可能触发应用自己的绑定；「按了 ⌘C 却改变了别的状态」是不可接受的副作用。
4. 时序上要和用户的真实 ⌘C 抢，需要「等到剪贴板 changeCount 变化或超时」的等待，最坏 200–300 ms，还要处理「宿主应用根本没响应复制」。

所以 v1 明确写：**AX 失败就退回输入框**，并在面板里给一行可关闭的说明（§3.5）。⌘C 兜底留作后续可选增强，实现契约写在 §8 第 2 项，维护者要的话照那个契约做。

### 2.2 macOS 系统词典（Dictionary Services）

**接口**：`CoreServices.framework/Frameworks/DictionaryServices.framework` 的 `DCSGetTermRangeInString` / `DCSCopyTextDefinition`（头文件 `DictionaryServices.h`，两者都 `API_AVAILABLE(macos(10.5))`）。签名是纯 C，返回 `CFRange` 与 `CFStringRef`，**没有回调、没有结构体按值返回**，正是 purego 最舒服的形态。

**本轮实测结果**（`CGO_ENABLED=0`，Go 1.25.9，purego v0.11.1，dlopen 子框架路径）：

| 输入 | 用 `offset=0` 的自动区间 | 用途 |
| --- | --- | --- |
| `hello` | 区间 `0,5`，710 字节释义 | 单词正常 |
| `serendipity` | 区间 `0,11`，440 字节释义 | 单词正常 |
| `take into account` | 区间 `0,4` → 命中 `take`，16656 字节 | **命中的是第一个词，不是词组** |
| `out of the box` | 区间 `0,14` → 命中 `box`，4438 字节 | 同上 |
| `不存在的词zzz` | 区间 `0,1` → 命中 `不` | 中文输入也会硬命中一个字 |

释义是**一整段纯文本**，形如：

```
serendipity ser·en·dip·i·ty | ˌserənˈdipədē | noun the occurrence and development of events by chance in a happy or beneficial way: a fortunate stroke of serendipity | … ORIGIN 1754: coined by Horace Walpole, …
```

也就是说：词头、音节点、音标、词性、义项、例句、词源全在一个字符串里，没有结构，读音用 `|` 与 `·` 分隔。**界面上只能按纯文本显示**，不做结构化解析（解析等于猜词典格式）。

**三条必须写进实现的硬约束**：

1. **不要传整串区间**。把 `CFRange{0, 整串长度}` 传给 `DCSCopyTextDefinition` 时，实测该调用会把进程常驻内存顶到 **11.5 GB**（`/usr/bin/time -l` 的 `maximum resident set size` 为 11518001152），进程随即被系统杀掉。只能传 `DCSGetTermRangeInString` 返回的区间，并且只在「返回区间覆盖了整个输入」时才认为命中（这样 `take into account` 会被判为「不是单词、不查词典」）。
2. **同一词条在一个进程里只能查一次**。实测：

   | 情形 | 最大常驻内存 |
   | --- | --- |
   | 查 `serendipity` 一次 | 约 176 MB |
   | 同一个词查两次 | 约 11.5 GB |
   | 查 `serendipity`、`hello` 各一次 | 约 409 MB |
   | `serendipity` → `hello` → `serendipity`（同词第二次） | 约 11.4 GB |
   | `hello` 与 `Hello`（大小写不同） | 约 8.7 GB |

   即「同一词条的重复查询」会触发这条路径（键看起来不区分大小写），不同词条连续查则正常。原因没查明（可能是词典引擎的缓存/映射行为），但后果明确：**必须做进程级缓存，键用 `strings.ToLower(strings.TrimSpace(term))`，命中缓存绝不二次调用**。缓存用一个有上限的 map（例如 64 条、超出丢最旧），只在内存里，不落盘。

3. **离线可用**：释义在 70–80 ms 的整进程耗时内返回（含进程启动），说明走的是本地词典数据；系统里存在 `AssetsV2` 下的词典资产目录。**本轮没有断网验证**，所以「离线可用」按「有本地资产、实测毫秒级返回」表述，不断言「拔网也一定行」。

**为什么单词才查词典**：上面的表已经说明词组查不到整串；再叠加「同词二次查询内存爆掉」这条，把词典限制成「单个英文单词」既符合数据，也让调用次数天然稀少（同一个词再看一次命中缓存）。

### 2.3 钥匙串与 API Key

**不需要自己写 purego**：MyGo v0.6.2 已经公开 `mygo.Secrets`（`mygo@v0.6.2/secrets.go` 的 `SecretsModule.Set/Get/Delete`、`Service`、`ErrSecretNotFound`、`MaxSecretSize = 2560`），macOS 上就是登录钥匙串的 generic password，内部实现是 purego 调 `SecItemAdd` / `SecItemCopyMatching` / `SecItemUpdate` / `SecItemDelete`（`mygo@v0.6.2/internal/darwin/secrets.go` 的 `keychain`）。

采用它的三个理由：

1. 已经在本仓库的依赖里，不新增依赖，也不用自己维护 CFDictionary 的构造与释放（那是最容易泄漏的一段）。
2. MyGo 的注释明确写了它在 macOS 上用文件型钥匙串、`Secrets.Get` 可以从任意 goroutine 调用并且可能阻塞（系统可能要求解锁或确认），主线程不被卡住——正是我们要的语义。
3. 服务名默认取应用标识符；`Secrets.Service("…")` 可指定。**不用指定**：同一个应用的配置与密钥放一起，别的程序读不到。

约定：

- 键名固定 `translate-api-key`；`Get` 返回 `mygo.ErrSecretNotFound` 表示未设置。
- 读写都在 worker goroutine 上做，主线程只拿结果。
- 界面只显示「已保存 / 未设置」与「替换」「清除」两个文字按钮，**永不回显明文**，也永不写日志。Key 的输入用一个 `ui.TextInput`（`ui/api_gen.go`，约 2200 行）：`ui` 目前没有密码掩码样式，所以输入框只显示占位符 `TranslateKeyPlaceholder`，输入内容按 `•` 显示需要自己画（v1 不做：提交后立刻清空输入框、只留「已保存」状态，明文不在屏幕上停留）。
- 首次写入可能触发系统钥匙串授权框（未实测）；失败时 `settingsError` 用 `TranslateKeyError`，不清空已有值。
- 0600 配置文件作为**不采用**的备选：它更简单，但明文落盘且随备份/同步外流，与「公开仓库不存凭据」的纪律不匹配。

### 2.4 系统语音

**两条路，先 AVSpeech，再 `say`。**

- **AVSpeechSynthesizer**：Objective-C 类，本轮实测 `objc_getClass("AVSpeechSynthesizer")`、`objc_getClass("AVSpeechUtterance")`、`objc_getClass("AVSpeechSynthesisVoice")` 在 dlopen `AppKit` 与 `AVFAudio` 之后都能取到非零地址（不 dlopen 时 `NSSpeechSynthesizer`/`NSApplication` 取到 0，说明必须先 dlopen 对应框架——这条要写进实现的注释）。调用方式：`alloc` + `init`，`utteranceWithString:`，`setVoice:`（`voiceWithLanguage:` 取当前语言），`speakUtterance:`，停止用 `stopSpeakingAtBoundary:`。
- **`say` 兜底**：`/usr/bin/say` 存在；`say -v '?'` 能列出音色。用 `exec.Command` 起子进程，`Process.Kill` 停止；不需要权限，最坏是多一个进程。

选择：默认走 AVSpeech（不落子进程、能立刻打断）；任何一步（dlopen、类解析、alloc、speak）失败就退回 `say`。两个都失败时，按钮的失败提示用 `TranslateSpeakFailed`（tooltip），不弹窗。

**未实测**：是否真的出声、能否在朗读中被打断、与系统「朗读所选内容」是否抢同一个通道。这些都归入 §6.2 的维护者实测项。为了不在无人值守时出声，**自动发音只在「面板正在前台显示 + 输入是单个英文单词 + 开关打开」三个条件同时成立时触发**，且每次打开最多一次。

### 2.5 MyGo 的浮窗、快捷键与输入

### 2.6 默认快捷键的选取

已有占用：`⌃⌥⌘K`（常亮）、`⌃⌥⌘J`（JSON）、`⌃⌥⌘P`（卡片面板）、`⌥.`（命令面板）、`⌘,`（设置），都在 `config.go` 的 `defaultConfig`（约 94 行）与 `knownShortcutConflict`（`awake_view.go`，约 393 行）里。

| --- | --- | --- |
| `⌃⌥⌘T` | 与前四个同族、同手指区（左手三键 + T），不在 `knownShortcutConflict` 的任何一组里；T 的系统级占用是 ⌘T/⌘⇧T（应用内）与 ⌃⌘T（部分 IDE），都不是 ⌃⌥⌘ | **采用** |

### 2.7 本轮实验记录（可复现的最小实验）

放在仓库外的临时目录，`CGO_ENABLED=0` 编译一个不依赖 MyGo 的程序（只用 `purego` v0.11.1），跑完删除。

```go
lib, _ := purego.Dlopen("/System/Library/Frameworks/CoreServices.framework/Frameworks/DictionaryServices.framework/DictionaryServices", purego.RTLD_LAZY|purego.RTLD_GLOBAL)
var termRange func(dict, text uintptr, offset int64) cfRange
var copyDef func(dict, text uintptr, r cfRange) uintptr
purego.RegisterLibFunc(&termRange, lib, "DCSGetTermRangeInString")
purego.RegisterLibFunc(&copyDef, lib, "DCSCopyTextDefinition")
```

得到的结论就是 §2.2 的表与内存数字。**要复现内存现象**：同一个词调用 `DCSCopyTextDefinition` 两次，用 `/usr/bin/time -l` 看 `maximum resident set size`。**注意别在主力会话里跑**，它会把进程顶到十几 GB。

AX 的最小实验：`AXIsProcessTrusted()` → `AXUIElementCreateSystemWide()` + `AXFocusedUIElement`（本轮 `-25204`）→ 再用前台应用 pid 的 `AXUIElementCreateApplication` + `AXFocusedUIElement`（本轮 `0`，角色 `AXWebArea`），最后 `kAXSelectedTextAttribute`（本轮 `-25212`；另一个前台窗口是文本框时返回 `0` 且长度 0）。**要验证有选中**的情况，需要人先在某个应用里选中一段文字再跑同一段代码。

### 3.2 状态

`phase` 是唯一的状态字段，界面只按它渲染；不允许出现两个字段互相矛盾。唯一例外是 `speaking bool`：它可以与 `done` 同时成立（译文已经出完、正在朗读），所以单独一个布尔量，不塞进 `phase`。

### 3.3 结果排版：单词时谁在上

**定稿：模型的中文/英文译文在上，系统词典在下。**

理由：

1. 本模块的主诉是「英文单词短语查中文」。中文译文是要看的东西，词典是佐证与补充（本轮实测本机启用的词典对英文词返回英文释义），把英文释义放上面等于让用户先读英文。
2. 词典返回极快（毫秒级），模型要几百毫秒到几秒。若词典在上、译文在下，译文逐字流出时**下方内容的位置不变**，视觉更好；但用户要先在两段英文/中文之间来回跳。居中权衡后选「译文在上」，并用**预留最小高度**（译文区至少 2 行、60 pt）抵消「先空后满」的跳动。
3. 单词查询时，词典块仍然「先到先显示」：译文区显示加载骨架的那一刻，词典已经可以出现在下方，用户不会空等。

具体规则：

- 单词查询（`isSingleEnglishWord` 为真）：并发发起词典与模型；词典可能在 `loading` 阶段就画出来，位置固定在结果区下半部分（与译文区用分隔线分开，不因译文变长而移位）。
- 非单词：不查词典，结果区只有译文一段，没有分隔线、没有词典标题。
- 词典块高度上限 5 行（约 90 pt）+ 内部滚动；超出部分靠滚动，不做「展开/收起」按钮（多一个控件就多一层信息）。
- 词典块不加标题（低信息密度），只在块首用 `ColorTextDisabled` 12 号显示一个 `book` 类图标会被省略——**直接不加图标**，用一段与译文不同的颜色区分即可。
- 单词查询时若词典查不到（少见：词不在已装词典里），词典块整块不出现，不留空行。

### 3.4 设置页「翻译」模块

| 设置 | 模型（`TranslateModel`） | 单行输入（宽 200）+ `refresh-cw` 图标按钮（测试连接） | **③** info `TranslateModelInfo`（供应商文档里的模型标识） |

规则：

- **四行同属「设置」一张卡片**（分组标题复用既有的 `GroupSettings`，与常亮页同名），顺序固定：地址、Key、模型、单词自动发音。不做「提供商预设」下拉（公开仓库不能内置地址）。
- Key 行右侧状态：`未设置`（`ColorTextDisabled` 状态点）/ `已保存`（实心 `ColorText` 点）；异常（钥匙串读不出、写失败）用 `triangle-alert` + tooltip `TranslateKeyError`。
- 「测试连接」只发一次 `max_tokens: 1` 的最小请求，超时 10 s；结果用行尾图标表达，2 s 后自动收起（同 007 的 `updateStatus` 手法）。它**不**写成「已是最新」这类文案，避免和更新页混淆。
- 模块关闭时：「设置」组整组折叠（连标题一起不画），快捷键行保留并置灰（007 §2.4 的同一规则），tooltip 用 `ModuleShortcutOff`。
- 窗口高度（按 `settings_view.go` 的真实公式算，不是估算）：`sectionHeight` = 56 + Σ(8 + 24 + 8 + card)，`cardHeight` = Σ行高 + (行数 − 1)，②的行高是 64，其余 48。翻译页两张卡片：设置卡 `64+48+48+48+(3)` = **211**，快捷键卡 **48**，合计 `56 + 40 + 211 + 40 + 48` = **395**；`settingsHeight` 再加 `2×Space24` 得 443，向上取 4 的倍数 → **444**。
  - 现在的 `settingsMinimumHeight` 是 **388**（008 定稿），因此加这一页会把最小窗口抬到 **444**（+56），6 个页面共享这个下限，其余页面底部会多 56 pt 空白。这是本规格唯一会改动已合并决定的副作用，列为 §8 第 14 项。
  - 更省的备选是「设置卡四行都用 ③」：卡高 `48×4+3 = 195`，页面 `56+40+195+40+48 = 379`，窗口 **428**，比推荐值只省 16 pt，代价是接口地址与 Key 的说明从第二行降级成 info 图标 + tooltip。**只保留 5 行就守不住 388**：要回到 388 以下，只能把「单词自动发音」这一行移出设置页，而工作单明确要求它在设置里，所以本页注定抬高下限。推荐 444（说明留在看得见的地方），428 作为备选。
- 说明文字一律按 007 §3.1 的三级规则：一句话且控件窄用 ①，一句话但长或控件宽用 ②，需要两句或随状态变化用 ③。翻译页只用到了 ①②③ 各一两次，没有第 4 类。

### 3.5 无权限与未配置的引导（不弹窗）

- **没有辅助功能权限**：快捷键按下时不弹任何系统框，直接打开空输入框，结果区上方一行 12 号灰字 `TranslateSelectionDenied` + 文字按钮 `TranslateGrantAccess`。按钮打开 `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`（一个 `open` 调用，不需要额外权限）。该行**每次应用启动最多出现一次**（内存里的布尔量），用户开始输入立即消失，避免反复打扰。
- 用户点了「去授权」之后，不再主动探测；下一次按快捷键时再 `AXIsProcessTrusted()` 一次即可。
- **开发构建的已知现象**：TCC 按签名与构建标识记录授权，重新构建后可能需要重新勾选（Apple 平台通例，本仓库的开发包未签名/临时签名，**未实测**）。这一点写进 README 之外的实现注释，不进界面。
- **未配置模型**：不弹窗、不改激活策略，只在面板里给一行 `TranslateNotConfigured` + 「打开翻译设置」按钮，点击 `a.selectSettingsPage(settingsTranslate); a.show()`（与命令面板的 `settings.*` 同一条路径），并先 `a.hideTranslate()`。

- 不加 `Actions`（⌘K 动作）：本模块的动作都在浮窗里，加一层只会让 `翻译 hello` 变成两步。

### 5.5 CLI 协议

**新增 action**，不改协议版本（006 §3.3：加字段不升版本）：

```
→ {"v":1,"id":"…","op":"run","action":"translate","bytes":22}
Hello, this is a test.            ← 正文帧：恰好 bytes 个字节的原文，UTF-8，与 json.new 同一套定长帧
← {"v":1,"id":"…","ok":true,"code":"","message":"你好，这是一次测试。",
   "translate":{"source":"auto","target":"zh-Hans","text":"你好，这是一次测试。","model":"…"},
   "state":{…}}
```

| 项 | 规定 |
| --- | --- |
| `action` | `translate`。`internal/cli/protocol.go` 增加 `ActionTranslate = "translate"` |
| 原文来源 | **正文帧**（`bytes > 0`）。这样长段落不受 `MaxArg` 128 字节限制，也不用把正文塞进一行 JSON |
| `bytes == 0` | 表示「翻译 macOS 当前选中的文字」。应用没有权限或没有选中时回 `TranslateNoSelection`，退出 4——**不**打开面板（CLI 是给脚本用的，弹窗会打断人） |
| `--to auto\|zh\|en` | 新增可选参数，缺省 `auto`；显式给出时覆盖 `detectDirection` 的结果。`zh` → 目标简体中文，`en` → 目标英文 |
| 正文上限 | 沿用 `cli.MaxPayload`（64 MiB），但应用侧只取前 `MaxTranslateInput = 4000` 字符送入模型；超出时仍然 `ok:true`，并在 `translate.clipped` 里给出丢弃的字符数（字段只增不改） |
| 响应 | `Result` 增加 `Translate *TranslateResult`：`{source, target, text, model, clipped}`。`message` 是译文原文（可含换行），人读时 CLI 直接把 `message` 原样写到 stdout；`lines` 仍只给 `status` 用，不混 |
| 退出码 | 复用 006 的六档，全部落到 4：未配置 → `TranslateNotConfigured`、鉴权失败 → `TranslateAuthError`、限流 → `TranslateRateLimited`、超时 → `TranslateTimeout`、网络失败 → `TranslateNetworkError`、未取到选中 → `TranslateNoSelection`、模块关闭 → `disabled`。唯一的 1 是协议或内部错误（与 006 一致）。理由见 §8 第 13 项 |
| 阻塞语义 | 翻译在 worker goroutine 上跑，**不占主线程**：`applyCLI` → `applyCLIAsync` 走既有的异步回调通道（`cli_server.go`，约 576 行，合盖用的就是它），完成后回主线程提交结果并回包 |
| 服务端超时 | 该 action 单独放宽到 55 s（`cliServer.actionTimeout` 目前固定 15 s，见 `applyReq`，约 253 行）；其余 action 不变 |
| 客户端超时 | `cubbix translate` 的 `--timeout` 缺省改成 **30 s**（其它命令仍是 5 s），上限仍按 006 的 60 s；help 里注明 |
| 静音 | 与 006 一致：默认不弹屏幕提示，`--notify` 才发；但翻译从不发提示（面板本身就是反馈，CLI 也不该因为一次翻译弹通知），所以 `--notify` 在 `translate` 上是用法错误（退出 2） |
| 应用未运行 | 默认后台拉起（`open -g -a`，与 006 §3.4 同一条），`--no-launch` 直接退 3 |
| 日志 | 只记 `code`，不记原文、不记译文、不记 URL 与 Key |

CLI 命令表新增一行（`cmd/cubbix/args.go` 的 `helpText`）：

```
  translate [TEXT]     Translate text (or the current selection)
                       [--to auto|zh|en] [--text STR | --file PATH | -]
```

参数解析与 `json new` 的 `--text/--file/-` 共用同一段代码（`cmd/cubbix/args.go` 的 `readBody` 与 `cmd/cubbix/main.go` 的 `readBody`/`readStdin`），`checkOptions` 里把 `--to` 加入 `translate` 的允许集合。

**为什么不复用 `json.new` 的正文帧却要新加 action**：`json.new` 的正文语义是「文档内容」，会额外触发窗口、剪贴板、文件路径等副作用；翻译只需要文本进、文本出，混在一条 action 里会让 `applyCLI` 的分支既管窗口又管网络。

### 5.6 与 URL scheme 的关系（明确不做）

006 §2.2 立过一条规矩：「CLI 的**动作种类**＝URL 白名单」。翻译会打破这条，必须写清理由，并建议在 006 里改一句话：

1. **写不进去**：`cubbix://translate?text=…` 要按 URL 编码搬运整段文字，长度、编码、换行都受 URL 限制，脚本会立刻撞墙。
2. **不该写进去**：URL 是任何应用与网页都能触发的通道。原文与译文属于用户内容，一旦进 URL 就会进浏览器历史、系统日志、其它应用的 URL 处理链。
3. **没有回程**：URL 没有响应体，译文拿不回来，只剩「弹个窗口」这一半功能，而这半功能用 `cubbix://palette` + 命令面板已经能做到。

因此：**`translate` 只在 CLI 与命令面板提供**。建议把 006 §2.2 那句改成「不需要返回值的动作集合与 URL 白名单一致；需要返回值的只读或计算型动作（`status`、`translate`）只在 CLI 上」。这条建议由评审决定要不要同时改 006 的正文（本 PR 不改 006）。

### 6.2 只能由维护者实测（都必须前台、留证据）

1. **划词成功率**：在 Safari、Chrome、Pages、Word、Notes、VS Code、Terminal、微信/飞书这类应用里各选一段文字按快捷键，记录「拿到 / 退回输入框」，以及焦点在搜索框、地址栏、PDF 阅读器、密码框时的表现。

10. **CLI**：`cubbix translate "…"` 在应用未运行时能否拉起并返回；管道输入；`--json` 的字段；应用被关掉时的退出码。

## 8. 待维护者决定

每项给推荐；括号里是推荐落地的位置。

| # | 问题 | 推荐 | 理由 |
| --- | --- | --- | --- |
| 1 | 单词查询时，中文译文与系统词典谁在上？ | **中文译文在上，词典在下**（§3.3） | 主诉是查中文；词典是英文释义，放上面等于让人先读英文；译文区预留 2 行抵消跳动 |

| 6 | 从卡片面板打开时，要不要预填剪贴板内容？ | **不预填**，只开空输入框并聚焦 | 剪贴板经常与翻译无关；误把密码、Token 塞进提示词是不可接受的风险（提示词会发到第三方接口） |
| 7 | 卡片面板要不要放「翻译」卡片？ | **放一张单行卡片**（§5.4） | 鼠标用户否则完全看不到这个功能；只占 40 pt，不加状态、不加列表 |
| 8 | 温度、最大 token、系统提示词要不要暴露到设置？ | **都不暴露**；温度固定 0.2，不传 `max_tokens`，提示词写在代码里 | 维护者只想用最基础的功能；暴露越多，出问题时越难判断是谁的问题 |
| 9 | Key 存哪？ | **macOS 钥匙串（`mygo.Secrets`）**，配置文件只存地址与模型（§2.3） | 已在依赖里、接口现成、不落明文；公开仓库与配置同步都不会带走密钥 |
| 10 | 流式还是等完整结果？ | **流式**（§3.2、§5.2） | 整段翻译的首字延迟通常 0.5–2 s，流式能把等待变成阅读 |
| 11 | 命令面板里除了 `翻译 <文本>`，要不要 `翻译剪贴板` 这个动作？ | **v1 不加** | 剪贴板风险同第 6 项；真要加就等 ⌘C 兜底那一版一起考虑 |
| 12 | `cubbix translate` 的默认超时？ | **30 s**（上限仍 60 s），其余命令保持 5 s | 冷启动拉起应用 + 一次完整生成常常超过 5 s；脚本里超时比慢更难查 |
| 13 | 翻译失败算退出码 4 还是 1？ | **4**（未配置、鉴权、限流、超时、网络、无选中、模块关闭都算「应用拒绝了这次请求」），1 只留给协议与内部错误（§5.5） | 脚本只要看 4 就知道「换个时间或换个配置再试」，不用逐条认 `code`；与 006 现有的 4/1 划分也一致 |
| 14 | 设置窗口最小高度从 388 抬到 444（§3.4 的算式），要不要接受？ | **接受 444** | 翻译页有 5 行（地址/Key/模型/自动发音/快捷键），只要全留在设置页，下限就必然超过 388；最省的写法（四行全 ③）也要 428。444 换两条看得见的一行说明，其他 5 页只多 56 pt 底部空白。第三条路是让翻译页自己滚动，但那要改 007「主页不滚动」的规则，不推荐 |
