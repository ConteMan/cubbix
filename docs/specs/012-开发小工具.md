## 1. 同类产品怎么把结果交到手上

本节只写交互路径：怎么触发、输入在哪、结果出现在哪、怎么拿走、中间有几步。功能名单不展开。Raycast 手册和 uTools 文档没有直接打开成功，这两处的键位以检索摘要为准；摘要里丢失的键位符号标「未证实」。其它结论来自下列链接的公开页面。没有在本机安装或打开这些应用。

### 1.1 各家的路径

**Raycast 内置计算器**

- 触发：根搜索里直接打，没有单独的「打开工具」这一步。[手册](https://manual.raycast.com/calculator) 写它能算时区、单位、日期和货币，日期可以写成 ISO 8601 的 Zulu，也可以写成 `time in brisbane + 4 hours`（跨夏令时仍留在那个城市）和 `August 5 + 5`。手册的内置例子里没有裸的 Unix 时间戳。

### 1.2 共识、差异、以及用在 Cubbix 的哪一层

共识是一条一步路径：输入或选中已经就绪，结果行或预览出现，回车（或点击）复制。粘贴到前台是第二动作，Raycast 的 `Action.Paste`、Alfred DevToolbox 的 ⌘↩ 都是这样，不是每个内置功能的默认键。

零步只出现在「这次唤出就是对着选中文字或剪贴板」的时候：uTools 超级面板、DevUtils 的检查热键、He3 复制后的推荐。它不适合每一次都从空查询开始的命令面板。`showPalette` 打开时把 `query` 置空；若每次打开都去读选中文字，辅助功能那次读取会挡在输入前面。010 已把划词放在快捷键路径上，命令面板不读。本规格沿用这条边界。

差异：

| 产品 | 裸 Unix 时间戳 | 结果出现的位置 | 拿走结果 |
| --- | --- | --- | --- |
| Raycast 内置 | 手册例子里没有 | 根搜索的答案 | ↵ 复制；粘到前台未证实 |
| uTools / DevUtils / He3 | 有，常靠剪贴板进入 | 超级面板、工具页或搜索预览 | 点击或回车复制 |
| DevToys / Boop | 有 | 窗口或草稿纸 | 生成或变换之后再复制 |

Cubbix 已经有命令面板和工具窗口，对应关系：

- 一步放在命令面板：整段查询命中就在顶部给出结果行，回车复制。不先打开一个窗口。同名的普通命令仍留在下面，保留普通搜索的逃生路径。
- 零步只做成「空查询时的剪贴板建议」，而且默认不选中。误判一个 10 位数字时，回车仍执行原来的第一条命令，不会把剪贴板抄出去。
- 批量 UUID 第 1 步全部在面板里复制（1–100 个）；工具窗口是第 2 步的可选入口。大写与去横线是这一次结果的动作（⌘K），不写配置，也不强制开窗口。
- ⌘回车粘到前台是第二动作，与 Alfred 的 ⌘↩ 同级，不作为回车的默认。

## 2. 范围

### 2.1 第一批

1. 时间戳与日期互转。单位是秒、毫秒、微秒、纳秒。本地时区与 UTC。ISO 8601 / RFC3339。当前时间。
2. UUID：生成 v4 与 v7；解析粘进来的 UUID，并标出版本半字节和变体。可选大写、去横线、批量。

两件事共用同一套「结果行」。后面若要加 Base64 之类，加的是识别器，不是另一套面板。

### 2.2 第一批不做

| 工具 | 为什么留到后面 |
| --- | --- |
| Base64、URL 编解码 | 和结果行同构，但填充、换行、`+` / `%` 的误判比时间戳多 |
| MD5、SHA-256 | 标准库就能算，但结果不可逆，和「换算」放在同一行里容易抄错 |
| JWT 解码 | 只解码、不验证签名，必须单独写清楚；第一批的界面装不下这句警告 |
| 随机字符串 / 密码 | 字符集和长度是一组设置，不适合塞进「只有开关和快捷键」的设置页 |
| 多时区对照 | 要一张时区列表。第一批只有本地和 UTC |

宁少勿多：第 1 步交付之后，时间戳和 UUID 已经能从命令面板复制出去。上面五行都是后续，不进本规格的实现拆分。

### 2.3 库

`go.mod` 没有 uuid 依赖。Go 1.27.1 的标准库有 `package uuid`（`go doc -all uuid` 与最小编译运行均已确认）。`go.mod` 为 Go 1.27.1 / MyGo v0.6.2，`scripts/release.sh` 与 `scripts/selftest.sh` 也固定同一 GOTOOLCHAIN 和 `CGO_ENABLED=0`，可以直接使用。

已确认的签名：

```go
type UUID [16]byte
func New() UUID
func NewV4() UUID
func NewV7() UUID
func Parse(string) (UUID, error)
func MustParse(string) UUID
func Nil() UUID
func Max() UUID
func (UUID) String() string
```

`Nil` 与 `Max` 是函数，不是变量。程序只调用 `NewV4`、`NewV7`、`Parse`、`Nil()`、`Max()`；`NewV4` 与 `NewV7` 都返回 `UUID`，不是 `(UUID, error)`。包文档写明 v4/v7 并引用 RFC 9562；`NewV7` 的排序递增有系统时钟回拨例外，产品不额外承诺严格单调。

不使用 `github.com/google/uuid`。标准库已经覆盖 v4、v7 和解析。

时间只用标准库 `time`。时区用 `time.Local` 与 `time.UTC`，不内置城市表。

### 2.4 仓库外实验（Go 1.27.1，程序已删除）

**UUID `Parse`**

| 输入 | 结果 |
| --- | --- |
| 32 位无横线十六进制 | 成功，输出仍是带横线的标准串 |
| 大写、带横线 | 成功 |
| `{...}` 花括号 | 成功 |
| `urn:uuid:` 前缀 | 成功；`URN:UUID:` 与 `urn:uuid:{...}` **不被 `Parse` 接受**，所以外壳要自己剥 |
| 版本半字节为 0 | 成功。`Parse` 不是版本识别器 |
| Nil（全 0） | 成功，变体高两位是 `00` |
| `NewV4` / `NewV7` | 版本半字节分别是 4 和 7，变体高两位都是 `10` |
| `00000000-0000-7000-c000-…` / `…-e000-…` | 都能 Parse，版本半字节都是 7，高两位都是 `11`，但变体分别是 Microsoft 与保留 |
| `00000000-0000-7000-0000-…` | 能 Parse，变体是 NCS |

因此识别必须先看文本形状，再调用 `Parse`。不能把「`Parse` 成功」当成「这是用户想换算的 UUID」，也不能用高两位完整表示 variant。

**时间**

| 输入 | 结果 |
| --- | --- |
| `time.Unix(2147483648, 0)` | `2038-01-19T03:14:08Z`。没有 2038 溢出 |
| `time.Unix(-1, 0)` | `1969-12-31T23:59:59Z` |
| `time.Date(2000, 1, 1, …)` 的 Unix 秒 | `946684800`，9 位 |
| `time.Unix(1000000000, 0)` | `2001-09-09T01:46:40Z`。10 位秒、13 位毫秒都从这一刻起算 |
| `time.Date(2100, 1, 1, …)` 的 Unix 秒 | `4102444800` |
| `2016-12-31T23:59:60Z` | `Parse` 报 `second out of range`；产品文案单独写「暂不支持闰秒」 |
| 纽约 `2026-03-08 02:30:00` | `ParseInLocation` **不报错**，得到 `2026-03-08T01:30:00-05:00`。跳空被折进跳空前的钟面 |
| 纽约 `2026-11-01 01:30:00` | `ParseInLocation` 得到 `2026-11-01T01:30:00-04:00`（较早的一次，EDT）；加一小时得到 `-05:00` 的一次 |
| 伦敦 `2026-10-25 01:30:00` | `ParseInLocation` 得到 `01:30Z`，是**后一次**；减一小时才是 `01:30+01:00` |
| `Australia/Lord_Howe 2026-04-05 01:45:00` | 两次相差 30 分钟，固定加/减一小时都不对 |
| `2006-01-02 15:04:05` 这个版式 | 对同一秒上的 500 ms 和 999 ms 都停在该秒，没有进到下一秒 |
| `0001-01-01T00:00:00+14:00` | UTC 年份是 0；`9999-12-31T23:59:59-12:00` 的 UTC 年份是 10000 |
| 年份 0 的日期 | `time.Parse` 能接受；产品要自己拒绝 |
| `+24:00`、`+00:60` | `time.Parse` 接受，后者被归一成 `+01:00`；产品要在解析前拒绝 |
| 公元 10000 年 | `Format` 返回 `10000-01-01T00:00:00Z`，**不报错** |
| 公元 1 年与 9999-12-31 | 都能格式化。公元 1 年的 Unix 秒是 `-62135596800`，11 位 |

两条直接写进规则的推论：

- 纯位数不能覆盖 2000 年到 2001-09-09。9 位秒、12 位毫秒在裸输入里不自动换算。
- 不能靠 `Format` 的报错来拒绝五位年份。年份 1–9999 是产品规则。

## 3. 交互

识别函数放在 `internal/devtools`，命令面板、第 2 步的窗口和 CLI 调用同一套。它不读剪贴板、不生成窗口；第 1 步只由面板调用。生成单独一个函数，并且只在查询变化时调用一次。

`refreshPalette` 每帧都跑。结果若在 `refreshPalette` 里调用 `NewV4`，UUID 会每一帧变一次，回车复制到的不是用户看见的那一串。生成结果按查询字符串缓存在 `paletteState` 上，查询没变就复用；`showPalette` 重开、模块关闭或模块重开都清空缓存，`now` 同样只在这次查询开始时取一次 `time.Now()`。大写与去横线转换的是这份缓存里的原值，不重新生成。

### 3.1 什么时候换成结果行

模块关闭时不识别，面板与现在一样。

模块打开时，在 `refreshPalette` 做普通搜索之前，对去掉首尾空白的整段查询按下面的顺序判断。命中的结果行放在列表顶部，同名的普通命令仍排在下面；普通搜索的逃生路径不被隐藏。

1. 第一个词是 `ts`、`timestamp` 或 `时间戳`（大小写不敏感）：走时间。没有参数、或参数是 `now`，表示当前时间。其余参数按 §3.2 的「带前缀」规则解析。解析失败是错误行，不退回搜索。
2. 整段就是 `now`：当前时间。
3. 第一个词是 `uuid`、`uuid4`、`uuidv4`、`uuid7`、`uuidv7`：走 UUID 生成。个数规则见 §3.3。`uuid v4` 这种中间再加版本词的写法不接受，整段退回搜索。
4. 整段是 UUID 字面量：解析，不生成。
5. 整段是落在窗口里的裸整数：当时间戳。
6. 整段是日期：当日期。
7. 否则普通搜索。

前缀按**完整 token** 匹配：第一个词必须整体等于识别词。`settings`、`timestamped`、`ts946684800` 都不命中。现有命令的 `Keywords` 里没有 `uuid`、`ts`、`now`、`timestamp`、`时间戳`（本轮读了 `commands.go` 的静态关键字）。第 2 步新增的命令关键字也不得占用这五个词。

`devtools`、`开发工具` 不是识别词。第 2 步它们是一条普通命令，打开空的工具窗口；第 1 步不注册这条命令，也不留死入口。

不从一句话里摘时间戳或 UUID。`see 1700000000` 是普通搜索。

### 3.2 时间

**裸输入和剪贴板**只用非负整数，并且必须同时满足位数和区间。区间外不当作错误，退回搜索或忽略剪贴板。

| 位数 | 单位 | 区间（左闭右开） |
| --- | --- | --- |
| 10 | 秒 | `[1000000000, 4102444800)` |
| 13 | 毫秒 | `[1000000000000, 4102444800000)` |
| 16 | 微秒 | `[1000000000000000, 4102444800000000)` |
| 19 | 纳秒 | `[1000000000000000000, 4102444800000000000)` |

右端点是 `2100-01-01T00:00:00Z`。9、11、12、14、15、17、18 位都不猜。`946684800`（2000-01-01）是 9 位，裸输入不换算。

**带 `ts` 前缀**时：

- 可有一个负号。不允许正号，不允许 `1e9`。
- 无后缀：1–10 位当秒，13 / 16 / 19 位当毫秒 / 微秒 / 纳秒。11、12、14、15、17、18 位是错误 `DevtoolsUnit`，不猜。9 位秒（如 `946684800`）必须带 `ts` 前缀；12 位毫秒必须带 `ms`（如 `946684800000ms`）。错误 tooltip 与规格例子都写清这两点。
- 后缀 `s`、`ms`、`us`、`µs`、`μs`、`ns` 优先于位数，大小写不敏感，后缀前的空格可有可无。
- 整数解析必须带溢出检查。超过所选整数表示范围的文本明确拒绝（`DevtoolsRange`），不允许回绕。
- 构造时间时按单位拆成「秒 + 纳秒余数」，再调用 `time.Unix(秒, 纳秒)`；不先把输入乘成 `int64` 纳秒或 `time.Duration`。公元 1 年和 9999 年的 `UnixNano` 已超出其定义范围，乘法会溢出。
- 得到的瞬间，本地年份与 UTC 年份都必须在 1–9999，否则 `DevtoolsRange`。不能只看输入年份，也不能靠 `Format` 报错：`0001-01-01T00:00:00+14:00` 的 UTC 年份是 0，`9999-12-31T23:59:59-12:00` 的 UTC 年份是 10000。
- `ts 946684800` 覆盖裸输入够不着的 2000-01-01。`ts 946684800000` 是 12 位且没有后缀，仍然是 `DevtoolsUnit`；要写 `ts 946684800000ms`。

**日期**接受：

- RFC3339 与 RFC3339Nano，小数秒支持到 9 位。
- `2006-01-02`、`2006-01-02 15:04`、`2006-01-02 15:04:05`，以及带小数秒的同一形状（如 `2026-11-12 00:00:00.123456789`）。
- 斜杠版 `2006/01/02`，时间部分同上。

不接受 `01/02/2006`，也不接受没有补零的月日。字符串里的偏移优先于本地。没有偏移时用 `time.Local`。带偏移的输入要在解析前严格校验：小时 00–23、分钟 00–59，`+24:00` 与 `+00:60` 都拒绝（`DevtoolsDateInvalid`），不能交给会归一化的解析器。年份 0000 拒绝（`DevtoolsRange`）。

**闰秒**不处理，但文案独立：秒为 60 时给「暂不支持闰秒」（`DevtoolsLeapSecond`），不映射成 `DevtoolsRange`，也不把原文的 `second out of range` 给用户看。

**跳空与重叠**都按实际时区过渡求候选瞬间，不把 `+1h` 当通用算法：

- 以输入的钟面字段构造一个「墙上时间」，在 `time.Local`（或输入自带的固定偏移）周围的两天里用 `time.Time.ZoneBounds` 枚举相关偏移。每个偏移给出一个候选瞬间，再把候选换回该时区逐字段回验（年、月、日、时、分、秒、纳秒都相同）。
- 无候选 = 跳空，错误行 `DevtoolsSkipped`，不给出被改过的时间。纽约 `2026-03-08 02:30` 仍是这个结果。
- 两个候选 = 重叠。按瞬间排序，默认较早者；两个都展示，后一个标题仍是同一个钟面，hint 写另一个偏移（`DevtoolsOverlap`），载荷是该候选的 RFC3339Nano。纽约 `2026-11-01 01:30` 默认 `-04:00`；伦敦 `2026-10-25 01:30` 默认 `+01:00`；`Australia/Lord_Howe 2026-04-05 01:45` 默认 `+11:00`，另一个是 `+10:30`。
- 去重按瞬间；两个以上候选也全部展示，默认仍是最早的。

**结果行**，默认选中第 1 行。标题是要展示的文本，载荷是要复制的文本；两者可以不同。回车复制载荷。

时间戳输入：

1. 本地 `2006-01-02 15:04:05`，hint「本地」。有小数秒时标题仍可不显示，载荷保留小数（去掉末尾 0）。
2. UTC，同一版式，hint「UTC」，载荷同样保留小数。
3. 本地 RFC3339**Nano**。
4. 另一单位的整数：秒输入给毫秒，毫秒输入给秒，微秒与纳秒给秒和毫秒两行。

日期输入：

1. Unix 秒。
2. Unix 毫秒。
3. UTC 的 RFC3339**Nano**。
4. 本地 `2006-01-02 15:04:05`，载荷保留小数。输入自带偏移时，这一行是那个瞬间在本地的钟面，不用本地偏移盖掉输入里的偏移。
5. 重叠时追加一行「另一次」，见上。

`now`、无参数的 `ts`：

1. Unix 秒。
2. Unix 毫秒。
3. 本地 `2006-01-02 15:04:05`。
4. UTC 的 RFC3339Nano。

所有可复制的 RFC 行统一用 `RFC3339Nano`，微秒、纳秒和带小数的日期输入都不丢精度。默认钟面可以不显示小数。Go 1.27.1 上，不带小数的版式对 500 ms 和 999 ms 没有进位；没有读 `Format` 的源码，不把「一律截断」写成库的保证。

### 3.3 UUID

**生成**

| 查询 | 行 |
| --- | --- |
| `uuid`、`uuid4`、`uuidv4` | 两行。第 1 行 v4，默认选中。第 2 行 v7 |
| `uuid7`、`uuidv7` | 只有 v7 |
| `uuid 8`、`uuid4 8` | 8 个 v4 |
| `uuid7 8` | 8 个 v7。`uuid7 N` 只生成 v7 |

个数是不含正号的十进制整数。`uuid 08` 等于 8。`uuid +8`、`uuid 8x`、`uuid v4` 整段退回搜索。`uuid 0`、负数、大于 100 是错误行 `DevtoolsCountInvalid`，回车不关闭面板。计数解析也要有溢出检查。

1 个是一行。单个 v7 再加一行：从前 48 位取出的 UTC 毫秒，版式 `2006-01-02 15:04:05.000 UTC`，载荷是毫秒整数。

2–100 个是**一行**。标题是第一条，hint 是「共 N 个」（`DevtoolsCount`）。载荷是 N 行，用 `\n` 连接。回车复制全部，不复制标题。第 1 步不在 21 个处切换到窗口：1–100 都在面板里复制。批量不逐条展开，也不为批量加时间行。

默认文本是小写、带横线。hint 写版本和变体：版本是 `byte[6]` 的高 4 位，变体按 RFC 9562 完整分类：

| `byte[8]` 高几位 | 变体 |
| --- | --- |
| `0xxx` | NCS |
| `10xx` | RFC 9562 |
| `110x` | Microsoft |
| `111x` | 保留 |

只有 `10xx` 且版本半字节为 7 时才解释前 48 位为 v7 时刻。Nil 与 Max 单独标记（`DevtoolsNil` / `DevtoolsMax`），不当作普通版本 7。

**解析**先剥外壳，再看形状，最后 `Parse`：

1. 去掉首尾空白。
2. 若开头是大小写不敏感的 `urn:uuid:`，剥掉一次。
3. 若首尾是 `{` 与 `}`，剥掉**一层**。
4. 剩下的核心必须是 `8-4-4-4-12` 或 32 位十六进制。
5. 形状通过后才调用 `uuid.Parse`。

因此 `urn:uuid:{...}`、`{...}`、`urn:uuid:...` 都接受；`{urn:uuid:...}`、`{{...}}`、双层前缀都不接受。版本不限，v1、v5、Nil 都显示。Nil 的内容全 0，变体 NCS；Max 全 F，变体是保留。形状不符就退回搜索，不用错误行打断普通输入。

**大写和去横线**是这一次结果的动作（§3.5），只改缓存里这一批载荷，不写配置，也不重新生成。入口是这一行的 ⌘K。窗口里的两个开关才写入配置（第 2 步）。

### 3.4 剪贴板建议

`showPalette` 在模块打开、且这次是空查询时读一次剪贴板。条件全部满足才出现一组「剪贴板」，插在收藏之前：

- 去掉首尾空白后的字节数 ≤ 128。
- 整段命中 §3.2 的裸时间戳、§3.2 的日期，或 §3.3 的 UUID 字面量。带 `ts` / `uuid` 前缀的文本不当作剪贴板命中。

默认选中仍走现有的 `bestCommand`，不选这一组。方向键可以上去。用户改过查询之后，这一组消失。面板开着的时候不再读第二次，避免刚复制出去的结果立刻变成下一次按键的目标。关闭后再打开，才重新读。

读失败当空，不提示。不落盘，不写日志。模块关闭时不读，并清掉上一次留下的建议。超长文本或普通句子是「读取一次后不识别、不保存」；只有模块关闭可以断言根本不调用剪贴板 seam。卡片、命令、CLI 不读剪贴板。打开面板时不读选中文字。

误判留在「未选中」这一层处理：10 位订单号可能落进秒的区间。它出现在独立的组里，回车的默认对象仍是原来的命令。

**第 2 步的专用快捷键**（`⌃⌥⌘D`）是明确的上下文入口，与通用面板分开：

| 打开时的状态 | 填入 |
| --- | --- |
| 命中选区 | 选区文字 |
| 选区存在但不命中 | 空窗口，保留选区意图，不读剪贴板 |
| 无选区或读取超时 | 尝试剪贴板，命中则填入 |
| 读取忙或权限拒绝 | 空窗口；权限拒绝时按二维码既有保护只提示一次 |

专用入口可以默认选中预填后的首个结果；通用 `showPalette` 不加同步 AX。读取沿用 `captureSelectionContext` 的限时、共享 CAS 与 `beginQRSelection` 的 generation。

### 3.5 拿走结果

结果行复用 `paletteRow` 现有的默认绘制：图标、标题、右侧 hint，行高 `SizePaletteRowHeight`。不新开行高 Token。标题是给人看的，载荷另放。单个结果时二者可以相同；批量时标题只是第一条。

**状态机**（不只改 `movePaletteSelection` 与 `runPalette`；`refreshPalette` 的首选、`selectionKey`、回到普通列表后的请求状态和 `bestCommand` 都要照顾）：

- 结果行有自己的稳定 key：`devtools.result.<序号>`，剪贴板建议是 `devtools.clipboard.<序号>`。同一查询的同一行 key 不变，方向键和动作返回都能恢复。
- 确定结果在顶部时，默认选中第 1 个结果行；错误行也是默认选中项，回车不关闭。空查询的剪贴板建议不改变现有首选。没有可用命令、也没有结果时是空选择，回车不执行。
- 方向键可以经过结果行、错误行、剪贴板建议行和普通命令。输入文字改变查询时，保留的 `selectionKey` 清空，重新取默认。
- 结果缓存按查询保存，但 `showPalette` 重开、模块关闭后重开必须失效；`now` 和 UUID 不能跨会话复用。
- 执行时再次检查模块启用状态；模块在行出现后关闭，旧行不可复制。会话代次与模块开关一起负责让旧缓存失效。
- 大写/去横线只转换缓存里同一批原值，不重新生成。
- 回车不双执行：输入框的 `OnSubmit` 与列表的 `OverlayShortcut(0, ui.KeyEnter)` 可能都对同一次按键作出反应，结果复制成功后置一次执行标记，下一次重开或查询变化才清掉。

回车（以及点击结果行）：

- 错误行：留下面板，行上和搜索框显示 `ErrorKey`。与非法常亮参数一样，不关闭。
- 其余：把载荷写入剪贴板，关闭面板。不调用 `recordRecent`。不弹 002 的提示。
- 写入失败：留下面板，错误行 `DevtoolsCopyFailed`。

结果行不进收藏，不进最近使用。能收藏的只有第 2 步「开发工具」这条打开窗口的命令。

⌘K 不走 `command.Actions`。结果行单独分支：有动作才显示顶部 keycaps，没有动作（错误行、空选择）就不显示。keycaps 做成可点击按钮，tooltip「操作 (⌘K)」（`PaletteActionTooltip`），点击与 ⌘K 等价。

| 动作 | 时间行 | UUID 行 | 第几步 |
| --- | --- | --- | --- |
| 复制 | 有，等同回车 | 有 | 1 |
| 大写 | 无 | 有，只改这次载荷 | 1 |
| 去横线 | 无 | 有，只改这次载荷 | 1 |
| 粘贴到前台 | 第 2 步 | 第 2 步 | 2 |
| 在窗口中打开 | 第 2 步 | 第 2 步 | 2 |

动作不进最近使用。大写或去横线执行后回到原来的结果行；复制执行后关闭面板。

**⌘回车粘贴（第 2 步）**

第 1 步只做回车复制，不实现 ⌘回车，不探测粘贴权限，也不留下调用 `CGRequestPostEventAccess` 的分支。

第 2 步做法：先写入剪贴板，关闭面板，再合成 ⌘V。不恢复原来的剪贴板。010 已确认 `CGEventCreateKeyboardEvent` 与 `CGEventPost` 能解析，并且明确不模拟 ⌘C、不用 `AXIsProcessTrustedWithOptions` 弹框。

权限只做 preflight，不在粘贴路径申请：Apple DTS 在 [这篇讨论](https://developer.apple.com/forums/thread/789896)（2025-10）里说 `CGEvent.post` 使用单独的 TCC `PostEvent`，系统设置里显示在「辅助功能」下，用 `CGPreflightPostEventAccess` 探测、`CGRequestPostEventAccess` 申请；它和 `kTCCServiceAccessibility` 不是同一个服务。第 2 步只用 preflight：已有权限就粘贴；没有权限或符号不可用就只复制并关闭，不打开系统设置，不调用 Request，也不报告「已粘贴」。若以后需要授权入口，单独设计。

另外三件未实测：非 ANSI 键盘上 V 的虚拟键码（ANSI 是 `0x09`）；安全输入框会吞掉合成按键；面板关掉之后前台是不是原来的应用。固定 50 ms 延迟只是起点，放成常量，不进设置。第 2 步要补：目标前台应用、面板关闭、修饰键释放、仅执行一次的 seam 约定，并分别验收已授权、未授权、符号不可用与安全输入四种情况。MyGo v0.6.2 的 `ui/textinput.go` 的 `OnTextKey` 与 `ui/editor_navigation.go` 的 `editor.wants` 已说明 Cmd+Enter 可在提交前分流，不必再把它当未知；但实际前台粘贴仍由维护者验收。

### 3.6 工具窗口

第 2 步。第 1 步不创建窗口、不写 `devtools_placement.go`，也不改 `window_placement.go` 的 `repairWindowPlaces`。

第 2 步把开发工具窗口纳入显示器变化后的座位修复：`repairWindowPlaces` 目前显式枚举设置、JSON、翻译、二维码，要加入开发工具；拔屏、工作区变化和不可用屏幕的延迟位置处理都要覆盖，并测试打开恢复、关闭保存与退出清理。风格与座位键对齐二维码，`openDevtools` 只关浮层，`showPalette` / `showMenubarPanel` 不关这个窗口；关闭模块只关自己。

样式对齐 `qrWindowOptions`：`TitleBarHidden`、红绿灯在 `Space12` / `Space16`、`DisableFullScreen`、背景 `ColorCard`、创建时 `Hidden`、`DevToolsDisabled`。单实例。⌘W 与 Esc 关闭。失焦不关。按屏记几何，键 `devtools_windows`，照 `qr_placement.go` 的座位写，不动 JSON、翻译、二维码的座位。

`openDevtools` 只关浮层（`hideMenubarPanel`、`hidePalette`），不关 JSON、翻译、二维码。`showPalette` 与 `showMenubarPanel` 也不关这个窗口。关闭模块只关自己。

尺寸是新 Token：宽 480，高 440，最小高 360，最小宽与宽相同。011 给二维码也是新开的一套，不复用二维码的高。

布局：

- 工具栏：标题「开发工具」，右侧分段「时间 | UUID」，再右侧置顶。分段记住上次的选择，记在窗口状态里，不进设置页。
- 时间：一个输入框。本地即时刷新，不做翻译那种 200 ms 防抖。下面是 §3.2 的结果行。点击一行即复制。⌘C 与回车复制选中行。⌘回车走 §3.5。输入为空时显示 `now` 的四行。
- UUID：各显示一个 v4 和一个 v7。`refresh-cw` 再生成一对。两个开关「大写」「去横线」写入 `DevtoolsUUIDUpper` 与 `DevtoolsUUIDPlain`，默认都关。它们不出现在设置页，和 JSON 的分栏开关一样只留在窗口里。批量是多行文本，点击复制全部。
- 「在窗口中打开」要带**完整生成请求**（版本、个数、大写、去横线），不能只传 N 再按窗口默认版本重生成；`uuid7 21` 到窗口后仍是 21 个 v7。加一条跨入口测试。第 1 步没有这个入口。

快捷键打开窗口时才读选中文字，顺序对齐二维码：选中文字整段命中则填入；否则剪贴板整段命中则填入；否则空。命中规则与 §3.4 相同，上限也是 128 字节。命令、卡片打开的是空窗口，不读。

快捷键默认 `Ctrl+Alt+Cmd+D`。`knownShortcutConflict` 的三组里没有这一串（本轮读了 `awake_view.go` 的表）。011 写过 Apple 系统快捷键表里的 ⌃⌥⌘ 只有 C、P、逗号和句号；本轮没有重新打开那张表。U 留给「只生成 UUID」会太窄，所以不用 U。

### 3.7 卡片与 CLI

**卡片**第 2 步加。一张单行卡，图标 `blocks`，标题「开发工具」，打开空窗口。`menubarPanelRows` 增加 `devtools`。空状态从「常亮、JSON、翻译、二维码都关」改成五个都关。只开开发工具时不得同时画出空状态。

**CLI** 第 2 步要有。生成与识别都走 `internal/devtools`，不在 `cmd/cubbix` 里复制一份规则。

```
cubbix ts [TEXT|now]
cubbix uuid [--v4|--v7] [--upper] [--plain] [-n N]
```

| 项 | 规定 |
| --- | --- |
| `ts` 无参数且没有管道 | 当前时间 |
| 管道与参数 | 二者互斥，同时给则退出 2。管道由 CLI 读入后放进请求的 `arg`，不用正文帧 |
| `ts` 的文本 | 与 §3.2 的「带前缀」规则相同，但用户不必再写 `ts`。空文本退出 2。超过 `MaxArg`（128）退出 2 |
| `uuid` | 默认 v4、1 个、小写、带横线。`--v4` 与 `--v7` 同时给则退出 2 |
| `-n` | 默认 1，允许 1–100。小于 1 或大于 100 退出 2。CLI 的批量上限与面板一致，不强制开窗口 |
| 人读输出 | 每个结果一行。时间的第一行是 §3.2 的默认行 |
| `--json` | 一行 JSON。`lines` 是全部结果，`message` 是默认那一行，`state` 与现在相同 |
| `--notify` | 退出 2。这个模块不弹提示 |
| 模块关闭 | `disabled`，退出 4 |
| 退出码 | 沿用 006：0 / 1 / 2 / 3 / 4 / 5 |
| 超长 | `--json` 若经 `EncodeLine` 超过 `MaxLine`（4096），沿用现有的超限失败，不截断。100 只是个数上限，不是对 `state` 体积的测量；是否调整 `MaxLine` 另按编码后的真实大小决定 |

`cli.Request.Validate` 要写清两个 action 的字段白名单：`ts` 只接受 `arg`，`uuid` 只接受 `count`、`uuidVersion`（0 表示默认 4）、`upper`、`plain`；`count` 缺省 1、范围 1–100，旧 action 带新增字段按现有未知字段规则拒绝。成功响应 `Bytes=0`、`Translate=nil`，不写正文帧。

`cliServer.handle` 手工从 Result 组 Response、`Response.Result()` 再组 Result，两处目前都已经带 `Lines`，本轮规格没有新增响应结构字段。第 2 步补一条端到端回归，证明两跳保留 `lines` 与 `message`；以后加新字段才需同时更新两处。批量策略与交互窗口分开，脚本里不要求超过 20 个就开窗口。

不改 `Tiles`。不扩 `cubbix://`。不升 `Protocol`。

### 5.3 拟议签名

```go
// internal/devtools/devtools.go
type Kind int // KindTime / KindUUID

type Row struct {
    Kind     Kind
    Title    string  // 面板上的文字
    Payload  string  // 复制出去的文本；批量是多行
    HintKey  string  // 资源键，例如 DevtoolsLocal
    HintArgs []any   // 交给 fmt.Sprintf 的参数；没有就为空
}

type Output struct {
    Kind     Kind
    Rows     []Row
    Payload  string  // 默认行的载荷
    ErrorKey string  // 错误时只有这个，没有行
}

// Query 识别整段查询；recognized=false 表示这只是普通搜索。
func Query(text string, now time.Time, loc *time.Location) (Output, bool)

func ConvertTime(text string, now time.Time, loc *time.Location) Output
func CurrentTime(now time.Time, loc *time.Location) Output
func ConvertBareTimestamp(text string, loc *time.Location) (Output, bool)
func ConvertDate(text string, loc *time.Location) (Output, bool)
func GenerateUUID(version, n int, upper, plain bool) Output
func GenerateUUIDPair() Output // uuid 无参数：v4 行在前，v7 行在后
func ParseUUID(text string) (Output, bool)
```

`version` 只允许 4 或 7，`n` 只允许 1–100。`loc` 为 nil 时用 `time.Local`。错误都落在 `ErrorKey`，不把 `time.Parse` 的原文带出这个包。`HintKey` 由界面层格式化，包内不写界面语言。

```go
// devtools_app.go
// 第 1 步
func (a *application) changeDevtoolsEnabled(target bool)
// 第 2 步
func (a *application) openDevtools(req devtoolsRequest)
func (a *application) toggleDevtools()
func (a *application) closeDevtools()
```

第 1 步的 `changeDevtoolsEnabled`：取消正在进行的录制；与现值相同则只刷新并返回；**先**写 `DevtoolsEnabled`，再保存、刷新设置，并调用 `invalidatePaletteAfterModuleChange` 清掉结果缓存、剪贴板建议和执行守卫。没有快捷键、没有窗口可关，所以不注销快捷键、不关窗口。

第 2 步再按 `changeQREnabled` 的顺序补：打开则 `registerSlot("devtools", …)`；关闭则 `releaseOwnedShortcut` → `clearSlotError` → `closeDevtools`。先赋值这一步不能省，否则 `applyCLI` 仍认为模块开着。`openDevtools` 收完整生成请求，不只是个数。

### 5.4 第七个快捷键槽（第 2 步）

第 1 步不注册快捷键槽，也不写 `DevtoolsShortcut`；设置页只有页头开关。第 2 步逐处加 `devtools`，一处不漏：

- `shortcutSlots`
- `shortcutSlotEnabled`：返回 `DevtoolsEnabled`，不要掉进最后的 `return true`
- `setSlotError`、`slotError`、`clearSlotError`：各自一个字段，例如 `devtoolsShortcutError`
- `shortcutSettingsRow`：标签、录制键、模块名、`DevtoolsShortcut`
- `recordShortcut`：`case "devtools": a.config.DevtoolsShortcut = acc`，放在现有 `case` 里。不增加会写别的槽的 `default`

`restoreShortcuts` 按 `shortcutSlots` 循环，不用改。注册只走 `registerSlot("devtools", a.config.DevtoolsShortcut, a.config.DevtoolsEnabled, a.toggleDevtools)`。默认组合不加入 `knownShortcutConflict`。

### 5.5 协议

`Protocol` 保持 1。加 action 与加 omitempty 字段都不算不兼容。

| 项 | 规定 |
| --- | --- |
| action | `ts`、`uuid` |
| `ts` 的文本 | 放在现有的 `arg`。拒绝 `bytes`、`notify`、`page`、`mode`、`follow`、`lid`、`blank`、`to` |
| `uuid` | 新字段 `count`（缺省 1，范围 1–100）、`uuidVersion`（0 表示默认 4）、`upper`、`plain`，均为 omitempty。不用正文帧 |
| 响应 | 不新增结果结构体。`lines` 承载全部行，`message` 承载默认行。`Result()` 已经拷贝 `Lines`；若有人把新字段只加在 `Response` 上，必须同时加进 `Result()` |
| `Validate` | `ts` 只接受 `arg`；`uuid` 只接受 `count`、`uuidVersion`、`upper`、`plain`；旧 action 带新增字段按未知字段拒绝 |
| 两跳回归 | `cliServer.handle` 与 `Response.Result()` 目前都已带 `Lines`；补一条端到端测试证明两跳保留 `lines`/`message` |
| `applyCLI` | 与二维码一样，先看 `DevtoolsEnabled` |
| `state` | 不放入生成的 UUID，避免 100 行把单行 JSON 撑过 `MaxLine` |

### 5.6 与既有规格的边界

- **001**：第 2 步加一张单行卡。**002**：不弹提示。**003**：不新增 `paramText` 命令；结果行是新的行种类，⌘K 的动作页也能没有 `command`。
- **006**：第 2 步两个 action，不升协议版本。**007**：第 8 页；第 1 步只有页头，第 2 步补 ③ 级快捷键行。共享下限按 §4.4 第 1 步就改为 456。
- **008**：第 2 步新座位 `devtools_windows`，并加入 `repairWindowPlaces`。**010 / 011**：不改翻译和二维码的划词。第 2 步快捷键预填若与翻译的读取冲突，打开空窗口，不读剪贴板，也不把冲突当成「没有选中」。这条与 011 §6.7 的 CAS 失败相同。

## 6. 测试

### 6.1 单元测试

不建窗口，不注册快捷键，不读系统剪贴板。剪贴板用 seam，和二维码的 `qrReadClipboard` 一样。

| 测试 | 覆盖 |
| --- | --- |
| 裸整数 | 10 / 13 / 16 / 19 位且在区间内命中；9 位 `946684800`、11 与 12 位、区间外的 10 位退回「不是时间戳」；`4102444800` 本身不在裸区间内 |
| 前缀 | `ts 946684800` 是 2000-01-01；`ts -1` 是 `1969-12-31 23:59:59` UTC；`ts 946684800000` 无后缀为 `DevtoolsUnit`；`ts 946684800000ms` 成功；后缀优先于位数；`ts +8`、`ts 1e9` 拒绝 |
| 2038 与年份 | `ts 2147483648` 得到 `2038-01-19 03:14:08` UTC；本地与 UTC 年份不在 1–9999 都是 `DevtoolsRange`；整数解析溢出拒绝且不回绕 |
| 闰秒 | `2016-12-31T23:59:60Z` 拒绝，文案键是 `DevtoolsLeapSecond`，不含 `second out of range` |
| 精度 | 微秒非整毫秒、纳秒非整微秒、带小数的 RFC3339 与日期输入，载荷里都有 RFC3339Nano 或等价精度；默认钟面可以没有小数 |
| 跳空 | 固定用 `America/New_York`，`2026-03-08 02:30:00` 为 `DevtoolsSkipped`，输出里没有 `01:30` |
| 重叠 | 纽约 `2026-11-01 01:30`、伦敦 `2026-10-25 01:30`、`Australia/Lord_Howe 2026-04-05 01:45` 都两行，默认较早者，另一个偏移分别正确；字段回验与去重 |
| 日期形状与偏移 | RFC3339 的偏移得以保留；`2006-01-02` 用传入的 loc；`01/02/2006`、`2026-3-8` 不命中；`+24:00`、`+00:60` 拒绝；年份 0000 拒绝 |
| 句子 | `see 1700000000`、一句里夹一个 UUID，都不命中；`settings`、`timestamped`、`ts946684800` 不命中 |
| UUID 生成 | v4 的版本半字节是 4，v7 是 7，变体高两位都是 `10`；默认小写带横线；`upper` 与 `plain` 只改文本；`uuid7 N` 只生成 v7 |
| UUID 解析 | 无横线、大写、花括号、`urn:uuid:`、`urn:uuid:{...}` 都成主行的小写带横线；`{urn:uuid:...}`、双层包裹拒绝；Nil/Max 单独标记；NCS / RFC / Microsoft / 保留四种变体只有 RFC+版本 7 才解出时刻 |
| v7 时刻 | 用已知的 16 字节构造，前 48 位与手算的毫秒一致。不把「单调」写进测试 |
| 批量 | 1 与 `uuid` 不同（`uuid` 是 v4+v7 两行）；2–100 一个载荷、N 行、hint「共 N 个」；0、101、负数、计数溢出为 `DevtoolsCountInvalid`；`uuid +8`、`uuid 8x` 不是错误 |
| 缓存 | 同一查询连续刷新，`GenerateUUID` 只被调用一次；查询改变才再调用；`showPalette` 重开、模块关闭后重开都失效 |
| 剪贴板 | 空查询、128 字节内、整段命中才出现组；129 字节、普通句子、模块关闭都不产生建议（关闭时根本不调用 seam）；默认选中不是该组；面板保持打开时第二次刷新不读；改查询后组消失 |
| 面板执行 | 回车复制载荷而不是标题；批量复制全部行；不调用 `recordRecent`；写入失败不关闭；错误行不关闭；输入框/列表回车不双执行；模块关闭后旧行不可复制；动作返回原行 |
| 面板状态机 | 稳定结果 key；默认选第 1 个结果；方向键经过结果、错误、剪贴板建议；无可用命令时空选择；`⌘K` 在无动作时不显示，有动作时 keycaps 可点击 |
| 动作 | 大写/去横线转换同一批原值，不重新生成；动作页没有 `command` 也能返回结果行 |
| 开关 | 关闭后识别停用、缓存与建议清空；打开恢复；缺键读出默认开 |
| 设置页 | 第 1 步页高 56；侧栏 453；`settingsMinimumHeight` 为 456；0–6 页码不变；页序含开发工具且在二维码与快捷键之间；第 2 步断言快捷键行后页高 144 |
| CLI（第 2 步） | `--notify`、超 128、`-n 0`、`-n 101`、两个版本同时给，都是用法错误；模块关闭退出 4；`Result()` 带上 `lines`；两跳保留 `lines`/`message`；人读输出的第一行等于默认载荷 |

### 6.2 只能由维护者实测

1. 命令面板输入 10 位秒、13 位毫秒、一个日期、`now`、`uuid`、`uuid7 8`，回车后到别的应用粘贴，确认是载荷而不是标题，批量是全部行。
2. 空面板时剪贴板分别是时间戳、一段普通文字、超过 128 字节的文字。第一种出现建议且默认不选中；后两种没有这个组。
3. 本机时区下找一个真实的跳空和一个真实的重叠（不一定是纽约），确认跳空被拒绝、重叠有两行。
4. 第 2 步：⌘回车在已授权、未授权、符号不可用与安全输入框四种情况下各一次。未授权或符号不可用时应当只复制，不报告「已粘贴」。
5. 快捷键在选中文字、只有剪贴板、两者都不是这三类文本时，窗口里填入的内容是否符合 §3.6。
6. 非 ANSI 键盘上合成的 ⌘V 是否仍是 V。
7. CLI：应用没运行时能否拉起；`--json` 在状态快照较大时是否因 `MaxLine` 失败而不是截断。

### 6.3 合并门槛

`./scripts/selftest.sh` 全绿。所有 `go test` 带 `-timeout`（单项 120s；整包因既有渲染测试较慢，用 10m，均不抢焦点）。
