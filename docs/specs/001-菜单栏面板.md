# 详细设计 001：菜单栏面板重设计（多格子承载与一步到位交互）

- 文档状态：待评审（Design Spec）
- 关联问题：多格子架构扩展、常用操作交互扁平化、JSON 格子接入
- 适用版本：Cubbix 0.2.0+

---

## 1. 使用场景与操作频率分析

### 1.1 现状痛点

当前 Cubbix 菜单栏采用 macOS 系统原生菜单（`*mygo.Menu` / `NSMenu`，见 `awake_app.go:115-144` 与 `main.go:193-206`），存在两个结构性瓶颈：

1. **操作层级过深**：调整常亮参数必须在「模式」和「时长」两个子菜单中深层穿梭。例如设置「开启 1 小时常亮」，需要依次点击猫标、鼠标悬停移入「时长 >」子菜单、等待系统子菜单展开、点击「1 小时」、再点击顶层「开启常亮」，滑动手势繁琐且极易因指针滑出子菜单区域而导致菜单意外收起。
2. **缺乏多格子承载力**：当前菜单完全围绕单一「常亮」格子编写。正在开发的 JSON 格子（见 `design/rounds/R07-2026-10-30-JSON/README.md`）包含新建窗口、活跃窗口列表，后续还将引入更多独立格子。若继续沿用单维纵向原生菜单，项目增至 3 个格子时，菜单项将膨胀至 25 行以上，视觉杂乱且难以快速定位目标操作。

### 1.2 典型操作频率排序与步骤对比

根据维护者与日常使用场景，将常亮与 JSON 格子的典型操作按**调用频率从高到低**排序，并对比改造前后的操作步数：

| 排名 | 操作场景 | 用户目标 | 原有原生菜单路径与步数 | 重设计面板路径与步数 | 最大步数 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | **开启 1 小时常亮** | 日常开会/看代码，快速进入默认常亮状态 | 点猫标 → 悬停时长 → 点 1 小时 → 点开启（共 **4 步**） | 点猫标 → 点击 `[1h]` 药丸（**直接启动**）（共 **2 步**） | **2 步** |
| **2** | **关闭正在运行的常亮** | 任务结束，恢复系统休眠 | 点猫标 → 点停止常亮（共 **2 步**） | 点猫标 → 点击总开关（或快捷键）（共 **2 步**） | **2 步** |
| **3** | **切换常用时长** | 从 1 小时调整为 30 分钟、2 小时或不限时 | 点猫标 → 悬停时长 → 选中新时长（共 **3 步**） | 点猫标 → 点击目标时长药丸（共 **2 步**） | **2 步** |
| **4** | **新建 JSON 窗口** | 从剪贴板粘贴或输入新 JSON 进行校验/转换 | 原有菜单未接入；若按原生菜单需点击「新建 JSON 窗口」 | 点猫标 → 点击「新建 JSON 窗口」（或全局 `⌃⌥⌘J`）（共 **2 步**） | **2 步** |
| **5** | **切换已打开的 JSON 窗口** | 在多个独立 JSON 对照窗口间来回切换 | 需在系统 Dock 或 Mission Control 逐个辨识查找 | 点猫标 → 在已打开列表中点击目标文件名（共 **2 步**） | **2 步** |
| **6** | **切换常亮模式** | 在「保持屏幕常亮」与「仅保持任务」间切换 | 点猫标 → 悬停模式 → 点目标模式（共 **3 步**） | 点猫标 → 点击两段式分段开关（共 **2 步**） | **2 步** |
| **7** | **自定义时长 / 截止时刻** | 设定精确的几点几分或特定分钟数结束 | 点猫标 → 悬停时长 → 点自定义/截止 → 小窗口输入（共 **4 步+**） | 点猫标 → 点击 `[•••]` → 选自定义/截止 → 弹窗输入（共 **3 步+**） | **3 步** |
| **8** | **跟随某个 Agent 进程** | 绑定 claude / codex 运行周期 | 点猫标 → 悬停时长 → 点跟随进程… → 搜进程（共 **4 步+**） | 点猫标 → 点击 `[•••]` → 点跟随进程… → 搜进程（共 **3 步+**） | **3 步** |
| **9** | **打开 Cubbix 设置** | 调整格子开关、快捷键或多语言 | 点猫标 → 点击设置…（共 **2 步**） | 点猫标 → 底部点击设置图标按钮（共 **2 步**） | **2 步** |
| **10** | **退出 Cubbix** | 完全退出后台常驻应用 | 点猫标 → 点击退出 Cubbix（共 **2 步**） | 点猫标 → 底部点击退出图标按钮（共 **2 步**） | **2 步** |

**交互设计原则**：将占比 80% 以上的前 5 项高频操作，全部压减至「呼出面板 + 1 次单点」即刻完成（最大 2 步）；低频或高维配置收归二级浮层或小弹窗。

## 2. 方案比较与 MyGo v0.6.2 技术能力查证

### 2.1 候选方案概览

- **方案 A（重新组织的系统原生菜单）**：基于 AppKit `NSMenu`，保留系统弹出菜单机制，仅在菜单项结构上进行扁平化（例如将常用时长提到一级菜单，移除子菜单）。
- **方案 B（自定义弹出面板，挂在猫标下方）**：点击猫标时不展开 `NSMenu`，而是通过悬浮无边框面板（Flyout / Panel）展示原生 UI 视图组件树，呈现卡片式多格子布局。

### 2.2 MyGo v0.6.2 技术能力严格事实查证

针对方案 B 是否可行，全面查证项目锁定的底层框架 `github.com/egoist/mygo@v0.6.2` 的源码与文档，核验结果如下：

| :--- | :---: | :--- | :--- |

### 2.3 方案优劣对比

| 评估维度 | 方案 A：重新组织的系统原生菜单 | 方案 B：自定义悬浮面板（推荐） |
| :--- | :--- | :--- |
| **布局表现力** | **极差**。macOS `NSMenuItem` 在 MyGo 中仅支持单行单列文本排版，无法水平并排药丸按钮或两段分段器。 | **极佳**。自由使用 MyGo 原生 UI 布局树（`ui.Row`、`ui.Column`、`ui.SegmentedBase`），完美实现药丸按钮与卡片。 |
| **操作效率** | **低**。常用时长必须拆成 5 行独立菜单项，垂直占用极大，无法做到「一排选项一步到位」。 | **高**。模式两段式、时长一排药丸横排，高频操作单次点击即可达成。 |
| **多格子可扩展性** | **差**。随着未来格子增加，整条菜单无限拉长，信息密度与层级失控。 | **高**。以卡片为单元垂直模块化排列，格子顺序与显隐完全可配置化。 |
| **视觉风格一致性** | 局限于 macOS 原生菜单样式，无法与应用内黑白灰 Design Tokens、间距、圆角体系无缝统一。 | 100% 消费项目的 Design Tokens，中英文排版、深浅主题与设置窗口保持完全一致的质感。 |
| **实现与调试成本** | 极低，仅需修改 Go 侧 `awakeMenu` 切片拼装。 | 中等，需编写面板的原生 UI 视图组件，但框架已提供成熟样例（`examples/menubar-flyout`）。 |

### 2.4 方案结论

**明确推荐方案 B（自定义弹出面板）**。
具体技术实现路径选型：使用 `mygo.NewFlyout`，配置 `Tray: a.tray`, `Placement: mygo.PlacementBottom`, `Popover: false`, `Focusable: true`, `CornerRadius: 12`, `Shadow: true`。
不采用 `Popover: true` 的理由：`Popover: false` 底层基于 `styleNonactivatingPanel` + `collectionFullScreenAuxiliary`，能确保在全屏桌面下弹出时不切 Space、不强制激活主应用，且不带 NSPopover 原生系统尖角箭头，视觉更利落。

## 3. 推荐方案的详细设计

### 3.1 整体结构与格子编排

面板采用固定宽度、垂直卡片流式布局：

- **面板容器**：
  - 宽度：固定 `SizeMenubarPanelWidth = 320`（建议新增 Token，见 3.7 节）。
  - 外圆角：`RadiusWindow = 12`。
  - 背景：`ColorMenuSurface`（浅色 `#FFFFFFEB`，深色 `#2C2C2CEB`），结合窗口 `Vibrancy` 保持毛玻璃通透感。
  - 内留白：四周统一 `Space12 = 12`，各分区纵向间隔 `Space8 = 8`。
- **格子分区卡片 (Tile Cards)**：
  - 每个启用的业务格子为一个独立卡片，背景色 `ColorCard`，圆角 `RadiusCard = 8`，描边 `StrokeHairline = 1` 配合 `ColorSeparator`，卡片内 padding 为 `Space10 = 10`。
  - 格子的显示状态与上下顺序，由设置「格子」页配置严格控制：
    - 若 `config.AwakeEnabled == false`，常亮分区整块不渲染，不占任何空间；
    - 若 `config.JSONEnabled == false`，JSON 分区整块不渲染；
    - 若全部格子均关闭，面板居中展示「未启用任何格子」弱化提示（`ColorTextSecondary`），下方保留系统操作栏。
- **底部系统操作栏**：
  - 独立于业务卡片，固定位于面板最底端，高度 `SizeNavHeight = 32`。

### 3.2 常亮格子 (Keep Awake) 分区设计

常亮卡片自上而下分为 4 行：

```
+-----------------------------------------------------------+
|  [Icon: sun] 常亮                            (•) 开关 [On] | <- 行 1：标题与总开关
|  +---------------------------+-------------------------+  |
|  |       保持屏幕常亮        |        仅保持任务       |  | <- 行 2：两段切换模式
|  +---------------------------+-------------------------+  |
|  [ 30m ]    [ 1h* ]    [ 2h ]    [  ∞  ]      [ ••• ]     | <- 行 3：时长药丸行
|  屏幕常亮 · 剩余 54 分钟                                  | <- 行 4：运行状态条
+-----------------------------------------------------------+
```

#### 1. 行 1：标题与总开关
- **左侧**：常亮图标（Lucide `sun`，尺寸 `SizeIcon = 16`，颜色 `ColorText`）与标题「常亮」（字号 `FontSizeBody = 13`，字重 `FontWeightSemibold = 600`）。
- **右侧**：总开关（SwitchBase，尺寸 `SizeSwitchWidth = 34` × `SizeSwitchHeight = 20`，滑块 `SizeSwitchThumb = 14`）。
  - 开启态：背景 `ColorAccent`，滑块 `ColorThumb`；
  - 关闭态：背景 `ColorControl`，滑块 `ColorTextSecondary`。
- **开关行为**：
  - 当前处于开启中：点击总开关立即**停止常亮**，还原未开启状态；
  - 当前处于未开启：点击总开关立即**按当前记忆的模式和时长开启常亮**。

#### 2. 行 2：两段模式切换 (2-Segment Switch)
- **控件**：复用设置页同款两段分段器（`ui.SegmentedBase`），高度 `SizeSegmentHeight = 28`，外底色 `ColorControl`，内边距 `Space2 = 2`，圆角 `RadiusControl = 6`。
- **选项**：左侧「保持屏幕常亮」（对应配置 `awake_mode: "screen"`），右侧「仅保持任务」（对应配置 `awake_mode: "tasks"`）。
- **选中样式**：选中滑块背景 `ColorAccent`，文字 `ColorOnAccent`；未选中背景透明，文字 `ColorText`。
- **交互逻辑**：
  - 点击任一模式立即更新 `config.AwakeMode` 并写入磁盘；
  - 若常亮当前正在运行，**立即热切换**底层 `caffeinate` 进程参数（`-d -i` ↔ `-i`），无缝保持剩余时间，无需用户手动重启常亮。

#### 3. 行 3：常用时长药丸与「更多」
- **排布**：单行水平排列 5 个等高药丸按钮（高度 `SizeButtonHeight = 28`，圆角 `RadiusControl = 6`，间距 `Space6 = 6`）：
  - 预设药丸：`[ 30m ]`、`[ 1h ]`、`[ 2h ]`、`[ ∞ ]`；
  - 更多入口：`[ ••• ]`（图标为 Lucide `ellipsis` 或文字 `更多`）。
- **按钮状态样式**：
  - 默认/未选中态：背景 `ColorControl`，悬停 `ColorControlHover`，文字 `ColorText`；
  - 激活/选中态：背景 `ColorAccent`，文字 `ColorOnAccent`，字重 `FontWeightMedium = 500`。
- **核心交互语义：选择时长是否等于立即开启？**
  - **明确规定：在未开启状态下，点击任一预设时长药丸（30m/1h/2h/∞）等于「选择该时长并立即开启常亮」**。
  - **设计理由**：满足 80% 场景下「一步到位」的核心诉求。用户点击猫标后，直奔所需时长单次点击（例如 `[1h]`），系统立即更新配置、启动常亮、高亮该药丸、右上角总开关切为打开态，无需再点一次开关。
  - **在已开启状态下**：点击另一时长药丸，视为**立即延长/重置为新时长**（例如从 30m 切换到 2h，重置为 2 小时倒计时）；点击当前已选中的药丸则无副作用。
  - **点击 `[ ••• ]`（更多）的行为**：
    - 弹出二级悬浮菜单或唤起既有小窗口（自定义时长、直到某时刻、跟随进程，见 `awake_view.go:17-150`）；
    - 用户在小窗口中点击「确定」后才正式启动。

#### 4. 行 4：运行状态条
- 仅在常亮开启或异常时展示，高度 `Space20 = 20`，字号 `FontSizeSmall = 12`，颜色 `ColorTextSecondary`。
- 文本格式严格遵循现有国际化模板：
  - 倒计时：`屏幕常亮 · 剩余 54 分钟`；
  - 截止时刻：`屏幕常亮 · 直到 18:30`；
  - 不限时：`屏幕常亮 · 不限时`；
  - 跟随进程：`仅保持任务 · 跟随 codex (PID 12480)`。

### 3.3 JSON 格子分区设计

JSON 格子卡片服务于轻量查看、新建与多窗口对照：

```
+-----------------------------------------------------------+
|  [Icon: braces] JSON                        [Icon: plus]  | <- 标题栏与快速新建
|  +-----------------------------------------------------+  |
|  |  [Icon: file-code] 未命名 1                    (置顶) |  | <- 活跃窗口列表
|  |  [Icon: file-code] items.json                       |  |
|  +-----------------------------------------------------+  |
|  [ + 新建 JSON 窗口 (⌃⌥⌘J)                             ]  | <- 主操作按钮
+-----------------------------------------------------------+
```

1. **标题行与快捷入口**：
   - 左侧：Lucide `braces` 图标与标题「JSON」；
   - 右侧：Lucide `plus` 图标按钮（尺寸 `SizeIconButton = 28`，圆角 `RadiusControl = 6`），配 Tooltip「新建 JSON 窗口 (⌃⌥⌘J)」，点击即开。
2. **活跃窗口列表（已打开窗口）**：
   - **直显规则**：最多显示 **4 个**当前已打开的 JSON 窗口。
   - **列表条目外观**：单行高度 `SizeNavHeight = 32`，圆角 `RadiusControl = 6`，悬停底色 `ColorNavHover`。
     - 左侧：文件图标（未保存文档使用 `file`，磁盘文件使用 `file-code`）+ 窗口标题（如 `未命名 1`、`data.json`），字号 `FontSizeSmall = 12`；
     - 右侧：若该窗口处于置顶状态，显示弱化置顶标记（Lucide `pin`，尺寸 12）。
   - **点击行为**：点击任意窗口条目，立即调用窗口实例的 `BringToFront()` 激活置顶，同时自动收起菜单栏面板。
   - **超出处理**：若当前打开窗口数 > 4，列表底部显示「查看全部 (共 N 个) >」，点击后展开或弹出子菜单定位。
   - **空状态**：若当前无打开的 JSON 窗口，列表区域自然收拢，仅保留「新建 JSON 窗口」主按钮。
3. **主操作按钮**：
   - 底部全宽按钮「新建 JSON 窗口」，高度 `SizeButtonHeight = 28`，圆角 `RadiusControl = 6`，背景 `ColorControl`，居中对齐。
   - **剪贴板智能感知**：若系统剪贴板包含合法 JSON 字符串，新建窗口自动带入内容并完成语法高亮；若无则呈现空编辑器（符合 ADR 001 与 R07 规范）。

### 3.5 全场景状态规格矩阵 (All States Matrix)

| 状态场景 | 面板界面呈现 | 猫标状态（菜单栏图标） | 触发机制与流转规则 |
| :--- | :--- | :--- | :--- |

| **有时长常亮中 (Timed Active)** | 常亮总开关呈 On（`ColorAccent`）；对应时长药丸处于选中填充；状态行显示实时倒计时（如 `剩余 01:24`）。 | 睁眼单色猫标 (`menubar-template-active.tiff`) | 点击 30m/1h/2h 等药丸，或小窗口设定自定义时长后启动。 |

| **电池供电提醒后 (Battery Triggered)** | 常亮保持运行，总开关与药丸状态不变；状态行左侧出现中性电池小图标（Lucide `battery`），提示「已切换到电池供电，常亮仍在运行」。 | 保持当前运行猫标（睁眼） | 系统从交流电源拔下切换到电池时，后台已发送一次系统通知（ADR 004/R05B）；面板内仅作无干扰的状态提示，无阻断弹窗。 |

### 3.6 键盘操作规范与快捷键提示展示

#### 1. 键盘导航逻辑
- **Tab / Shift+Tab**：在面板内部所有可聚焦控件之间单向循环遍历：
  `常亮总开关` → `模式分段器` → `时长药丸(当前选中项)` → `更多按钮` → `JSON 新建按钮` → `JSON 打开窗口条目(逐项)` → `底部设置按钮` → `底部退出按钮` → 回到 `常亮总开关`。
- **方向键 (Left / Right / Up / Down)**：
  - 在模式分段器聚焦时：`←` / `→` 键即时在「屏幕常亮」与「仅保持任务」之间切换；
  - 在时长药丸聚焦时：`←` / `→` 键在 `[30m]`、`[1h]`、`[2h]`、`[∞]`、`[•••]` 之间循环移动焦点；按 `Space` 或 `Enter` 确认生效；
  - 在 JSON 窗口列表聚焦时：`↑` / `↓` 键在窗口列表条目之间上下切换。
- **Enter / Space**：触发当前聚焦的控件动作（启动常亮、切换开关、打开窗口等）。
- **Esc**：立即关闭菜单栏悬浮面板，底层前台应用焦点保持不变。

#### 2. 快捷键提示展示规则
- 遵循 `AGENTS.md`「低信息密度：以图标引导为主，不写说明文字」的既定规则；
- 面板主体卡片内**绝不常驻**大段文字快捷键说明；
- 全局快捷键（如 `⌃⌥⌘K`、`⌃⌥⌘J`）仅在控件悬停或键盘聚焦时的 Tooltip 中显示（例如 Hover 新建按钮时显示 `新建 JSON 窗口 (⌃⌥⌘J)`）；
- 仅底部系统操作行中的「设置…」与「退出」，在行末以次要灰色文本右对齐弱化展示 `⌘,` 与 `⌘Q`，便于键盘用户形成肌肉记忆。

## 4. 与现有代码的衔接方案

### 4.1 现有代码审计与改动范围

当前项目主入口与常亮逻辑位于根目录：
- `awake_app.go:24-38`：`refreshAwake()` 每次会话改变均调用 `a.tray.SetMenu(a.menu())` 重新装载原生系统菜单。
- `awake_app.go:115-144`：`awakeMenu(locale)` 负责组装原生的单列、深层子菜单 `*mygo.MenuItem`。
- `main.go:193-206`：`menuForLocale(locale)` 将常亮菜单与底部设置/退出条目组合。
- `main.go:240-270`：`ready(win)` 初始化 `mygo.NewTray(...)` 并绑定托盘图标与初始菜单。

#### 需要修改的地方：
1. **Tray 交互重构** (`main.go` / `awake_app.go`)：
   - 移除初始 `mygo.TrayOptions.Menu` 的静态主菜单配置（依据 `mygo@v0.6.2/docs/menus.md:213-215`，有菜单时左键会被 AppKit 原生拦截）；
   - 为 `a.tray` 注册 `tray.OnClick(a.toggleMenubarPanel)` 实现左键点击呼出/收起自定义面板；
   - 注册 `tray.OnRightClick(a.showNativeContextMenu)`，保留一个精简的原生右键菜单（包含「设置…」「退出」及版本更新提示），作为兜底备用路径。
2. **状态刷新重构** (`awake_app.go:24-38`)：
   - 改造 `refreshAwake()`：保留托盘猫标（闭眼/睁眼）的 TIFF 替换逻辑；
   - 当面板处于显示状态时，调用面板窗口的 `Invalidate()` 触发实时局部重绘，驱动倒计时与按钮状态刷新。
3. **新增面板视图文件** (`menubar_panel_view.go`)：
   - 实现 `(a *application) toggleMenubarPanel()`；
   - 负责创建或复用 `mygo.NewFlyout` 实例；
   - 编写 `(a *application) menubarPanelView(c *ui.Context)` 纯原生 UI 声明式组件树。

#### 可以 100% 复用的地方：
1. `awakeController`（`keepawake.go`）：常亮进程生命周期、`caffeinate` 参数派生、PID 心跳检测、状态快照等完全复用，无需做任何改动。
2. 配置持久化与加载（`config.go`）：直接读写 `a.config.AwakeEnabled`、`a.config.AwakeMode`、`a.config.AwakeMinutes`。
3. 三个既有参数弹窗（`awake_view.go:17-150`）：自定义时长、截止时刻、进程选择器 3 个无标题栏输入窗口全部直接复用，从面板药丸行末尾的 `[•••]` 触发唤起。
4. 电源监控与通知（`battery_notification.go`）：电源切换采样与静默系统通知逻辑保持不变。
5. 国际化资源加载（`a.catalog`、`a.text(locale, key)`）：直接使用现有多语言资源引擎。

### 4.2 与 `feat/json` 分支的接入规范

JSON 格子目前正在 `feat/json` 分支开发（设计参见 `design/rounds/R07-2026-10-30-JSON/README.md`），面板与 JSON 格子的衔接约定如下：

1. **窗口注册中心**：
   - `application` 维护打开状态的 JSON 窗口切片：`jsonWindows []*jsonWindow`；
   - 每个 JSON 窗口在 `NewWindow` 成功后向 `application` 注册，在 `OnClosed` 事件中反注册并通知面板更新（`a.invalidatePanel()`）。
2. **动作接口解耦**：
   - 面板的「新建 JSON 窗口」按钮直接调用 `a.newJSONWindow(initialText)`；
   - 激活目标窗口统一调用 `win.Show()` 与 `win.Focus()`；
3. **格子开关条件编译 / 运行时兼容**：
   - 在 `config.go` 中规范化添加 `JSONEnabled bool` 字段；
   - 面板渲染时判断：`if a.config.JSONEnabled { a.renderJSONTile(c, t, text) }`；
   - 在 `feat/json` 合并入主干前，若 `JSONEnabled` 为 false，面板天然不呈现 JSON 区域，保持零污染平滑演进。

## 6. 待维护者决定的问题

以下 4 个工程与产品权衡点，已给出推荐答案供维护者快速决策：

### 问题 1：面板展开时右键点击猫标的交互行为
- **选项 A（推荐）**：弹出简版系统原生上下文菜单（包含「打开设置」「检查更新」「退出 Cubbix」），并收起自定义面板。
- **选项 B**：右键与左键行为完全一致，均用于切换自定义面板的展开与收起。
- **推荐理由**：符合 macOS 顶级工具箱应用标准（如 Bartender、Raycast、CleanShot X）。保留一个原生简版右键菜单，能在自定义 UI 渲染异常或极端卡顿场景下，为用户保留一个绝对可靠的「打开设置」与「退出」兜底通道（`examples/menubar-native/main.go:142-154` 亦推荐该实践）。

### 问题 2：JSON 活跃窗口列表超出 4 个时的展示策略
- **选项 A（推荐）**：直显最近活跃的最多 4 个窗口，第 5 个起折叠为「查看全部 (共 %d 个) >」，点击后在面板内展开滚动列表。
- **选项 B**：直接按最后使用时间截断，严格仅展示前 4 个，超出部分不提供列表入口（用户需通过快捷键或 Mission Control 寻找）。
- **推荐理由**：4 个窗口已覆盖 90% 以上的多文档对比工作流；硬截断可能导致用户找不到后台窗口，折叠展开兼顾了面板的紧凑高度与多文档可达性。

### 问题 3：常亮未开启时，点击时长药丸所继承的模式
- **选项 A（推荐）**：严格沿用用户上次保存的模式偏好（即读取 `config.AwakeMode`，新安装首次默认为「保持屏幕常亮」）。
- **选项 B**：每次通过时长药丸重新唤起时，强制重置为「保持屏幕常亮」。
- **推荐理由**：尊重用户的个性化记忆。经常使用「仅保持任务」下载文件的用户，无需每次开启都重新切一次分段器。

### 问题 4：面板宽度 Token 取值
- **选项 A**：沿用既有 Token `SizeR05MenuWidth = 352`。
- **选项 B（推荐）**：新增 Token `SizeMenubarPanelWidth = 320`。
- **推荐理由**：320pt 在 13~16 英寸 MacBook 屏幕上的悬挂比例最为适中。常亮 5 个药丸按钮（每个 48pt，间隔 6pt，总宽 264pt）加上卡片内边距（两边各 10pt，容器外边距各 12pt，总宽恰好 308~320pt），排版极为紧凑饱满，不会产生不必要的横向留白。
