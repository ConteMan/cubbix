# 详细设计 001：菜单栏面板重设计（多格子承载与一步到位交互）

- 文档状态：已按 Grok 复核意见完成第二轮修订（Design Spec）
- 关联问题：多格子架构扩展、常用操作交互扁平化、JSON 格子接入
- 适用版本：Cubbix 0.2.0+

---

## 1. 使用场景与操作频率分析

### 1.1 现状痛点

当前 Cubbix 菜单栏采用 macOS 系统原生菜单（`*mygo.Menu` / `NSMenu`，见 `awake_app.go` 的 `awakeMenu` 方法（约 139-163 行）与 `main.go` 的 `menuForLocale` 方法（约 222-232 行）），存在两个结构性瓶颈：

1. **操作层级过深**：调整常亮参数必须在「模式」和「时长」两个子菜单中深层穿梭。例如设置「开启 1 小时常亮」，虽然在子菜单中点击「1 小时」已内置 `start` 逻辑（`awake_app.go` 的 `setDuration` 方法，约 86-91 行），但仍需依次点击猫标、鼠标悬停移入「时长 >」子菜单、等待系统子菜单展开、再点击「1 小时」（共 3 步），滑动手势繁琐且极易因指针滑出子菜单区域而导致菜单意外收起。
2. **缺乏多格子承载力**：当前菜单主要围绕单一「常亮」格子编写。已合并至 `main` 主干的 JSON 格子（`json_app.go`、`json_documents.go`）包含新建窗口、活跃窗口列表等能力。若继续沿用单维纵向原生菜单，项目增至 3 个格子时，菜单项将膨胀至 25 行以上，视觉杂乱且难以快速定位目标操作。

### 1.2 典型操作频率排序与步骤对比

根据维护者与日常使用场景，将常亮与 JSON 格子的典型操作按**调用频率从高到低**排序，并对比改造前后的操作步数：

| 排名 | 操作场景 | 用户目标 | 原有原生菜单路径与步数 | 重设计面板路径与步数 | 最大步数 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | **开启 1 小时常亮** | 日常开会/看代码，快速进入默认常亮状态 | 点猫标 → 悬停时长展开 → 点 1 小时直接启动（`awake_app.go` 的 `setDuration`，约 86-91 行，共 **3 步**） | 点猫标 → 点击 `[1h]` 药丸（**直接启动**）（共 **2 步**） | **2 步** |
| **2** | **关闭正在运行的常亮** | 任务结束，恢复系统休眠 | 点猫标 → 点停止常亮（共 **2 步**） | 点猫标 → 点击总开关（或快捷键）（共 **2 步**） | **2 步** |
| **3** | **切换常用时长** | 从 1 小时调整为 30 分钟、2 小时或不限时 | 点猫标 → 悬停时长 → 选中新时长（共 **3 步**） | 点猫标 → 点击目标时长药丸（共 **2 步**） | **2 步** |
| **4** | **新建 JSON 窗口** | 从剪贴板粘贴或输入新 JSON 进行校验/转换 | 点猫标 → 点击「新建 JSON 窗口」（共 **2 步**）或全局 `⌃⌥⌘J`（共 **1 步**） | 点猫标 → 点击快速新建或主按钮（共 **2 步**）或全局 `⌃⌥⌘J`（共 **1 步**） | **2 步** |
| **5** | **切换已打开的 JSON 窗口** | 在多个独立 JSON 对照窗口间来回切换 | 点猫标 → 查找目标窗口（满 6 个进子菜单，共 **2~3 步**） | 点猫标 → 在已打开列表中点击目标文件名（共 **2 步**） | **2 步** |
| **6** | **切换常亮模式** | 在「保持屏幕常亮」与「仅保持任务」间切换 | 点猫标 → 悬停模式 → 点目标模式（共 **3 步**） | 点猫标 → 点击两段式分段开关（共 **2 步**） | **2 步** |
| **7** | **自定义时长 / 截止时刻** | 设定精确的几点几分或特定分钟数结束 | 点猫标 → 悬停时长 → 点自定义/截止 → 弹窗输入（共 **4 步**） | 点猫标 → 点击 `[•••]` → 选自定义/截止 → 弹窗输入（共 **3 步**） | **3 步** |
| **8** | **跟随某个 Agent 进程** | 绑定 claude / codex 运行周期 | 点猫标 → 点跟随进程…（顶层菜单项，`awake_app.go` 的 `awakeMenu` 约 158 行）→ 搜进程（共 **3 步**） | 点猫标 → 点击 `[•••]` → 点跟随进程… → 搜进程（共 **3 步**） | **3 步** |
| **9** | **打开 Cubbix 设置** | 调整格子开关、快捷键或多语言 | 点猫标 → 点击设置…（共 **2 步**） | 点猫标 → 底部点击设置图标按钮（共 **2 步**） | **2 步** |
| **10** | **退出 Cubbix** | 完全退出后台常驻应用 | 点猫标 → 点击退出 Cubbix（共 **2 步**） | 点猫标 → 底部点击退出图标按钮（共 **2 步**） | **2 步** |

**交互设计原则**：将占比 80% 以上的前 5 项高频操作，全部压减至「呼出面板 + 1 次单点」即刻完成（最大 2 步）；低频或高维配置收归二级浮层或小弹窗。

## 2. 方案比较与 MyGo v0.6.2 技术能力查证

### 2.1 候选方案概览

- **方案 A（重新组织的系统原生菜单）**：基于 AppKit `NSMenu`，保留系统弹出菜单机制，仅在菜单项结构上进行扁平化（例如将常用时长提到一级菜单，移除子菜单）。
- **方案 B（自定义弹出面板，挂在猫标下方）**：点击猫标时不展开 `NSMenu`，而是通过悬浮无边框面板（Flyout / Panel）展示原生 UI 视图组件树，呈现卡片式多格子布局。

### 2.2 MyGo v0.6.2 技术能力严格事实查证

针对方案 B 是否可行，全面查证底层框架 `github.com/egoist/mygo@v0.6.2` 的源码与文档，核验结果如下：

### 2.3 方案优劣对比

| 评估维度 | 方案 A：重新组织的系统原生菜单 | 方案 B：自定义悬浮面板（推荐） |
| :--- | :--- | :--- |
| **布局表现力** | **极差**。macOS `NSMenuItem` 在 MyGo 中仅支持单行单列文本排版，无法水平并排药丸按钮或两段分段器。 | **极佳**。自由使用 MyGo 原生 UI 布局树（`ui.Row`、`ui.Column`、`ui.SegmentedBase`），完美实现药丸按钮与卡片。 |
| **操作效率** | **低**。常用时长必须拆成 5 行独立菜单项，垂直占用极大，无法做到「一排选项一步到位」。 | **高**。模式两段式、时长一排药丸横排，高频操作单次点击即可达成。 |
| **多格子可扩展性** | **差**。随着未来格子增加，整条菜单无限拉长，信息密度与层级失控。 | **高**。以卡片为单元垂直模块化排列，格子显隐根据配置响应（本次不做排序，沿用固定顺序）。 |
| **视觉风格一致性** | 局限于 macOS 原生菜单样式，无法与应用内黑白灰 Design Tokens、间距、圆角体系无缝统一。 | 100% 消费项目的 Design Tokens，中英文排版、深浅主题与设置窗口保持完全一致的质感。 |
| **实现与调试成本** | 极低，仅需修改 Go 侧 `awakeMenu` 切片拼装。 | 中等，需编写面板的原生 UI 视图组件，但框架已提供成熟样例（`examples/menubar-native`）。 |

### 2.4 方案结论与窗口行为约定

**明确推荐方案 B（自定义弹出面板）**。
具体技术实现路径选型：使用 `mygo.NewFlyout`，配置 `Tray: a.tray`, `Placement: mygo.PlacementBottom`, `Popover: false`, `Focusable: true`, `CornerRadius: 12`, `Shadow: true`。

**关键窗口行为约定**：
1. **采用 `Popover: false`**：AppKit 原生 Popover 会在 `showPopover()` 中强行执行 `activateIgnoringOtherApps: 1`（`internal/darwin/popover.go` 的 `showPopover`，约 70-79 行），强制将应用切换为前台活动主应用并激活 Dock；而 `Popover: false` 的 Flyout 采用 `styleNonactivatingPanel`，不抢占主前台应用状态，视觉利落无原生箭头。
2. **全屏防切 Space 与激活策略（调用既有 API，单一策略）**：
   - **调用 MyGo 已有 API**：面板窗口创建后直接调用 `win.SetVisibleOnAllWorkspaces(true)`（`window.go` 约 1062 行）。macOS 底层会自动在现有 behavior 上按位或 `canJoinAllSpaces`（`internal/darwin/window.go` 的 `SetVisibleOnAllWorkspaces`，约 879-883 行），无需修改 MyGo 内部代码。
   - **激活策略保持现有机制**：
     - 面板弹出采用 `showFlyout`（`internal/darwin/window.go` 约 609-621 行），仅调用 `makeKeyAndOrderFront:`，未调用 `activateIgnoringOtherApps:`，不会抢占主应用焦点；
     - 当设置窗口（`a.window`）或 JSON 独立窗口（`d.window`）可见时，应用保持既有的 `ActivationPolicyRegular`（`main.go` 的 `visibility`，约 176-192 行）；面板因设置了 `SetVisibleOnAllWorkspaces(true)` 仍可在当前 Space 使用；但按 MyGo 文档（`docs/windows.md` 约 165-169 行、`internal/darwin/window.go` 约 884-887 行），**只有 Accessory 状态的应用窗口才能盖住其他应用的全屏 Space**，应用为 Regular 时面板能否出现在别人的全屏 Space 上**未实测**，实现阶段需要验证；若不行，接受这一限制（此时用户正在使用 Cubbix 自己的窗口），不为此切换激活策略。

## 3. 推荐方案的详细设计

### 3.1 整体结构与格子编排

面板采用固定宽度、垂直卡片流式布局：

- **面板容器**：
  - 宽度：固定 `SizeMenubarPanelWidth = 320`（新增 Token，入 `cubbix.pen`，见 3.7 节）。
  - 外圆角：`RadiusWindow = 12`。
  - 毛玻璃与背景：面板窗口启用 `Vibrancy`。根据 `docs/windows.md`（约 269-270 行）规范，**有 Vibrancy 材质时根容器不要再铺设 `ColorMenuSurface`**，而应使用 `c.Root().Background(ui.Transparent)`，让系统原生毛玻璃底色自然透出；各业务卡片内部铺设 `ColorCard`。
  - 内留白：四周统一 `Space12 = 12`，各分区纵向间隔 `Space8 = 8`。
  - 动态高度更新：`NewFlyout` 默认尺寸为 200×200（`flyout.go` 约 77, 156-157 行）。当渲染多格子、格子开关切换或 JSON 窗口列表增减导致高度变化时，必须显式调用 `win.SetContentSize(width, height)`（`flyout.go` 的 `SetContentSize`，约 232-241 行），触发内部 `setFlyoutSize` 重新计算边界与 `placeFlyout` 定位。
- **格子分区卡片 (Tile Cards)**：
  - 每个启用的业务格子为一个独立卡片，背景色 `ColorCard`，圆角 `RadiusCard = 8`，描边 `StrokeHairline = 1` 配合 `ColorSeparator`，卡片内 padding 为 `Space10 = 10`。
  - 格子启用状态严格由 `config` 控制：
    - 若 `config.AwakeEnabled == false`，常亮分区整块不渲染，不占任何高度；
    - 若 `config.JSONEnabled == false`，JSON 分区整块不渲染；
    - 格子排序：当前设置页仅提供格子开关（`awake_view.go` 约 388-395 行），**本次重构不新增格子拖拽/自定义排序**（沿用固定顺序：常亮在上方，JSON 在下方）。
    - 若全部格子均关闭：遵循低信息密度原则，居中弱化展示精简占位标签（不写冗长说明整句），下方保留系统操作栏。
- **底部系统操作栏**：
  - 独立于业务卡片，固定位于面板最底端，高度 `SizeNavHeight = 32`。

### 3.2 常亮格子 (Keep Awake) 分区设计

常亮卡片自上而下分为 4 行：

```
+-----------------------------------------------------------+
|  [Icon: sun] 常亮                            (•) 开关 [On] | <- 行 1：标题与总开关
|  +---------------------------+-------------------------+  |
|  |       保持屏幕常亮        |        仅保持任务       |  | <- 行 2：两段切换模式
|  +---------------------------+-------------------------+  |
|  [ 30m ]    [ 1h* ]    [ 2h ]    [  ∞  ]      [ ••• ]     | <- 行 3：时长药丸行
|  保持屏幕常亮 · 剩余 1:24                                  | <- 行 4：运行状态条
+-----------------------------------------------------------+
```

#### 1. 行 1：标题与总开关
- **左侧**：常亮图标（Lucide `sun`，尺寸 `SizeIcon = 16`，存在于 `design/assets/lucide-0.468.0/`，颜色 `ColorText`）与标题「常亮」（`Awake`，字号 `FontSizeBody = 13`，字重 `FontWeightSemibold = 600`）。
- **右侧**：总开关（SwitchBase，尺寸 `SizeSwitchWidth = 34` × `SizeSwitchHeight = 20`，滑块 `SizeSwitchThumb = 14`）。
  - 开启态：背景 `ColorAccent`，滑块 `ColorThumb`；
  - 关闭态：背景 `ColorControl`，滑块 `ColorTextSecondary`。
- **开关行为**：
  - 当前开启中：点击立即**停止常亮**（`a.awake.stop()`，底层见 `keepawake.go` 的 `stopLocked`，约 129-133 行），恢复未开启状态；
  - 当前未开启：点击立即**按当前记忆的模式和时长开启常亮**（`a.startAwake(a.selectedSession())`）。

#### 2. 行 2：两段模式切换 (2-Segment Switch)
- **控件**：复用设置页同款两段分段器（`ui.SegmentedBase`），高度 `SizeSegmentHeight = 28`，外底色 `ColorControl`，内边距 `Space2 = 2`，圆角 `RadiusControl = 6`。
- **选项**：左侧「保持屏幕常亮」（键 `R05Screen`，`awake_mode: "screen"`），右侧「仅保持任务」（键 `R05Tasks`，`awake_mode: "tasks"`）。
- **选中样式**：选中滑块背景 `ColorAccent`，文字 `ColorOnAccent`；未选中背景透明，文字 `ColorText`。
- **交互逻辑**：
  - 点击任一模式立即更新 `config.AwakeMode` 并保存；
  - 若常亮当前正在运行，**立即热切换**底层 `caffeinate` 进程参数（`-d -i` ↔ `-i`），无缝保持剩余时间（`awake_app.go` 的 `setMode`，约 78-85 行）。

#### 3. 行 3：常用时长药丸与「更多」
- **排布**：单行水平排列 5 个等高药丸按钮（高度 `SizeButtonHeight = 28`，圆角 `RadiusControl = 6`，间距 `Space6 = 6`，基准宽度 `SizePillButtonWidth = 48`）：
  - 预设药丸：`[ 30m ]`、`[ 1h ]`、`[ 2h ]`、`[ ∞ ]`；
  - 更多入口：`[ ••• ]`（直接使用文本 `•••`，无需引入缺失图标）。
- **核心交互语义：选择时长即刻启动**：
  - **未开启状态下**：点击任一预设时长药丸（30m/1h/2h/∞）等于「选择该时长并立即开启常亮」（调用 `setDuration(minutes)`，见 `awake_app.go` 约 86-91 行，内部已调用 `startAwake`）。
  - **已开启状态下**：点击另一时长药丸，视为立即重置为新时长倒计时；点击当前已选中的药丸无副作用。
- **药丸高亮规则 (Highlight Rules)**：
  - 当生效或记忆时长为预设时：对应 `[ 30m ]`、`[ 1h ]`、`[ 2h ]` 或 `[ ∞ ]` 高亮（背景 `ColorAccent`，文字 `ColorOnAccent`）；
  - 当生效设置为 **4 小时**（`config.AwakeMinutes == 240`）、**自定义分钟**、**截止时刻**（`config.AwakeUntil != ""`）或**跟随进程**（`Session.PID > 0`）时：预设 4 颗药丸均不选中，**`[ ••• ]` 药丸进入高亮选中态**（背景 `ColorAccent`，文字 `ColorOnAccent`），表明当前运行的是来自「更多」的扩展配置，具体参数由第 4 行状态条展示；
  - 未开启态（Off）：总开关关闭，药丸行显示最后记忆的时长项（弱化底色，不呈活动强调）。
- **点击 `[ ••• ]`（更多）的行为**：
  - 唤起既有小窗口（自定义时长、直到某时刻、跟随进程，见 `awake_view.go` 约 17-150 行）；
  - **焦点与激活约定**：`awake_view.go` 的小窗打开逻辑（约 34-35 行）中会调用 `d.window.Show()` 与 `d.window.Focus()`。由于小窗聚焦并接收键盘输入，**这一步会激活应用，浮动面板按 MyGo 既有失焦逻辑自动平滑收起**。

#### 4. 行 4：运行状态条
- 仅在常亮开启或异常时展示，高度 `Space20 = 20`，字号 `FontSizeSmall = 12`，颜色 `ColorTextSecondary`。
- 文本格式与状态输出逻辑说明：
  - **倒计时**：`保持屏幕常亮 · 剩余 1:24`（键 `R05Screen`/`R05Tasks` + `AwakeRemaining`，格式为 `剩余 %d:%02d` / `%d:%02d left`，见 `awake_app.go` 约 125-134 行）；
  - **截止时刻**：`保持屏幕常亮 · 直到 18:30` / `Keep display awake · until 18:30`。
    - **新增语言键与格式说明**：现有 `awake_app.go` 的 `awakeStatus`（约 130-132 行）对任何非零 `End` 仅输出剩余时间（`AwakeRemaining`），缺少针对截止时刻的动态状态格式化；而设计稿里的 `R05UntilStatus`（`zh-CN.json:48` / `en.json:48`）只是静态占位文案（`"屏幕常亮 · 直到 02:30"` / `"Display awake · until 02:30"`）。
    - 为此**新增状态格式语言键**：`AwakeUntil`（简体中文 `"直到 %s"`，英文 `"until %s"`），状态格式为 `fmt.Sprintf(text("AwakeUntil"), timeStr)`，整体拼装形如 `text(mode) + " · " + fmt.Sprintf(text("AwakeUntil"), timeStr)`；在 `awakeStatus` 中，当属于截止时刻（`a.config.AwakeUntil != ""`（会话结构 `awakeSession` 没有 Until 字段，截止时刻只存在于配置 `config.AwakeUntil`））时，优先以此格式输出，避免被倒计时覆盖；
  - **不限时**：`保持屏幕常亮 · 不限时`（键 `R05Unlimited`，`zh-CN.json:62`，`en.json:62` 为 `"Indefinitely"`）；
  - **跟随进程**：`仅保持任务 · 跟随 codex`（键 `AwakeFollowing`，`zh-CN.json:124`，`en.json:124` 为 `"following %s"`，**不带 PID**，与 `awake_app.go` 约 135 行保持一致）；
  - **进程异常退出**：显示红色警告图标（Lucide `triangle-alert`，`ColorDanger`）与错误文案（复用既有键 `ProcessEnded`：`zh-CN.json:130` 为 `"所选进程已结束，请重新选择"`，`en.json:130` 为 `"The selected process has ended. Choose another."`）。
- **关于电池行**：底层 `powerMonitor`（`awake_app.go` 约 170-174 行）仅在切到电池时发一次系统通知（发送通知在 `battery_notification.go` 的 `send` 约 32 行，权限被拒后静默在约 36-38 行），并无持续供电数据源，且常驻电池文字违反低信息密度原则，**面板内不设常驻电池说明行**。

### 3.6 键盘操作规范与开着面板时的交互处理

#### 1. 焦点与导航
- **Tab / Shift+Tab**：在面板内部所有可聚焦控件之间单向循环遍历：
  `常亮总开关` → `模式分段器` → `时长药丸(选中项)` → `更多药丸` → `JSON 新建入口` → `JSON 窗口列表` → `底部设置` → `底部退出`。
- **方向键**：
  - 模式分段器：`←` / `→` 即时切换模式；
  - 时长药丸：`←` / `→` 在药丸间移动焦点；`Space` 或 `Enter` 生效。
- **Esc 键处理规范**：
  - **根视图不得手动注册 Esc 快捷键**（避免破坏 MyGo 原生分发机制，见 `ui/input.go` 约 912-913 行）；
  - 当界面有 Tooltip 浮起时，Tooltip 自身注册了 `OverlayShortcut(0, KeyEscape)`（`ui/tooltip.go` 约 85 行），首次按下 Esc 仅关闭 Tooltip；
  - Tooltip 关闭后，再次按下 Esc 会作为未捕获按键传递给 `rt.host.escape()`，自动关闭悬浮面板并恢复焦点。

#### 2. 面板打开时的事件响应与生命周期
- **常亮到期**：到期由底层 `poll()` 触发 `awakeChanged()`（`awake_app.go` 约 15-23 行）。面板若处于打开状态，`refreshAwake()` 触发面板局部重绘，总开关即刻切为 Off，状态条隐藏。
- **全局快捷键**：
  - 面板打开期间，系统全局快捷键不会被面板拦截吃掉；
  - 按下常亮快捷键 `⌃⌥⌘K`：触发 `toggleAwake()`，面板实时响应开关状态刷新；
  - 按下 JSON 快捷键 `⌃⌥⌘J`：触发 `newJSONWindow()`，新建并聚焦 JSON 窗口；由于 JSON 窗口获得焦点并激活应用，**应同时主动关闭菜单栏面板**（`a.panel.Close()`）。

- 紧凑布局基准总宽：`264 + 20 + 24 = 308pt`。在 `320pt` 面板内，剩余 `12pt` 空间可微调卡片内边距或均分，排版舒适饱满。

## 4. 与现有代码的衔接方案

### 4.1 现有代码审计与改动范围

当前项目主入口与常亮逻辑位于根目录：
- `awake_app.go` 的 `refreshAwake`（约 24-38 行）：控制托盘图标更新；
- `awake_app.go` 的 `awakeMenu`（约 139-163 行）：原生常亮菜单组装，其中顶层包含「跟随进程…」（约 158 行）；
- `main.go` 的 `menuForLocale`（约 222-232 行）：组合菜单与右键条目；
- `main.go` 的 `initTray`（约 324-345 行，托盘初始化约 332 行）；
- `main.go` 的 `openSettings`（约 282-287 行）：设置窗口激活与展现；
- `json_app.go` 的 `newJSONWindow`（约 134-141 行）与 `json_documents.go` 的 `jsonMenu`（约 75-85 行）：JSON 窗口与多文档列表。

#### 必须修改的代码位置：
1. **Tray 交互重构** (`main.go` / `awake_app.go`)：
   - 移除 `mygo.TrayOptions.Menu` 静态绑定；
   - 注册 `tray.OnClick(a.toggleMenubarPanel)` 实现左键呼出/收起自定义面板；
   - 注册 `tray.OnRightClick(a.showNativeContextMenu)`，右键弹出精简原生菜单（包含「设置…」「重启以完成更新（更新就绪时）」与「退出 Cubbix」，参考 `examples/menubar-native/main.go` 的 `main` 约 158-166 行与 `docs/menus.md` 的「Context menu on right click」约 239-243 行）。
2. **常亮控制器进程检测修复** (`keepawake.go` 的 `poll`，约 145-154 行)：
   - **不再声称控制器零改动**。当前 `poll()` 在 PID 消失时清空了 `k.state.Error`：
     ```go
     // 当前代码：
     if s.Active && ((!s.Session.End.IsZero() && !k.now().Before(s.Session.End)) || (s.Session.PID > 0 && !k.alive(s.Session.PID, s.Session.Identity))) {
         k.stopLocked()
         k.state.Error = ""
     }
     ```
   - **修改方案**：将到期与 PID 消失解耦。到期时正常结束，`k.state.Error = ""`；当目标 PID 消失时，单独记录错误 `k.state.Error = "ProcessEnded"`，以便驱动面板状态行展示 `triangle-alert` 红色告警。
3. **状态格式与刷新联动** (`awake_app.go`)：
   - 在 `awakeStatus`（约 121-137 行）中，当会话为截止时刻（`a.config.AwakeUntil != ""`（会话结构 `awakeSession` 没有 Until 字段，截止时刻只存在于配置 `config.AwakeUntil`））时，使用新增键 `AwakeUntil` 格式化（`fmt.Sprintf(text("AwakeUntil"), timeStr)`），避免被现有剩余时间覆盖；
   - `awakeChanged()`（约 15-23 行）在到期或快捷键触发时被调用，若面板处于打开状态，调用面板窗口重绘；
   - 全局快捷键 `⌃⌥⌘J` 被触发时，在调用 `a.newJSONWindow()` 的同时显式收起面板；
   - 点击 `•••` 打开小窗口时，`awake_view.go`（约 34-35 行）执行 `Focus()` 激活小窗，面板自然收起。
4. **面板尺寸动态适配** (`menubar_panel_view.go`)：
   - 面板采用 `NewFlyout` 创建，根据渲染内容计算高度后，主动调用 `win.SetContentSize(width, height)`（`flyout.go` 的 `SetContentSize`，约 232-241 行）。
5. **全屏防切 Space（调用既有 API，无需修改 MyGo 内部代码）**：
   - 面板创建后直接调用 `win.SetVisibleOnAllWorkspaces(true)`（`window.go` 约 1062 行），MyGo 在 macOS 底层（`internal/darwin/window.go` 约 879-883 行）自动在现有 behavior 上按位或 `canJoinAllSpaces`，无需修改 MyGo 内部代码；
   - 激活策略保持现有设计：设置窗口或 JSON 窗口可见时应用保持既有的 `ActivationPolicyRegular`（`main.go` 的 `visibility` 约 176-192 行）；面板因设置了 `SetVisibleOnAllWorkspaces(true)` 仍可在当前 Space 使用；但按 MyGo 文档（`docs/windows.md` 约 165-169 行、`internal/darwin/window.go` 约 884-887 行），**只有 Accessory 状态的应用窗口才能盖住其他应用的全屏 Space**，应用为 Regular 时面板能否出现在别人的全屏 Space 上**未实测**，实现阶段需要验证；若不行，接受这一限制（此时用户正在使用 Cubbix 自己的窗口），不为此切换激活策略。

#### 100% 复用的地方：
1. 常亮底层生命周期、caffeinate 参数派生（`keepawake.go` 约 1-144 行）；
2. 配置持久化与加载（`config.go`）；
3. 三个既有参数弹窗（`awake_view.go` 约 17-150 行）；
4. 电源切换监控与系统通知（`awake_app.go` 的 `powerMonitor` 约 170-174 行；通知发送在 `battery_notification.go` 的 `send` 约 32 行，拒绝后静默约 36-38 行）；
5. JSON 文档管理中心 `a.jsonDocuments`（`main.go` 的 `application` 约 29 行）、`a.showJSON` 与智能剪贴板感知（`json_app.go`、`json_documents.go`）。

- **结论**：弹出精简原生菜单，条目为「设置…」（`MenuSettings`）、若更新就绪则展示「重启以完成更新」（`MenuRestartUpdate`，`main.go` 的 `menuForLocale` 约 227-228 行，ADR 004）、以及「退出 Cubbix」（`Quit`）。

### 问题 3：未开启时点击时长药丸继承的模式
- **结论**：沿用 `config.AwakeMode`，默认 `"screen"`（`config.go` 约 35 行），尊重用户偏好记忆。

- **结论**：采纳 `SizeMenubarPanelWidth = 320`、`SizePillButtonWidth = 48` 与 `SizeIconSmall = 12`，明确新 Token 必须录入 `design/cubbix.pen` 并由脚本同步生成。置顶图标改用 Token `SizeIconSmall`，不再写死 12。横排紧凑基准净宽为 308pt，在 320pt 内排版舒适。

### 问题 5：本次是否新增格子排序功能
- **结论**：**本次不做排序**。设置页目前仅有格子开关（`awake_view.go` 约 388-395 行），面板沿用固定顺序（常亮在上、JSON 在下）。
