## 1. 范围

本期解决设置主窗口、JSON 工具窗口的选屏与位置记忆，并抽取 005 已有的通用几何。命令面板的交互、默认高度、参考线、吸附、外观均不改变。

不增加按屏尺寸、实时跟随鼠标、显示器排列编辑器、每屏主题、CLI / URL 参数或 Space 特判。「固定屏幕」变更在下次从隐藏打开时生效，不立刻搬窗口。所有既有设置入口继续走 `show()`。

007 是未合并的设计依赖：先以实现后的 007 布局为基线做 008 界面；若布局变了，按实际组件公式复算并更新测试，不能仅把 008 的行塞进 main 当前的旧页面，也不在本文分支实现或合并 007。

## 2. 行为

### 2.1 两种方式下选哪块屏幕

- 跟随鼠标：打开时读取一次 `displays := a.displays()` 和一次 `a.cursorPoint()`，用纯函数 `displayNearest(displays, point)`。生产含义等同 MyGo 的 `Screen.DisplayNearestPoint(Screen.CursorScreenPoint())`，但测试不访问真实屏幕，且一次操作使用同一份显示器快照。
- 固定屏幕：在同一快照中按 §2.6 匹配。
- 单屏：直接得到该屏，隐藏控件但保留用户原来的固定选择；零屏：返回未找到，不摆位、不保存、不递归调用真实选屏 API。
- 跟随指针只决定打开位置，不代表跟随视线。005 当前 `placePalette` 也通过 `paletteDisplayNearest` 与 `paletteCursorPoint` 选屏，指针未移动时两者判据相同。

### 2.2 窗口放在那块屏幕的什么位置

设置与 JSON 以 `Window.Bounds()` 的**外框**为单位；`Size()`、`Position()`、`SetPosition()` 均由外框实现。005 的位置则是去掉透明阴影边距后的**面板**左上角，不能在抽取时改成窗口外框。

| 项 | 规则 |
| --- | --- |
| 键 | `strconv.FormatInt(Display.ID, 10)`，保持 005 的既有键 |
| 值 | `x = outer.X - WorkArea.X`、`y = outer.Y - WorkArea.Y`；负偏移合法，不在加载时强行改为零 |
| 无记录 | `x = WorkArea.X + (WorkArea.Width-width)/2`、`y = WorkArea.Y + (WorkArea.Height-height)/2`；整数除法沿用 Go 向零截断 |
| 有记录且该轴放得下 | 还原偏移，再夹到 `[work 起点, work 终点 - size]` |
| 宽度放不下 | 忽略旧 X 偏移，水平居中；该轴不夹取 |
| 高度放不下 | 忽略旧 Y 偏移，顶对齐 `WorkArea.Y`，使顶部拖动区域与工作区相交；超宽时窗口按钮仍可能在屏外；该轴不夹取 |
| 应用顺序 | 隐藏窗口先 `SetPosition`，再 `Show`；不保存自动摆位结果 |

坐标事实（MyGo v0.6.2）：

- `internal/darwin/system.go` 的 `screen.Displays` 将 `NSScreen.frame` / `visibleFrame` 经 `rectFromMac` 转为 `Bounds` / `WorkArea`；`CursorPoint` 也使用 `primaryScreenHeight()` 翻转 Y。
- `internal/darwin/window.go` 的 `rectFromMac` 用 `Y = primaryHeight - nativeY - height`；`rectToMac` 逆变换，`SetBounds` 调 `setFrame:display:`。因此窗口、显示器、鼠标处于同一套全局 DIP 坐标：主屏左上为原点，X 向右、Y 向下；左侧／上方副屏可以有负坐标。
- 原生 AppKit 点与 MyGo DIP 在此对应；`ScaleFactor` 是另一个字段。Retina 不把这些值再乘除 2，也不混用截图像素、物理分辨率或元素局部坐标。UI 拖动事件到屏幕坐标仍保留 005 的转换。
- `WorkArea` 反映系统提供的可用矩形；菜单栏、Dock、自动隐藏等占用一律以当次 `visibleFrame` 结果为准，不写死菜单栏高度，不假定每块副屏都扣相同高度。使用 `Bounds` 居中与使用 `WorkArea` 居中会有差别，但不能一概声称只偏半条菜单栏。

现状：设置与 JSON 的 `WindowOptions` 都未填 X/Y，`window.go.platformOptions` 因两者为零设置 `Center`，Darwin 创建时调用 `NSWindow.center`；代码没有明确选中主屏，不能从这条调用推出必在主屏。本文直接按目标屏 `WorkArea` 算位置，不依赖 `center` 的 AppKit 选屏行为。原生初始中心、菜单栏与 Dock 实际表现未实测。

### 2.3 大小

定稿：保留 `window_width` / `window_height` 与 `json_width` / `json_height` 各一份全局外框尺寸。

- 设置创建时继续 `settingsSize` 抬到 `settingsMinimumSize`，本期下限改为 720 × 388。`rememberWindowSize` 的隐藏及 `OnResize` 写入方式保留。
- JSON 继续沿用 `buildJSONWindow` 的尺寸默认值与 `SizeJSONEmptyWidth` / `SizeJSONEmptyHeight` 下限。
- 不按工作区自动缩小，也不把自动调整的位置写回尺寸。跨屏时保持大小更容易预期，配置与 005 位置表也无需扩字段。
- 已知限制：用户在大屏拉大的窗口到小屏可能有左右或底部超出；§2.2 保持顶边可达，用户可拖动、缩放。只要尺寸大于工作区，就不能承诺外框全部可见。无需运行应用即可确定这一几何限制，实际交互仍须验收。

### 2.4 打开时摆位的完整流程

`main.go.show()` 的当前入口包括托盘菜单、应用菜单 `Cmd+,`、命令面板设置命令、URL / CLI 的设置动作及激活回调。目标流程：

```go
func (a *application) show() {
    if a.window == nil {
        return
    }
    if a.window.IsMinimized() {
        a.window.Restore()
        // Repair a changed display layout, but do not follow the cursor.
        a.reconcileSettingsDisplayIfNeeded()
    } else if !a.window.IsVisible() {
        a.placeSettingsWindow()
    }
    a.visibility(true)
    a.window.Show()
    a.window.Focus()
}
```

这是目标控制流，新增方法在 `window_placement.go` 实现。`Restore`、`IsMinimized` 是 MyGo 已有公开 API；不能只猜测最小化时 `IsVisible()` 的返回值。

`placeSettingsWindow`：获取一份屏幕快照 → 选屏（找不到直接返回）→ 读当前 `Bounds()` → 查 `WindowPositions` → `screenPlacement` → 经 §2.9 的受控移动入口 `SetPosition` → 回读实际外框作为基线。自动摆位不保存位置、固定选择或解析所得 ID，不通知。

`visibility(true)` 可能激活应用，原生 `Show()` 也会提到前台；这不是新增后台测试入口。评审和自动验证不得通过调用此流程运行 Cubbix。

### 2.5 已经打开时再触发「打开」

| 场景 | 定稿 |
| --- | --- |
| 可见时重复设置、`Cmd+,`、URL、CLI | 不调用摆位、不改变外框，只沿用 Show / Focus |
| 最小化后再打开 | 显式 Restore，保持原屏原位；仅当显示器布局已变时恢复可达位置，不按当前鼠标重选 |
| 显式隐藏后再打开 | 按当前方式重新选屏及恢复该屏位置 |
| 修改方式或固定屏选择 | 只保存选择并重画；当前窗口不移动 |
| 拖到另一块屏 | 保存到实际最大重叠屏；固定选择不随拖动变化 |

上述「不跳」保证的是应用不重算打开位置；Show / Focus、Restore 及系统 Space 行为不能由静态源码保证无视觉变化，须实测。

### 2.6 固定的那块屏幕不在时怎么退回

`settingsDisplay` 返回 `(display, matched)`：`matched` 表示找回固定目标，用于 alert；空列表另以 `display.ID == 0` 表示没有可摆位屏。顺序如下：

1. 非零 `WindowDisplayID` 精确命中。
2. 原始名称非空，且名称和 `Bounds.Width × Height`（逻辑 DIP 尺寸）都匹配，**恰有一个**候选。
3. 原始名称非空，且名称相等，**恰有一个**候选，允许分辨率／缩放改变。
4. 前三步失败或有歧义，使用 `Primary` 屏；快照异常没有 Primary 则取第一块，`matched = false`。
5. 空快照返回零值、`matched = false`，保持系统位置。不能在空列表时再次向真实 API 问「鼠标所在屏」。

不采用「仅尺寸相同」匹配；不同设备同尺寸很常见。不在多块同型号候选中按数组顺序猜目标。系统语言变化可能使名称变化，ID 又改变时允许退回主屏。

退回屏使用自己的位置表，缺项则居中。原固定选择及失联屏记录保持不变，重接后重新匹配。名称匹配成功但 ID 变了时，位置仍按当前 ID 查；旧 ID 的座位不复制、不迁移，新屏缺记录就用默认位置。该降级不报配置错误。

主屏的定义是 `Display.Primary`：MyGo Darwin 将 `NSScreen.screens` 第零块标为 Primary；不是内建屏，也不是当前 key window 所在的 `NSScreen.mainScreen`。现代系统可能每屏都有菜单栏，不能靠「看见菜单栏」判断。

### 2.7 显示器拔插与分辨率变化

现有 `ready` 已用 `OnDisplaysChanged` + `mygo.RunOnMain(a.paletteDisplaysChanged)`。改为主线程上的 `a.displaysChanged()`：先调用 005 原处理，再处理设置和 JSON，最后 `invalidateWindow()` 刷新控件。

必须保存一份上一轮显示器快照，以及每个窗口最后已知的 `displayID`、外框与位置观测状态（§2.9）。**不能只在通知后对当前外框调用最大重叠函数来判断屏是否消失**：AppKit 可能已经把窗口搬到别屏，而最大重叠函数即使没有交集也会返回第一块屏。

| 情形 | 可见设置／JSON 窗口 | 隐藏或最小化窗口 |
| --- | --- | --- |
| 当前 ID 仍在，工作区或排列变了 | 将缓存位置相对旧 WorkArea 的偏移映射到同 ID 的新 WorkArea，再逐轴夹回；放不下按 §2.2 默认轴；不按鼠标重选 | 不显示、不聚焦、不写配置；记录需要恢复 |
| 当前 ID 消失或完全离开全部屏幕 | 设置按当前方式、JSON 按鼠标重新选屏；恢复目标屏记录或默认位置 | 隐藏窗口下次打开选屏；最小化窗口 Restore 时恢复可达位置 |
| 仅插入另一块屏，当前工作区没变 | 不移动 | 不移动 |
| 没有显示器 | 不移动，不保存；保留最后有效状态，等下一次有效快照 | 同左 |

处理前取消位置脏状态，自动变化后刷新外框基线，不覆盖落盘座位。取舍是：尚未隐藏／关闭、尚未保存的一次手动拖动，若紧接着遇到拓扑变化，可能被放弃；优先保护已有记录不被系统恢复动作污染。重复通知但几何快照未变时只刷新选项，不清掉正常拖动的待保存值。

`OnMove` 若先发现新旧 ID / Bounds / WorkArea / ScaleFactor 快照不同，应先走该恢复流程，再判断移动来源；这样不依赖 `OnMove` 与显示器通知的先后顺序。处理期间的回调按 §2.9 忽略。同屏仍有效时不重新居中；不自动回到刚插回的固定屏，直到下一次从隐藏打开。

WorkArea 的每种变化是否都触发该通知，源码没有逐项保证；打开前总读新快照，且需验证 Dock、旋转、主屏切换。不能把通知注释扩大成所有系统布局事件都必定覆盖。

### 2.8 全屏 Space

设置与 JSON 创建时均为 `DisableFullScreen: true`；MyGo 的 `platformOptions` 与 Darwin `createWindow` 使其不能自己进入全屏。`visibility(true)` 切为 Regular，窗口显示还会激活应用；这些现状保留。

不增加 Space 检测、`moveToActiveSpace` 或改变 collection behavior。设置坐标不等于能在任意 Space 显示；目标屏正运行别人的全屏应用时窗口出现在哪、是否切 Space，以及「显示器有自己的 Space」开关的影响，均留给维护者实测，不能作为后台已验证结果。`moveToActiveSpace` 本身是 AppKit 公共选项，不称其为私有 API。

### 2.9 什么时候写位置

单个 `windowMoved` 布尔值加 `placing = true/false` 不足以定义保存：MyGo 的 `OnMove` 不携带用户来源或移动代次。源码证实 `SetPosition` 走主线程 `SetBounds`，`windowDidMove:` 直接调用 `Moved()` 再分发，但不保证 AppKit 通知总在 setter 返回前到达；`RunOnMain` 在主线程立即执行，也不能当「下一帧」使用。

设置与每个 `jsonDocument` 各有一份 `windowPlaceState`，至少含：`placing`、最后观测的原点与有效标志、所属显示器 ID、上一份有效外框、待保存的 `(displayID, seat)` 快照及全局移动序号。应用另保留每屏最近已提交 JSON 移动序号（仅本轮运行，不写配置），避免先移动但后关闭的旧窗口覆盖更新座位。不是只有一个应用级 placing。

| 事件 | 状态与写盘 |
| --- | --- |
| 创建、打开摆位、夹回、拓扑恢复 | 受控移动入口：先清待保存值并设 placing，SetPosition 后回读实际外框作为基线，再清 placing；不落盘 |
| OnMove | 先检查拓扑变化；placing 时忽略。否则读取当前实际原点，与最后观测值相同则忽略（包含迟到的程序移动通知）；隐藏／最小化时只刷新基线，不置脏。其余真实变化按正面积最大交集取屏，无交集不存；缓存该屏当时 WorkArea 的偏移及递增序号，不写盘 |
| 设置 hide / 退出 | 消费缓存的待保存座位；没有待保存值就不写。hide 必须在 Hide 前处理，退出在窗口销毁前处理 |
| JSON 普通关闭 | OnClose 中、窗口仍存活时刷新及保存缓存；不改变关闭是否被允许的现行规则 |
| JSON destroyJSON | Destroy 前保存；Destroy 不触发 OnClose，不能漏掉此入口 |
| JSON OnClosed / removeJSONDocument | 只清状态、移除文档，不读窗口位置，不再次保存 |
| 退出批量保存 | 每屏只取移动序号最大的待保存 JSON 记录，且必须比该屏本轮已提交序号新；合并设置位置后统一保存一次，不按文档创建顺序覆盖 |

隐藏、关闭、Destroy 与退出的保存入口，应在句柄存活且拓扑一致时先通过同一观测逻辑采集最终外框，覆盖末次 OnMove 尚未送达的情况；若拓扑已变则先按 §2.7 恢复并取消待保存值，不将系统移动当最终用户位置。beforeQuit 保持退出 watchdog 先 arm，再在窗口清理／销毁前归并保存，不等通知、不延长现有退出预算。

`rememberWindowPlace` / `rememberJSONPlace` 消费的是**移动时缓存的座位快照**，不在隐藏时重新按变化后的 WorkArea 计算。JSON 普通关闭也先与该屏已提交序号比较，旧序号直接丢弃；提交较新序号后更新内存序号，即使座位数值相同也要推进序号。位置表条目没变则不 save。保存复用现有 `save()` 错误反馈，不在回调每帧写盘；不新增与既有尺寸／选择写入竞争的文件写入器。

重要源码边界：`windowHandler.Closed` 在触发 OnClosed 前已将 `w.native = nil`；`Bounds()` / `Position()` 此时返回零值。初稿建议在 `removeJSONDocument` 读取原生位置会存错，必须按上表提前采集。

这套基线过滤处理同步／迟到／合并的程序移动通知，不用固定次数吞事件或延时猜测。MyGo 无法直接区分用户拖动、缩放导致的原点改变和其它外部移动，因此本文把拓扑稳定时的外部位置变化也视为可记忆移动；不承诺识别每种 OS 自动移动来源。原生事件顺序须按 §8 验收，发现偏离时应修复适配并加回归，不能直接把所有 OnMove 当用户操作。

## 3. 显示器怎么标识

### 3.1 `Display.ID` 是什么

`internal/darwin/system.go.screen.Displays` 从 `deviceDescription["NSScreenNumber"]` 取 `unsignedIntValue` 转 int64；MyGo `modules.go.Display` 原样公开，没有硬件序列号或持久 UUID。Apple 的 [deviceDescription 文档](https://developer.apple.com/documentation/appkit/nsscreen/devicedescription) 也说明该键对应 CGDirectDisplayID。

`Display.Label` 来自 `localizedName`，可能为空、同名或随系统语言改变；不是唯一键。`Bounds` 尺寸是逻辑 DIP，不是物理像素分辨率；改变缩放也可能改变它。`Primary` 与坐标转换见 §2。

### 3.2 它在重启、换线后是否稳定

定稿：**将 ID 作为可复用的尽力匹配键，不作为跨重启／接口永久身份保证。**「运行时编号」不等于每次启动必变，也不等于一定稳定。

Apple 的 [Quartz Display Services 概览，Display IDs](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/QuartzDisplayServicesConceptual/Articles/Overview.html) 描述了分配给在线显示器的标识与跨进程复用，并以重启作为稳定性的边界。本文不据此承诺现代所有连接组合的实际行为，也不把单机重启一次的结果当 API 保证。旧稿「相同接口跨开机通常稳定」缺少足以支持本项目保证的证据，删除。

本期保持 005 的十进制键，所有未命中都是正常路径：设置／JSON 用默认位置，固定选择走 §2.6。ID 被重新分配或同型号设备被替换时仍可能误认旧座位；恢复时夹回，用户可移动重记。名称与尺寸兜底也只是启发式，不能证明是同一台硬件。

不新增 UUID 桥接。Apple 提供 [ColorSync 的 CGDisplayCreateUUIDFromDisplayID](https://developer.apple.com/documentation/colorsync/cgdisplaycreateuuidfromdisplayid(_:))，它不是 MyGo 当前公开字段，也不能在未调研前宣称无条件跨扩展坞稳定；若以后要求强持久身份，应另立设计，核对系统框架、失败路径及三张位置表的兼容迁移，不能在 008 顺便替换 005。

### 3.3 固定选择与位置表分开

```toml
window_placement = "display"
window_display_id = 732561
window_display = "外接显示器一号"
window_display_size = "1920x1080"
```

三个选择字段由用户切到固定方式时（尚无选择）或明确选择屏幕时一起更新：名称取原始 Label，尺寸取 Bounds 的 DIP 宽高，ID 取当前值。切回跟随方式保留三项。自动解析命中名称时不顺手改 ID、不保存；下一次明确选择才更新。

位置表只存 ID 与 x/y，不加入名称、尺寸或 UUID。固定选择在本地配置存一份显示名称，作为本期已定的启发式兜底；这不改变公开仓库禁止个人设备信息的规则，示例、测试与公开截图只用假数据。空白 Label 不作为名称兜底依据，显示用的尺寸文案也不冒充原始名称。

### 3.4 选项列表怎么生成与显示

- 每次构建视图取一份显示器快照，按系统顺序显示，主屏在前；不保存下标。`Display.ID` 的十进制字符串是控件的选项值。
- 显示 Label；空白则显示 `宽 × 高`（DIP）。同名时追加逻辑尺寸；仍同名同尺寸时追加列表序号（纯数字），只供当次选择消歧，不用作持久身份。完整显示文本用于 tooltip / 可访问名称，触发器可省略长名称。
- 固定解析命中时显示目标；失配时显示退回屏并给 alert。呈现退回项不等于用户重新选择，构建视图不能写配置。即使退回项已是 selected，显式点选它也必须能提交为新固定选择，不能只依赖值改变时才触发的 `OnChange`；Item 的激活处理须覆盖「选同值」并单测。
- 零屏无选项，不造 ID 0 记录。拔插时重建选项并关闭旧 popup，防止旧下标／旧 ID 继续提交；提交前在最新快照核对 ID 仍存在。
- MyGo `ui/base.go.selectParts.Popup` 只搭 popup，不自动加滚动；Item 只调用 `ScrollIntoView`。实现必须给 popup 选项容器显式有限高度的 `ui.Scroll`，高度最多六行并受当前可用空间约束，键盘高亮项能滚入视野；不另做搜索。

## 4. JSON 窗口

### 4.1 结论：同一套位置记忆，只跟随鼠标

JSON 不提供独立固定屏设置，也不受设置窗口固定选择影响。使用 `json_positions`，各窗口有独立移动状态，但**每屏只保存一个最后记忆位置**，并非每份文档分别持久化。已经打开的窗口再次 focus 不重摆；只有新窗口执行 §4.3。每屏最终保留本轮已提交记录中移动序号最新的一份；关闭顺序不改变这个优先级。

### 4.2 现状与调用落点

`json_app.go.buildJSONWindow` 创建 Hidden 窗口，未指定 X/Y，使用系统 center；不能从源码断言每扇都在主屏。`newJSONWindow`、`newJSONWindowBlank`、`openJSONText` 的生产路径经 `createJSONWindow` 到此处。`focusJSONWindow` 只 Show / Focus；现有 OnResize 写尺寸，OnClosed 移除文档。

新建窗口在 `buildJSONWindow` 末尾、`LoadURL` 之前摆位并初始化移动基线；同一同步主线程流程完成后再显示。接入 OnMove 与 OnClose，Destroy 前及 beforeQuit 保存，OnClosed 不读几何（§2.9）。状态字段放 `json_documents.go.jsonDocument`，不能把同一个 placing / moved 共用于所有窗口。拓扑恢复处理每个存活窗口，且不参与新建错开。

### 4.3 多开错开

初稿用「本次运行累计打开数」会跨屏串扰、关闭后继续漂移，达到上限还会永久叠在同一点，删除该计数与 `jsonOpened` 字段。定稿算法：

1. 读取一次屏幕与鼠标，选目标屏；空列表则跳过位置操作。查目标屏 `JSONPositions`，用 `screenPlacement` 得基点。
2. 候选为基点加 `(24*k, 24*k)`，`k = 0,1,2,3,4`，即 0／24／48／72／96 DIP。24 取 `Space24`，是本产品的错开步长，不宣称为 macOS 标准值。
3. 每个候选按工作区夹取；放不下的轴维持 §2.2 的默认轴，不继续偏移。夹取后去重，避免不同 k 实际落同一点。
4. 比较**目标屏当前未关闭的 JSON 窗口**（包含刚创建但尚未显示的窗口，不包含自己）的当前外框原点；优先取 k 最小且原点未被占用的候选。窗口已被拖到其它屏就不占本屏候选；最小化窗口仍算存活。
5. 候选都被占用时取与这些窗口外框交叠面积总和最小的候选；相同则选 k 小者。没有现存窗口时一定用基点；关闭后释放候选，不维持累计计数。

每屏独立计算，同屏默认顺序为 0／24／48／72／96，第六扇只作有限范围的尽力错开。工作区太小、基点贴边、窗口很大时允许重叠，不能承诺「永不叠窗」。自动错开不写位置表，未移动就关闭也不保存错开位置；手动移动后才缓存新座位。重新打开使用该屏最后保存的基点，再对当前存活窗口避让，不为每份 JSON 记独立位置。

### 5.2 交互

- 选跟随：写方式并 save，隐藏第 5 行，窗口不动。
- 首次选固定且尚无选择（ID 为零且原始名称为空／全空白；尺寸单独不算选择）：默认取**当前窗口最大正面积重叠屏**，完全离屏则取指针最近屏；三项一起写入并 save。已有但失联的完整选择保留，不被切换方式悄悄覆盖。

### 5.3 只有一块显示器时

`len(displays) < 2` 时第 4、5 行都隐藏，位置记忆仍生效，保留固定选择。多屏恢复后重现。单屏时固定失联 alert 也随整组隐藏，这是已定取舍；不会悄悄改选主屏。

OnDisplaysChanged 必须 `invalidateWindow()`；视图和高度计算使用同一个快照及相同条件，不在渲染中写配置或改变原生窗口尺寸。

### 5.4 说明与文案级别

按 007：第 4 行用 ③ 级常驻 info + tooltip；第 5 行不加正常说明，只有固定目标未匹配才显示异常 alert。info 解释记忆与生效时机；alert 解释「将退回」而非谎称当前窗口已经搬过去。不为每次打开、夹回或保存成功增加通知。

### 5.5 高度与最小窗口

| 状态（含 CLI 行） | 卡片 | 内容自然高 `pageHeight` | 加上下 48 后 | 对齐 4 的窗口自然高 |
| --- | --- | --- | --- | --- |

| 多屏跟随，四行 | 195 | 291 | 339 | **340** |
| 多屏固定，五行 | 244 | 340 | 388 | **388** |

联动接口定为扩展 007 `pageHeight(t, page, awakeOn)`：增加 `showPlacement bool`、`fixedDisplay bool`、`hasCLI bool`，三个布尔值由同一份视图状态得出；只有 page 0 使用这些新增状态。`settingsHeight` 同步接收并转发，不能只改 pageHeight 不改其测试／QA 调用方。

### 6.2 新文件 `screen_placement.go` 的接口与契约

```go
type screenPoint struct{ X, Y int }
// screenSize describes the object being placed: a palette panel or an outer frame.
type screenSize struct{ Width, Height int }
type seat struct {
    X int `toml:"x"`
    Y int `toml:"y"`
}

func seatKey(id int64) string
func seatOffset(p screenPoint, work mygo.Rectangle) seat
func seatPoint(s seat, work mygo.Rectangle) screenPoint
func screenRect(p screenPoint, size screenSize) mygo.Rectangle
func screenRectContains(r mygo.Rectangle, p screenPoint) bool
func clampToWorkArea(p screenPoint, size screenSize, work mygo.Rectangle) screenPoint
func centeredPoint(display mygo.Display, size screenSize) screenPoint
func displayMatching(displays []mygo.Display, r mygo.Rectangle) mygo.Display
func displayNearest(displays []mygo.Display, p mygo.Point) mygo.Display
// New window-only helper: no positive overlap means not found.
func windowDisplayMatching(displays []mygo.Display, r mygo.Rectangle) (mygo.Display, bool)
func screenPlacement(display mygo.Display, remembered *seat, size screenSize) screenPoint

type seatTable struct{ seats *map[string]seat }
func (t seatTable) lookup(display mygo.Display) (seat, bool)
func (t seatTable) store(display mygo.Display, p screenPoint) bool
// storeSeat commits an already captured offset without reading the current work area.
func (t seatTable) storeSeat(id int64, value seat) bool
func (t seatTable) forget(display mygo.Display) bool
```

以上是目标接口清单，不是可直接编译的函数声明文件；`seat` 可继续定义在 config.go。store / storeSeat / forget 返回是否改变内容，**不调用 save**；store 用 seatOffset 后调用 storeSeat，保存待提交快照直接调用 storeSeat，避免拿当前 WorkArea 再算一次。lookup 不分配，nil map 可读，store / storeSeat 分配 nil map，nil map 的 forget 安全。共享层保留所有十进制 ID（包括旧键 0）的存取能力，不改变 005 的边界行为；设置与 JSON 调用方在 ID 0 时跳过读写／删除。保持 `putPaletteSeat` 薄包装供兼容测试亦可，但只保留一份偏移换算逻辑。

`displayMatching` 必须保留当前 `bestArea=-1`：非空列表即使全无交集也返回第一块，面积相等取靠前；只有空列表返回零值。`displayNearest` 距离平方相等也取靠前，按 Bounds 距离而非 WorkArea。新增 `windowDisplayMatching` 单独要求正面积交集；无交集返回 false，不能为新窗口需求悄悄改掉 005 的函数契约。

`clampToWorkArea` 逐轴容得下才夹，容不下原样返回。通用窗口默认函数如下，**005 不调用此函数**：

```go
func screenPlacement(display mygo.Display, remembered *seat, size screenSize) screenPoint {
    p := centeredPoint(display, size)
    if display.WorkArea.Height < size.Height {
        p.Y = display.WorkArea.Y
    }
    if remembered != nil {
        at := seatPoint(*remembered, display.WorkArea)
        if display.WorkArea.Width >= size.Width { p.X = at.X }
        if display.WorkArea.Height >= size.Height { p.Y = at.Y }
    }
    return clampToWorkArea(p, size, display.WorkArea)
}
```

### 6.3 迁移与 005 不变条件

- `placePalette` 仍从 `paletteDefaultPoint` / `palettePosition` 起算：横向居中、Y 为 TopOffset，工作区太矮时贴顶；仅放得下的轴使用旧 seat，最后 clamp。不能把「居中 + TopOffset」当同一公式，不能改用设置窗口的垂直居中。
- `paletteSize()` 仍是面板内容尺寸；`palettePanelPoint` 加阴影 margin、`movePalettePanelTo` 减 margin，位置表仍存面板而非透明外窗。参考线 overlay 的工作区局部坐标不变。
- `storePaletteSeat` 可转调 seatTable.store，但维持松手提交、双击重置、取消不存的既有行为；共享表不自动 save，不吞掉面板自己必要的 save。
- `paletteDisplaysChanged` 拖动捕获中仍清拖动／收参考线并立即返回，不存、不移动；空闲可见面板仍 placePalette。外层 displaysChanged 不得再对 palette 调通用恢复，导致取消后又摆位。
- 通用用例可迁到 `screen_placement_test.go`，原断言保留；吸附／参考线留原测试。更新 seam、类型及重命名涉及的**所有**调用方，不能宣称 palette_geometry_test.go 不动；反馈 seam 不动。
- `palette_position_native_darwin_test.go` 中设置最小尺寸断言／输出随 008 改 388，面板 704 × 464 外窗、透明阴影边距等断言不改。现有负坐标、小工作区、配置往返及拖动状态机测试都保留，不用只测新 `screenPlacement` 替代。
