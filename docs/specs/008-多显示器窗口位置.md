## 0. 结论摘要

| 项 | 结论 |
| --- | --- |
| 两种方式 | 设置项「窗口位置」= **跟随鼠标** 或 **固定屏幕**；两者都按显示器记住窗口位置，大小仍用既有的 `window_width` / `window_height` 一份（§2） |
| 选屏 | 跟随鼠标：`Screen.DisplayNearestPoint(Screen.CursorScreenPoint())`；固定屏幕：按「ID → 名称 + 分辨率 → 系统主屏」的顺序找回选中的那块（§2.1、§3） |
| 位置 | 存「窗口左上角相对该显示器 `WorkArea` 原点的偏移」，按 `Display.ID` 分组（与 005 同一套）；没有记录就在该屏 `WorkArea` 居中；打开时一律夹回工作区（§2.2、§2.4） |
| 大小 | **不按屏分别记**（推荐）：全局一份，显示器变小时只夹位置、不改尺寸；理由与将来扩展路径见 §2.3 |
| 已打开时再「打开」 | **不移动窗口**（推荐）：只有窗口从隐藏变可见时才摆位，`show()` 里判 `IsVisible()`（§2.5） |
| 固定屏幕不在 | 退回**系统主屏**（推荐），仍然居中或用它记住的位置；没有主屏（`Displays()` 为空）时用鼠标所在屏（§2.6） |
| 显示器拔插与分辨率变化 | 窗口可见时夹回当前工作区；所在屏消失时搬到退回屏；窗口隐藏时什么都不写，下次打开按当时屏幕摆位（§2.7） |
| 全屏 Space | 设置窗口 `DisableFullScreen: true` → `fullScreenNone`，不改；摆位只依赖 `WorkArea`，不按 Space 特判。能否出现在别人的全屏 Space 仍未证实（§2.8） |
| 显示器标识 | 复用 005 的 `Display.ID`（`NSScreenNumber` = `CGDirectDisplayID`），**运行时编号，不是序列号**；重启、换线后是否稳定无法在本机静态查证，所以「找不到 ID → 用默认位置」必须当正常路径；「固定屏幕」的选择额外存名称 + 分辨率做兜底（§3） |
| 选项列表 | 用 `Display.Label`（macOS 取 `localizedName`），为空时退成「宽 × 高」；顺序按 `Screen.Displays()`（主屏在前）（§3.4） |
| JSON 窗口 | **同一套规则**（推荐）：新建窗口跟随鼠标所在屏，按屏记住位置；不提供「固定屏幕」；多开时逐级错开（§4） |
| 设置项 | 007 的「通用」页加一行「窗口位置」（分段控件「跟随鼠标 / 固定屏幕」），选「固定屏幕」时多出一行「屏幕」（下拉）；只有一块屏幕时整组隐藏；说明用 007 的 ③ 级 info + tooltip（§5） |
| 高度 | 通用页自然高 300 → **348**（跟随）/ **396**（固定多一行）；`settingsMinimumSize` 高 **380 → 396**（§5.5） |
| 共享模块 | 把 005 的「按显示器记位置、夹回、取显示器」从 `palette_geometry.go` 抽到 `screen_placement.go`，改名去 `palette` 前缀，`paletteSeat` → `seat`；命令面板与两个窗口共用（§6） |
| 配置 | 新增 `window_placement`、`window_display`、`window_display_size`、`window_display_id`、`[window_positions.<id>]`、`[json_positions.<id>]`；不升 `configVersion`，旧配置缺键即默认值（§5.6） |

## 1. 范围

本期只解决「设置窗口（主窗口）与 JSON 窗口打开在哪、开在什么位置」，以及为它准备的一个设置项。

不在本期：

- 窗口尺寸按显示器分别记忆（§2.3 说明理由，作为将来的扩展点）。
- 让「固定屏幕」在窗口已打开时立刻把窗口搬过去（§2.5 定为不搬）。
- 每块屏各自的吸附/参考线（005 的参考线只属于命令面板拖动）。
- 显示器排列的可视化、每屏独立主题或缩放。
- CLI / URL 的新参数（现有 `settings` 命令与 `cubbix://settings` 都走 `show()`，行为自然跟随，见 §7）。

## 2. 行为

### 2.1 两种方式下选哪块屏幕

| 方式 | 选屏 | 依据 |
| --- | --- | --- |
| 跟随鼠标 | `mygo.Screen.DisplayNearestPoint(mygo.Screen.CursorScreenPoint())`，即指针所在的那块屏 | 与 005 的 `paletteCursorPoint` 同一套（`palette_drag.go`）；`DisplayNearestPoint` 与 `CursorScreenPoint` 都是 MyGo 公开 API（`mygo@v0.6.2/modules.go` 的 `ScreenModule`） |
| 固定屏幕 | 按 §3.3 的顺序在 `Screen.Displays()` 里找回用户选的那块 | —— |
| 单一显示器 | 两种方式等价，选屏就是那块 | 见 §5.3（此时设置项整组隐藏） |

要点：

- 跟随鼠标的判定发生在**打开窗口的那一刻**，不是启动时也不是鼠标移动时。用户在两块屏之间移动指针、然后从菜单栏执行「设置」，窗口就开在指针所在屏。
- 这里的「鼠标所在屏」与 005 命令面板用的判据完全相同（`DisplayNearestPoint(CursorScreenPoint())`），所以「按 ⌥. 出的面板」和「接着打开的设置窗口」默认落在同一块屏上。

### 2.2 窗口放在那块屏幕的什么位置

**存什么**：窗口**外框**（`Window.Bounds()`，含隐藏标题栏，单位 DIP）左上角相对该显示器 `WorkArea` 左上角的偏移。

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 键 | `Display.ID` 的十进制字符串 | 与 005 的 `paletteSeatKey` 完全一致（`palette_geometry.go`），复用同一套表结构 |
| 值 | `x`、`y`，相对 `WorkArea` 原点的偏移 | 显示器换摆放、换主屏后仍然成立；绝对坐标会失效（005 §4.1 的同一理由） |
| 记录的是外框还是内容区 | **外框** | `Window.Size()` / `Bounds()` / `SetPosition` 都是外框（`mygo@v0.6.2/window.go` 的 `Size`、`Bounds`、`SetPosition`；`internal/darwin/window.go` 的 `SetBounds` → `setFrame:display:`）。`window_width` / `window_height` 现在记的也是外框（`rememberWindowSize` 用 `window.Size()`），两边同一口径 |

**打开时怎么算位置**（`screenPlacement`，§6.2）：

1. 若该屏有记录 → `x = WorkArea.X + seat.X`、`y = WorkArea.Y + seat.Y`。
2. 否则 → 在该屏 `WorkArea` 里**居中**：`x = WorkArea.X + (WorkArea.Width - width)/2`、`y = WorkArea.Y + (WorkArea.Height - height)/2`。
3. **逐方向判断容得下**（沿用 005 `paletteClamp` 与 `placePalette` 的口径）：某方向上 `WorkArea` 比窗口小，该方向**不用记忆偏移、改用居中**，并且不做夹取（夹取在容不下时是恒等）——这样分辨率缩小后旧偏移不会把窗口顶出屏幕。
4. 其余方向夹回 `[WorkArea 起点, WorkArea 终点 - 窗口尺寸]`。
5. 位置算好后**先 `SetPosition` 再 `Show`**，避免窗口先出现在旧位置再跳一下（§2.5）。

现状对照：设置窗口创建时没有给 `X`/`Y`，MyGo 因此把 `Center` 置为真（`mygo@v0.6.2/window.go` 的 `platformOptions`：`Center: o.X == 0 && o.Y == 0`），创建时调 `center`（`internal/darwin/window.go` 的 `createWindow`）→ **现在就是系统主屏居中，之后 `Show()` 不再改位置**（`main.go` 的 `show`）。`center` 用的是窗口当时所在屏的 `visibleFrame` 还是 `frame`，属 AppKit 行为，**未实测**；本文改成自己按 `WorkArea` 居中，就不再依赖它。

「居中」用 `WorkArea`（已排除菜单栏与 Dock），不用 `Bounds`：菜单栏在副屏也占一条，用 `Bounds` 居中会让窗口整体上移半个菜单栏（005 §3.1 的同一结论）。

### 2.3 大小

**结论（推荐）：沿用现有的一份全局尺寸，不按显示器分别记。**

| 项 | 现在 | 本期 |
| --- | --- | --- |
| 配置键 | `window_width`、`window_height`（`config.go` 的 `Config`） | 不变 |
| 写入时机 | `rememberWindowSize`（`main.go`）：`hide()` 与 `window.OnResize` 里各调一次，值变了才 `save()` | 不变 |
| 读取时机 | `createSettingsWindow` 里 `settingsSize(a.config.WindowWidth, a.config.WindowHeight)` | 不变 |
| 下限 | `settingsMinimumSize()`：宽 `SizeWindowWidth` 720、高按快捷键页算（007 定为 380，本期改为 396，见 §5.5） | 不变，跟着 007 的改法 |

为什么不按屏记：

1. 窗口有硬下限（720 × 396），几乎每块现代屏幕都放得下；真正放不下的场景是「外接 4K 上拉到很大、再回到 1440 宽的内建屏」，此时按屏记会突然变小，不比「一份尺寸 + 位置夹回」更可预期。
2. 一份尺寸意味着从一块屏换到另一块屏时窗口**大小不变**，只有位置变；两个变量一起变最容易让人以为「窗口跑乱了」。
3. 配置与代码都小：位置表仍然只有 `x`/`y`，`window_width`/`window_height` 的位置和含义都不用动。

已知限制（写进验收）：如果记住的尺寸在目标屏的 `WorkArea` 上放不下，窗口会**保持原尺寸**，可能有一边落到屏幕外；用户自己拉一次即可，拉动会立刻写回配置。要彻底解决得「尺寸也按屏记」或「按 `WorkArea` 自动缩小」，两者都涉及 `rememberWindowSize` 回写口径，见 §9 第 3 项（推荐本期不做）。

### 2.4 打开时摆位的完整流程

**现状**：所有「打开设置」的入口最后都调到 `main.go` 的 `show()`——托盘右键菜单的「设置」、应用菜单的 `Cmd+,`、命令面板的「设置」命令（`commands.go`）、`cubbix://settings` 与 CLI 的 `settings`（`cli_server.go` 的 `runURL`）、`mygo.App.OnActivate` 的激活回调；`show()` 现在是 `visibility(true)` → `window.Show()` → `window.Focus()`。

改成：

```go
// show opens the settings window where this display remembers it.
func (a *application) show() {
	if a.window == nil {
		return
	}
	if !a.window.IsVisible() {
		a.placeSettingsWindow()
	}
	a.visibility(true)
	a.window.Show()
	a.window.Focus()
}
```

`placeSettingsWindow` 的步骤：

1. `displays := a.displays()`（§6 的 seam，生产指向 `mygo.Screen.Displays`）。
2. `display := a.settingsDisplay(displays)`（§2.1 的两种方式）；`display.ID == 0`（拿不到任何显示器，正常不会发生）就直接返回，不摆位，窗口留在系统给的位置。
3. `width, height := a.window.Size()`（当前外框；用户改过尺寸也以窗口为准，不必再读配置）。
4. 取该屏的记录，`seat, ok := seatTable{&a.config.WindowPositions}.lookup(display)`，有就传指针、没有传 `nil`。
5. `p := screenPlacement(display, remembered, screenSize{Width: width, Height: height})`。
6. `a.window.SetPosition(p.X, p.Y)`。

要点：

- **只在窗口隐藏时摆位**（第 3 行 `IsVisible()`）。用户点「设置」时窗口已经在前台，重复摆位等于把它从用户眼前搬走。
- 摆位在 `Show()` 之前，窗口不会先出现在旧位置。
- 摆位**不写配置**（005 §4.2 的同一规则：只是打开不该改配置，否则显示器临时变化会覆盖用户的位置）。
- 摆位不发通知、不弹提示（002 的规则：有可见结果就不要多一条提示）。

### 2.5 已经打开时再触发「打开」

**结论（推荐）：保持原位，不跳到别的屏幕。**

| 场景 | 行为 |
| --- | --- |
| 窗口已可见，再执行「设置」/`Cmd+,` | `IsVisible()` 为真 → 不摆位；`Show()` 只把已有窗口提到最前，`Focus()` 给它键盘（现状如此） |
| 窗口最小化（`DisableMinimize` 未设，可以最小化） | 最小化的窗口在 `IsVisible()` 上仍算可见（**推断**），所以也不摆位；`Show()` 是否顺带取消最小化**未实测**，本期不改，验收时记录实际表现 |
| 窗口隐藏后再次打开 | 按 §2.4 摆位，可能落在另一块屏（这就是「跟随鼠标」） |
| 在设置里把方式从「固定屏幕」改成「跟随鼠标」，或改选另一块屏 | **不搬窗口**（同 §2.4 的规则）；下一次打开才生效。设置项只存选择，不改当前窗口位置 |
| 用户把窗口拖到别的屏 | 按松手后的实际位置记到那块屏（§2.9）；「固定屏幕」的选择**不**跟着变——那是用户明确选定的，不该被一次拖动改写 |

为什么不做「已打开也跳过去」：窗口在前台时用户正在里面改设置，把窗口搬到另一块屏等于打断；而且「跟随鼠标」真要做到「跳」，就得跟着指针一路搬，那是另一个功能（面板式跟随），不是本次需求。

### 2.6 固定的那块屏幕不在时怎么退回

**结论（推荐）：退回系统主屏（菜单栏所在的那块）。**

匹配顺序（`settingsDisplay`，固定方式）：

1. `Display.ID == config.WindowDisplayID` 的屏（正常路径）。
2. 名称与分辨率都等于 `config.WindowDisplay` + `config.WindowDisplaySize` 的屏（ID 变了、屏还在）。
3. 名称相等、分辨率不等，或分辨率相等、名称不等，且**只有一块**候选（换语言、换分辨率后的兜底）。
4. 系统主屏：`Primary` 为真的那块（`mygo@v0.6.2/modules.go` 的 `ScreenModule.PrimaryDisplay`；`internal/darwin/system.go` 的 `Displays` 把 `screens` 的第 0 个标成 `Primary`，也就是菜单栏所在屏）。
5. `Displays()` 为空或没有 `Primary` 时，用鼠标所在屏（与「跟随鼠标」同一判据），再不行放弃摆位（保持窗口当前位置）。

为什么是主屏而不是鼠标所在屏：

- 「固定屏幕」的语义是**位置确定**。用户拔掉外接屏后，主屏是系统里唯一稳定、可预期的答案；退回鼠标所在屏会让同一个设置在两次打开之间给出不同结果。
- 副屏没接时「鼠标所在屏」几乎总是内建屏，实际结果一样，但主屏这条规则不需要看指针。

「屏幕不在」不等于「显示器 ID 变了」：§3 会把这两种情况分开处理——**屏还在、ID 变了**时窗口仍开在那块屏上（靠名称 + 分辨率找回），只是它原来的位置记录找不到了，于是居中（这是可接受的降级，用户再拖一次就重新记住）。

### 2.7 显示器拔插与分辨率变化

`mygo.Screen.OnDisplaysChanged` 在「显示器增删或分辨率变化」时回调（`mygo@v0.6.2/modules.go`，注释即此意），`main.go` 的 `ready` 已经接了：

```go
mygo.Screen.OnDisplaysChanged(func() {
	mygo.RunOnMain(a.paletteDisplaysChanged)
})
```

本期把回调收成一个 `a.displaysChanged()`：命令面板照旧（`paletteDisplaysChanged` 的现有逻辑）、窗口摆位、`invalidateWindow()`（§7）。

| 情形 | 设置窗口可见 | 设置窗口隐藏 |
| --- | --- | --- |
| 分辨率变小、Dock 变大、屏幕旋转导致 `WorkArea` 变化，窗口所在屏仍在 | 夹回该屏 `WorkArea`（`screenPlacement` 的第 4 步）；不换屏、不居中 | 什么都不做 |
| 窗口所在屏被拔掉 | 先按 §2.1 重新选屏（固定方式得到退回屏，跟随方式得到鼠标所在屏），再用那块屏的记录（有就还原、没有就居中）搬过去 | 什么都不做 |
| 插上一块屏 | 不动窗口（用户没要求搬） | 什么都不做 |
| 摆位期间显示器又变化 | 每次回调都按当时的 `Display` 列表重算，无状态残留 | —— |

要点：

- **不要**在显示器变化时写配置：窗口被夹回的临时位置不该覆盖用户记住的位置（005 §4.2 的同一条）。
- **不要**在跟随鼠标方式下按指针变化实时搬窗口：`OnDisplaysChanged` 不是指针移动事件，摆位只在打开与上面两行发生。
- 回调在主线程上执行（`feedback.go` 里同一个 seam 的注释写明「The callback comes from the main thread」，本处也一样），摆位与 `SetPosition` 都可以直接做；`paletteDisplaysChanged` 已经是这个前提。

### 2.8 全屏 Space

事实：

- 设置窗口创建时带 `DisableFullScreen: true`（`main.go` 的 `createSettingsWindow`），MyGo 因此置 `Fullscreenable: false`（`mygo@v0.6.2/window.go` 的 `platformOptions`），于是 `collectionBehavior` 取 `collectionFullScreenNone`（`internal/darwin/window.go` 的 `createWindow`）——它自己不会进入全屏 Space。
- 摆位只依赖显示器的 `WorkArea`，与 Space 无关；本文不引入任何 Space 判断。
- 「应用处于 `Regular` 时能否出现在别的应用的全屏 Space 上」在 003 §6.4 第 6 项已记为**未证实**，设置窗口同样是 `Regular`（`visibility(true)` 把激活策略设成 `Regular`），本期沿用同一口径，不改、不为此增加特判。

需要维护者实测的三点（§8.3）：目标屏正显示别人的全屏应用时窗口出现在哪；系统设置里「显示器有自己的 Space」开着与关掉时的差异；窗口在 Space 之间切换后是否还在记住的位置。

不做的事：不为「全屏时换一块屏」写特判，也不用 `setCollectionBehavior:` 的 `moveToActiveSpace` 一类私有行为去抢 Space——那会让窗口在切换 Space 时自己跳，与 §2.5「不跳」冲突。

### 2.9 什么时候写位置

| 时机 | 写不写 |
| --- | --- |
| 用户拖动窗口（`DragWindow` 拖动侧栏或内容空白处，`main.go` 的 `view`） | **不立即写**：`Window.OnMove`（`mygo@v0.6.2/window.go`，`internal/darwin/window.go` 的 `windowDidMove:` → `Moved()`）只置脏标记。拖动中每帧写盘会反复 `save()` 并 `invalidateWindow()`（`main.go` 的 `save`），代价太大 |
| 窗口隐藏（`hide()`：`Cmd+W`、Esc、关闭按钮、`OnClose`） | **写**：先 `rememberWindowPlace()` 再 `rememberWindowSize()`（`hide()` 现在只调后者） |
| 退出应用（`beforeQuit`） | **写**：窗口可能一直可见到退出，`beforeQuit` 现在不调 `rememberWindowSize`，本期补上 `rememberWindowPlace()`（尺寸不补：`OnResize` 已经逐次写过） |
| 打开窗口、夹回、显示器变化 | **不写** |
| 切换方式、改选屏幕 | **不写位置**（只写选择本身） |

`rememberWindowPlace` 的行为：

```go
// rememberWindowPlace stores where the settings window sits on its display.
func (a *application) rememberWindowPlace() {
	if a.window == nil || !a.windowMoved {
		return
	}
	a.windowMoved = false
	display := a.windowDisplay()
	x, y := a.window.Position()
	seatTable{&a.config.WindowPositions}.store(display, screenPoint{X: x, Y: y})
	a.save()
}
```

- 只在 `OnMove` 之后置脏、且只在脏的时候写，避免每次隐藏都写盘。
- 自己 `SetPosition` 摆位时也会触发 `windowDidMove:` → `OnMove`，所以摆位前后要吞掉这一次：`placeSettingsWindow` 里 `a.placing = true` → `SetPosition` → 下一帧或同步复位（`OnMove` 回调里 `if a.placing { return }`）。MyGo 的 `Moved` 是不是同步发出**未实测**，实现时按「同步发出」写，若实测是异步的，就在 `SetPosition` 之后用一个 `generation` 计数比对，不要用固定次数的忽略。
- 位置写到「窗口外框中心/最大重叠所在的那块屏」，判据与 005 拖动松手一致（`displayMatching`）。

## 3. 显示器怎么标识

### 3.1 `Display.ID` 是什么

| 事实 | 依据 |
| --- | --- |
| `Display.ID` 在 macOS 上就是 `NSScreenNumber`，也就是 `CGDirectDisplayID` | `mygo@v0.6.2/internal/darwin/system.go` 的 `screen.Displays`：`deviceDescription` 里取 `NSScreenNumber`，`unsignedIntValue` 后存进 `platform.Display.ID`；`modules.go` 的 `Display` 把它原样暴露成 `ID int64`，没有任何序列号或持久标识字段 |
| 它是**运行时显示器编号**，不是序列号、不是显示器名 | 同上；005 §4.1 已按同一口径写过「公开配置里不出现设备信息」 |
| `Display.Label` 来自 `localizedName`（macOS 10.15+），可能为空 | 同文件 `Displays` 里 `if respondsTo(s, "localizedName")` 才填；README 说明合盖功能要求 macOS 13+，所以实际环境里可用 |
| `Display.Primary` = `NSScreen.screens` 的第 0 个（菜单栏所在屏），`Displays()` 也保证主屏在前 | 同文件 `Primary: i == 0`；`modules.go` 的 `Displays` 注释「the primary one comes first」 |
| `Display.Bounds` / `WorkArea` 来自 `frame` / `visibleFrame`，是屏幕坐标（DIP，原点在主屏左上角） | 同文件；`mygo@v0.6.2/window.go` 的 `Rectangle` 注释即此意；`WorkArea` 已排除菜单栏、Dock |

### 3.2 它在重启、换线后是否稳定

**结论：无法在本机静态查证，按「可能变」设计。**

- 不能查证的直接原因：判定稳定性要重启、换线、换扩展坞各测一次，而本轮不运行 Cubbix（工作单规则），也不能替维护者重启机器。
- 已知口径（沿用 005 §4.3 的记录）：`CGDirectDisplayID` 在同一显示器、同一接口的连续开机之间通常稳定；换接口、接扩展坞、显示器休眠后重新枚举、改变显示器连接顺序后可能变。005 已经据此要求把「找不到键 → 用默认位置」当**正常路径**。
- 因此本设计的判据：**任何依赖 `Display.ID` 的查找都必须有兜底，且兜底失败等于「回到默认位置」，不报错、不提示。**

需要维护者实测的最小集合（§8.3）：重启一次后设置窗口是否还在上次那块屏的同一位置；把外接屏换到另一个接口后再打开；带扩展坞与不带扩展坞各一次。

### 3.3 兜底：屏还在、ID 变了

分两类，处理不同：

| 数据 | 键 | ID 变了会怎样 | 兜底 |
| --- | --- | --- | --- |
| 窗口位置（`window_positions`、`json_positions`） | `Display.ID` | 找不到该屏的记录 | **不兜底**：按「没有记录」居中。用户拖一次即重新记住。理由：位置是低价值、一次操作可重建的数据，为它引入名称匹配不值得（005 对命令面板也是这个口径） |
| 「固定屏幕」的选择（`window_display` 三项） | `window_display_id` + 名称 + 分辨率 | 按名称 + 分辨率找回同一块屏 | §2.6 的四级匹配 |

「固定屏幕」的三项存法：

```toml
window_placement = "display"
window_display_id = 732561
window_display = "内建视网膜显示器"   # Display.Label 的当时值
window_display_size = "1512x982"      # Display.Bounds 的宽 × 高（DIP）
```

| 字段 | 用途 | 备注 |
| --- | --- | --- |
| `window_display_id` | 首选匹配 | 每次打开匹配成功后顺手更新成当前 ID（屏没变、只是重新枚举过） |
| `window_display` | `ID` 失效时的主判据 | `localizedName` 是**本地化**的，切换系统语言后会变，所以不能单独用 |
| `window_display_size` | 消歧与第二判据 | 分辨率不同一定不是同一块屏；两块同型号同分辨率的屏无法区分，取 `Displays()` 里靠前的那块，属已知限制（§9 第 8 项） |

是否要把设备名称写进配置，和 005 的口径有轻微冲突（005 的理由是「公开配置里不出现设备信息」）。本设计的取舍：**位置表里一个设备名都不写**，只有用户在设置里明确选过「固定屏幕」时才写一行名称，且文档、Issue、截图里一律用「外接显示器一号」这类泛称。若维护者不接受任何设备名进配置，改用 §9 第 8 项的备选（排列坐标），行为规则不变，只是匹配更脆。

### 3.4 选项列表怎么生成与显示

| 项 | 做法 |
| --- | --- |
| 数据源 | `mygo.Screen.Displays()`，顺序即 `NSScreen.screens` 的顺序（主屏在前） |
| 显示文本 | `Display.Label`；为空或只有空白时退成 `fmt.Sprintf("%d × %d", Bounds.Width, Bounds.Height)`（纯数字与乘号，不需要新文案） |
| 是否标注主屏 | **不标**。主屏在列表里排第一，加「主屏」后缀会让同一行文案随显示器增减变长；用户靠名称就够选 |
| 顺序 | 与系统一致（主屏在前），不排序、不按名称排——排序会让同一个列表在两次打开之间改变顺序 |
| 选择存什么 | 存 ID + 名称 + 分辨率三项（§3.3），不存列表下标：下标在拔插后会指向另一块屏 |
| 选中态显示什么 | 显示**当前实际会用到的那块屏**（§2.6 的第 1～4 级结果）。选中的屏不在时，这里显示退回屏的名称，并在行尾加 `triangle-alert` + tooltip `WindowDisplayMissing`；用户选任意一块屏就改写存的选择 |
| 屏幕多于 6 块 | 下拉出现滚动（`SelectParts` 的 popup 是否自带滚动**未实测**）；不另做搜索 |

## 4. JSON 窗口

### 4.1 结论（推荐）：同一套规则，不提供「固定屏幕」

| 项 | 设置窗口 | JSON 窗口（推荐） |
| --- | --- | --- |
| 选屏 | 可选跟随鼠标 / 固定屏幕 | **只跟随鼠标** |
| 位置记忆 | `window_positions`，按屏 | `json_positions`，按屏 |
| 尺寸记忆 | `window_width` / `window_height`（全局） | `json_width` / `json_height`（全局，现状） |
| 已打开时 | 不搬 | 不搬（每个窗口各自记，互不影响） |
| 显示器变化 | 可见时夹回、所在屏消失时搬走 | 同上，逐个窗口处理 |

为什么 JSON 不提供「固定屏幕」：JSON 窗口是工具窗口，可以同时开多个，而且它的入口是快捷键（`⌃⌥⌘J`）——用户按下时**眼睛在哪块屏上就在哪块屏上**，跟随鼠标是正确的默认。给工具窗口加「固定屏幕」会引出「多个窗口同时固定到一块屏如何错开」的次级问题，收益为零。

### 4.2 现状与要改的地方

现状（`json_app.go`）：`buildJSONWindow` 创建窗口时不给 `X`/`Y`，`Center` 因此为真（§2.2 的同一机制）→ **每个新 JSON 窗口都在主屏正中创建，多个窗口正好叠在一起**（源码推论：没有任何其它摆位调用）。`focusJSONWindow` 只 `Show()` + `Focus()`；`OnResize` 写回 `json_width`/`json_height`；`OnClosed` → `removeJSONDocument`。

要改：

1. `newJSONWindow` / `newJSONWindowBlank` / `openJSONText` 都经过 `createJSONWindow`（seam）→ `buildJSONWindow`，在 `buildJSONWindow` 末尾、`LoadURL` 之前按 §4.3 摆位（窗口此时 `Hidden`，摆位不影响首帧）。
2. `OnMove` 置脏（`d.moved = true`，摆位时用 `d.placing` 吞掉自己的移动）。
3. `removeJSONDocument`（`OnClosed` 与 `destroyJSON` 都会走到）与 `beforeQuit` 里写位置。
4. 显示器变化时对每个可见 JSON 窗口做 §2.7 的处理。

### 4.3 摆位规则

1. `display = DisplayNearestPoint(CursorScreenPoint())`。
2. `seat := seatTable{&a.config.JSONPositions}.lookup(display)`；有就还原，没有就居中（§2.2）。
3. **多开错开**：若同一轮运行里已经开过 n 个（n > 0）JSON 窗口，把位置往右下推 `n × Space24`，最多 4 级，然后夹回工作区。理由：现在多开完全重叠（§4.2），错开 24 是 macOS 自己叠窗口的量级，够看出「开了两个」，又不会把窗口推到屏幕外。
4. 尺寸：现有 `json_width` / `json_height`（≥ `SizeJSONEmptyWidth` / `SizeJSONEmptyHeight` 才用，否则用默认尺寸），与位置一样只夹位置、不改尺寸（§2.3 同一口径）。

已知限制：把 JSON 窗口从大屏拖到小屏后，尺寸可能超出工作区；用户自己拉一次即可（`OnResize` 会写回）。

### 5.3 只有一块显示器时

**结论（推荐）：整组隐藏（第 4、5 行都不画）。**

理由：

1. 一块屏时「跟随鼠标」与「固定屏幕」结果完全相同，控件是无意义的二选一；AGENTS 的低信息密度规则要求正常状态不写说明文字，一条解释「为什么它没差别」的灰字会一直挂着。
2. 隐藏不损失能力：位置记忆照样生效（窗口还是开在上次的位置），用户感知不到差别。
3. 一块屏时「退回主屏」这条规则也永远命中同一块屏，隐藏后不必解释退回。

备选（§9 第 6 项）：第 4 行保留但 `Disabled(true).Opacity(t.OpacityDisabled)`，第 5 行换成一句 ② 级说明「只连接了一块屏幕，窗口跟随鼠标」。代价是通用页从 348 长到 396 以上，且要为新文案加键。推荐隐藏。

检测方式：视图里用 `len(a.displays()) < 2`。不要在拖动或打开时另外判断；显示器增减已经有 `Screen.OnDisplaysChanged`，但现在的回调只处理命令面板（`paletteDisplaysChanged`），不重画设置页，本期在回调里补一句 `a.invalidateWindow()`（§7），视图下一帧按当时的 `Displays()` 重算。

### 6.2 新文件 `screen_placement.go` 的接口

```go
package main

import "github.com/egoist/mygo"

// screenPoint is a position in screen DIPs: the space whose origin is the
// main display's top-left corner.
type screenPoint struct{ X, Y int }

// screenSize is a window's outer size in DIPs.
type screenSize struct{ Width, Height int }

// seatKey is the config key of a display: its runtime display number, never a
// serial number or a name.
func seatKey(id int64) string

// seatOffset turns a window position into the offset stored for a display.
func seatOffset(p screenPoint, work mygo.Rectangle) seat

// seatPoint turns a stored offset back into a screen position.
func seatPoint(s seat, work mygo.Rectangle) screenPoint

// screenRect is a window's rectangle at a position.
func screenRect(p screenPoint, size screenSize) mygo.Rectangle

// clampToWorkArea keeps a window inside the work area. A work area too small
// for it leaves that axis where the caller put it.
func clampToWorkArea(p screenPoint, size screenSize, work mygo.Rectangle) screenPoint

// centeredPoint centres a window in a work area.
func centeredPoint(display mygo.Display, size screenSize) screenPoint

// displayMatching returns the display overlapping r the most.
func displayMatching(displays []mygo.Display, r mygo.Rectangle) mygo.Display

// displayNearest returns the display closest to p.
func displayNearest(displays []mygo.Display, p mygo.Point) mygo.Display

// screenPlacement is where a window of a size opens on a display: at the
// remembered offset when one fits, centred otherwise, and always inside the
// work area.
func screenPlacement(display mygo.Display, remembered *seat, size screenSize) screenPoint

// seatTable is one per-display position table of the config: the palette's,
// the settings window's and the JSON windows' each keep one.
type seatTable struct{ seats *map[string]seat }

func (t seatTable) lookup(display mygo.Display) (seat, bool)
func (t seatTable) store(display mygo.Display, p screenPoint) // makes the map when nil
func (t seatTable) forget(display mygo.Display)
```

`screenPlacement` 的语义（对应 §2.2 的 1～4 步，**唯一**需要单测的摆位函数）：

```go
func screenPlacement(display mygo.Display, remembered *seat, size screenSize) screenPoint {
	p := centeredPoint(display, size)
	if remembered != nil {
		at := seatPoint(*remembered, display.WorkArea)
		if display.WorkArea.Width >= size.Width {
			p.X = at.X
		}
		if display.WorkArea.Height >= size.Height {
			p.Y = at.Y
		}
	}
	return clampToWorkArea(p, size, display.WorkArea)
}
```

命令面板的 `placePalette` 改用它自己的默认位置（居中 + `SizePaletteTopOffset`），其余步骤与这里一致；`paletteClamp` 换成 `clampToWorkArea`，行为不变（005 §4.3 第 2 版的语义）。
