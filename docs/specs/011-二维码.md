## 1. 场景与流程

### 1.1 场景

四类：把电脑上的链接送到手机（每天数次）；临时分享一段短文本（每周数次）；把二维码拖到别的应用或存成 PNG（每周数次）；脚本里生成一张码（低频）。频率低、功能单一，所以一律偏向「少占界面、少加状态」：不做历史、不做颜色/尺寸/纠错等级设置、不做 logo、不做批量。

### 1.2 主流程

```text
⌃⌥⌘R → beginQRSelection（AX 读取 ≤ 200 ms，先于显示与激活）
  ├─ 有选中文本 → openQRText(选中文本)
  ├─ 无选中但剪贴板是 http/https 网址 → openQRText(剪贴板文本)
  └─ 都没有 → openQRText("")
openQRText → hideMenubarPanel / hidePalette → 复用或新建工具窗口 → 显示并聚焦输入
输入变化 → 200 ms 防抖 → 后台编码 → 主线程替换位图（代次不符则丢弃）
工具栏：置顶 / 复制图片（PNG 进剪贴板）/ 存 PNG（Dialog.Save）
二维码区域：直接拖出（transfer.PNG）
Esc / ⌘W / 红绿灯 / 关模块 → 保存几何，销毁窗口，作废在途编码
```

`openQRText` 是 UI 唯一入口；快捷键、卡片面板、命令面板都调用它。CLI 走自己的路径，不打开窗口（§5）。

### 1.3 内容来源的三条规则

1. **选中文字优先**：复用 `translate_selection.go` 的 `a.captureSelection()`（`selectionReader` 接口、200 ms 总预算、`a.selectionReading` 单飞、迟到结果按代次丢弃）。QR 自己维护 `qrSelectionGeneration`，不复用翻译的代次。
2. **剪贴板只在「没有选中文字」且「是网址」时预填**：`mygo.Clipboard.ReadText()` 取纯文本（图片读不到）。判定：`strings.TrimSpace` 后以 `http://` / `https://`（大小写不敏感）开头，且 `net/url` 的 `Parse` 得到非空 `Host`；超过 2048 字节不预填。普通句子、代码、数字一律**不预填**，避免把无关内容变成二维码。
3. **其它入口不读剪贴板**：卡片面板、命令面板、CLI 只带自己的参数（与 010 §8 第 11 行同一取舍）。

无权限时的引导沿用 010 §3.5：不弹系统框，输入框下沿一行灰字 + 「去设置」文字按钮，每次启动最多一次，`accessibilitySettingsOpened` 与翻译共用。

## 2. 技术选型

### 2.1 候选库对照

三个候选都读过源码（版本见下），`rsc.io/qr` 与 `skip2/go-qrcode` 还在仓库外的临时目录里实际生成并解码过。

| 项 | `rsc.io/qr` v0.2.0 | `skip2/go-qrcode` 伪版本 2020-06-17 | `piglig/go-qr/v2` v2.7.0 |
| --- | --- | --- | --- |
| 许可 / 依赖 | BSD-3-Clause；仅标准库 | MIT；仅标准库 | MIT；`go.mod` 只有 `go 1.23`，无 require |
| 维护 | 最后提交 2022-04-17（`pushed_at` 2022-10-08） | master 顶端即 2020-06-17 那次提交，无 tag，35 个 open issue（`pushed_at` 2024-03-01 来自未合并分支） | 提交到 2026-10-19，tag 到 v2.7.0，提交集中在单一维护者 |
| 纠错等级 | L/M/Q/H | Low/Medium/High/Highest | ECCLow…High，可按版本余量自动升级（可关） |
| 掩码 | **不做选择**，`qr.go` 留着 `TODO: Pick appropriate mask`，始终掩码 0 | 遍历 8 个掩码按惩罚分选最优 | 同左（可用 `WithMask` 固定） |
| 中文 | 字节模式写原始 UTF-8，无 ECI | 同左 | 可选 `WithUTF8ECI()`；默认还会用 Kanji（Shift-JIS）压缩 CJK |
| 容量（字节模式） | 2953 / 2331 / 1663 / 1273（L/M/Q/H，实测） | 2953 / 2331（实测） | 2331（M、不 boost，实测） |
| 渲染 | `Image().At()` 忽略静区与缩放（625 个模块里 312 个与 `Black()` 不符，角像素为黑），`PNG()` 在 `Scale=1` 时 `panic: invalid flate repeat` | `Image(size)` 用浮点比例映射模块，非整数倍会糊；静区随版本变 | `Image(WithScale, WithQuietZone)` / `WritePNG` / `String()`（`█▀▄` 半块）/ `SVG` 都按整数模块绘制 |
| 解码 / 超容量 | 无 / `errors.New("text too long…")` | 无（自带解码测试要外部 `zbarimg`）/ `errors.New("content too long…")` | **有** `Decode(img, opts...) (*DecodeResult, error)`（v2 里没有 `DecodeDetailed`，旧名已并入 `Decode` 与 `DecodedSegment`），纯 Go 零依赖 / 哨兵 `ErrDataTooLong`，可 `errors.Is` |

### 2.2 推荐

**采用 `github.com/piglig/go-qr/v2` v2.7.0**：同一个依赖既能编码又能解码，§7 的「生成后解码比对」不用再引第二个库；按最低惩罚选掩码（`rsc.io/qr` 固定掩码 0，长文本上更容易扫不动）；`WithQuietZone` / `WithScale` / `WithUTF8ECI` / `WithSimpleSegmentation` / `WithoutECCBoost` 正好是需要的那几个旋钮；自带 `String()` / `WriteText()` 的 `█▀▄` 半块输出，CLI 的终端渲染不用自己写（§5）。

风险与对策：库较新、单维护者、star 数在两位数到三位数之间。对策是**固定版本**（`go.mod` 写 `v2.7.0`，不用 `latest`），并且 §7.1 的往返测试会解码自己生成的图 —— 真出问题会在 selftest 里立刻暴露，而不是等到扫码失败。

> 事实边界：star 数与提交时间取自仓库页面（调研时），会随时间变化；「渲染不一致」「掩码 0」「panic」三条是读源码 + 实跑确认的。

### 2.3 一次性的生成/解码实验（仓库外，程序已删除）

用 `CGO_ENABLED=0` 的临时模块，把三个库都生成一遍，用两个独立解码器（`piglig` 自带解码器、`makiuchi-d/gozxing` v0.1.1 的 `qrcode.QRCodeReader`）读回来：

- **解码往返**：124 条随机语料（ASCII + 中文 + emoji，3–300 字符），`piglig` 自解码 124/124，`gozxing` 的 `PURE_BARCODE` 模式 124/124；`gozxing` 普通模式 121/124，3 条失败都在 version ≥ 8 的长符号上，是解码器的定位问题而非符号本身。
- **`rsc.io/qr` 的两个缺陷**：`PNG()` 在 `Scale=1` 时 4 条语料全部 panic；`Image().At()` 与 `Black()` 在 625 个模块里 313 个不符（角像素为黑）。
- **容量（M、字节模式）**：ASCII 2331 字节；中文 776 字（2328 字节）；多 1 字节即 `ErrDataTooLong`。纯数字 5596 位、全大写 3391 字符（实测）；非 ASCII 的 2328、2329、2330 通过，2331 失败。所以 2331 是字节模式的容量，不是一切内容的上限。
- **版本与模块数**：19 B → v2/25；49 B → v4/33；300 B → v13/69；2331 B → v40/177。
- **速度**：短 URL 编码约 12 µs；2320 字节约 241 µs；编码加 `PNG` scale 4 约 1.1 ms。
- **PNG 体积**：v40、静区 4：4 px/模块 2746 B、10 px/模块 5696 B、16 px/模块 10557 B。边长 `(177+8)×16 = 2960`，v4 为 `(33+8)×16 = 656`。

实验只用于选型，不进仓库，也不成为测试依赖。

### 2.4 生成参数（固定，不进设置）

```go
const (
    qrQuietZone      = 4  // 静区，模块数（ISO/IEC 18004 要求 ≥ 4）
    qrExportModule   = 16 // 导出 PNG 时每个模块的像素数
)

// internal/qr 里唯一的编码入口。库 import 一律加别名（如 qrlib），
// 否则和 internal/qr 这个包装包同名，读代码时分不清调用的是哪一个。
qrlib.Encode(text, qrlib.WithECC(qrlib.ECCMedium), qrlib.WithoutECCBoost(),
    qrlib.WithSimpleSegmentation(), qrlib.WithUTF8ECI())
```

`WithSimpleSegmentation()` 是库的「能装下全文的最紧凑单段」：纯数字走 numeric、字母数字走 alphanumeric、其余走 byte，不含 Kanji。`WithUTF8ECI()` 只在非 ASCII 时加 ECI 26，纯 ASCII 网址加不加这一项模块相同。默认的最优分段会把 Shift-JIS 表内的「漢字」编成 Kanji，所以这个选项确实必要。

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 纠错等级 | **M（15%）**，`WithoutECCBoost()` | 屏幕码与打印码都够用。不 boost 是为了让「同一段文本 → 同一张图」，测试与文档里的模块数、容量都可复现；boost 会让等级随内容长度跳变，排查困难 |
| 分段 | `WithSimpleSegmentation()` + `WithUTF8ECI()` | 单段字节模式，CJK 不落进 Kanji（Shift-JIS）模式，容量按 UTF-8 字节算，规则单一；ECI 显式声明 UTF-8，扫出来的字符集不靠猜 |
| 掩码 / 静区 | 库自动选最低惩罚 / 4 模块 | 都不暴露。静区低于 4 实测仍能解，但手机在复杂背景上会失败 |
| 屏幕渲染 | `side = modules + 8`（含静区）；`px = max(1, floor(box × scale / side))`；位图像素边长 `side × px`；`ui.Image` 的 DIP 边长 = 位图像素边长 / `scale` | 模块边缘落在整像素上才不糊；`box` 是外层白底的 DIP 边长（≤ `SizeQRCodeMax` 320），位图在白底里居中、不被 `Fit(Contain)` 拉伸。`scale` 取窗口所在屏的 `ScaleFactor`；换屏或缩放变化时重算位图（不必重新编码）。`Pixelated()` 不能代替这个公式 |
| 导出 PNG | 16 px/模块 | v4 约 656 px、v40 约 2960 px，单一规则。v40、静区 4 实测：scale 4 为 2746 字节、scale 10 为 5696 字节、scale 16 为 10557 字节 |
| 超容量 | **不截断**，报错 | 截断后的网址是错的二维码，比不生成更糟。2331 字节是**字节模式**的容量（中文约 776 字；纯数字与全大写能装更多），超出后窗口显示「内容太长，二维码放不下」（§4.3），输入保留。判定只走 `errors.Is(err, ErrDataTooLong)`，不本地预判长度 |

## 4. 界面

### 4.1 结构

```text
┌──────────────────────────────────────────────┐
│ 红绿灯  二维码                  置顶 复制 存 │
├──────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────┐ │
│ │ https://example.com/orders/2026          │ │ ← 灰底多行输入，固定 72 高
│ └──────────────────────────────────────────┘ │
│          ┌────────────────────┐              │
│          │    （二维码）      │              │ ← 白底黑码，居中，
│          └────────────────────┘              │   可拖动，最长边 320
└──────────────────────────────────────────────┘
```

| 元素 | 规格 |
| --- | --- |
| 窗口 | 隐藏标题栏、红绿灯偏移 `Space12` / `Space16`、默认 480 × 520、最小 480 × 440、禁全屏、背景 `ColorCard` |
| 工具栏 | 高 `SizeJSONToolbarHeight` 44、padding 8/12/8/`SizeJSONTitleInset` 80；标题区 `DragWindow()`；右侧三个 `SizeIconButton` 28 图标按钮（`pin`、`copy`、`download`），图标 16、`ColorTextSecondary`、`RadiusControl`、悬停 `ColorControlHover` |
| 输入 | `ColorControl` 灰底、`RadiusControl`、左右 `Space12`、固定高 72（约 3 行，超出内部滚动）、`FontSizeBody` |
| 二维码 | 外层白底方块（`RadiusCard`、`#FFFFFF`）内嵌位图，`#000000` / `#FFFFFF` 是**唯一写死的两个颜色**（与 JSON 语法色同属「内容本身」的例外，不进 Token）；最长边 `SizeQRCodeMax` 320，随窗口缩小、居中；位图按 §2.4 的整数设备像素生成，DIP 边长 = 位图像素边长 / `scale`，**不拉伸**；静区已含在位图里，外层白底让静区在深色主题下也成立。白底里的提示文字用浅色主题的 Token：深色主题的灰写在白底上读不清 |
| 二维码交互 | 整块是拖出源（`DragDataFrom` + `transfer.PNG`），按下并移动几个 DIP 才起拖；单击不做事（避免误触） |
| 位置与焦点 | 首次鼠标屏居中；关闭时按屏存 x/y/width/height；已有实例只前置；屏幕变化按 008 夹回；Esc / ⌘W / 红绿灯 / 关模块都销毁窗口并作废在途编码；**所有状态失焦保留**；显式唤出聚焦输入 |

### 4.2 深浅色

二维码本身**始终黑码白底**：深色主题下外层白底方块必须保持 `#FFFFFF`，不跟随 `ColorCard`。理由是可扫性——反色码在部分扫码器（尤其旧版 iOS 与第三方 App）里读不出来。其余元素（工具栏、输入框、提示文字）全部走现有 Token，深色主题正常变暗。

### 4.3 状态

`qrPhase` 是唯一的主状态字段（`qrEmpty` / `qrReady` / `qrTooLong` / `qrFailed`），`denied`、`pending` 是叠加标记：

| 状态 | 输入区 | 二维码区 | 触发 |
| --- | --- | --- | --- |
| `empty` | 聚焦，placeholder `QRInputPlaceholder` | 白底方块 + 一行 12 号灰字 `QREmpty`（块高 44） | 打开且没有内容 |
| `ready` | 显示内容 | 白底黑码，居中 | 编码成功 |
| `tooLong` | 内容保留、可编辑 | `triangle-alert` + `QRTooLong` + 一行 `QRTooLongHint`（只说字节模式的容量，不当成一切内容的上限） | `errors.Is(err, qrlib.ErrDataTooLong)` |
| `failed` | 内容保留 | `triangle-alert` + `QRFailed` | 其它编码错误（理论上只有内存不足） |
| `denied`（叠加） | 聚焦 | 输入框下沿一行 `QRSelectionDenied` + 文字按钮 `QRGrantAccess` | 快捷键取词因权限失败，每次启动一次；用二维码自己的标记 `qrSelectionHintShown`，不碰翻译的 `translateSelectionHintShown` |

错误文案只来自资源键，**不显示库返回的原始错误文本**（里面带版本号与容量数字，用户看不懂；容量数字由 `QRTooLong` 按 §2.4 的常量格式化）。

### 4.4 文案

全部进 `design/locales/zh-CN.json` 与 `en.json`（各 374 键，本规格加 17 个 → 391）。

| --- | --- | --- |

| `QRPageDesc` | 把一段文字或网址变成二维码，可复制、保存或直接拖出 | Turns text or a link into a QR code you can copy, save or drag out |

### 4.5 设置页「二维码」

第 7 页，侧栏插在「翻译」与「快捷键」之间：`通用 / 常亮 / JSON / 翻译 / 二维码 / 快捷键 / 关于`（`settingsNav` 的顺序是模块在前、全局在后）。

只有两行：头部卡片（图标 `qr-code`、名称 `QR`、说明 `QRPageDesc`、模块总开关）与快捷键行（`QRShortcutLabel` + 复用 `shortcutSettingsRow` 的录制器，③ 级）。**没有「设置」分组** —— 纠错等级、静区、导出尺寸、掩码都写死在 §2.4，不暴露。

## 5. CLI

### 5.1 命令

```
cubbix qr [TEXT] [--text STR | --file PATH | -] [--png PATH] [--json] [--no-launch] [--timeout DURATION]
```

| 项 | 规定 |
| --- | --- |
| 输入 | `TEXT` / `--text` / `--file`（`-` 读标准输入）/ 管道，四者互斥，多于一个退出 2；显式空文本退出 2（不回退管道） |
| 校验 | 非空 UTF-8、无二进制控制字符（允许 `\n` `\r` `\t`）；超 `cli.MaxPayload` 退出 2；超二维码容量**不本地判**，由应用回 `QRTooLong`（退出 4）——容量与纠错等级绑定，规则只放一处 |
| 默认输出 | 终端 Unicode 半块字符画（`█` `▀` `▄` 与空格），两行模块合成一行，静区 **4**（与导出 PNG 一致）。由 CLI 在应用返回成功之后本地用 `internal/qr` 生成：`disabled` 与 `QRTooLong` 不画，否则本地先画会绕过 §6.4 的关闭拦截 |
| `--png PATH` | 写 PNG（16 px/模块、静区 4），不打印字符画；成功时 stdout 为空，退出 0；写文件失败退出 1 |
| `--json` | 一行 JSON：`{v,ok,code,message,qr:{version,ecc,modules,bytes,png}}`。`--json` 时 stdout **只有这一行元数据**，图像只写文件，`png` 若出现只是路径。**不含字符画**（v40 约 41 KB，远超 `MaxLine` 4096；图像本身 base64 后也超过 `MaxLine`，所以只能走文件） |
| 终端宽度 | 长内容可达 185 列，超过常见终端宽度会折行、扫不出来；help 里提示「宽内容用 `--png`」 |
| 退出码 | 沿用 006 §1.4：0 / 1 / 2 / 3 / 4（含 `disabled` 与 `QRTooLong`）/ 5 |
| 静音与启动 | `--notify` 是用法错误（退出 2），二维码从不弹提示；应用未运行默认后台拉起，`--no-launch` 退出 3 |
| 日志 | 只记 `code`，不记文本内容 |

**为什么字符画在 CLI 本地生成**：`internal/qr` 只依赖标准库与第三方纯 Go 库，`cmd/cubbix` 允许 import `internal/`（AGENTS「CLI 只 import 标准库与 `internal/`」）。这样不需要像 010 §5.5 那样为译文加响应正文帧：一次往返只拿元数据（几百字节），永远小于 `MaxLine`，协议改动最小。

**为什么还要问应用**：模块关闭要能拦住 CLI（`disabled`，退出 4），且版本号等元数据要和窗口里一致。所以 `qr` 仍是一个 action，只是响应很小。

### 5.2 协议增量

| 项 | 规定 |
| --- | --- |
| action | `qr`（`internal/cli/protocol.go` 加 `ActionQR`） |
| 请求 | 正文帧承载文本（`bytes > 0`），与 `json.new` / `translate` 同一套定长帧；`Request.Validate` 允许 `bytes`，拒绝 `arg` / `mode` / `follow` / `lid` / `blank` / `page` / `notify` |
| 响应 | `Result` 与 `Response` 各加 `QR *QRResult`，`Response.Result()` 一起拷贝，`cli_server.go` 手工组装 `cli.Response{...}` 的地方也要带上；`QRResult = {version, ecc, modules, bytes, png}`，**不带文本、不带像素**。顶层 `bytes` 保持 0，长度只放 `qr.bytes`：`internal/cli/client.go` 的 `readTranslationBody` 对非 `translate` 响应看到 `Bytes != 0` 或 `Translate != nil` 就报 `CodeInternal` |
| 版本与等待 | 不升 `Protocol`（加字段与加 action 都不算不兼容，006 §3.3 仍成立）；用默认 15 s（编码在毫秒级，不需要 010 的 70 s 特例） |

### 6.3 第六个快捷键槽

照 010 §2.5 的写法逐处加 `qr` 分支，一处不漏：`awake_view.go` 的 `shortcutSlots`、`shortcutSettingsRow`、`recordShortcut`、`slotError`、`clearSlotError`、`shortcutSlotEnabled`、`restoreShortcuts`（本身按 `shortcutSlots` 循环，不用改），以及 `awake_app.go` 的 `setSlotError`。

两条硬要求：

1. **`recordShortcut` 的 `default` 分支不得兜底写任何快捷键**（010 已改成显式 `case`，新增 `case "qr": a.config.QRShortcut = acc`，未知 target 什么都不写）。

### 6.4 模块关闭联动

`changeQREnabled` 照 `changeTranslateEnabled` 的顺序：`cancelShortcutRecording()`；与现值相等则只 `invalidateWindow()` 并返回；否则**先赋值** `a.config.QREnabled = target`；打开时 `registerQRShortcut()`（即 `registerSlot("qr", …)`）；关闭时才 `releaseOwnedShortcut("qr")` → `clearSlotError("qr")` → `closeQR()`（保存几何、作废编码、销毁窗口、`visibility(false)`）；最后 `save()` → `invalidateWindow()` → `refreshMenubarPanel()` → `invalidatePaletteAfterModuleChange()`。少了先赋值这一步，配置仍是开启，`applyCLI` 的 `!a.config.QREnabled` 拦不住，重开也恢复不了。

关闭后：快捷键注销（重开恢复原值不换键，`registerSlot` 已有语义）；设置页只剩头部开关与置灰的快捷键行 + `ModuleShortcutOff` tooltip（007 §2.4）；卡片面板整块不画；命令面板 `Available` 返回 false；CLI 在 `applyCLI` 入口判 `!a.config.QREnabled` 回 `cli.CodeDisabled`（退出 4）；URL 不扩（§6.8）。

### 6.6 工具窗口互不关闭

四个模块的窗口都是工具窗口，互不关闭：

- `openQRText` 只关**浮层**（`hideMenubarPanel` / `hidePalette`），不关翻译，也不关 JSON。
- `showPalette` / `showMenubarPanel` 只互相关闭（两者是同一个位置上的浮层），**不关**翻译与二维码。PR #86 把翻译改成工具窗口后，这两处的 `closeTranslate` 调用已删除并补了测试。
- 关闭模块仍然只关自己的窗口。

### 6.7 划词复用的三个边界

1. **CAS 失败**（`selectionReading` 已被翻译的读取占用）：`captureSelectionContext` 返回 `busy`，二维码打开**空窗口**，不读剪贴板，也不把这当成「没有选中」。
2. **二次触发**：`beginQRSelection` 用 `qrSelectionGeneration`；第二次按下取消在途读取并打开空窗口，与 `beginTranslateSelection` 同形，但代次独立。
3. **无权限提示**：用二维码自己的 `qrSelectionHintShown` 与 `qrState.denied`，不调用 `showSelectionHintOnce`（那个写翻译的标记与翻译状态）；`accessibilitySettingsOpened` 与翻译共用，一次启动只开一次系统设置。

### 6.8 与既有规格的边界

- **001**：加一张单行卡（高 `SizeNavHeight` + `Space8`），只在 `menubarPanelRows` / `menubarPanelHeight` / 视图加分支。**002**：不弹提示，不改。**005**：不用浮层规则，不改。
- **003**：加一条 `paramText` 命令「二维码」；`RawArg` 保留原文大小写的机制 010 已实现，直接复用。
- **006**：新增 `qr` action 与子命令，不改协议版本。**007**：第 7 页，只用 `settingsRow` / `pageHeader` / `settingsSection`，共享下限不变。
- **008**：复用普通工具窗口的按屏几何，新增独立 `qr_windows`，不动 JSON / 翻译的座位。
- **010**：复用 `captureSelection`、`selectionReader`、无权限引导与工具窗口写法；不改翻译，`beginQRSelection` 是新函数，不复用 `beginTranslateSelection`。

**不扩 URL scheme**：二维码没有回程通道，内容还可能很长；`cubbix://` 里没有 `qr`。

### 7.2 只能由维护者实测（都要前台、留证据）

1. **真机扫码**：手机相机扫短网址、长网址（v40）、中文、emoji，确认内容一致且能直接打开链接；再把窗口缩到最小尺寸扫一次。
2. **Retina 清晰度**：外接非 Retina 显示器上模块边缘是否仍整齐（整数像素算法的真实表现）。
3. **拖出**：拖到备忘录、Finder、信息、聊天应用各一次，确认得到图片；拖动预览是否正常；Esc 取消拖动后窗口状态是否正常。
4. **复制与保存**：复制后粘到别的应用是否为图片；保存对话框的默认文件名、扩展名、取消行为；只读目录下的失败提示。
5. **划词**：Safari / Chrome / 备忘录 / 终端 / VS Code 里各选一段网址按快捷键，记录「拿到 / 退回剪贴板 / 退回空」；焦点在地址栏、密码框时的表现。
6. **剪贴板边界**：剪贴板是图片、富文本、多个条目、超长文本时都不预填。
7. **焦点与 Space**：置顶、失焦保留、其他应用全屏 Space、多显示器首次居中与恢复；中文输入法下 Esc 关闭是否残留 composing。
8. **CLI**：应用未运行时能否拉起、管道输入、窄终端（80 列）下的折行与 `--png` 建议、`--json` 字段。

### 8.2 待维护者决定（4 项，均已按推荐定稿）

| # | 问题 | 推荐 | 备选与代价 |
| --- | --- | --- | --- |
| 1 | 默认快捷键 | **⌃⌥⌘R**（`Ctrl+Alt+Cmd+R`）：与前五个同族、同手指区，不在 `knownShortcutConflict` 的三组里；Apple 那张系统快捷键表里 `⌃⌥⌘` 系列只有 `C`、`P`、`,`、`.`（不含 `R`）。`R` 可记作 QR 的 R | ⌃⌥⌘Y（同样空闲，但离 ⌃⌥⌘ 的字母区更远）；⌃⌥⌘Q（更像 QR，但紧邻系统锁屏 `⌃⌘Q`，容易误触） |
| 2 | 纠错等级 | **M（15%）、不 boost、单段字节模式 + UTF-8 ECI**：容量与模块数可复现，中文按 UTF-8 字节算，不落进 Shift-JIS 的 Kanji 模式 | 打开 boost（同尺寸下更抗污损，但等级随内容跳变，测试与文档里的数字不再固定）；Q（更抗污损，但容量降到约 1663 字节，长网址更容易超限） |
| 3 | 导出 PNG 的清晰度 | **16 px/模块**（v4 约 656 px、v40 约 2960 px、约 10.5 KB） | 8 px/模块（体积减半，但打印与小尺寸显示时模块偏软）；按固定边长 1024 px（非整数倍，模块边缘不齐） |
| 4 | CLI 默认输出 | **终端 Unicode 半块字符画**（静区 4，与导出图一致），`--png` 写文件，`--json` 只给元数据 | 默认不输出、必须给 `--png`（脚本友好但人读时多一步）；把字符画塞进 JSON（v40 约 41 KB，远超 4096 的 `MaxLine`，必须为此加响应正文帧，不值得） |
