# 详细设计 007：设置页按「模块」重组（格子 → 模块）

- 状态：文档待评审；设计稿 R16 待维护者确认后才可进入实现。
- 日期：2026-11-05
- 本轮只写文档与设计稿，不改应用代码、不运行 Cubbix、不弹窗。文中「现状」均指 `origin/main`（`364e617`，版本 0.5.7）里读到的代码。

## 0. 结论摘要

1. **叫法**：界面统一用「模块」／英文 **Modules**。配置键、CLI 协议字段、Go 类型名保留 `tile(s)`，只改界面文案，见 §1。
2. **信息架构（推荐 B）**：**每个模块在侧栏单独占一项**——通用 / 常亮 / JSON / 快捷键 / 关于。每个模块页拥有自己的总开关、设置项和快捷键；「快捷键」页只放 Cubbix 级（命令面板、卡片面板）与反馈设置。参考 macOS 设置页的「头部卡片 + 分组标题 + 行内说明 + 状态」写法，见 §2。
3. **设置行说明规范**：新增独立一节，三级：① 行内灰色小字 ② 标题下方第二行（行高 48 → 64）③ `info` 图标 + tooltip。逐行给出该用哪一级与中英文文案，见 §3。这是本轮新增的**设置页设计语言**，同时写进 `design/README.md`。
4. **快捷键与模块联动**：模块关闭时快捷键**注销**（现有代码已经这样做）、同一页上的快捷键行**置灰**并带 `info` 一句话原因；重新打开自动恢复注册。冲突检测跳过被关闭的槽位。见 §4。
5. **全链路联动**：卡片面板、命令面板、URL、CLI、运行中会话、菜单栏图标逐项对照现有代码，多数已经实现，需要改的只有文案、设置页视图、页码别名与 `settingsHeight`，见 §5。
6. **通用页「命令行工具」**：右侧的 ✓ 图标 + ✕ 按钮改成和「开机启动」一样的开关；六种链接状态逐一映射到「开关位置 + 是否可点 + `triangle-alert` + 一句 tooltip」，见 §6。
7. **高度**：行高、各页自然高度、`settingsHeight` 改法、最小窗口见 §7；最小窗口改为 720 × 380（快捷键页 378）。
8. 需要维护者拍板的十项在 §12，每项都给推荐。

## 2. 信息架构

### 2.1 侧栏（推荐 B：每个模块一项）

```
┌──────────────┐
│ 🐱 Cubbix    │
│              │
│ [⚙] 通用      │
│ [☀] 常亮      │  ← 模块页
│ [{] JSON      │  ← 模块页
│ [⌨] 快捷键    │
│ [i] 关于      │
└──────────────┘
```

- 侧栏宽仍为 `SizeSidebarWidth` 144，内边距 `Space12`，子项间距 `Space16`（与 `main.go` 的 `view` 一致）。红绿灯在 (12, 12)，品牌区因此从 **y = 40** 开始（12 + 红绿灯 12 + `Space16`，R12 已定）。
- **品牌区两套方案**（R16 都画了）：

  | 方案 | 做法 | 优点 | 代价 |
  | --- | --- | --- | --- |
  | **A（推荐）** | 品牌行右移 `Space8`：猫标 20 放进与导航图标同宽的 28 单元并居中（中心与导航图标同在 x=34），名称 Cubbix 13/600 从 x=56 开始，与导航文字左边缘对齐；品牌与导航之间加一条 `StrokeHairline` + `ColorSeparator` 的分隔线（左右各内缩 `Space8`），分隔线上下各 `Space16` | 品牌和导航共用同一套左边缘与图标列，看起来是「第 0 行」而不是浮在左上角；分隔线把品牌与模块列表明确分开；名称 13/600 与导航 12/500 拉出层级 | 侧栏多一条 1px 线与约 32 的竖向空间 |
  | B | 品牌行贴左边（猫标左边缘 12），不加分隔线，只靠 `Space16` 间距与字号字重区分 | 结构最简单、竖向最省 | 猫标比导航图标列左移 8，仍显得偏左；与模块列表的分界靠间距，辨识度弱 |
  | C（不画） | 把品牌换成纯文本「Cubbix」或只留猫标 | 更紧凑 | 维护者现有品牌 lockup（R12）会被推翻，收益不足 |

  推荐 **A**：它同时解决「偏左」和「和模块导航区分度不高」两个问题，且不需要新 Token。R16 的「品牌区：与导航对齐」一节把 A、B 并排画出；其余页面窗口都用 A。
- 导航项：高 40（`SizeNavHeight` 32 + `Space8`，见 §7.1 的新 Token 建议），左右内边距 `Space8`、间距 `Space8`、圆角 `RadiusCard` 8。
  - 左：**图标方块** 28 × 28，`RadiusControl` 6，底色 `ColorControl`，内部 Lucide 图标 16，`ColorTextSecondary`；
  - 右：名称，`FontSizeSmall` 12、`FontWeightMedium`；
  - 选中：整行底色 `ColorAccentSoft`，图标与文字保持 `ColorText`/`ColorTextSecondary` 不变（与现有 `Navigation item` 的选中写法一致，仍只有灰阶）；
  - 悬停：`ColorNavHover`（现有 `view` 的写法）。
- **切换动效**：参考稿里选中底色是渐变的。MyGo v0.6.2 的 `ui` 是否有可用的隐式过渡（`Element.Transition` 一类）**尚未核对**；推荐先做「无动效、瞬时切换」，把它列为可选项（§12 第 13 项）。不要为动效自绘帧循环。
- 侧栏顺序固定为：通用、常亮、JSON、快捷键、关于。模块页排在前面、全局项排后面，与参考稿一致。

### 2.2 每页的骨架：头部卡片 + 分组标题 + 行

所有设置页统一成三段：

```
┌ 头部卡片 ────────────────────────────────┐
│ [☀] 常亮           保持屏幕或任务常亮，可合盖   [开关] │  ← 56 高
└──────────────────────────────────────────┘
设置                                              ← 分组标题 12/500 次要色，24 高
┌ 卡片 ────────────────────────────────────┐
│ [◔] 低电量下限                    10% 20% 30% │
│     低于此电量自动恢复睡眠                       │  ← ② 级说明，行高 64
└──────────────────────────────────────────┘
快捷键
┌ 卡片 ────────────────────────────────────┐
│ 开关常亮                            ⌃⌥⌘K    │
└──────────────────────────────────────────┘
```

1. **头部卡片**（新）：宽 528、高 56、`RadiusCard` 8、`ColorCard` + `StrokeHairline`/`ColorSeparator`、内边距 `Space8`/`Space16`、间距 `Space12`。左：图标方块 28（同侧栏方块，底色 `ColorControl`）、模块名（`FontSizeBody` 13/600）、一行灰字说明（`FontSizeSmall` 12 `ColorTextSecondary`，单行省略；**说明比名称小一号**，与 §3 的 ① 同一规则；它是第二行，左对齐名称，不参与基线对齐）。右侧是**页面级操作**：模块页放该模块的总开关；关于页放「检查更新」文字按钮；通用页、快捷键页没有右侧操作。
2. **分组标题**（新）：在卡片上方，24 高，`FontSizeSmall` 12/500 `ColorTextSecondary`，左对齐卡片边缘。参考稿的「Installed」就是这个层级。
3. **卡片与行**：沿用现有设置卡片（`RadiusCard`、`ColorCard`、`ColorSeparator` 描边、行间 `ui.Divider`）。行内结构见 §3。
4. **页面级错误**：`settingsError` / `awake.snapshot().Error` 不再单独占一行画在页面底部，改为**头部卡片右侧的 `triangle-alert`**（`ColorDanger`，tooltip 为原因）。参考稿把状态收进头部与行内，页面底部不堆错误行；这也让页面高度固定。

窗口级布局不变：`ColorWindow` 底、侧栏 `ColorSidebar` 填满高度、右侧内容宽 `SizeContentMaxWidth` 528 水平居中、上下内边距 `Space24`。红绿灯仍是系统控件，位置不变（`TrafficLightPosition` 12/12）。

### 2.4 模块关闭时

| 元素 | 表现 | 理由 |
| --- | --- | --- |
| 头部卡片的总开关 | 关 | 页面唯一的模块开关 |
| 设置行（如低电量下限） | **折叠**，所在分组连标题一起不画 | 与本轮「关掉模块就屏蔽相关入口」一致；卡片面板（001）与命令面板（003）在模块关闭时也整块消失 |
| 快捷键行及其分组 | **保留并置灰**（`Disabled(true).Opacity(0.45)`），行尾 `info` 图标 + tooltip「常亮已关闭，快捷键已注销」 | 用户需要看见「它还在，只是被注销了」；这也是模块与快捷键联动的可见证据 |
| 页面级错误 | 头部卡片右侧 alert | 见 §2.2 |

备选：设置行也置灰、不折叠（与 `feedbackPositionRow` 同一写法）。推荐折叠，见 §12 第 2 项。

### 2.6 参考设计与方案比较

维护者给了一份「设计感强的 macOS 设置页（深色）」参考。逐条借鉴如下：

| # | 参考做法 | 落到 Cubbix | 备注 |
| --- | --- | --- | --- |
| 1 | 侧栏每项是「圆角方块图标 + 名称」，每个功能模块单独一项，选中项有底色高亮，切换有轻微动效 | 侧栏 5 项，图标方块 28 中性灰底 + 单色图标，选中 `ColorAccentSoft`；动效列为可选（§2.1） | 只借鉴形状与层级，不用参考稿的彩色强调 |
| 2 | 每页顶部一张头部卡片：图标 + 名称 + 一行灰字说明 | 所有设置页加头部卡片 56 高，说明文案见 §8 | 说明用 ① / ③ 之外的第三类文本：**页面说明**，只出现在头部卡片 |
| 3 | 分组上方有小号灰色分组标题 | 分组标题 24 高，12/500 `ColorTextSecondary` | 模块页的分组是「设置」「快捷键」；快捷键页是「Cubbix」「反馈」 |
| 4 | 行是「图标 + 标题 + 第二行灰字」，右侧是状态（圆点 + 文字）再加 `›` 进入详情 | 有意义的行才加前置图标（命令行工具、低电量下限、自动更新）；右侧：控件行放控件，详情行放「状态点 + 文字」或 `›` | 状态点用 `ColorSuccess`（Token 现值等于 `ColorText`，中性）与 `ColorTextDisabled`，**不引入绿色**；`ColorDanger` 只给失败 |
| 5 | 页面级操作放在窗口右上角工具栏（如 Install from Folder…） | 放在头部卡片右侧（视觉上就是窗口右上角）：模块页放总开关，关于页放「检查更新」 | 不新增系统工具栏，避免与隐藏标题栏的红绿灯抢位置 |

其中第 4 条有取舍：现有设置行大多右侧是开关或分段控件，没有「详情页」可进。只有「更新内容」这一行真的会打开子页，所以 `›` 只用在那里；模块页的行不加 `›`，避免暗示存在不存在的详情。

**维护者确认（2026-11-05）：配色完全不参考这份参考稿，继续用 Cubbix 的黑白灰。**「已启用 / 已安装 / 已是最新」这类状态一律用中性色：实心中性深灰（`ColorText`）圆点 + 文字，或直接用一个开关表达；关闭 / 未安装用 `ColorTextDisabled`。只有错误与异常沿用现有 `ColorDanger` + `triangle-alert`。**不新增任何彩色 Token**（含绿色成功色）。

**信息架构比较**：

| 维度 | A：单一「模块」页 + 分组卡片 | **B：每个模块单独一个侧栏项（推荐）** |
| --- | --- | --- |
| 侧栏 | 4 项：通用 / 模块 / 快捷键 / 关于 | **5 项：通用 / 常亮 / JSON / 快捷键 / 关于** |
| 模块与快捷键 | 分居两页，联动只能靠置灰提示 | **同页：模块开关、设置、快捷键在一张页面里，关掉模块立刻看到自己的快捷键置灰** |
| 参考稿契合 | 低：参考稿把每个功能作为一级导航 | **高：与参考稿的 Agent Hook / Webhook / Extensions / Tools 一一对应** |
| 模块变多 | 一页变长，分组堆叠 | 每个模块页仍然短；侧栏变长但每项一行 |
| 头部卡片 | 一页只有一个「模块」头部，指代含糊 | **每页一个头部，说明这页做什么** |
| 全局项安放 | 快捷键页承载全部快捷键 | 快捷键页只放 Cubbix 级（命令面板、卡片面板）与反馈，语义清楚 |
| 代价 | 侧栏短、页面少 | 侧栏随模块增加；跨模块比较快捷键要来回切页（有 4 个键，可接受） |

**推荐 B。** 理由：维护者原始需求是「模块和快捷键要联动，整体串起来」；同页展示让「关掉常亮 → 常亮页里的快捷键立刻置灰」成为看得见的事实，而 A 需要用户再切一页去确认。参考稿也把每个功能作为一级导航。A 保留为备选（§12 第 1 项）。

## 3. 设置行说明规范（三级）

这是本轮新增的设置页设计语言。所有设置行只能按下面三级之一来写说明；「什么都不写」也是合法状态（第 0 级）。

### 3.1 三级定义

| 级别 | 形态 | 字号 / 颜色 / 间距 | 行高 | 用在哪 |
| --- | --- | --- | --- | --- |
| **①** 行内 | 标题右侧、同一行的灰色小字，与标题 `Space8` 间距；控件仍在最右。**字号比标题小一号**（12 < 13）、次要色、**与标题底部对齐**（不是垂直居中） | `FontSizeSmall` 12、`ColorTextSecondary`、字重 400、`LineHeightBody` | **不变** `SizeRowHeight` 48 | 一句话能说完、且右侧控件窄（≤ 120：开关 34、图标按钮 28、纯文字值） |
| **②** 第二行 | 标题下方第二行，**横跨整行的宽度**（有前置图标时缩进 `SizeIcon` + `Space8`），灰色小字，**单行、超出省略** | `FontSizeSmall` 12、`ColorTextSecondary`；标题与第二行 `Space2` 间距 | **`SizeRowHeight` + `Space16` = 64** | 一句规则，但比 ① 长（> 18 个汉字 / > 40 字符），或右侧控件是分段控件（318 宽）没有横向空间 |
| **③** 提示符号 | 标题右侧一个 Lucide `info` 图标 16（`ColorTextSecondary`，和标题 `Space6` 间距），内容放 tooltip | 图标 `SizeIcon` 16；tooltip 内文 `FontSizeSmall` 12、`ColorTooltipText`、`ColorTooltip` 底、`RadiusControl` 6、内边距 6 / 8、最大宽 320 | **不变** 48 | 多条规则、步骤、错误原因、随时间变化的数据、同一行的状态解释（如快捷键冲突原因） |

规则细节：

- **层级与基线**：说明文字一律比标题小一号（标题 `FontSizeBody` 13 / 600 或不加粗，说明 `FontSizeSmall` 12），次要色。① 的说明与标题**底部对齐**，不要用垂直居中——两者字号不同，居中会让说明看起来「浮起来」；② 是独立一行，左对齐标题、不做基线对齐。③ 的图标与标题同高、垂直居中。
- ①②③ 互斥，同一行只用一级。**例外**：异常状态（链接冲突、快捷键被占用、更新失败）用 `triangle-alert` + tooltip，这与 ③ 不冲突：③ 是常驻的「解释」，alert 是「现在出问题了」。图标顺序：alert 在 info 左边，都贴控件。
- ② 只允许一行：MyGo 文案用 `SingleLine()`，超长省略；第二行**不换行、不展开**。要写第二句就升级到 ③。
- ③ 的图标必须可聚焦（`Focusable()` + `Label`/`Description`），否则键盘与读屏用户拿不到内容。MyGo 的 tooltip 是**指针穿透**的（`lid_view.go` 的注释），所以：常驻说明挂在可控元素（info 图标、开关、录制器）上；需要在 tooltip 里放可点按钮的场景（如 004 的「去系统设置允许」）继续用 `ui.PopoverBase`。
- 「页面说明」不属于这三级：它只在头部卡片里出现一行（§2.2），不参与行长计算。
- 行前置图标（参考稿第 4 条）只给「名称本身不直观」的行：命令行工具（`terminal`）、低电量下限（`gauge`）、自动更新（`refresh-cw`）。其余行不加图标，避免每行都长一遍。
- 文案里不写「点此」「点击」；动词短语只写结果。

### 3.2 判断标准

1. 先问「不说这句，用户会不会做错？」不会 → 第 0 级，什么都不写。
2. 会，而且一句话、控件窄 → ①。
3. 一句话但太长或控件宽 → ②。
4. 需要两句以上、或内容随状态变化、或要解释一个异常 → ③。

### 3.3 与现有代码的衔接

- 现在行的写法是 `main.go` 的 `row(c, t, label, right)`：固定 `SizeRowHeight` 48、标题 `FontSizeBody`、右控件。新增一个带级别的版本（签名示意）：

```go
// settingsRowOpts 描述一行的说明级别；零值即第 0 级。
type settingsRowOpts struct {
    icon     string // 前置 Lucide 名，空表示不画
    hint     string // ① 行内小字，或 ② 第二行
    level    int    // 0 / 1 / 2 / 3
    tooltip  string // ③ 的 tooltip 文案
    status   string // 右侧状态文字（与状态点一起画）
    chevron  bool   // 右侧 ›，只给真的会打开子页的行
    disabled bool   // 置灰（模块关闭时的快捷键行）
}
func (a *application) settingsRow(c *ui.Context, t tokenValues, label string, o settingsRowOpts, right func())
```

`row` 保留给不需要说明的行，内部转调 `settingsRow`（`o` 为零值），避免一次改完所有调用点。

- 行高：新增 `func rowHeight(t tokenValues, level int) float32`，② 返回 `t.SizeRowHeight + t.Space16`，其余返回 `t.SizeRowHeight`。`settingsHeight` 改为调用它（§7）。
- ① 的布局：`Row` 内是 `[图标?][标题与说明的组][Spacer][控件]`。标题与说明放在一个**底部对齐**的子组里（`ui.Row` + `AlignItems(ui.End)`，间距 `Space8`）；子组高度取标题行高 + `Space2`，避免 12pt 的说明被 13pt 的行框裁掉。MyGo 的布局只支持 `start` / `center` / `end`，**没有真正的基线对齐**，所以「底部对齐」是按行盒底部而非字形基线，误差在 1pt 以内；实现后按 R16 的局部放大对照。① 小字用 `SingleLine()`；MyGo 没有「文本省略」样式属性，`SingleLine()` 是否带省略号**需实测**（R12 的标题截断已用过这个组合）。
- ② 的布局：整行是一个 `Column`（`rowHeight` = 64、间距 `Space2`、垂直居中），第一行是标题行（图标 + 标题 + `Spacer` + 控件），第二行是 ② 小字（`SingleLine()`，占满整行宽度；有前置图标时左侧留 `SizeIcon` + `Space8` 的缩进，与标题文字对齐）。这样英文长句不会挤在标题与分段控件之间被截得过短。
- ③ 的布局：标题 `Row`，标题文本后 `Space6` + `ui.Icon(c, icon("info"))`，图标 `Focusable().Label(text).Description(text)` + `Tooltip(text)`；Lucide `info` 已在 `design/assets/lucide-0.468.0` 与设计源（`Icon/info` = `uTgqT`）。
- 状态点：6 × 6 圆点，`ColorSuccess`（Token 现值等于 `ColorText`，中性）表示「已启用 / 已是最新」，`ColorTextDisabled` 表示「已关闭」；右侧文字 `FontSizeSmall` `ColorTextSecondary`。**不新增绿色 Token**。若维护者希望真的有绿色成功色，需要新 Token（`ColorSuccessFill`），属于改设计系统，见 §12 第 11 项。

「自动更新」的第二行整句示例：「启动时和每 24 小时检查一次 · 上次检查 13:20」。同一天不写「今天」前缀（当天就是默认语境），跨天才加「昨天」或日期。

「上次检查」的数据来源：**现在没有记录**。`updates.go` 的 `updateState` 只有 `Phase`、`Version`、`ErrorKey`、`Notes*`；`updateManager.request` 完成时只改相位与错误，没有任何时间戳。要显示它需要：

1. `updateState` 增加 `CheckedAt time.Time`；
2. `request` 收尾写相位的那一段（`installed` / `context.Canceled` / `err` / `nil` 四个分支之后）统一写 `u.state.CheckedAt = time.Now()`；
3. 视图按语言格式化：同一日历日 → 只写 `15:04`；前一天 → `UpdateYesterday` + `15:04`（昨天 13:20）；更早 → 中文 `1月2日 15:04`、英文 `Jan 2, 15:04`（Go layout `"1月2日 15:04"` / `"Jan 2, 15:04"`）；
4. `CheckedAt` 为零值时不显示「上次检查」，只显示频率（首次启动、自动更新关闭且还没手动检查过）。

显示规则（`CheckedAt` 与 `ErrorKey` 的组合，逐条定死）：

| 情况 | `updateState` | 第二行 |
| --- | --- | --- |
| 从未检查 | `CheckedAt` 为零 | 启动时和每 24 小时检查一次 |
| 检查成功，同一天 | `CheckedAt` 为今天、`ErrorKey` 为空 | 启动时和每 24 小时检查一次 · 上次检查 13:20 |
| 检查成功，昨天 | `CheckedAt` 为昨天 | … · 上次检查 昨天 13:20 |
| 检查成功，更早 | 更早 | … · 上次检查 11月3日 13:20 / Nov 3, 13:20 |
| **检查失败** | `CheckedAt` 有值、`ErrorKey` 非空 | **与成功时相同**（显示最后一次尝试的时间），失败本身只由版本行右侧的 `triangle-alert` + tooltip（`UpdateNetworkError`／`UpdateSignatureError` 等现有键）表达；第二行不写错误句子，避免把 ② 变成会变化的错误行 |
| 自动更新关闭 | `CheckedAt` 保留 | 频率那句仍然成立（手动检查不受开关影响，ADR 004）；「上次检查」只反映最近一次手动或自动检查 |

实现要点：`CheckedAt` 在 `request` 收尾时**无论成功失败**都写 `time.Now()`，否则「失败后时间戳不前进」会让用户以为任务卡住；失败原因只体现在 `ErrorKey` 与版本行 alert 上。

推荐**只存在内存**：自动更新开启时启动就会检查一次，重启后几秒内即可再有值；要跨重启保留就得加配置键 `update_last_check`（RFC3339）并处理时钟回拨，收益很小。若维护者要求跨重启，见 §12 第 8 项。

## 4. 快捷键与模块联动

### 4.1 注销与恢复（已实现）

- `changeAwakeEnabled`（`awake_app.go`）关闭时 `a.unregisterShortcut(a.config.AwakeShortcut)`；`changeJSONEnabled`（`json_app.go`）关闭时同样注销。
- `registerAwakeShortcut` / `registerJSONShortcut` 在 `!config.XxxEnabled` 时直接 return，不注册。
- `shortcutSlots()` 的 `Enabled` 字段就是 `config.AwakeEnabled` / `config.JSONEnabled`，注册与冲突检测都读它。
- 模块重新打开 → `changeXxxEnabled` 调用 `registerXxxShortcut`，自动恢复注册。

### 4.2 模块页上的快捷键行

- 模块关闭：该行 `Disabled(true).Opacity(t.OpacityDisabled)`（0.45），录制器不可点（**需实测** MyGo 对 `Disabled` 按钮的点击拦截）；行尾 `info` 图标（不参与 0.45 透明度）tooltip `ModuleShortcutOff`，一句话：常亮已关闭，快捷键已注销。
- 行标题保持可读（跟着 0.45 变淡，但仍是可识别的位置），分组标题不置灰——用户需要知道这是哪一组。
- 为什么置灰而不是折叠：`ModuleShortcutOff` 要能解释「为什么按了没反应」；折叠会让快捷键凭空消失，只剩下「我设的键去哪了」。

### 4.3 冲突检测与被屏蔽的快捷键

- `shortcutConflict(acc, target)` 只比较 `slot.Enabled` 为真的槽位：模块关闭后它的组合键**不占位**，别的槽位可以用同一个组合。
- 被屏蔽期间该槽位的 `XxxShortcutError` 不显示（视图按模块开关隐藏 alert）；重新打开模块时若组合已被别人占用，`registerXxxShortcut` 会写入 `JSONShortcutConflict` 并在该行显示 alert + tooltip。**推荐不改**：这是「重新开启时告诉你被占了」，比静默换键好。
- 需要补的一处小漏洞：`registerAwakeShortcut` 在 `!a.config.AwakeEnabled` 时提前 return，**没有清空 `a.shortcutError`**；关闭模块后错误会留在内存里，重新打开时若注册成功也不会清。推荐两个 `registerXxxShortcut` 的早退分支也清掉各自的 error 键（或让 `changeXxxEnabled` 的关闭分支清）。

### 4.4 录制时的模块状态

`beginTileShortcutRecording` 会先注销**所有已启用槽位**再进入录制（`shortcutSuspended`），取消时 `cancelShortcutRecording` 重新注册四个槽位——`registerAwakeShortcut` / `registerJSONShortcut` 自己判模块开关，所以录制期间关闭的模块不会被注册回来。这条已经正确，不需要改。

### 5.5 运行中的会话

**常亮在运行时关闭模块**（`changeAwakeEnabled` 的 false 分支）：先 `stopAwake()`，内部顺序是 `lid.stop()`（恢复 `disablesleep=0` 并读回）→ 清会话的 lid 标记 → `awake.stop()`（停 `caffeinate`）；任一步失败都返回错误，调用方把 `AwakeEnabled` 回滚成 true 并设 `settingsError = "LidRestoreFailed"`，**不允许留下一个没人负责的 `disablesleep=1`**。随后才 `unregisterShortcut` 与 `lid.service.Unregister()`，卸载失败同样回滚。这段已实现，本设计不改，只要求把失败显示在常亮页头部卡片右侧（§2.2）。

**合盖在开启时关闭模块**：同上，`lid.stop()` 先恢复；失败即回滚，模块开关弹回开。

**JSON 关闭时**（`changeJSONEnabled`）：注销快捷键 → `destroyJSON` 遍历关闭所有窗口。JSON 是工具窗口，规则是「关闭不询问未保存」，所以这里也不提示（R08 已定规则）。**风险写进验收**：用户可能正在编辑，关掉模块等于丢弃；既有规则，本轮不新增确认框。

## 6. 通用页：命令行工具改成开关

### 6.1 现状与问题

`cli_settings.go` 的 `cliSettingsRow` 现在按 `cliPaths.status()` 画：

- 已安装：`check` 图标（`ColorTextSecondary`）+ `x` 图标按钮（`CLIRemove`）；
- 缺失：`terminal` 图标按钮（`CLIInstall`）；
- 失效 / 冲突：`triangle-alert` + `terminal` 按钮（`CLIRepair`）；
- 转写（translocation）：`triangle-alert` + 禁用的 `terminal` 按钮。

问题（维护者原话）：✓ 看起来像按钮，✕ 看起来像报错；「安装 / 卸载」是开关语义，却画成两个图标。

### 6.2 改成开关：六种状态逐一映射

控件变成与「开机启动」同一个 `switchControl`：开 = 在 `~/.local/bin/cubbix` 建链接，关 = 删链接；异常状态在开关左边加 `triangle-alert`（`ColorDanger`，可聚焦），原因放 tooltip。

| 状态（`status()`） | 判据（现有函数） | 开关 | 行内 alert | tooltip（中 / 英） | 开关可点 | 动作 |
| --- | --- | --- | --- | --- | --- | --- |
| `cliAbsent` | 包内没有可执行的 `bin/cubbix` | **不画这一行** | — | — | — | — |
| `cliMissing` | 链接不存在，目标可用 | 关 | 无 | `CLIInstall`（现成）：安装命令行工具 / Install command line tool | 可 | 开 → `installCLILink(paths)` |
| `cliInstalled` | 链接指向本包 CLI | 开 | 无 | `CLIInstalled`（现成，带路径）：已安装：%s / Installed: %s | 可 | 关 → `removeCLILink(paths)` |
| `cliBroken` | 是我们的链接，但目标文件没了 | 开 | `triangle-alert` | `CLILinkBroken`（改文案）：链接已失效，关掉再打开可重建 / The link is broken. Turn it off and on to rebuild it | 可 | 关 → `removeCLILink`（该状态允许删除）；再开 → 重建 |
| `cliConflict` | 该路径是别人的链接或普通文件 | 关 | `triangle-alert` | `CLILinkConflict`（现成）：%s 已存在，未覆盖 / %s already exists; not replaced | 可（重试） | 开 → `installCLILink` 失败，保持关，`settingsError` 沿用现有 `cliLinkResult`；用户处理掉那个文件后再点一次 |
| `cliTranslocated` | 应用在 `AppTranslocation` 路径 | 关 | `triangle-alert` | `CLITranslocated`（现成）：请先把 Cubbix 放进「应用程序」 / Move Cubbix to Applications first | **不可**（`Disabled(true).Opacity(t.OpacityDisabled)`） | — |

实现要点：

- 开关的绑定值：`on := state == cliInstalled || state == cliBroken`（`cliBroken` 时链接确实在）。`OnChange` 里按目标值调用 `installCLILink` / `removeCLILink`，不要用 `!on` 反推，避免状态在两帧之间变化。
- 失败不写开关本身：`cliLinkResult(err)` 只写 `settingsError` 并 `invalidateWindow()`，开关下一帧仍按 `status()` 重画，天然不会出现「失败却显示已开」。
- 为了能重试，`cliMissing` / `cliConflict` / `cliBroken` 的开关**不要**永久禁用；只有 `cliTranslocated` 禁用。
- 现有 `CLIRepair` 键使用后可以删除；`check`/`x` 图标不再出现在这一行。
- 无障碍：`switchControl` 已有 `Label`；`triangle-alert` 需要 `Focusable().Label(reason)`。

### 6.3 「不在 PATH」

**现状事实**：代码里没有任何 PATH 检查；`cliPaths` 只算 `link`、`target`、`bundle`。006 §9 第 3 项已明确决策「`~/.local/bin` 不在 PATH 时不提示」，理由是低信息密度，命令写在 README 与 tooltip。

推荐**沿用 006 的决策**，不在本轮新增 PATH 探测，因为：

1. GUI 进程由 launchd 启动，`os.Getenv("PATH")` 是 `/usr/bin:/bin:/usr/sbin:/sbin` 一类，几乎永远不含 `~/.local/bin`，会误报。
2. 真正的判断要跑用户的登录 shell（`$SHELL -lc 'echo $PATH'`），那等于执行用户配置脚本，慢、可能有副作用。
3. 解析 shell 配置文件是启发式，误报比不报更糟：用户会去修一个本来就对的东西。

替代做法：`cliInstalled` 的 tooltip 里已经带完整路径（`CLIInstalled` 的 `%s`），README 与 006 文档给出手动加 PATH 的一行命令。若维护者仍要异常态，需要先定探测口径，见 §12 第 6 项。

### 7.3 `settingsHeight` 改法

现状（`main.go`）是按页硬编码行数的 if 链，改为按「页面单元表」拼装：

```go
// cardHeight 返回一张卡片的高度：行高之和 + 行间分隔线。
func cardHeight(t tokenValues, rows ...float32) float32 {
    var total float32
    for i, row := range rows {
        if i > 0 { total += t.StrokeHairline }
        total += row
    }
    return total
}

// pageHeight 是页面内容的自然高度，不含窗口内边距。
func pageHeight(t tokenValues, page int, awakeOn bool) float32 {
    header := float32(56) // SizePageHeader
    group := float32(24)  // SizeGroupHeader
    section := func(cards ...float32) float32 { /* header + 8 + Σ(group + 8 + card) */ }
    switch page {
    case 0:
        return section(cardHeight(t, t.SizeRowHeight, t.SizeRowHeight, t.SizeRowHeight))
    case 1:
        return section(cardHeight(t, t.SizeRowHeight, t.SizeRowHeight,
                                  t.SizeRowHeight+t.Space16))
    case 2:
        if awakeOn {
            return section(cardHeight(t, t.SizeRowHeight, t.SizeRowHeight+t.Space16),
                           cardHeight(t, t.SizeRowHeight))
        }
        return section(cardHeight(t, t.SizeRowHeight))
    case 3:
        return section(cardHeight(t, t.SizeRowHeight, t.SizeRowHeight),
                       cardHeight(t, t.SizeRowHeight, t.SizeRowHeight))
    case 4:
        return section(cardHeight(t, t.SizeRowHeight))
    }
    return 0
}
```

`settingsHeight(t, page, hasError)` 保留给测试与 QA 截图：返回 `max(SizeWindowMinHeight, pageHeight + 2×Space24)` 并对齐 4。错误不再占行高（§2.2 的头部 alert），`hasError` 参数可以删掉；若为了少改测试暂时保留，就让它只影响返回值注释。

### 7.4 最小尺寸

- `settingsMinimumSize` 改为**常量**：宽 `SizeWindowWidth` 720、高 **380**（快捷键页自然高 378，对齐 4）。当前值是 368，来自「6 行 + 错误图标」，分组后这一页变成 330 + 48，最小值随之改为 380。
- 页面切换仍然不改变窗口尺寸（0.0.3 规则）：所有页面自然高 ≤ 380，最小窗口下不会出现截断，因此**本期不引入滚动**。若将来某一页超过 380，再加 `ui.Scroll`（`notesView` 里已有先例），而不是继续抬高最小高度。
- `settingsSize(width, height)` 的夹取逻辑不变。

### 7.5 参考稿的切页动效

侧栏选中底色的渐变属于「轻微动效」，依赖 MyGo `ui` 是否提供过渡 API，**未核对**。推荐先实现无动效版本；若框架支持，再只给侧栏选中底色加 120–160ms 的过渡，不改变布局尺寸（§12 第 13 项）。
