# 详细设计 007：设置页按「模块」重组（格子 → 模块）

- 状态：第 3 版（工程评审），设计方向已批准；本文完成工程定稿，可据此开工。PR #67 保持开放、不合并。
- 日期：2026-11-06
- 本轮只修订文档，不改应用代码、不运行 Cubbix、不弹窗。应用代码基线为 `364e617`（版本 0.5.7），与评审时 `origin/main` 的应用代码一致；`origin/main` 已于 `ce189b8` 合入 008 文档，尚未实现 007／008 的新布局。007 原稿基线 `fbf7697`，MyGo 固定 v0.6.2。

## 0. 结论摘要

1. **叫法**：界面统一用「模块」／英文 **Modules**。配置键、CLI 协议字段、Go 类型名保留 `tile(s)`，只改界面文案，见 §1。
2. **信息架构（已定 B）**：**每个模块在侧栏单独占一项**——通用 / 常亮 / JSON / 快捷键 / 关于。每个模块页拥有自己的总开关、设置项和快捷键；「快捷键」页只放 Cubbix 级（命令面板、卡片面板）与反馈设置。参考 macOS 设置页的「头部卡片 + 分组标题 + 行内说明 + 状态」写法，见 §2。
3. **设置行说明规范**：新增独立一节，三级：① 行内灰色小字 ② 标题下方第二行（行高 48 → 64）③ `info` 图标 + tooltip。逐行给出该用哪一级与中英文文案，见 §3。这是本轮新增的**设置页设计语言**，同时写进 `design/README.md`。
4. **快捷键与模块联动**：模块关闭时快捷键**注销**（现有代码已经这样做）、同一页上的快捷键行**置灰**并带 `info` 一句话原因；重新打开自动恢复注册。冲突检测跳过被关闭的槽位。见 §4。
5. **全链路联动**：卡片面板、命令面板、URL、CLI、运行中会话、菜单栏图标逐项对照现有代码，现有基础可复用，但仍须补录制状态、异步关闭门禁、关闭提交时序和缓存入口刷新，见 §5。
6. **通用页「命令行工具」**：右侧的 ✓ 图标 + ✕ 按钮改成和「开机启动」一样的开关；六种链接状态逐一映射到「开关位置 + 是否可点 + `triangle-alert` + 一句 tooltip」，见 §6。
7. **高度**：行高、各页自然高度、`settingsHeight` 改法、最小窗口见 §7；与已合并的 008 及更新就绪卡片一起取最大值，最小窗口 **720 × 388**；自然高度与实际窗口下限分开计算。
8. 已批准方向与本次工程取舍见 §12，不留开工前的确认点；实现后的运行验收仍须完成。

```
│              │
│ [⚙] 通用      │
│ [☀] 常亮      │  ← 模块页
│ [{] JSON      │  ← 模块页
```

- **品牌区两套方案**（R16 都画了）：

  | 方案 | 做法 | 优点 | 代价 |
  | --- | --- | --- | --- |
  | **A（已定）** | 品牌行右移 `Space8`：猫标 20 放进与导航图标同宽的 28 单元并居中（中心与导航图标同在 x=34），名称 Cubbix 13/600 从 x=56 开始，与导航文字左边缘对齐；品牌与导航之间加一条 `StrokeHairline` + `ColorSeparator` 的分隔线（左右各内缩 `Space8`），分隔线上下各 `Space16` | 品牌和导航共用同一套左边缘与图标列，看起来是「第 0 行」而不是浮在左上角；分隔线把品牌与模块列表明确分开；名称 13/600 与导航 12/500 拉出层级 | 侧栏多一条 1px 线与约 32 的竖向空间 |

  - 悬停：`ColorNavHover`（现有 `view` 的写法）。

### 2.2 每页的骨架：头部卡片 + 分组标题 + 行

所有设置页统一成三段：

```
┌ 头部卡片 ────────────────────────────────┐
│ [☀] 常亮           保持屏幕或任务常亮，可合盖   [开关] │  ← 56 高
└──────────────────────────────────────────┘
设置                                              ← 分组标题 12/500 次要色，24 高
┌ 卡片 ────────────────────────────────────┐
│ [◔] 低电量下限                    10% 20% 30% │
│     低于此电量自动恢复睡眠                       │  ← ② 级说明，行高 64
└──────────────────────────────────────────┘
快捷键
┌ 卡片 ────────────────────────────────────┐
│ 开关常亮                            ⌃⌥⌘K    │
└──────────────────────────────────────────┘
```

1. **头部卡片**（新）：宽 528、高 56、`RadiusCard` 8、`ColorCard` + `StrokeHairline`/`ColorSeparator`、内边距 `Space8`/`Space16`、间距 `Space12`。左：图标方块 28（同侧栏方块，底色 `ColorControl`）、模块名（`FontSizeBody` 13/600）、一行灰字说明（`FontSizeSmall` 12 `ColorTextSecondary`，单行省略；**说明比名称小一号**，与 §3 的 ① 同一规则；它是第二行，左对齐名称，不参与基线对齐）。右侧是**页面级操作**：模块页放该模块的总开关；关于页放「检查更新」文字按钮；通用页、快捷键页没有右侧操作。
2. **分组标题**（新）：在卡片上方，24 高，`FontSizeSmall` 12/500 `ColorTextSecondary`，左对齐卡片边缘。参考稿的「Installed」就是这个层级。
3. **卡片与行**：沿用现有设置卡片（`RadiusCard`、`ColorCard`、`ColorSeparator` 描边、行间 `ui.Divider`）。行内结构见 §3。
4. **页面级错误**：`settingsError` / `awake.snapshot().Error` 不再单独占一行画在页面底部，改为**头部卡片右侧的 `triangle-alert`**（`ColorDanger`，tooltip 为原因）。参考稿把状态收进头部与行内，页面底部不堆错误行；这也让页面高度固定。

错误归属：ConfigError 为窗口级持久化错误，任一页头都可见；LidRestoreFailed／AwakeStopError／awake或lid快照错误只在常亮页，CLI操作错误只在通用页，更新失败只在版本行。恢复错误直接从尚未解决的controller／事务状态派生，不能靠易被save清空的settingsError独占保存。多个错误可在同一alert的可访问说明中组合，恢复错误优先，ConfigError不丢失；图标不额外撑高。保留卡片面板中004的恢复popover／强制恢复入口，关闭失败时设置组不折叠，不能让用户只剩一条tooltip而无恢复操作。

窗口级布局不变：`ColorWindow` 底、侧栏 `ColorSidebar` 填满高度、右侧内容宽 `SizeContentMaxWidth` 528 水平居中、上下内边距 `Space24`。红绿灯仍是系统控件，位置不变（`TrafficLightPosition` 12/12）。

### 2.4 模块关闭时

| 元素 | 表现 | 理由 |
| --- | --- | --- |
| 头部卡片的总开关 | 关 | 页面唯一的模块开关 |
| 设置行（如低电量下限） | **折叠**，所在分组连标题一起不画 | 与本轮「关掉模块就屏蔽相关入口」一致；卡片面板（001）与命令面板（003）在模块关闭时也整块消失 |
| 快捷键行及其分组 | **保留并置灰**（`Disabled(true).Opacity(t.OpacityDisabled)`），行尾 `info` 图标 + tooltip「常亮已关闭，快捷键已注销」 | 用户需要看见「它还在，只是被注销了」；这也是模块与快捷键联动的可见证据 |
| 页面级错误 | 头部卡片右侧 alert | 见 §2.2 |

已定为设置组折叠、快捷键保留并置灰。关闭进行中与失败时仍按已提交的开启态显示，直到 §5.5 的安全关闭成功。

### 2.6 参考设计与方案比较

维护者给了一份「设计感强的 macOS 设置页（深色）」参考。逐条借鉴如下：

| # | 参考做法 | 落到 Cubbix | 备注 |
| --- | --- | --- | --- |
| 1 | 侧栏每项是「圆角方块图标 + 名称」，每个功能模块单独一项，选中项有底色高亮，切换有轻微动效 | 侧栏 5 项，图标方块 28 中性灰底 + 单色图标，选中 `ColorAccentSoft`；动效列为可选（§2.1） | 只借鉴形状与层级，不用参考稿的彩色强调 |
| 2 | 每页顶部一张头部卡片：图标 + 名称 + 一行灰字说明 | 所有设置页加头部卡片 56 高，说明文案见 §8 | 说明用 ① / ③ 之外的第三类文本：**页面说明**，只出现在头部卡片 |
| 3 | 分组上方有小号灰色分组标题 | 分组标题 24 高，12/500 `ColorTextSecondary` | 模块页的分组是「设置」「快捷键」；快捷键页是「Cubbix」「反馈」 |
| 4 | 行是「图标 + 标题 + 第二行灰字」，右侧是状态（圆点 + 文字）再加 `›` 进入详情 | 有意义的行才加前置图标（命令行工具、低电量下限、自动更新）；右侧：控件行放控件，详情行放「状态点 + 文字」或 `›` | 状态点用 `ColorSuccess`（Token 现值等于 `ColorText`，中性）与 `ColorTextDisabled`，**不引入绿色**；`ColorDanger` 只给失败 |
| 5 | 页面级操作放在窗口右上角工具栏（如 Install from Folder…） | 放在头部卡片右侧（视觉上就是窗口右上角）：模块页放总开关，关于页放「检查更新」 | 不新增系统工具栏，避免与隐藏标题栏的红绿灯抢位置 |

其中第 4 条有取舍：现有设置行大多右侧是开关或分段控件，没有「详情页」可进。只有「更新内容」这一行真的会打开子页，所以 `›` 只用在那里；模块页的行不加 `›`，避免暗示存在不存在的详情。

**维护者确认（2026-11-05）：配色完全不参考这份参考稿，继续用 Cubbix 的黑白灰。**「已启用 / 已安装 / 已是最新」这类状态一律用中性色：实心中性深灰（`ColorText`）圆点 + 文字，或直接用一个开关表达；关闭 / 未安装用 `ColorTextDisabled`。只有错误与异常沿用现有 `ColorDanger` + `triangle-alert`。**不新增任何彩色 Token**（含绿色成功色）。

**信息架构比较**：

| 维度 | A：单一「模块」页 + 分组卡片 | **B：每个模块单独一个侧栏项（已定）** |
| --- | --- | --- |
| 侧栏 | 4 项：通用 / 模块 / 快捷键 / 关于 | **5 项：通用 / 常亮 / JSON / 快捷键 / 关于** |
| 模块与快捷键 | 分居两页，联动只能靠置灰提示 | **同页：模块开关、设置、快捷键在一张页面里，关掉模块立刻看到自己的快捷键置灰** |
| 参考稿契合 | 低：参考稿把每个功能作为一级导航 | **高：与参考稿的 Agent Hook / Webhook / Extensions / Tools 一一对应** |
| 模块变多 | 一页变长，分组堆叠 | 每个模块页仍然短；侧栏变长但每项一行 |
| 头部卡片 | 一页只有一个「模块」头部，指代含糊 | **每页一个头部，说明这页做什么** |

### 2.8 页面切换与焦点

- 模块开关仍经 `changeAwakeEnabled` / `changeJSONEnabled`，视图不直接改会话、服务或注册表。`ui.SwitchBase` 会先改绑定值，必须绑定本帧局部 `on`，把目标值传给应用层事务；应用层提交前仍保留原 `config.XxxEnabled`。禁止把临时 false 提前保存或暴露给 CLI／面板。
- 开关使用稳定 Key；关闭后设置组消失，开关仍保留。鼠标或键盘操作后不主动夺取焦点；若焦点原在被删除／禁用的控件中，在下一次视图构建对模块开关一次性 `Focus()`，随即清掉请求标记，不能每帧调用。

## 3. 设置行说明规范（三级）

这是本轮新增的设置页设计语言。所有设置行只能按下面三级之一来写说明；「什么都不写」也是合法状态（第 0 级）。

### 3.1 三级定义

| 级别 | 形态 | 字号 / 颜色 / 间距 | 行高 | 用在哪 |
| --- | --- | --- | --- | --- |
| **①** 行内 | 标题右侧、同一行的灰色小字，与标题 `Space8` 间距；控件仍在最右。**字号比标题小一号**（12 < 13）、次要色、**与标题底部对齐**（不是垂直居中） | `FontSizeSmall` 12、`ColorTextSecondary`、字重 400、`LineHeightBody` | **不变** `SizeRowHeight` 48 | 一句话能说完、且右侧控件窄（≤ 120：开关 34、图标按钮 28、纯文字值） |
| **②** 第二行 | 标题下方第二行，**横跨整行的宽度**（有前置图标时缩进 `SizeIcon` + `Space8`），灰色小字，**单行、超出省略** | `FontSizeSmall` 12、`ColorTextSecondary`；标题与第二行 `Space2` 间距 | **`SizeRowHeight` + `Space16` = 64** | 一句规则，但比 ① 长（> 18 个汉字 / > 40 字符），或右侧控件是分段控件（318 宽）没有横向空间 |
| **③** 提示符号 | 标题右侧一个 Lucide `info` 图标 16（`ColorTextSecondary`，和标题 `Space6` 间距），内容放 tooltip | 图标 `SizeIcon` 16；tooltip 内文 `FontSizeSmall` 12、`ColorTooltipText`、`ColorTooltip` 底、`RadiusControl` 6、内边距 6 / 8、最大宽 320 | **不变** 48 | 多条规则、步骤、错误原因、随时间变化的数据、同一行的状态解释（如快捷键冲突原因） |

规则细节：

- **层级与基线**：说明文字一律比标题小一号（标题 `FontSizeBody` 13 / 600 或不加粗，说明 `FontSizeSmall` 12），次要色。① 的说明与标题**底部对齐**，不要用垂直居中——两者字号不同，居中会让说明看起来「浮起来」；② 是独立一行，左对齐标题、不做基线对齐。③ 的图标与标题同高、垂直居中。
- ①②③ 互斥，同一行只用一级。**例外**：异常状态（链接冲突、快捷键被占用、更新失败）用 `triangle-alert` + tooltip，这与 ③ 不冲突：③ 是常驻的「解释」，alert 是「现在出问题了」。图标顺序：alert 在 info 左边，都贴控件。
- ② 只允许一行：MyGo 文案用 `SingleLine()`，超长省略；第二行**不换行、不展开**。要写第二句就升级到 ③。
- ③ 的图标必须可聚焦（`Focusable()` + `Label`/`Description`），否则键盘与读屏用户拿不到内容。MyGo 的 tooltip 是**指针穿透**的（`lid_view.go` 的注释），所以：常驻说明挂在可控元素（info 图标、开关、录制器）上；需要在 tooltip 里放可点按钮的场景（如 004 的「去系统设置允许」）继续用 `ui.PopoverBase`。
- 「页面说明」不属于这三级：它只在头部卡片里出现一行（§2.2），不参与行长计算。
- 行前置图标（参考稿第 4 条）只给「名称本身不直观」的行：命令行工具（`terminal`）、低电量下限（`gauge`）、自动更新（`refresh-cw`）。其余行不加图标，避免每行都长一遍。
- 文案里不写「点此」「点击」；动词短语只写结果。

### 3.2 判断标准

1. 先问「不说这句，用户会不会做错？」不会 → 第 0 级，什么都不写。
2. 会，而且一句话、控件窄 → ①。
3. 一句话但太长或控件宽 → ②。
4. 需要两句以上、或内容随状态变化、或要解释一个异常 → ③。

### 3.3 与现有代码的衔接：可复用设置行

目标接口放 `settings_view.go`，本段是实现契约；资源、控件状态由调用方提供，不让组件读取具体模块或 008 的配置：

```go
// Zero options produce a plain row; hint and tooltip are localized text.
type settingsRowOpts struct {
    icon     string
    hint     string
    level    int // 0 / 1 / 2 / 3
    tooltip  string
    status   string
    chevron  bool
    disabled bool
}
func (a *application) settingsRow(c *ui.Context, t tokenValues,
    label string, o settingsRowOpts, right func())
func rowHeight(t tokenValues, level int) float32
```

- 旧 `row` 转调零选项的 `settingsRow`；`rowHeight` 对②返回 `SizeRowHeight+Space16`，其余返回 `SizeRowHeight`。空 hint 不自动降高，布局与测高都按 level 决定。可见行由调用方先筛选，分隔线只在相邻可见行之间画一次；外层卡片只有水平 `Space16` padding，描边不额外加高。
- **② 是通用两行组件**：外层 64 高 `Column`，上下各 `Space8`，`Space2` 间隔；第一行固定 `SizeSegmentHeight=28`，`[图标?][标题][Spacer][right]`，控件 `Shrink(0)`；第二行高 `FontSizeSmall×LineHeightBody=18`，字号 12、次要色，`FillWidth().MinWidth(0).SingleLine()`。总高 `16+28+2+18=64`。有图标时第二行缩进 `SizeIcon+Space8`，占卡片内可用宽度减缩进，横跨控件下方。说明被截断时在说明本身挂全文 tooltip，控件 `Description` 也包含全文；图标不得单独挤占第二行宽度。
- ② 可复用于 008 及后续偏好，不把字段名、开关或分段数量写入组件。调用示意：`settingsRow(c, t, text("WindowPlacement"), settingsRowOpts{level: 2, hint: text("WindowPlacementInfo")}, placementControl)`。008 当前已定该行用③，实施时仍按 008 使用③；此示例只证明同一 API 能承载后续②行，不改变 008 交互。
- ①：标题和说明放在底部对齐子组 `AlignItems(ui.End)`、间距 `Space8`，字框按实际行高，外组 `Grow(1).MinWidth(0)`；说明 `SingleLine`，控件不收缩。MyGo **支持** `ui.Baseline`，但批准要求是底部对齐，仍用 End；删除原稿“没有基线”和“误差小于 1pt”的无依据结论。
- ③：info 为独立、启用的兄弟节点，`Focusable().Label(fullText).Description(fullText).Tooltip(fullText)`；稳定 Key。异常 alert 同样可访问，原因由调用方格式化完再传入，不能留下 `%s`。
- `disabled` 只作用于标题／录制器主体，`Opacity(t.OpacityDisabled)` 只加一次；关闭原因 info 与 alert 不放在 Disabled 祖先下。MyGo `ui/tooltip.go` 会排除 disabled anchor，不能把 tooltip 只挂在禁用录制器上。`Disabled` 已由源码确认阻止点击和聚焦；自定义 HandleInput 仍检查模块 Enabled 与录制状态。
- `SingleLine()` 默认使用省略号，`Ellipsis` 可改尾缀，已由 MyGo API 与文本实现确认。实际宽度、字形和焦点仍在实现时做中英渲染／交互验证。
- 状态点 6×6（`Space6`），用现有 `ColorSuccess`（解析后等于 `ColorText`）／`ColorTextDisabled`，不增加颜色 Token。

「自动更新」的第二行整句示例：「启动时和每 24 小时检查一次 · 上次检查 13:20」。同一天不写「今天」前缀（当天就是默认语境），跨天才加「昨天」或日期。

1. `updateState.CheckedAt time.Time` 与可注入时钟 `now func() time.Time` 加到 updateManager。在 `u.check(ctx)` 返回、尚未调用 `up.install` 前记录；网络／签名／源错误等已完成失败也记时间。`context.Canceled`（关自动更新或退出取消）不记；`DeadlineExceeded` 是一次超时失败，要记。若 check 已成功返回后才取消下载，已记的检查不撤销。
2. request 被 stopped／busy／ready／自动开关门禁拒绝时不更新时间；`loadNotes`、3 秒状态复位、进度刷新也不写。`CheckedAt` 与检查结果在 manager 锁内更新，notify 在解锁后执行；check 返回即 notify，让下载期间也可显示本次检查时间，不等 install 返回。不要在锁内调应用 save 或 UI。安装错误仍走现有 ErrorKey，不二次修改 CheckedAt。
3. 配置新增 `UpdateLastCheck string`，TOML `update_last_check,omitempty`，存 UTC RFC3339Nano 字符串；`configVersion` 仍 1。缺键／空串为零；格式无效、早于 Unix epoch 或晚于加载时钟的值忽略并在内存归一为空，不使整个配置加载失败、不在加载时立即写盘。合法记录启动时注入 manager；即使自动更新关闭也显示。保留所有旧键与 008 新键。
4. `main.go` 的 `updates.changed` 经 `RunOnMain` 读 snapshot：仅 CheckedAt 与配置记录不同才格式化并调用 `saveConfig`；进度／notes／3 秒复位不落盘。保存失败保留内存时间、头部显示 `ConfigError`，后续 save 可重试；成功不能顺手清掉尚未解决的合盖恢复错误。不能直接从 worker 写 `a.config`。`restartUpdate`／正常退出保存前也同步最新已完成 CheckedAt，避免 UI 通知尚未消费而丢记录；已取消的退出任务不制造新记录。
5. 时间比较使用当前本地时区的日历日，昨天用 `now.AddDate(0,0,-1)` 而非减 24 小时，支持夏令时。当日 `15:04`；昨天 `UpdateYesterday` + `15:04`；同年更早中文 `1月2日 15:04`、英文 `Jan 2, 15:04`；跨年中文 `2006年1月2日 15:04`、英文 `Jan 2, 2006, 15:04`。未来记录（运行中时钟回拨）暂时隐藏，不改写保存值；下一次完成检查按实际墙钟覆盖，不取历史最大值。
6. 零值只显示频率；非零追加 ` · ` + `fmt.Sprintf(text("UpdateLastCheck"), formatted)`。全文作为第二行 tooltip 及控件 Description，截断不丢可访问内容。开关关闭时频率使用新键 `UpdateScheduleOff`「自动检查已关闭」／“Automatic checks are off”；手动检查仍可用，不能继续写“启动时和每 24 小时检查”。

## 4. 快捷键与模块联动

### 4.1 已实现的注册基础

`changeAwakeEnabled`／`changeJSONEnabled` 成功关闭时注销对应组合，开启时调用 register；`registerAwakeShortcut`／`registerJSONShortcut` 在模块关闭时早退；`shortcutConflict` 跳过 `slot.Enabled=false`。模块关闭释放组合，保留磁盘上的快捷键值；重开后尝试注册原值，不静默换键。注册成功分支**已经清空**相应 error，原稿说“重开成功也不清错”不成立。

### 4.2 关闭、重开与实际注册所有权

- 快捷键组不折叠，录制器 Disabled、主体 0.45，独立 info 显示 `fmt.Sprintf(text("ModuleShortcutOff"), moduleName)`；隐藏旧冲突 alert。成功关闭时清该槽位 error，避免残留诊断；恢复失败时不清仍有效的错误。
- 开启模块与快捷键注册是两件事：组合被其它已启用槽位／系统占用时，模块仍开，快捷键保留原值，行内 alert 显示现有 `JSONShortcutConflict`／`ShortcutUnavailable`，其它入口仍可用。
- **补注册所有权**：关闭时不能无条件 `Unregister(config.XxxShortcut)`。例如关常亮→JSON 录入同一组合→重开常亮注册冲突→再关常亮，原代码会误注销 JSON。按 target 保存成功注册的实际组合，只注销本 target 持有的注册；失败注册不取得所有权。四个槽位统一使用此登记，录制 suspend／恢复也更新登记。应用内配置冲突检测不能替代实际注册所有权。

### 4.3 冲突反馈

内部四槽仍按 Enabled 比较；系统保留组合使用 `knownShortcutConflict`，框架注册失败仍是 `ShortcutUnavailable`。保持 `shortcutReasonKey` 的具体来源说明。与关闭模块同值不算冲突；重开时冲突不覆盖占有者。关闭清错、重开重新探测；不在渲染时尝试注册。

### 4.4 录制与模块状态的交互（需补）

现有 begin 会注销全部启用槽位，cancel 会按当前 Enabled 恢复；但 changeXxxEnabled 并不检查 `shortcutSuspended`，可在录制中提前注册或让隐藏录制继续改值，不能宣称完整正确。

### 5.5 运行中的会话：安全关闭事务

004 的不变量仍有效：**先确认我方合盖已安全恢复，才能停普通常亮、卸载助手并提交模块关闭**。当前已有 stop → Unregister → 注销快捷键基础，但并非整条事务已完备：`awake.stop` 无 error 返回且忽略 Kill 错误；`awakeChanged` 会中途 save；change 的失败分支也未统一刷新。

目标顺序：

1. 在 UI 主线程取消录制。`lidBusy`（授权／enable）或 `lidPolling` 尚在运行时，关闭请求保持开启、返回可重试失败，不排队关闭、不等待控制器锁阻塞主线程；进行中画loader；被回调门禁拒绝时用新键 `ModuleBusy` 表达。开关、卡片／命令入口在 busy 时 Disabled，回调仍做门禁。请求 generation 与异步 completion 校验当前模块状态，关闭成功后迟到回调不得重新启用合盖。
2. 保留已提交 `AwakeEnabled=true`，设置内部关闭中标记，阻止新 start／toggle／URL／CLI／快捷键请求；已有 stop／恢复操作仍可收敛。CLI 此时用既有 `busy`，不能提前报 disabled。耗时的 lid.stop／service.Unregister 在 worker 串行执行，结果回主线程提交；worker 不改 config、不触碰 UI。controller 既有锁继续保护 stop／poll／enable。
3. `lid.stop()`：无 connection 且无我方标记、无 on／restore-failed 状态时可无操作成功；否则重连、发送 disable，只有 `r.OK && r.Value != nil && *r.Value==0` 且本机标记移除成功才算成功。helper 负责 pmset 写入、读回与 journal；应用不得自行跳过 controller、伪造读回或覆盖 `on-foreign`。恢复失败／读取不确定／标记删除失败立即中止，不卸载，不停 caffeinate，不注销快捷键，不提交 false；保留 004 的恢复入口。
4. 合盖确认恢复后清 session lid，再停止普通常亮。`awake.stop()` 当前无 error，因此本期不能称“任一步失败都能回滚”；实施时在关闭事务的停止路径确认子进程已退出（Kill/Wait 的错误通过控制器受控处理），停止未确认则保持模块开、错误 `AwakeStopError`，不得卸载或伪称已停。涉及既有子退出 watcher 时避免二次 Wait；按 generation 收敛。关闭事务使用非阻塞UI的停止确认接口，复用已有Wait监听结果，有界等待3秒（moduleStopTimeout）；超时视为停止未确认。已在步骤3恢复的路径不再从beforeStop同步重做一次IPC；通知须在controller解锁后派发，主线程不得等待一个正在RunOnMain等待主线程的worker。`awakeChanged` 只保存当前已确认的会话状态，事务期间绝不能保存 Enabled=false。
5. 如果服务已注册且 Available，才调用 service.Unregister。卸载失败仍保留模块开、显示 `LidRestoreFailed`，但合盖与普通常亮**已停止，不重新启动旧会话**；这是保持模块可用的回退，不是系统状态全量回滚。无服务／不支持合盖时跳过卸载。
6. 全部成功才在主线程提交 Enabled=false，按实际持有者注销快捷键，清槽位错误／临时状态，保存并刷新 §5.7 的所有表面。保存失败显示 ConfigError，运行时仍已安全关闭、配置待重试，不为了“回滚文件”重新开启系统会话。任何失败出口都清关闭中标记、恢复开关并 invalidate；安全错误不能被随后普通 save 清掉。

没有合盖的普通常亮也必须先停止、确认退出再关闭；不活动但有遗留 marker／restore-failed 仍走恢复，不能仅看 Active。重新开启模块只恢复入口与快捷键，不自动恢复本次关闭前的常亮或合盖会话；保留用户时长／模式／合盖偏好供下次明确启动。

**JSON**：成功关闭时注销本槽持有的快捷键、移除 JSON 菜单、遍历副本 destroyJSON 全部窗口（包括置顶窗口），按既有工具窗规则丢弃未保存内容、不询问。与 008 接线时 Destroy 前采集合法待保存位置、OnClosed 只移除文档，不读已销毁句柄。关闭进行中的文件读取／bridge 回调必须检查 document.closed 和模块 Enabled，不得补建新窗；重开只允许新建，不复活旧文档。

### 6.3 「不在 PATH」

**现状事实**：代码里没有任何 PATH 检查；`cliPaths` 只算 `link`、`target`、`bundle`。006 §9 第 3 项已明确决策「`~/.local/bin` 不在 PATH 时不提示」，理由是低信息密度，命令写在 README 与 tooltip。

定稿**沿用 006 的决策**，不在本轮新增 PATH 探测，因为：

1. GUI 进程由 launchd 启动，`os.Getenv("PATH")` 是 `/usr/bin:/bin:/usr/sbin:/sbin` 一类，几乎永远不含 `~/.local/bin`，会误报。
2. 真正的判断要跑用户的登录 shell（`$SHELL -lc 'echo $PATH'`），那等于执行用户配置脚本，慢、可能有副作用。
3. 解析 shell 配置文件是启发式，误报比不报更糟：用户会去修一个本来就对的东西。

替代做法：`cliInstalled` 的 tooltip 里已经带完整路径（`CLIInstalled` 的 `%s`），README 与 006 文档给出手动加 PATH 的一行命令。本期不追加PATH异常态或探测流程，见§12第5项。

```go
    var height float32
    for i, row := range rows {
        if i > 0 { height += t.StrokeHairline }
        height += row
    }
    return height
}

func pageHeight(t tokenValues, page int, awakeOn, showPlacement,
    fixedDisplay, hasCLI, ready bool) float32 {
    section := func(cards ...float32) float32 {
        height := t.SizePageHeader
        for _, card := range cards {
            height += t.Space8 + t.SizeGroupHeader + t.Space8 + card
        }
        return height
    }
    // Each iteration already contributes Space8 before its group.
    switch page {
    case 0:
        rows := []float32{rowHeight(t, 0), rowHeight(t, 1)}
        if hasCLI { rows = append(rows, rowHeight(t, 1)) }
        if showPlacement {
            rows = append(rows, rowHeight(t, 3))
            if fixedDisplay { rows = append(rows, rowHeight(t, 0)) }
        }
        return section(cardHeight(t, rows...))
    case 1:
        height := section(cardHeight(t, rowHeight(t, 0),
            rowHeight(t, 0), rowHeight(t, 2)))
        if ready { height += t.Space8 + t.SizeRowHeight + t.Space24 }
        return height
    case 2:
        if awakeOn {
            return section(cardHeight(t, rowHeight(t, 2)),
                cardHeight(t, rowHeight(t, 3)))
        }
        return section(cardHeight(t, rowHeight(t, 3)))
    case 3:
        return section(cardHeight(t, rowHeight(t, 3), rowHeight(t, 3)),
            cardHeight(t, rowHeight(t, 3), rowHeight(t, 3)))
    case 4:
        return section(cardHeight(t, rowHeight(t, 3)))
    }
    return 0
}
```

008 的显示器快照在一帧开始时只读一次，`showPlacement=len(displays)>=2`，`fixedDisplay=config.WindowPlacement=="display"`；hasCLI 从同帧 paths.status 得到（含 broken、不含 absent 或 paths 不可用），ready 从同一个 update snapshot 得到。不可让视图与测高各自探测一次，造成分隔线／行数不一致。总开关位于页头，不是行数据。

`ceil4(x)=ceil(x/Space4)×Space4`。`settingsHeight` 接收上述全部状态并转发，返回 `ceil4(max(globalMinHeight, pageHeight+2×Space24))`；删除旧 hasError 参数及所有调用，错误不加高。可另抽 settingsNaturalHeight 供逐页断言，不能把自然高误当实际最小窗口。

### 7.4 最小尺寸与全部调用方

`globalMinHeight = ceil4(max(SizeWindowMinHeight, sidebarNaturalHeight, maxAllPageContent+2×Space24))`。maxAllPageContent 枚举所有可见组合（含 CLI、008 固定五行、常亮开／关、关于就绪），是**稳定全局最大值**，不随当前屏数、模块开关、语言或 CLI 安装状态变化。品牌 A 侧栏自然高 `2×12+12+20+1+3×16+(5×40+4×4)=321`，不控制最大值。全局最终为 **720 × 388**（五行通用与关于就绪并列最高）。

- `settingsMinimumSize()` 使用同组 Token 和最高状态求最大值；不要另写 380 常量，更不能用当前可见页求下限。
- `settingsSize`、createSettingsWindow 的 MinWidth/MinHeight、旧尺寸加载夹取、rememberWindowSize、测试、截图 QA 与隐藏原生 helper 全部同步；旧 368／380 抬到 388，用户较大尺寸保留。
- 切页、开关模块、008 切方式／拔插屏只 invalidate，不 SetSize；所有主页在最小窗口无滚动，更新内容子页已有滚动。分组／文案状态不能隐式撑高。将来内容增长超出时另设计滚动，不在本期预先加滚动。

### 7.5 MyGo 已核对的过渡

导航项用稳定 Key，仅 `Transition(ui.ElementTransition{Duration: 140*time.Millisecond, Colors: true})`。不设置 Position／Size／Enter／Exit，不动画折叠与窗口尺寸。API 文档已说明颜色支持与 ReduceMotion 行为；真实主题切换／选中／键盘表现留实现验收，不再列“是否存在 API”为待决定事项。

## 14. 实施记录（2026-11-06）

分支 `feat/settings-modules` 按本文实现，`./scripts/selftest.sh` 全绿。以下为落地时按最保守方式处理的五处长尾，均不改变本文已定的方向：

1. **命令面板的 busy 门禁**：面板的行没有「禁用」状态，因此模块关闭进行中时设置命令与常亮命令仍会列出，执行时按 §5.5 返回 `ModuleBusy` 并就地显示，不隐藏入口；卡片面板与全局快捷键走同一门禁。新键 `ModuleBusy` 的文案因此同时用作页头错误与面板就地错误。
2. **侧栏英文模块名**：`Keep awake` 在 12/500 下量到 68.56，比 144 侧栏里图标列加两处 `Space8` 后剩下的 68 宽多出约半个点。导航文字用 `Shrink(0)` 取自身宽度，多出的半像素落进右侧 8 的内边距，不截断、不改字号、不改几何。
3. **关闭事务的执行位置**：与 `lid.enable` 同一约定——只有原生助手路径（`lidAsync=true`）把 lid.stop、停止确认与卸载放到 worker 再经 `RunOnMain` 提交；无原生助手时（单元测试与不支持合盖的构建）三步在原地串行执行。停止确认由 `awakeController` 复用既有 `Wait` 监听，超时 `moduleStopTimeout=3s` 即报 `AwakeStopError`。
4. **快捷键 alert 的气泡**：异常 alert 的无障碍名称是「组合键 + 原因」一句完整文本，气泡则复用 R15 的键帽写法（`shortcutTooltip`），与 `#66` 合并后的录制器一致；③ 的 info 图标仍是纯文本 tooltip。
