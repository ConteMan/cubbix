## 结论摘要

| 项 | 结论 |
| --- | --- |
| 反馈方式 | 屏幕提示（默认）／系统通知／关闭 |
| 屏幕提示位置 | 左上、右上（默认）、左下、右下、居中 |

## 1. 触发范围

### 1.1 规则

**只在「操作本身没有其它可见结果」时提示。** 用户能从菜单、窗口或设置里看到结果的操作不提示，避免重复打扰。

| 触发点 | 是否提示 | 理由与依据 |
| --- | --- | --- |
| 全局快捷键开关常亮（默认 ⌃⌥⌘K） | **是** | 快捷键不打开任何窗口，菜单没有展开，用户看不到状态。注册见 `awake_app.go:103-110`，切换见 `awake_app.go:66-75` |
| 菜单「开启常亮」／「停止」 | 否 | 菜单本身显示状态行（`awake_app.go:138`）与随状态切换的开启／停止条目（`awake_app.go:140`、`awake_app.go:156`），用户已看到 |
| 菜单选择模式／时长／不限时、打开自定义与跟随窗口 | 否 | 菜单单选状态与小窗口即时反映 |
| 快捷键录制、冲突提示 | 否 | 设置页就地显示录制态与错误图标（`awake_view.go:356-416`） |
| 开机启动、语言、自动更新等设置项 | 否 | 开关与分段控件即时反映 |
| 电池提醒 | 系统通知，**恒开** | 属于状态与安全提醒，与「反馈方式」无关，见 §5.4 |
| JSON 新建窗口快捷键（规划 ⌃⌥⌘J） | 否 | 新窗口出现本身就是反馈 |
| JSON 复制结果、置顶等窗口内操作 | 否 | 沿用窗口内 check／选中态，见 R07 交付「顶部」一节 |

> JSON 格子目前只是设置页里的占位开关（`awake_view.go:361-370`），尚未实现。本节对它的要求只是「将来能复用同一个反馈组件」，不依赖 JSON 的实现顺序。

### 1.2 实现落点

反馈不能写在 `toggleAwake()` 里，否则菜单点击也会触发。为快捷键单独包一层：

```go
// 只在全局快捷键路径调用
func (a *application) shortcutToggleAwake() {
	a.toggleAwake()
	a.announceAwake()
}
```

`a.registerShortcut(..., a.toggleAwake)`（`awake_app.go:107`、`awake_view.go:337`）改成注册 `a.shortcutToggleAwake`。菜单回调（`awake_app.go:140`、`awake_app.go:156`）保持调用 `toggleAwake`／`awake.stop`，不产生提示。

`announceAwake()` 在切换之后读 `a.awake.snapshot()`（`keepawake.go:24-28`：`Active`、`Session{Mode, End, PID, Name}`、`Error`）合成文案；开启失败时用 `Error` 对应的失败文案（`awake_app.go:43-46` 会写入 `AwakeStartError`）。

## 2. 设置项

### 2.1 新增配置字段

按 `config.go:14-27` 的既有风格写入 TOML，字段顺序放在语言/启动项之后：

| 字段 | 类型 | 默认值 | 取值 |
| --- | --- | --- | --- |
| `FeedbackMode` | string | `hint` | `hint`（屏幕提示）、`notification`（系统通知）、`off`（关闭） |
| `FeedbackCorner` | string | `top-right` | `top-left`、`top-right`、`bottom-left`、`bottom-right`、`center` |

兼容性：`loadConfig` 先取 `defaultConfig()` 再 `toml.Unmarshal`（`config.go:30-38`），旧 `config.toml` 缺这两个键时自动落到默认值，**不需要升 `configVersion`**（`config.go:11`、`config.go:51-53`）。但要照 `config.go:54-60` 对语言的做法补枚举校验，非法值返回错误，避免手改配置后行为不可预期。

### 2.2 放在哪一页

放在**「快捷键」设置页**（`main.go:409-415` 的 `R05Shortcuts`，`awake_view.go:356-416` 的 `a.page == 3` 分支）。理由：反馈的意义是「快捷键按下去有没有生效」，和快捷键录制在同一页最容易被找到；「格子」页继续只放功能开关。

卡片内新增两行，排在「常亮开关」之后：

| 行 | 左 | 右（控件） |
| --- | --- | --- |
| 1 | 「反馈方式」`FeedbackMode` | 三段分段控件，文字：屏幕提示／系统通知／关闭 |
| 2 | 「提示位置」`FeedbackPosition` | 五段分段控件，每段一个「屏幕缩略框 + 一个点」的位置图标 |

控件细节：

- 反馈方式沿用语言选择的写法（`main.go:447-456`）：`ui.SegmentedBase` + `Track.Size(SizeLanguageSelectorWidth, SizeSegmentHeight)`，宽 318 与语言行同宽，视觉对齐。
- 提示位置：`ui.SegmentedBase(c.Key("feedback-position"), &a.feedbackCorner, 5)`，每段内画一个 `16 × 16` 方框（`StrokeHairline` 描边、`RadiusControl` 圆角、`ColorSeparator` 描边色）和一个 `Space4` 实心点（`ColorText`），点落在该段的四角或中心。选中的段与语言选择一致：底色 `ColorAccent`、内容 `ColorOnAccent`。全图标不依赖语言，避免英文「Top left」撑破约 28 px 宽的段。轨道宽 144（新 Token `SizeFeedbackPositionWidth`）。
- 可访问性：位置的每段用 `Label(text("FeedbackTopLeft"))` 之类做无障碍名（`docs/ui/segmented.md` 说明分段控件对辅助技术呈单选组）。
- 联动：`FeedbackMode != hint` 时，位置行整行 `Disabled(true)` 并降到 `OpacityDisabled`；不隐藏，避免布局跳动（设置窗口高度在 `main.go:112-122` 按行数计算，隐藏行会让高度计算变复杂）。
- 反馈方式被系统拒绝后（§5.3），「系统通知」这一段右侧加一个 `triangle-alert` 图标，tooltip 用 `FeedbackDenied`；不改用户的选择值。

行数变化的影响：快捷键页从 1 行变 3 行，卡片内是 4 行（含分隔线）。最小窗口 720 × 340（`settingsMinimumSize()`，`main.go:124-128`）已能容纳 4 行 × 48 + 3 × 1 + 上下 2 × 24 = 243，**不需要改窗口最小高度**。但 `settingsHeight()`（`main.go:112-122`）对 `page != 1` 的固定 2 行假设要改成按页最少行数计算，否则 4 行内容会溢出 176 的默认高度。

## 3. 屏幕提示

### 3.1 内容

一行：**图标 + 一句话**，无标题、无按钮、无说明文字。

| 状态 | 图标（Lucide 0.468.0，已随仓库打包） | 文案键 |
| --- | --- | --- |
| 常亮已开启（固定时长） | `sun` | `ToastAwakeOn` |
| 常亮已开启（不限时） | `sun` | `ToastAwakeOnUnlimited` |
| 常亮已开启（直到某时刻） | `sun` | `ToastAwakeOnUntil` |
| 常亮已开启（跟随进程） | `sun` | `ToastAwakeOnFollow` |
| 常亮已关闭 | `power` | `ToastAwakeOff` |
| 开启失败 | `triangle-alert` | `ToastAwakeError`（图标用 `ColorDanger`） |

- 图标取自 `design/assets/lucide-0.468.0/`（菜单栏图标是品牌 TIFF，不在此列；`eye` 不在打包集合内，因此不用菜单栏的睁眼/闭眼）。
- 时长短语复用已有键：`R05Half`（30 分钟）、`R05Hour`、`R05Two`、`R05Four`；自定义分钟用新键 `ToastMinutes`；跟随进程复用 `AwakeFollowing`（「跟随 %s」）。
- 单行，超长用 `SingleLine` + `Ellipsis("…")` 截断（`ui/api_gen.go:3628-3637`）。进程名过长时截断优先，不换行——两行会让浮层高度变化，位置计算要跟着改。

### 3.2 尺寸、圆角、颜色（全部引用 Token）

| 属性 | Token | 值（浅／深） | 说明 |
| --- | --- | --- | --- |
| 浮层槽宽 | `SizeToastSlotWidth`（**新增**） | 320 | 窗口宽度固定，理由见本节末段 |
| 浮层槽高 | `SizeToastHeight`（**新增**） | 36 | 单行文字 13 × 1.5 ≈ 20 + 上下各 `Space8` |
| 胶囊背景 | `ColorMenuSurface` | #FFFFFFEB / #2C2C2CEB | R05B 为菜单与系统通知定义的半透明表面，直接复用 |
| 胶囊圆角 | `RadiusWindow` | 12 | 归类为「窗口」档（`AGENTS.md` 三档圆角） |
| 文字 | `ColorText` | #202020 / #F5F5F5 | |
| 文字字号 | `FontSizeBody` | 13 | 与设置页正文一致 |
| 图标尺寸 | `SizeIcon` | 16 | |
| 图标与文字间距 | `Space8` | 8 | |
| 胶囊内水平留白 | `Space12` | 12 | |
| 关闭态图标色 | `ColorTextSecondary` | #636363 / #B5B5B5 | 「已关闭」比「已开启」视觉更轻 |
| 失败图标色 | `ColorDanger` | #BC3030 / #FF8D8D | 唯一允许彩色的语义 Token |
| 距屏幕边缘 | `Space24` | 24 | 与设置页主内容留白同值 |
| 描边 | 无 | — | 用系统或自绘阴影区分边界，见 §3.6 |

新增 Token 只有两个尺寸：`SizeToastSlotWidth = 320`、`SizeToastHeight = 36`；另加设置页用的 `SizeFeedbackPositionWidth = 144`。三者写进 `design/cubbix.pen` 的变量、`design/tokens.json`，再由 `python3 scripts/tokens.py` 生成 `tokens.go`（`scripts/tokens.py:1-46`），并在 `design/token-index.md` 的 R05B 之后追加一张表。其余全部引用既有 Token，不新增别名。

胶囊宽度由内容决定（图标 16 + 间距 8 + 文字宽 + 两侧 24），在固定宽 320 的槽内按位置对齐：右上／右下靠右，左上／左下靠左，居中居中。

槽宽固定是为了让**定位只依赖 Token**：贴边放置需要 `SetPosition` 知道窗口宽度，而 `ui` 的文本测量只在视图构建时可调（`Context.MeasureText`，`模块缓存/github.com/egoist/mygo@v0.6.2/ui/api_gen.go:340-348`），没有「先量再摆」的一步。固定槽宽把「量」这一步去掉，代价是超长文案被截断（§3.1）。槽外的透明区域看不见也点不到（鼠标穿透），不影响观感与点击。

### 3.3 浅色与深色

`applyTheme`（`main.go:370-388`）已把 `ColorMenuSurface`、`ColorText`、`ColorTextSecondary`、`ColorDanger` 注入 `ui.Theme`，浮层视图复用同一个 `applyTheme(c)`，因此浅深主题、中英字体（`FontFamily`）与主窗口自动一致，不需要单独分支。深色下 `ColorMenuSurface` 是 92% 不透明的 #2C2C2C，浅色下是 92% 的白色，两者的底色是 R05B 定义的既有表面色（`design/rounds/R05-2026-10-29-常亮/README.md`），提示里的文字对比度需按 `design/scripts/contrast.py` 的口径在 R08 画板阶段复核一次。

### 3.4 位置与边缘距离

以 `mygo.Display.WorkArea` 为准（`模块缓存/github.com/egoist/mygo@v0.6.2/modules.go:209-225`），它已排除菜单栏与 Dock，因此：

| 位置 | 计算 |
| --- | --- |
| 右上 | `x = WorkArea.X + WorkArea.Width - SlotWidth - Space24`，`y = WorkArea.Y + Space24` |
| 左上 | `x = WorkArea.X + Space24`，`y = WorkArea.Y + Space24` |
| 右下 | `x` 同右上，`y = WorkArea.Y + WorkArea.Height - Height - Space24` |
| 左下 | `x` 同左上，`y` 同右下 |
| 居中 | 在 `WorkArea` 内水平与垂直都居中 |

坐标原点在**主显示器左上角**（`模块缓存/github.com/egoist/mygo@v0.6.2/window.go:54-56` 的 `Rectangle` 说明），与 `Window.SetPosition` 同一坐标系，不需要翻转 Y。

居中取 `WorkArea` 的几何中心而不是黄金比例位置，理由：四个角与中心用同一条边距规则（角 24、中心对称），规则可一句话讲清，也不受 Dock 显隐影响。

### 3.5 多显示器

**显示在鼠标所在的屏幕。**

```go
d := mygo.Screen.DisplayNearestPoint(mygo.Screen.CursorScreenPoint())
```

（`模块缓存/github.com/egoist/mygo@v0.6.2/modules.go:267-288`；`DisplayNearestPoint` 对屏幕外坐标按包围盒最近距离退化，鼠标恰在边界时取最近的一块。）

理由：快捷键在任何一块屏幕上按都一样，鼠标位置是用户当下的注意力焦点；用菜单栏屏幕（`Screen.PrimaryDisplay()`，`modules.go:247-258`）会让提示跑到另一块屏幕，用户在多屏工作时容易漏看。

代价与兜底：纯键盘操作时鼠标可能停在别处，提示会出现在「不是正在看的那块」屏幕上。既然默认位置在右上且贴近菜单栏，接受这个代价；若维护者希望跟随焦点，改成 `PrimaryDisplay()` 只是一行替换（见 §9 待定项 4）。

### 3.6 出现与消失

浮层内容是原生 UI（`WindowOptions.Content` + `ui.View`），动画用 `ui.ElementTransition`（`模块缓存/github.com/egoist/mygo@v0.6.2/ui/transition.go:20-54`，`Motion` 见 `:55-68`）在「有／无胶囊」之间切换：

| 阶段 | 时长 | 缓动 | 动的属性 |
| --- | --- | --- | --- |
| 出现 | 150 ms | `ui.EaseOut` | 不透明度 0 → 1，缩放 0.96 → 1，沿所在角的方向位移 `Space4` |
| 停留 | 1200 ms | — | 静止 |
| 消失 | 150 ms | `ui.EaseIn` | 只做不透明度 1 → 0（不做位移，避免与再次触发叠加） |

合计约 1.5 s。计时全部在主线程用 `time.AfterFunc` + `mygo.RunOnMain`，不要跨线程碰窗口。

`Motion`（`transition.go:55-68`）的位移、缩放在系统「减少动态」下会自动瞬时完成，只有不透明度平滑过渡（`transition.go:85-88` 与 `ui/api_gen.go:2667-2682` 的说明），因此不需要为无障碍另写一套。

阴影：`DisableShadow: true` + 关闭窗口阴影（`SetHasShadow(false)`，`window.go:977`）。理由见 §4 核对表第 10 项——透明窗口的阴影形状没有公开控制，可能出现矩形硬边。如果评审希望在浅色桌面上强化边界，改用视图内 `Element.Shadow`（`ui/api_gen.go:5269`）配 `ColorOverlay`，在 Token 表里补一条模糊半径。

### 3.7 连续触发的合并

窗口、视图与计时器都**只有一个**：

| 情况 | 行为 |
| --- | --- |
| 同一文案重复触发（例如连按两次开关后又回到开启） | 只重置停留计时器，不重建页面、不重播入场动画 |
| 不同文案在停留期内到达 | 原位替换图标与文字，重置停留计时器，**不重播**入场动画（重播会闪烁）；文字替换用 `ContentTransition` 让它平滑切换 |
| 新的文案出现在消失动画期间 | 取消隐藏，从当前不透明度重新入场（`Transition` 会从当前状态继续，不跳变） |
| 上一个计时器尚未到期 | 每次显示把 generation 加一；计时器回调只在 generation 与当前一致时执行 `Hide()`，避免旧计时器提前关掉新提示 |

验收方式：连按快捷键 5 次，屏幕上只应看到一个胶囊，文案跟随最后一次状态，可见总时长为「最后一次触发 + 1.5 s」。

## 4. 不抢焦点：MyGo v0.6.2 能力核对

### 4.1 窗口创建参数

```go
w := mygo.NewWindow(mygo.WindowOptions{
	Title:             "Cubbix",
	Width:             int(t.SizeToastSlotWidth),
	Height:            int(t.SizeToastHeight),
	Hidden:            true, // 先建好，显示时才 ShowInactive
	Frameless:         true,
	Transparent:       true,
	DisableShadow:     true,
	DisableResize:     true,
	DisableMove:       true,
	DisableMinimize:   true,
	DisableMaximize:   true,
	DisableFullScreen: true,
	DisableClose:      true,
	Panel:             true, // 关键：不激活应用的浮层面板
	Content:           ui.View(a.feedbackView),
})
w.SetIgnoreMouseEvents(true)
```

显示只用 `w.ShowInactive()`，绝不用 `w.Show()` 或 `w.Focus()`。

### 4.3 需要实测的两项

1. **全屏应用之上**（第 6 项）：`FullScreenAuxiliary` + 浮动层是 AppKit 的标准组合，但 Cubbix 从未在真机上验证过「全屏 Safari／Terminal 里按快捷键能看到提示」。验收时必须在至少一个全屏应用上确认（见 §8）。若实测不成立，回退方案是 purego 把窗口层级提到 `NSStatusWindowLevel`（25）。
2. **透明窗口的自绘圆角与抗锯齿**（第 8 项）：需要在浅色与深色桌面墙上各看一眼边缘是否发毛、四角是否有底色残留。

### 4.4 purego 备用方案

仓库已经在用 `github.com/ebitengine/purego/objc` 调 AppKit（`awake_native_darwin.go:17-24`，读取运行中应用的图标），因此「MyGo 没提供的能力直接对 `NativeHandle()` 发消息」是既有做法，`Window.NativeHandle()` 是公开 API（`window.go:1095`）。

| 需要的 AppKit 行为 | 选择子 | 状态 |
| --- | --- | --- |
| 提高窗口层级到状态栏高度 | `setLevel:`（`NSStatusWindowLevel` = 25，浮层 3、弹出菜单 101，见 `internal/darwin/window.go:29-31`） | 调用方式与仓库现有 purego 用法一致；**该调用本身未在本机验证** |
| 鼠标穿透（若 MyGo 缺） | `setIgnoresMouseEvents:` | MyGo 已有公开 API，不需要；purego 路径**未证实** |
| 面板不成为 key window（若 MyGo 缺） | `NSPanel` 的 `setBecomesKeyOnlyIfNeeded:` 或 `setStyleMask:` 追加 nonactivating 位 | **未证实**（只在创建时带上 nonactivating 是 MyGo 注释的说法，`:137-142`） |
| 视图层圆角 | `layer.setCornerRadius:` + `setMasksToBounds:` | MyGo 在 flyout 里用过同名调用（`internal/darwin/window.go:254-267`），普通窗口**未证实** |

代码骨架（`//go:build darwin`）：

```go
func raiseToStatusLevel(handle uintptr) {
	if handle == 0 {
		return
	}
	const nsStatusWindowLevel = 25
	objc.ID(handle).Send(objc.RegisterName("setLevel:"), nsStatusWindowLevel)
}
```

只有在 §8 的实测项失败时才启用，并且要有对应 `//go:build darwin` 测试辅助（可参考 `native_darwin_test.go:20` 起的 `TestMain` 隐藏窗口辅助进程做法，它从不显示窗口、不激活应用）。

## 5. 系统通知

### 5.1 调用方式

```go
err := mygo.NewNotification(mygo.NotificationOptions{
	ID:     "cubbix.feedback.awake",
	Title:  a.text(locale, "Awake"),   // 「常亮」/「Awake」
	Body:   body,                      // 与屏幕提示同一句
	Group:  "cubbix.feedback",
	Silent: true,
}).Show()
```

- `Body` 与屏幕提示共用同一套文案键（§6），保证两种方式说同样的话。
- 固定 `ID`：同一 ID 的通知会替换仍在显示的那条（`modules.go:807-810`），天然实现「连续触发只保留一条」。**注意**：`ID` 固定意味着文案变化时是「替换」而不是「追加」，这正是我们要的行为。
- `Silent: true`：快捷键反馈是确认信息，不该每次都响（推荐值，见 §9 第 7 项）。
- `Group` 让通知在通知中心堆叠在一起，便于事后回看。
- 调用点与电池提醒一样在主线程（`awake_app.go:196-202` 的 `mygo.RunOnMain` 包裹），`Show()` 会阻塞到系统接收，不要在视图构建期间同步调用。

### 5.2 首次权限

macOS 上第一次 `Show()` 会弹出系统授权询问，`Show()` 等到用户作答（`modules.go:908-917`）。因此第一次按快捷键时会先看到系统授权弹窗，用户作答后才出现通知——这是平台行为，不做自定义前置说明。

### 5.3 被拒绝时

`Show()` 返回 `mygo.ErrNotificationsDenied`（`modules.go:908-910`，仓库已有同样的判断：`battery_notification.go:30-37`）。

**推荐：自动改用屏幕提示，并记住这次结果。**

| 步骤 | 行为 |
| --- | --- |
| 收到 `ErrNotificationsDenied` | 立即用屏幕提示把这条反馈补发一次（用户按了快捷键，必须得到反馈） |
| 记忆 | 本次运行内标记「通知不可用」，后续不再调用 `Show()`，直接走屏幕提示（与 `batteryNotifier.denied` 的 `battery_notification.go:23` 一致） |
| 设置页 | 「系统通知」段右侧显示 `triangle-alert`，tooltip `FeedbackDenied`；不改写用户存储的 `FeedbackMode` |
| 「关闭」时被拒绝 | 不降级：用户明确选择不要反馈，就什么都不显示 |

不推荐「被拒绝后就不提示」：通知权限是系统层面的设置，用户拒绝往往只是嫌通知吵，而快捷键反馈正是他们想要的静默确认，降级到屏幕提示更符合意图。

权限状态在应用重新启动后可能变化（用户去系统设置里打开），所以「记住拒绝」只在本次运行内有效，下次启动仍按用户选择的 `FeedbackMode` 尝试一次。

### 5.4 与电池提醒的关系

电池提醒保持现状：始终走系统通知（`battery_notification.go`、`awake_app.go:196-234`），**不受 `FeedbackMode` 影响**。理由：它是「常亮仍在运行，但已切到电池」的安全提示，属于通知，不属于操作确认；用户把反馈方式设成「关闭」不应该让电池提醒消失。
