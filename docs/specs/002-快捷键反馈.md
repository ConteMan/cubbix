## 1. 触发范围

### 1.1 规则

**只在「操作本身没有其它可见结果」时提示。** 用户能从菜单、窗口或设置里看到结果的操作不提示，避免重复打扰。

| 触发点 | 是否提示 | 理由与依据 |
| --- | --- | --- |
| 全局快捷键开关常亮（默认 ⌃⌥⌘K） | **是** | 快捷键不打开任何窗口，菜单没有展开，用户看不到状态。注册见 `awake_app.go:103-114`，切换见 `awake_app.go:66-75` |
| 菜单「开启常亮」／「停止」 | 否 | 菜单本身显示状态行（`awake_app.go:142`）与随状态切换的开启／停止条目（`awake_app.go:144`、`awake_app.go:160`），用户已看到 |
| 菜单选择模式／时长／不限时、打开自定义与跟随窗口 | 否 | 菜单单选状态与小窗口即时反映 |
| 快捷键录制、冲突提示 | 否 | 设置页就地显示录制态与错误图标（`awake_view.go:440-499`） |
| 开机启动、语言、自动更新等设置项 | 否 | 开关与分段控件即时反映 |
| 电池提醒 | 系统通知，**恒开** | 属于状态与安全提醒，与「反馈方式」无关，见 §5.4 |
| JSON 新建窗口快捷键（默认 ⌃⌥⌘J，已实现：注册 `json_app.go:50-63`，开窗 `json_app.go:134-141`） | 否 | 新窗口出现本身就是反馈 |
| JSON 复制结果、置顶等窗口内操作 | 否 | 沿用窗口内 check／选中态，见 R07 交付「顶部」一节 |

> JSON 格子已实现（PR #27）：「格子」页有开关（`awake_view.go:388-395`），「快捷键」页有独立的录制行（`awake_view.go:396-400`）。本节对它的要求只是「同一个反馈组件能被多个格子复用」，不改变 JSON 的现有行为。

### 1.2 实现落点

反馈不能写在 `toggleAwake()` 里，否则菜单点击也会触发。为快捷键单独包一层，并且**先拿到 `start` 的 error，再读快照**：

```go
// 只在全局快捷键路径调用
func (a *application) shortcutToggleAwake() {
	a.announceAwake(a.toggleAwakeResult())
}
```

`toggleAwake()`（`awake_app.go:66-75`）拆成返回 error 的内核，外加保持原签名的包装（菜单继续按原来的方式调）：

```go
func (a *application) toggleAwake() { _ = a.toggleAwakeResult() }

func (a *application) toggleAwakeResult() error {
	if !a.config.AwakeEnabled {
		return nil
	}
	if a.awake.snapshot().Active {
		a.awake.stop()
		return nil
	}
	return a.startAwake(a.selectedSession())
}
```

`startAwake`（`awake_app.go:39-47`）改签名 `func (a *application) startAwake(s awakeSession) error`：内部照旧写 `a.settingsError = "AwakeStartError"`（那是设置页的错误位，不是提示文案），并把 error 返回。

为什么必须用返回值：`awakeController.start`（`keepawake.go:103-121`）只在 `launch` 失败时写 `state.Error`（`:117`）；模式非法、已过期、跟随目标已退出这三种情况在 `:109-112` 直接 `return err`，不写 `state.Error`，`Active` 保持 false。此时只读快照会得到 `Active=false` 加空 `Error`，提示会错误地显示成「常亮已关闭」。另外 `stop()`（`keepawake.go:97-102`）会清空 `state.Error`，失败后紧接着的一次切换也可能把 error 抹掉。所以失败只看这次调用的返回值：

- `err != nil` → 失败提示（`ToastAwakeError`、`triangle-alert`、`ColorDanger`）。
- `err == nil` → 读 `a.awake.snapshot()`（`keepawake.go:24-28`：`Active`、`Session{Mode, End, PID, Name}`、`Error`）决定开启态或关闭态；这里不再读 `Error`，它只服务于菜单与设置页（`awake_app.go:120-122`）。

`a.registerShortcut(..., a.toggleAwake)`（`awake_app.go:111`、`awake_view.go:360`）改成注册 `a.shortcutToggleAwake`。菜单回调（`awake_app.go:144`、`awake_app.go:160`）保持调用 `toggleAwake`／`awake.stop`，不产生提示；对话框确认直接调 `a.awake.start`（`awake_view.go:139-142`），也不产生提示。

## 2. 设置项

### 2.1 新增配置字段

按 `config.go:14-32` 的既有风格写入 TOML，字段顺序放在语言/启动项之后：

| 字段 | 类型 | 默认值 | 取值 |
| --- | --- | --- | --- |
| `FeedbackMode` | string | `hint` | `hint`（屏幕提示）、`notification`（系统通知）、`off`（关闭） |
| `FeedbackCorner` | string | `top-right` | `top-left`、`top-right`、`bottom-left`、`bottom-right`、`center` |

兼容性：`loadConfig` 先取 `defaultConfig()`（`config.go:34-36`）再 `toml.Unmarshal`（`config.go:47-48`），旧 `config.toml` 缺这两个键时自动落到默认值，**不需要升 `configVersion`**（`config.go:12`、`config.go:51-53`）。但要照语言的做法（`config.go:54-58`）补枚举校验，非法值返回错误，避免手改配置后行为不可预期。默认值 `hint` 与 `top-right` 写进 `defaultConfig()`，并在 `config_test.go` 补一组断言。

### 2.2 放在哪一页

放在**「快捷键」设置页**（导航项 `R05Shortcuts` 在 `main.go:456-480`，内容分支为 `awake_view.go:386-401` 的 `else`）。理由：反馈的意义是「快捷键按下去有没有生效」，和快捷键录制在同一页最容易被找到；「格子」页（`awake_view.go:388-395`）继续只放功能开关。

与规格 003 合并后，这一页固定为三行录制（常亮／JSON／命令面板），新增两行反馈控件排在**三行录制之后**，卡片内共 5 行 + 4 条分隔线。命令面板实现先预留五行高度；反馈控件随本规格落地。

| 行 | 左 | 右（控件） |
| --- | --- | --- |
| 1 | 「常亮开关」录制 | 录制按钮（现有） |
| 2 | 「新建 JSON 窗口」录制 | 录制按钮（现有） |
| 3 | 「命令面板」录制 | 录制按钮（规格 003，默认 ⌥.） |
| 4 | 「反馈方式」`FeedbackMode` | 三段分段控件，文字：屏幕提示／系统通知／关闭 |
| 5 | 「提示位置」`FeedbackPosition`（值存 `FeedbackCorner`） | 五段分段控件，每段一个「屏幕缩略框 + 一个点」的位置图标 |

控件细节：

- 反馈方式沿用语言选择的写法（`main.go:495-506`）：`ui.SegmentedBase` + `Track.Size(SizeLanguageSelectorWidth, SizeSegmentHeight)`，宽 318 与语言行同宽，视觉对齐。
- 提示位置：`ui.SegmentedBase(c.Key("feedback-position"), &a.feedbackCorner, 5)`，每段内画一个 `16 × 16` 方框（`StrokeHairline` 描边、`RadiusControl` 圆角、`ColorSeparator` 描边色）和一个 `Space4` 实心点（`ColorText`），点落在该段的四角或中心。选中的段与语言选择一致：底色 `ColorAccent`、内容 `ColorOnAccent`。全图标不依赖语言，避免英文「Top left」撑破约 28 px 宽的段。轨道宽 144（新 Token `SizeFeedbackPositionWidth`）。控件用 int `a.feedbackCorner`（0–4 对应 `top-left`／`top-right`／`bottom-left`／`bottom-right`／`center`），保存时映射回字符串；启动时非法或缺失值落到 `top-right`。
- 可访问性：位置的每段用 `Label(text("FeedbackTopLeft"))` 之类做无障碍名（MyGo 文档 `docs/ui/segmented.md:44` 说明分段控件对辅助技术呈单选组）。
- 联动：位置行可编辑的条件是「这次真的会用屏幕提示」，即 `effectiveMode() == hint`：`FeedbackMode == hint`，或 `FeedbackMode == notification` 但本次运行已被系统拒绝并降级（标志从 `a.feedback` 读，§5.3）。其余情况（`notification` 正常、`off`）整行 `Disabled(true)` 并降到 `OpacityDisabled`；不隐藏，避免布局跳动。**降级生效期间位置行保持可改**：用户选了通知，实际看到的是屏幕提示，位置就必须能改；存储的 `FeedbackMode` 不动。
- 反馈方式被系统拒绝后（§5.3），「系统通知」这一段右侧加一个 `triangle-alert` 图标，tooltip 用 `FeedbackDenied`；不改用户的选择值。降级发生时调一次 `a.invalidateWindow()`，让告警图标与位置行的可用态一起重画。

行数变化的影响：快捷键页固定按 5 行 + 4 条分隔线计算：5 × `SizeRowHeight`（48）+ 4 × `StrokeHairline`（1）= 244，加上下 2 × `Space24`（24）后为 292，无需向上取整。`settingsHeight` 的快捷键页（page 3）按此公式计算，格子页和关于页保持各自公式。最小窗仍为 720 × 340，可容纳五行内容及错误图标；页面切换只重绘，不重设窗口大小。

## 3. 屏幕提示

### 3.1 内容

一行：**图标 + 一句话**，无标题、无按钮、无说明文字。

| 状态 | 图标（Lucide 0.468.0，已随仓库打包） | 文案键 |
| --- | --- | --- |
| 常亮已开启（固定时长） | `sun` | `ToastAwakeOn` |
| 常亮已开启（不限时） | `sun` | `ToastAwakeOnUnlimited` |
| 常亮已开启（直到某时刻） | `sun` | `ToastAwakeOnUntil` |
| 常亮已开启（跟随进程） | `sun` | `ToastAwakeOnFollow` |
| 常亮已关闭 | `power` | `ToastAwakeOff` |
| 开启失败 | `triangle-alert` | `ToastAwakeError`（图标用 `ColorDanger`） |

- 图标取自 `design/assets/lucide-0.468.0/`（菜单栏图标是品牌 TIFF，不在此列；`eye` 不在打包集合内，因此不用菜单栏的睁眼/闭眼）。
- 时长短语复用已有键：`R05Half`（30 分钟）、`R05Hour`、`R05Two`、`R05Four`；自定义分钟用新键 `ToastMinutes`；跟随进程复用 `AwakeFollowing`（「跟随 %s」）。
- 单行，超长用 `SingleLine` + `Ellipsis("…")` 截断（`SingleLine` 在 `ui/api_gen.go:5305-5312`，`Ellipsis` 在 `:3630-3637`）。进程名过长时截断优先，不换行——两行会让浮层高度变化，位置计算要跟着改。

#### 3.1.1 文案的数据来源

「1 小时」「直到 02:30」**不能只从快照合成**：`awakeSession` 只保留 `Mode`、`End`、`PID`、`Identity`、`Name`（`keepawake.go:16-22`），定时与「直到」都被压成 `End`——`awakeArgs` 只把 `End` 换成剩余秒数交给 `caffeinate -t`（`keepawake.go:72-78`），从 `End` 反推不出用户选的是「1 小时」还是「直到 02:30」；菜单状态行显示的是剩余时间（`awake_app.go:130-133`），也不适合当提示。所以 `announceAwake` 除快照外还要读配置：

| 情况 | 判断顺序 | 文案 |
| --- | --- | --- |
| 跟随进程 | `s.Session.PID > 0` | `ToastAwakeOnFollow` + `s.Session.Name` |
| 直到某时刻 | `a.config.AwakeUntil != ""` | `ToastAwakeOnUntil` + 时间串（`AwakeUntil` 已按 `15:04` 校验，见 `keepawake.go:182-192`；再以 `s.Session.End.Format("15:04")` 兜底跨天） |
| 不限时 | `a.config.AwakeMinutes == 0` | `ToastAwakeOnUnlimited` |
| 预设时长 | `AwakeMinutes` ∈ {30, 60, 120, 240} | `ToastAwakeOn` + `R05Half`／`R05Hour`／`R05Two`／`R05Four` |
| 自定义时长 | 其余 `AwakeMinutes > 0` | `ToastAwakeOn` + `ToastMinutes`（取 `AwakeMinutes`，不是剩余时间） |

这样「常亮已开启 · 1 小时」说的就是用户刚请求的时长；剩余时间继续只出现在菜单与 tooltip 里。注意：快捷键路径的 `selectedSession()`（`awake_app.go:48-64`）只设 `Mode` 与 `End`，不设 `PID`，所以「跟随进程」这一段在当前代码里不会由快捷键触发（跟随只能从菜单对话框开启，而对话框不发提示）；保留该键是为了将来复用同一套文案。

新增 Token 只有两个尺寸：`SizeToastSlotWidth = 320`、`SizeToastHeight = 36`；另加设置页用的 `SizeFeedbackPositionWidth = 144`。三者写进 `design/cubbix.pen` 的变量、`design/tokens.json`，再由 `python3 scripts/tokens.py` 生成 `tokens.go`（`scripts/tokens.py:1-46`），并在 `design/token-index.md` 的 R05B 之后追加一张表。其余全部引用既有 Token，不新增别名。

胶囊宽度由内容决定（图标 16 + 间距 8 + 文字宽 + 两侧 24），在固定宽 320 的槽内按位置对齐：右上／右下靠右，左上／左下靠左，居中居中。

槽宽固定是为了让**定位只依赖 Token**：贴边放置需要 `SetPosition` 知道窗口宽度，而 `ui` 的文本测量只在视图构建时可调（`Context.MeasureText`，`模块缓存/github.com/egoist/mygo@v0.6.2/ui/api_gen.go:340-348`），没有「先量再摆」的一步。固定槽宽把「量」这一步去掉，代价是超长文案被截断（§3.1）。槽外的透明区域看不见也点不到（鼠标穿透），不影响观感与点击。

### 3.3 浅色与深色

`applyTheme`（`main.go:418-436`）返回 `tokenValues`，同时把其中一部分写进 `ui.Theme`（`main.go:425-433` 的 `Background`／`Surface`／`Text`／`Danger` 等）。`ui.Theme`（MyGo `ui/theme.go:7`）**没有「菜单表面」字段**，`ColorMenuSurface` 不在里面：浮层视图每次构建都调 `applyTheme(c)`，胶囊背景直接取返回值的 `t.ColorMenuSurface`（`tokens.go:78`、`:173`、`:215`），不要去主题里找。显示中改浅深主题时，MyGo 会经 `ThemeChanged` 重建视图（`ui/window.go:81-85` 的 `conn.ThemeChanged` → `rt.themeChanged()`），重建走的还是 `applyTheme`，所以不需要为浮层单独接主题。`ColorText`、`ColorTextSecondary`、`ColorDanger` 主题里有，但同样建议直接用 `t` 里的 Token，与设置页写法一致。深色下 `ColorMenuSurface` 是 92% 不透明的 #2C2C2C，浅色下是 92% 的白色，两者的底色是 R05B 定义的既有表面色（`design/rounds/R05-2026-10-29-常亮/README.md`），提示里的文字对比度需按 `design/scripts/contrast.py` 的口径在 R08 画板阶段复核一次。

### 3.4 位置与边缘距离

以 `mygo.Display.WorkArea` 为准（`模块缓存/github.com/egoist/mygo@v0.6.2/modules.go:209-221`，字段在 `:215-216`），它已排除菜单栏与 Dock，因此：

| 位置 | 计算 |
| --- | --- |
| 右上 | `x = WorkArea.X + WorkArea.Width - SlotWidth - Space24`，`y = WorkArea.Y + Space24` |
| 左上 | `x = WorkArea.X + Space24`，`y = WorkArea.Y + Space24` |
| 右下 | `x` 同右上，`y = WorkArea.Y + WorkArea.Height - Height - Space24` |
| 左下 | `x` 同左上，`y` 同右下 |
| 居中 | 在 `WorkArea` 内水平与垂直都居中 |

坐标原点在**主显示器左上角**（`模块缓存/github.com/egoist/mygo@v0.6.2/window.go:54-56` 的 `Rectangle` 说明），与 `Window.SetPosition` 同一坐标系，不需要翻转 Y。

居中取 `WorkArea` 的几何中心而不是黄金比例位置，理由：四个角与中心用同一条边距规则（角 24、中心对称），规则可一句话讲清，也不受 Dock 显隐影响。


（`模块缓存/github.com/egoist/mygo@v0.6.2/modules.go:267-286`；`DisplayNearestPoint` 对屏幕外坐标按包围盒最近距离退化，鼠标恰在边界时取最近的一块。）

理由：快捷键在任何一块屏幕上按都一样，鼠标位置是用户当下的注意力焦点；用菜单栏屏幕（`Screen.PrimaryDisplay()`，`modules.go:252-265`）会让提示跑到另一块屏幕，用户在多屏工作时容易漏看。

代价与兜底：纯键盘操作时鼠标可能停在别处，提示会出现在「不是正在看的那块」屏幕上。既然默认位置在右上且贴近菜单栏，接受这个代价；若维护者希望跟随焦点，改成 `PrimaryDisplay()` 只是一行替换（见 §9 待定项 4）。

#### 屏幕被拔掉时

窗口的坐标会落在已经不存在的显示器上，既看不见也不会自动回收。所以注册一次 `mygo.Screen.OnDisplaysChanged`（`模块缓存/github.com/egoist/mygo@v0.6.2/modules.go:304-306`；回调由 `screensChanged:` 在主线程发出，`internal/darwin/app.go:349-351`），回调里：

| 情况 | 行为 |
| --- | --- |
| 当前没在显示 | 什么都不做（大多数情况就是全部） |
| 提示所在的显示器 ID 仍在 `Screen.Displays()`（`modules.go:231-250`）里，但 `WorkArea` 变了（改分辨率、Dock 位置） | 按 §3.4 重算并 `SetPosition`，停留计时不重置 |
| 提示所在的显示器 ID 已不在列表里 | 取消停留与隐藏计时器（generation 加一），跳过出场动画直接 `Hide()`：那块屏幕已经没了，动画没有落点 |

`feedbackPresenter` 记住当前使用的 `Display.ID`（int64，`modules.go:211`）并与 `Displays()` 的 `ID` 比对；`OnDisplaysChanged` 返回的 `off` 在 `Close()` 里调用。首次显示时若 `DisplayNearestPoint` 返回零值（无显示器可用），不显示并直接返回。

### 3.6 出现与消失

浮层内容是原生 UI（`WindowOptions.Content` + `ui.View`），动画用 `ui.ElementTransition`（`模块缓存/github.com/egoist/mygo@v0.6.2/ui/transition.go:20-51`，`Motion` 见 `:55-68`）。MyGo 的出入场有三条硬规则，按第 1 版写法动画不会出现：

- `Enter` 只在「父节点上一帧已经在、自己这一帧才出生」时播放（`ui/transition.go:441-443` 的条件 `e.st.born == rt.frame && e.parent.st.born != rt.frame`）。首帧父子一起出现不播——`ui/transition_test.go:112-120` 断言的正是「首帧元素直接出现，没有入场」。
- `Exit` 只在父节点仍在构建、且元素上一帧刚被布局过时播放（`transition.go:39-43`；`:652` 的 `r.laid+1 != rt.frame` 会跳过 ghost）。所以「停留结束立刻 `Window.Hide()`」或「`Hidden` 之后第一次 `ShowInactive` 直接带胶囊」都会跳过动画。
- 缓动只有一个 `Ease` 字段（`transition.go:22-24`），入场与出场不能各用一条曲线。

因此把「窗口」与「胶囊」拆成两级，窗口只在两次提示之间隐藏：

| 层级 | 生命周期 |
| --- | --- |
| 窗口 + 根视图（`ui.Column`，固定槽尺寸，永远构建） | 首次触发到出场结束后 `Hide()`；`Hidden: true` 创建，`ShowInactive()` 显示 |
| 胶囊（`ui.Row`，`Key("feedback-toast")`，带 `Transition`） | 只在停留期构建；停留结束从视图里移除，靠 `Exit` 的 ghost 收场 |

一次提示的时间线：

| 步 | 动作 | 目的 |
| --- | --- | --- |
| 1 | 窗口不可见时先 `ShowInactive()`，不带胶囊构建一帧 | 让根视图先出生一帧，成为「上一帧的父节点」 |
| 2 | 约一帧后（16 ms，`time.AfterFunc` + `mygo.RunOnMain`）置 `showing = true` 并 `Invalidate()` | 胶囊在旧父节点里出生，`Enter` 才会播 |
| 3 | 停留 1200 ms（`time.AfterFunc`，`mygo.RunOnMain` 里执行） | |
| 4 | 置 `showing = false` 并 `Invalidate()`：胶囊不再构建，根视图还在，`Exit` 的 ghost 播 150 ms | 出场动画有真实落点 |
| 5 | 再等 `Exit` 的 `Duration` + 一帧（约 166 ms）后 `Hide()` | 动画播完再收窗口，下一轮重新走第 1 步 |

动画参数（进出一条 `Ease`，`Duration` 150 ms）：

| 阶段 | 动的属性 | `Motion` |
| --- | --- | --- |
| 出现 | 不透明度 0 → 1、缩放 0.96 → 1、沿所在角的方向位移 `Space4` | `Enter: &ui.Motion{Y: -4, Scale: 0.96}`（上方的角用 -4、下方的角用 +4；居中只缩放不位移；`Opacity` 零值就是 0，不必写） |
| 消失 | 只做不透明度 1 → 0 | `Exit: &ui.Motion{}`（零值即「到透明、不位移」） |

即 `ui.ElementTransition{Duration: 150 * time.Millisecond, Ease: ui.EaseOut, Enter: ..., Exit: ...}`：`Ease` 只有一个字段（`transition.go:24`），进与出共用 `EaseOut`；「进 `EaseOut`、出 `EaseIn`」在 MyGo 里做不到。

第 2 步那一帧是必需的，也是本设计里唯一「等一帧」的地方：首次 `ShowInactive` 时整棵视图都是新的，`Enter` 一定不播（`transition_test.go:112-120`），必须让根视图先画出来。首帧与收尾各一帧计入总时长，实际是 16 + 150 + 1200 + 166 ≈ 1.53 s，仍在「约 1.5 s」以内。落地时先按这条时间线实测入场是否真的播放（§8 含逐帧截图）；若首帧被合并，改成投递两次 `mygo.RunOnMain` 再 `Invalidate()`，不要退回「显示即带胶囊」。

窗口已可见时（§3.7 的合并情况）跳过第 1、2 步，直接替换内容：胶囊上一帧已在，不重播 `Enter`。

减少动态不需要另写分支：入场 `Motion` 的 `Opacity < 1` 且不 `Collapse`（`transition.go:367` 的 `fades()`），系统开启减少动态时仍会淡入，只是位移与缩放瞬时到位（`transition.go:443` 的 `!still || m.fades()`，`docs/ui/transitions.md:113-121`）。

计时全部在主线程用 `time.AfterFunc` + `mygo.RunOnMain`，不要跨线程碰窗口。

阴影：`DisableShadow: true` + 关闭窗口阴影（`SetHasShadow(false)`，`window.go:977`）。理由见 §4 核对表第 10 项——透明窗口的阴影形状没有公开控制，可能出现矩形硬边。如果评审希望在浅色桌面上强化边界，改用视图内 `Element.Shadow`（`ui/api_gen.go:5269`）配 `ColorOverlay`，在 Token 表里补一条模糊半径。

### 3.7 连续触发的合并

窗口、视图与计时器都**只有一个**：

| 情况 | 行为 |
| --- | --- |
| 同一文案重复触发（例如连按两次开关后又回到开启） | 只重置停留计时器，不重建胶囊、不重播入场动画 |
| 不同文案在停留期内到达 | 原位替换图标与文字，重置停留计时器，**不重播**入场动画（重播会闪烁）；文字替换用 `ContentTransition` 平滑切换 |
| 新的文案出现在出场动画期间 | 取消待执行的 `Hide()`，重新构建胶囊；`Transition` 会把 ghost 从原处接回来（`transition.go:421-426`），不跳变；随后重置停留计时器 |
| 停留或隐藏计时器尚未到期 | 每次显示把 generation 加一；两个计时器的回调都只在 generation 与当前一致时执行（停留结束卸胶囊、出场结束 `Hide()`），避免旧计时器提前收掉新提示 |

验收方式：连按快捷键 5 次，屏幕上只应看到一个胶囊，文案跟随最后一次状态，可见总时长为「最后一次触发 + 1.5 s」。

### 4.3 需要实测的两项

1. **全屏应用之上**（第 6 项）：`FullScreenAuxiliary` + 浮动层是 AppKit 的标准组合，但 Cubbix 从未在真机上验证过「全屏 Safari／Terminal 里按快捷键能看到提示」。验收时必须在至少一个全屏应用上确认（见 §8）。若实测不成立，回退方案是 purego 把窗口层级提到 `NSStatusWindowLevel`（25）。
2. **透明窗口的自绘圆角与抗锯齿**（第 8 项）：需要在浅色与深色桌面墙上各看一眼边缘是否发毛、四角是否有底色残留。

### 4.4 purego 备用方案

## 5. 系统通知

### 5.1 调用方式

```go
err := mygo.NewNotification(mygo.NotificationOptions{
	ID:     "cubbix.feedback.awake",
	Title:  a.text(locale, "Awake"),   // 「常亮」/「Awake」
	Body:   body,                      // 与屏幕提示同一句
	Group:  "cubbix.feedback",
	Silent: true,
}).Show()
```

- `Body` 与屏幕提示共用同一套文案键（§6），保证两种方式说同样的话。
- 固定 `ID`：同一 ID 的通知会替换仍在显示的那条（`modules.go:807-811`），天然实现「连续触发只保留一条」。**注意**：`ID` 固定意味着文案变化时是「替换」而不是「追加」，这正是我们要的行为。
- `Silent: true`：快捷键反馈是确认信息，不该每次都响（推荐值，见 §9 第 7 项）。
- `Group` 让通知在通知中心堆叠在一起（`modules.go:817-821`），便于事后回看。
- 调用点与电池提醒一样在主线程（`awake_app.go:201-207` 的 `mygo.RunOnMain` 包裹），`Show()` 会阻塞到系统接收，不要在视图构建期间同步调用。

### 5.2 首次权限

macOS 上第一次 `Show()` 会弹出系统授权询问，`Show()` 等到用户作答（`modules.go:912-916`）。因此第一次按快捷键时会先看到系统授权弹窗，用户作答后才出现通知——这是平台行为，不做自定义前置说明。

### 5.3 被拒绝时

`Show()` 返回 `mygo.ErrNotificationsDenied`（`modules.go:908-910`，仓库已有同样的判断：`battery_notification.go:28-39`）。

**推荐：自动改用屏幕提示，并记住这次结果。**

| 步骤 | 行为 |
| --- | --- |
| 收到 `ErrNotificationsDenied` | 立即用屏幕提示把这条反馈补发一次（用户按了快捷键，必须得到反馈） |
| 记忆 | 本次运行内标记「通知不可用」，后续不再调用 `Show()`，直接走屏幕提示。标记放在 `feedbackPresenter` 里，**不复用** `batteryNotifier.denied`（`battery_notification.go:16`，置位在 `:37`——那是电池提醒自己的位，两者不能互相影响） |
| 设置页 | 「系统通知」段右侧显示 `triangle-alert`，tooltip `FeedbackDenied`；不改写存储的 `FeedbackMode`；降级期间位置行**保持可改**（§2.2），并 `Invalidate` 一次让告警图标与位置行一起重画 |
| 「关闭」时被拒绝 | 不降级：用户明确选择不要反馈，就什么都不显示 |

不推荐「被拒绝后就不提示」：通知权限是系统层面的设置，用户拒绝往往只是嫌通知吵，而快捷键反馈正是他们想要的静默确认，降级到屏幕提示更符合意图。

权限状态在应用重新启动后可能变化（用户去系统设置里打开），所以「记住拒绝」只在本次运行内有效，下次启动仍按用户选择的 `FeedbackMode` 尝试一次。

### 5.4 与电池提醒的关系

电池提醒保持现状：始终走系统通知（`battery_notification.go`、`awake_app.go:201-236`），**不受 `FeedbackMode` 影响**。理由：它是「常亮仍在运行，但已切到电池」的安全提示，属于通知，不属于操作确认；用户把反馈方式设成「关闭」不应该让电池提醒消失。

### 7.3 让常亮与 JSON 等格子共用

对外只暴露一个方法，参数是「已本地化的图标 + 文案」，与功能解耦：

```go
// 反馈入口：任何格子都调用它，不需要知道窗口、位置或模式
func (a *application) announce(msg feedbackMessage)
```

- `feedbackMessage{Icon string; Text string; Danger bool}`，`Icon` 是 Lucide 文件名，`Text` 由调用方用资源键合成（与 `a.text(locale, key)` 一致，`main.go:90`）。
- 常亮只写一个 `announceAwake(err error)`（§1.2）；JSON 若要提示新建窗口，加一行 `a.announce(feedbackMessage{Icon: "braces", Text: a.text(locale, "R07NewWindow")})` 即可，不需要改反馈组件。
- 反馈组件内部不读 `config` 以外的任何功能状态，因此新增格子不会影响常亮的提示文案。
