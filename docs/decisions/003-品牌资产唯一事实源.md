# ADR 003：品牌资产唯一事实源

- 状态：已采纳，按已定稿品牌规范执行。
- 日期：2026-10-28

## 背景

[Issue #5](https://github.com/ConteMan/cubbix/issues/5) 最初按源 SVG 规划品牌资产。后续品牌定稿已将可编辑母版收敛为 pen.dev 文件，并建立了脚本导出和校验流程。ADR 必须记录当前事实源，避免继续修改历史 SVG 或直接修补导出 PNG。

## 决策

- `brand/cubbix-logo.pen` 是猫标的唯一可编辑源，只由维护者在 pen.dev 桌面端编辑；CLI 只读取和导出，不改写母版。修改必须基于其中的定稿母版，保留源图形与负形关系，不从旧轮次重建标志。
- `brand/dist/` 的导出物全部由 `brand/scripts/export.py` 生成，不手工修改。独立标志 SVG、应用图标 PNG 与菜单栏模板图均从同一母版派生。
- 应用图标、菜单栏模板图的尺寸、布局、颜色、透明边距及瞳孔处理，统一引用 [brand/README.md 的已确认规范](../../brand/README.md#已确认的规范)。本 ADR 不复制这些数值，避免形成第二份规范。
- 按品牌 README 的固定依赖重新导出，并运行导出器的 `--check`。`brand/dist/manifest.json` 记录源、导出器和产物的摘要及必要元数据；同一源、脚本和依赖下重复导出应逐字节一致。
- 当前导出覆盖：应用图标 `app-icon-*.png`；独立标志 `mark.svg`／`mark-inverse.svg`；菜单栏模板 `menubar-template.png`／`menubar-template@2x.png`；浅深背景下的菜单栏预览 `menubar-preview-*.png`。独立标志用于界面品牌接入，品牌 README 展示图引用 `brand/dist/app-icon-128.png`。
- 应用的 `mygo.json` 中，`icon` 必须指向 `brand/dist/app-icon-1024.png`，由 `mygo build` 生成 `.icns`。当前仓库尚未建立应用配置，此处记录接入要求；不另复制一份图标源。
- 菜单栏状态变体（如常亮开启／关闭）尚未导出，随 M1 常亮格子定义，届时同步扩展 `brand/scripts/export.py` 和 `--check` 后生成；当前单一模板及浅深预览不代表已覆盖业务状态。
- DMG 目前沿用 `mygo build` 默认外观，不制作 DMG 专用图；不把现有应用图标或 README 展示图称为专用 DMG 设计。
- `brand/rounds/` 保留冻结评审历史，旧 SVG、各轮推荐和对比图不再作为当前品牌源。界面使用单色猫标的规则见 [ADR 002](002-设计源与评审留存.md)。

## 备选方案与不选的理由

- **继续以历史 SVG 为可编辑源**：与已定稿 `.pen` 母版形成双源，容易丢失后续调整；这是相对 Issue #5 初稿的明确修订。
- **分别绘制各尺寸、菜单栏与 README 标志**：造型容易分叉，无法保证更改能一致传播。
- **手改导出图后只更新校验清单**：产物无法从母版复现，校验摘要也失去来源意义。
- **在 ADR 再列一份尺寸和颜色表**：增加规范漂移风险，故只引用品牌 README。

## 后果

资产可重现、可校验，当前品牌造型有唯一修改入口。代价是修改源结构或增加用途时需同步维护导出器；遇到不支持或匹配含糊的结构，应停止导出并先补支持。`--check` 检查完整性和过期状态，不替代外观复核，也不等同于应用内菜单栏实测。
