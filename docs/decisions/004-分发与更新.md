# ADR 004：分发与更新

- 状态：已采纳，作为发布与更新实现约束；尚非发布验收记录。
- 日期：2026-10-28

## 背景

Cubbix 在 App Store 外分发，需要兼顾 macOS 的签名与公证、更新包可信性及常驻任务的连续性。公开仓库可以直接使用 GitHub Releases，无需另建更新服务。更新不能在用户编辑 JSON 或执行常亮会话时自动重启应用。

## 决策

### 构建与发布

- Developer ID 签名、公证和 DMG 均由 MyGo v0.6.2 的 `mygo build` 完成。发布构建需在 macOS 上具备有效签名与公证条件，不把 ad hoc 签名或跳过公证的构建当成正式交付。
- 使用本公开仓库的 [GitHub Releases](https://github.com/ConteMan/cubbix/releases) 作为唯一更新源，使用 MyGo Updater 校验并安装更新。发布内容包含安装 DMG 及 MyGo 生成的签名更新归档和清单；只发布 DMG 不能构成应用内更新。
- `mygo build -upload` 可上传至草稿 Release，复核产物与更新清单后再发布。此决策不引入 GitHub Actions，仍遵守仓库的本机自测要求。

### 密钥与信任连续性

Apple Developer ID 证书用于系统代码签名；更新签名密钥用于 MyGo Updater 的更新包校验，二者独立，不能互相替代。发布应用嵌入更新验证公钥，后续更新必须满足该信任关系。

签名、公证及更新所需的敏感材料仅由发布环境注入，不写入配置字面量，不进仓库或日志；更新私钥通过 `MYGO_UPDATER_PRIVATE_KEY` 注入。密钥材料不提交到仓库，验证公钥在构建时注入并嵌入发布应用。备份在仓库外进行：首次发布前将更新密钥对加密保存在密码管理器，并保留一份独立、受控的加密备份；验证能恢复且公私钥匹配，变更后同步维护备份，验证过程不得输出私钥。

若更新私钥丢失且无可用备份，已安装应用仍信任旧公钥，新生成的密钥无法为这些应用提供可接受的更新。重办 Apple 证书不能修复这一信任链，也不能假设已有应用会自动接受新公钥；必须通过另行交付、经 Developer ID 签名和公证的新安装包让用户手动迁移。若私钥泄露，攻击者可签发被旧公钥接受的更新，需停止使用并处理受影响的信任链，不能仅覆盖密钥文件后继续发布。

### 检查、下载与重启

设置页「关于」只保留四项功能：

| 项目 | 行为 |
| --- | --- |
| 版本（检查） | 展示当前版本并提供手动检查入口；发现新版本后下载、验签，成功后进入「重启更新」状态 |
| 更新内容 | 查看版本更新说明 |
| 自动更新 | 默认开启；开启时在启动时及运行期间每 24 小时检查，有新版则下载 |
| 重启更新 | 下载完成并验证成功后出现，同时在菜单栏提示；用户主动点击后才重启 |

关闭自动更新后不再发起自动检查和自动下载。手动检查不受「自动更新」开关影响：发现新版本后同样下载、验签，成功后进入「重启更新」状态。下载失败或验签失败不得进入可重启更新状态。无论自动还是手动路径，都不自动重启。

使用底层 `mygo.Updater` 配合 Cubbix 自己的调度和界面落实上述行为，不直接套用带有额外操作的默认插件窗口。MyGo 的 `Install` 会下载、验签并替换磁盘上的应用，运行中的进程继续执行，新版在重新启动后生效；因此「重启更新」是用户控制切换运行版本的入口，不把下载完成等同于新版已经运行。

更新后的常亮恢复与未保存 JSON 处理遵循 [当前设计规则](../../design/README.md)：常亮按剩余时间恢复，原进程仍运行时继续跟随；有未保存 JSON 时先提示，保留更改后再发起重启。确认依据见 [R02 已确认规则及提示方案](../../design/rounds/R02-2026-10-28-设计系统/README.md#维护者已确认的规则)，后续沿用情况见 [R04](../../design/rounds/R04-2026-10-28-收尾/README.md)。这些是实现要求，静态样张不能证明恢复或保存逻辑已经可用。

## 备选方案与不选的理由

- **另建更新服务或引入另一套更新框架**：公开 Releases 与 MyGo 已覆盖所需分发能力，额外服务和框架增加维护成本。
- **只依赖 Apple 证书，或丢失密钥后直接生成新密钥**：分别混淆了系统代码签名与更新签名、忽略了已有应用固定的信任关系。
- **直接使用默认 Updater 插件窗口**：其安装、稍后提醒、跳过版本等交互不符合当前四项功能约定；保留底层能力，自行组织产品交互。
- **下载后自动重启**：会中断常亮和编辑，违反明确由用户发起重启的要求。

## 后果

更新服务成本集中在公开 Release，发布链路沿用 MyGo；相应地，更新私钥必须长期可恢复，且每次发布需同时验证安装与应用内更新。Cubbix 仍需实现定时检查、状态提示、重启前保护和重启后恢复。MyGo 自更新要求应用安装位置可写，开发构建也不具备正式更新能力；这些限制与断网、验签失败等情况必须在实现验收中覆盖，不能仅用文档检查宣称已通过。
