# ADR 005：多语言与语言选择

- 状态：已采纳，作为语言资源与验收约束。
- 日期：2026-10-28

## 背景

项目从开始就要求中文与英文，后续设计评审进一步确认三项语言选择及默认值。原生菜单、设置页与 JSON WebView 需要保持同一种应用语言，不能分别写死文案或让框架默认行为覆盖产品约定。

## 决策

- 默认语言为简体中文，可切换英文，并提供「跟随系统」。设置中按「跟随系统／简体中文／English」排列；首次使用默认选中「简体中文」，不是默认跟随系统。
- 使用 MyGo v0.6.2 i18n：应用统一使用 `zh-CN` 表示简体中文、`en` 表示英文，简体中文作为源语言。界面文案通过资源键使用，不在 Go、HTML 或前端逻辑中写死。菜单、tooltip、错误与更新提示同样遵守这一要求；代码标识符和技术数据不作为待翻译文案。
- MyGo 默认按系统偏好匹配应用语言，单独设置中文源语言并不能保证英文系统首次仍显示中文。实现必须在首次初始化时显式选择简体中文，并保留用户后续的选择，不能每次启动重新覆盖。
- 显式选择中文或英文时使用 MyGo 的语言切换能力并持久保留；选择「跟随系统」时清除显式语言覆盖，通过 MyGo 按系统语言偏好匹配已提供的语言，无法匹配时回退到源语言。需区分「跟随系统」偏好与当前解析出的语言，不能仅凭当前显示中文就将其当成显式中文选择。
- 原生界面和 WebView 使用同一套 MyGo i18n 资源及应用语言。切换后同步应用自有菜单、窗口标题等一次性设置的文案；不将框架自有系统界面全部即时切换视为已获保证。
- 界面验收须提供中文、英文截图各一份，覆盖相同功能状态；检查两种语言的文案完整性、tooltip 与排版。已有设计语言资源和双语样张可用于对照，但不能替代应用运行截图。

### 标签、目录与自带翻译包

应用配置接入时，`i18n.dir` 指向存放语言资源的目录（如 `locales`），该目录内放 `zh-CN.json` 和 `en.json`，`i18n.source` 设为 `zh-CN`。MyGo 按目录根部的 `<tag>.json` 加载资源，不按每种语言新建子目录。当前仓库尚未建立应用配置；`design/locales/zh-CN.json` 与 `design/locales/en.json` 保持原名，无需改名。

对 MyGo v0.6.2 文档和源码的核对及最小验证结果如下：

| 核对点 | `zh-CN` | `zh-Hans` |
| --- | --- | --- |
| 标签规范化 | 合法且保留为 `zh-CN` | 合法且保留为 `zh-Hans` |
| 资源文件名与源语言 | `zh-CN.json` 配 `i18n.source: "zh-CN"` | `zh-Hans.json` 配 `i18n.source: "zh-Hans"` |
| 自带简体中文翻译包 | 生成器匹配并导入 `locales/zh-Hans` | 生成器匹配并导入 `locales/zh-Hans` |

`zh-CN` 表示带地区的中文标签，`zh-Hans` 显式表示简体脚本，二者不会被规范化为同一个标签。加载器要求源语言有同名 JSON 文件；只有 `zh-CN.json` 却把源语言设为 `zh-Hans`（或反过来）会报缺失源文件，不能依赖语言匹配补救文件命名。

自带翻译包的选择使用另一条路径：生成器以 `i18n.Match` 匹配应用语言和 MyGo 已提供的语言，再生成包导入；运行时文案目录也按语言匹配查找。验证中，两种源标签都生成了 `github.com/egoist/mygo/locales/zh-Hans` 导入，自带 `cancel` 均显示「取消」；现有设计资源以 `zh-CN` 加载也通过检查并选中了该翻译包。因此应用沿用 `zh-CN`，使设计资源与应用标签一致，无需为获得 MyGo 自带简体中文翻译而重命名；上游包路径仍为 `zh-Hans`，不改写为 `locales/zh-CN`。

## 备选方案与不选的理由

- **仅中文，后续再补翻译**：会把文案散落在实现中，违背项目从开始就保留语言资源的规则。
- **默认跟随系统或只提供中英两项**：与 R02 已确认的「默认简体中文、另有跟随系统」不符。
- **原生界面与 WebView 各用一套翻译机制**：资源键、语言选择和回退行为容易不一致，MyGo 已提供统一的资源与语言能力。
- **只依赖资源回退或只验中文截图**：回退可能掩盖缺少的英文文案，也不能验证英文布局。
- **应用资源统一改为 `zh-Hans`**：在该版本中同样有效，但已验证 `zh-CN` 能匹配自带简体中文包；此次保留既有设计资源及语言标识，避免没有功能收益的命名迁移。

## 后果

语言选择、资源与界面有统一约定，新增文案必须同步维护两种语言。首次默认值与后续跟随系统模式需要明确区分；切换时还要更新应用自行缓存的标题和菜单。MyGo 文档说明部分 AppKit／WebKit 自有文本在下次启动后才采用新的语言，实现验收应区分这些系统行为与应用自身文案。

### 更新记录（0.0.3 补充）

- 仓库内 `CHANGELOG.md` 是中文历史记录，`CHANGELOG.en.md` 是对应英文；二者保持相同版本、顺序和 ISO 发布日期（标题格式 `## 版本 — YYYY-MM-DD`），正文只描述用户能感知的变化。
- 应用同时嵌入这两个文件，依当前解析出的应用语言选择一份，作为当前及历史版本的离线说明。返回按钮、当前标记与应用／编辑菜单仍使用 `design/locales/*.json`，切换语言时同步刷新。
- 设置内「更新内容」子页按版本倒序显示，版本号和日期同行；仅正在运行的版本显示一处弱化的「当前」。Esc 返回关于页，⌘W 隐藏整个设置窗口。
- 新版本的远程说明继续读取公开平台更新清单，并使用 Release 的发布日期补充在内置历史之前；内置版本以仓库里的双语正文为准。旧 Release 正文及已发布清单不回写、不重签；已有发布记录不会因应用内措辞调整而改变。
