# ADR 002：设计源与评审留存

- 状态：已采纳，作为设计与实现交接约束。
- 日期：2026-10-28

## 背景

界面需要同时覆盖中英文、浅深主题和状态变化。若设计、截图、原型及代码各自维护样式，就难以确认当前规范以及每轮修改的原因。[设计评审记录](../../design/rounds/) 已保留从 R01 到 R04 的演变，后续实现需要继承已确认的规则，而不是恢复历史提案。

## 决策

- `design/cubbix.pen` 是界面的唯一设计源。维护者用 pen.dev 桌面端编辑，Agent 用 pen.dev headless CLI（`interactive --in/--out`）编辑；导出和复开检查均用 CLI。预览图和 HTML 不作为另一个可独立修改的设计源。
- `brand/cubbix-logo.pen` 只由维护者在 pen.dev 桌面端编辑，CLI 只读取和导出，不改写品牌母版。品牌资产的派生关系见 [ADR 003](003-品牌资产唯一事实源.md)。
- 每轮评审新建 `design/rounds/RNN-日期-主题/`，留存从设计源导出的预览图与 `README.md`，记录目标、评审意见、已定规则和仍待确认的提案。历史轮次冻结，不用新结果覆盖旧证据。
- HTML 交互原型保存在 `design/prototypes/`，用于说明交互；评审采纳的变化回写设计源和本轮记录。
- 画布颜色、字号、圆角、间距等样式引用 Token，不在节点另写固定数值。Token 名称与实现的 Go 字段一一对应，映射由 [token-index.md](../../design/token-index.md) 维护；`tokens.json` 是可审计快照，不是第二份设计事实源。
- 当前 CLI 不保留 width/height 变量绑定，几何尺寸按上述映射由 Size Token 解析；这项工具限制不允许另行维护一套尺寸常量。实现字段仍需在应用接入时落实，不能把映射表视为已有运行时代码。
- 界面采用黑白灰，彩色仅表达状态：失败或阻断使用语义红，成功 check 使用中性色。橘色只用于应用图标，不用于按钮、导航、开关或成功提示。界面猫标跟随文字颜色。
- 界面改动先出设计稿，经维护者确认后再实现；当前规则入口为 [design/README.md](../../design/README.md)，具体演变以各轮评审记录为据。

## 备选方案与不选的理由

- **截图、HTML 或代码与 `.pen` 并列为设计源**：同一控件会出现多个权威版本，无法可靠追踪变更。
- **节点写死样式、代码另配常量**：中英文和浅深主题容易漂移，无法保持 Token 与代码对应。
- **覆盖上一轮预览与评审记录**：会丢失决策过程，也容易把当时的提案误当成确认结论。
- **采用蓝色或橘色界面强调色、绿色成功态**：已被 R03 的黑白灰决策取代；旧轮次仍留档，不再指导当前实现。

## 后果

每次修改都能追溯到设计源、评审与 Token，代价是维护源、映射和导出记录的一致性。headless CLI 的变量和导出限制需要持续审计。静态设计检查不能代替应用中的菜单栏、焦点、快捷键或输入法验收。
