# ADR 001：技术栈与编辑器边界

- 状态：已采纳，作为实现约束；不代表运行时验收已完成。
- 日期：2026-10-28

## 背景

Cubbix 是 macOS 菜单栏常驻工具箱，当前规划常亮和 JSON 两个独立格子。[Issue #1 的确认结论](https://github.com/ConteMan/cubbix/issues/1#issuecomment-6464510053) 已验证 MyGo v0.6.2 的菜单栏、多窗口、原生界面与离线 WebView 混用及双向通信能力。项目需要在沿用原生能力的同时，复用成熟的文本编辑器，控制依赖与构建复杂度。

## 决策

- 固定 Go 1.27.1 与 MyGo v0.6.2。升级必须单独提 Issue 并说明理由，不随上游自动升级。
- 不使用 CGO。系统能力优先通过系统命令调用，不能满足时再采用 purego。常亮沿用 #1 已选定的 `caffeinate` 方案，不为此另写 IOKit 调用层。
- 编辑器类界面使用 MyGo WebView 嵌入成熟前端库；JSON 编辑器选择 CodeMirror 6。具体前端包必须固定精确版本并随应用打包，不在运行时从网络加载。「CodeMirror 6」是已选主版本系列，不替代实现阶段的精确版本锁定。
- JSON 的 `this` 表达式在独立 Web Worker 中求值，按 #1 设置 200ms 超时并终止超时 Worker，避免死循环阻塞界面；不在界面主线程执行。

## 备选方案与不选的理由

- **CGO 或直接为常亮实现 IOKit 调用**：增加构建与系统桥接负担；#1 的验证未显示它比系统命令方案更可靠。
- **Monaco**：#1 的对比验证中打包体积更大；当前 JSON 功能选择 CodeMirror 6 已足够，不承担额外编辑器负担。
- **自写原生文本编辑器或运行时加载前端依赖**：前者需要重新实现成熟编辑能力，后者引入网络可用性与版本漂移，均不符合固定、离线打包的约束。
- **主线程求值表达式**：无法在表达式死循环时保持界面响应，故使用可终止的 Worker。

## 后果

依赖与编译方式有明确边界；代价是升级需要专门评估，前端依赖仍需维护许可证与版本锁定。Worker 超时保障响应性，不等于对任意代码的完整安全隔离。#1 已指出超长单行 JSON 需要单独的大文件模式，且每个 JSON 窗口会增加 WebKit 进程；实现和验收不能将多行文件验证推广成所有文件都流畅或多窗口零成本。
