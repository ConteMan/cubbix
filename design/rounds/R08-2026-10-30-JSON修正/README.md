# R08 · JSON 修正与代码评审

本轮将使用反馈落实到 `design/cubbix.pen` 的独立 R08 轮次带。通过固定 pen.dev headless CLI 0.3.13 的 `interactive --in/--out` 编辑、保存、复开和导出；没有连接桌面编辑器。R07 保留为历史方案，其底部结果面板、灰阶语法和未保存确认已废弃。

## 设计规则与预览

编辑区在左、结果在右，默认 60／40；分隔条支持拖动与方向键，比例保存到配置，范围 25–75%，窄窗口还须保留两侧最小可用宽度。底部 `this` 输入框与编辑区等宽，四个工具在右侧；没有表达式时结果区留白，错误与超时只在输入框右侧显示图标，原因放 tooltip。

代码按键名、字符串、数字、布尔和 null 使用五类 `ColorSyntax*` Token，布尔和 null 按工作单共用深蓝色值；浅深两套语法色对 `ColorCard` 的对比度为 5.54–11.48:1。界面继续使用中性色，代码语法色为已授权例外。缩进线引用 `ColorSyntaxIndent`，每两字符一级；窗口名显示在红绿灯右侧，并同步系统标题与菜单。工具关闭、退出与更新不提示保存，显式保存快捷键保留。

## 评审发现与修正

- 原缩进线周期为 `1ch`，与两空格缩进错位：现使用编辑器缩进单位计算周期与总宽度。
- 标量结果原为普通文本：现字符串、数字、布尔和 null 与对象结果使用同一语法 Token。
- 宽窗口能拖过 Go 配置保存的 25–75% 范围：现前端与 Go 采用一致边界，并在丢失 pointer capture 时结束拖动。
- 删除更新流程残留的 `restartUpdateAfterJSON` 包装及过时的异步保存保护注释；退出处理提取为同一个生产函数，供真实退出集成测试复用。
- 原失焦验证没有触发原生事件，原拖动测试只发送方向键；现验证原生焦点/失焦回调、失活回调、指针拖动处理、磁盘比例回读、⌘W、原生关闭动作、带脏窗口更新与实际退出。
- 英文界面在首选字体不可用时落入衬线字体：标题与 tooltip 补充系统无衬线后备字体。测试 profile 每次独立，隐藏窗口折叠检查显式刷新 CodeMirror 测量，避免依赖后台动画帧。

## 第 6 条结论与验证边界

未发现 JSON 失焦后关闭或隐藏的应用路径。两个后台非激活窗口在真正的 Regular 原生策略下，经过两组 `windowDidBecomeKey:`／`windowDidResignKey:` 委托回调、`applicationDidResignActive:` 回调与 `deactivate` 调用，再执行可见性同步后，仍可见、未销毁、文档数量为 2，应用没有变为活动应用。

原生回调由测试主动发送，并用回调计数确认已进入 MyGo 事件路径；没有把窗口设为系统 key window，也没有真实切换前台应用或 Space。因此这是后台原生事件路径与存活性验证，不代表真实前台焦点切换的端到端验收。未调用 Focus／activate，不使用 Computer Use。此前策略缓存避免重复调用 MyGo 的激活包装，保留此修正；本轮没有发现新的失焦关闭原因。
