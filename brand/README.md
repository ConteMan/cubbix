# Cubbix Logo

`cubbix-logo.pen` 是唯一可编辑源，包含画板 `n0a0W`「Cubbix Logo · A1（1024，编辑母版）」和「菜单栏状态 · 常亮点」。维护者已在 pen.dev 亲手调整并确认母版造型；路径、圆的位置和尺寸以母版为准。两块画板背景统一引用 `canvas-bg = #FFFFFF`，只作编辑衬底，不参与导出。应用图标的橘色 `#FF9A3D` 是独立的输出规格，由导出脚本的 `ORANGE` 常量提供。`dist/` 全部由脚本生成，不手改；`rounds/` 是冻结的评审历史，旧 SVG 和各轮推荐不作为当前源。

## 已确认的规范

| 用途 | 规范 |
| --- | --- |
| 应用图标 | 1024×1024 透明画布；824×824 超椭圆（n=5），中心 (512,512)，每边 100px 透明边距；底色 `#FF9A3D`，猫标 `#202522` |
| 猫标布局 | 高 560px，水平中心 x=512，视觉中心 y=500；只对完整标志统一缩放和平移 |
| 菜单栏 template | 黑色与透明，18×18pt；1× 为 18px，2× 为 36px；猫标高 16pt，中心 (9,9)；去掉两枚瞳孔，保留眼洞及圆爪 |
| 常亮开启 template | 与默认模板相同的画布、猫标缩放和中心；按状态画板的留白圆擦除后叠加墨点，输出黑色与透明；点直径 ≥3pt、径向留白 ≥1pt |
| 独立标志 | 紧贴实际矢量边界的 SVG；`mark.svg` 为墨色，`mark-inverse.svg` 为白色，均透明背景 |

应用 PNG 尺寸为 16、32、64、128、256、512、1024px。小尺寸由 1024px 使用 Lanczos 缩小，不另改猫标。菜单栏预览各含 1×/2× 浅、深背景：浅色用黑色，深色用白色模拟系统 tint；实际 template 始终是黑色与透明。这里只检查静态导出物，应用接入留给 #8。

## 常亮状态与候选

状态画板 `rNNp5` 位于母版右侧 `(1144,0)`，间隔 120，同为 1024×1024。画板内只有「常亮点留白」和「常亮点」两个同心圆；坐标均相对各自画板左上角。留白圆保留现有 `logo-bg = #FF9A3D` 填色作为编辑提示，与白色画板衬底独立；填色不参与导出，也不作颜色校验，可换成白色或其他提示色。导出器只使用其圆形几何、位置和尺寸生成透明擦除遮罩，并校验与常亮点同心，不把提示色画进模板。导出器按画板名称识别状态板，其他顶层对象、额外图层和不支持的样式都会报错。

以下候选均以母版的实际猫标高度 `781.8232117896697` 为基准，`1pt = 高度 / 16 ≈ 48.86395` 源坐标单位。留白宽度指两圆半径之差。

| 候选 | 圆心（源坐标） | 点直径 / 留白圆直径 | 16pt 猫标下点直径 / 留白宽度 | 取舍 |
| --- | --- | --- | --- | --- |
| A（推荐，已保留） | (780,850) | 152 / 252 | 3.11pt / 1.02pt | 靠近箱子右下角，像通知角标压住箱角；满足最小尺寸并减少对箱体的遮挡 |
| B（向内） | (764,832) | 152 / 252 | 3.11pt / 1.02pt | 更靠箱内，对箱体右下区域的遮挡更明显，角标位置感较弱 |
| C（更大） | (776,840) | 168 / 268 | 3.44pt / 1.02pt | 点更醒目，但擦除区域更大，箱角缺口也更显著 |

画板只保存 A。[候选对照图](rounds/ACTIVE-2026-10-29/candidates.png) 包含默认模板、三个候选的浅深背景、原始 1×/2× 和 8× 矢量细节。点的边界为 `(704,774)–(856,926)`，位于原猫标边界约 `(160,146.1768)–(864,928)` 内。导出始终先按完整母版算边界，然后移除瞳孔、擦除留白、叠加点，不按常亮组合重新裁切或缩放。1×/2× 的默认和常亮模板透明通道边界也必须一致。原有 15 个图像/SVG 导出文件逐字节保持不变；清单随源、脚本和新增文件更新。

![常亮开启，浅色菜单栏 2×](dist/menubar-preview-active-light@2x.png)
![常亮开启，深色菜单栏 2×](dist/menubar-preview-active-dark@2x.png)

维护者调点时，在 pen.dev 打开状态画板：

1. 一起选中两个圆并平移相同距离，保持同心。推荐初始位置：点 `x=704,y=774,w=h=152`；留白 `x=654,y=724,w=h=252`。两个圆均为实心正圆；保留图层名称和常亮点的墨色变量；留白圆填色仅为提示，不加旋转、描边或特效。
2. 调大小时先确定圆心；分别设置 `x=圆心x−直径/2`、`y=圆心y−直径/2`、`w=h=直径`。点直径至少为实际猫标高度的 `3/16`，留白圆直径至少比点大实际猫标高度的 `2/16`。点必须留在原猫标边界内，两个圆必须留在 1024 画板内。
3. 保存后重新导出，检查浅深背景的 1×/2× 效果，并运行 `--check` 和下述测试。状态画板只作为叠加层源；猫标轮廓仍由母版提供，不需要复制到状态画板。不要移动、缩放或修改母版图层来迁就状态点。

新增模板为 `menubar-template-active.png`、`menubar-template-active@2x.png`；四张预览为 `menubar-preview-active-{light,dark}{,@2x}.png`。本次交付品牌资产，应用的状态切换接入不在本次范围。

## 修改母版

1. 在 pen.dev 打开 `brand/cubbix-logo.pen`，修改母版并保存；保持两块画板的 `canvas-bg` 白色编辑衬底。不要靠修改画板背景或 `logo-bg` 改应用图标底色；橘色规格由 `export.py` 的 `ORANGE` 决定。状态点仅在状态画板调整，不要添加其他画板或从历史 SVG 覆盖母版。
2. 保留独立 path / ellipse 图层和猫头内的两个眼洞。导出器保留原始 path 字符串、viewBox 到图层尺寸的映射及图层顺序，不拟合或重画母版。
3. 运行导出和检查，复核所有尺寸、透明边距、浅深菜单栏及独立 SVG，再提交母版、脚本与生成物。只调整编辑衬底或留白提示色时，全部 21 个图像/SVG 必须与修改前逐字节一致；源文件和导出脚本变更时，清单需同步更新各自的 SHA-256，保留完整性校验。

当前圆爪沿用旧的“瞳孔”图层名。导出器根据猫头眼洞范围识别真正的两枚瞳孔，不按图层名批量删除；匹配含糊或出现不支持的样式时停止导出。改动超出当前直接 path / ellipse 结构时，先扩展导出器支持，再生成产物。

## 安装与重新导出

依赖全部装在仓库外。已验证 Python 3.13 / 3.15、pen CLI 0.3.12、Node.js，以及以下固定渲染依赖。先按 pen.dev 官方安装说明准备 `pen`，确保 `pen version` 可运行；导出器通过 headless interactive 的 Get/Print 读取保存后的文档，不保存或改写源。

在仓库根目录执行（`mktemp` 默认创建仓库外临时目录）：

```sh
logo_env=$(mktemp -d)
python3.13 -m venv "$logo_env/venv"
"$logo_env/venv/bin/python" -m pip install -r brand/scripts/requirements.txt
npm install --prefix "$logo_env/render" --no-audit --no-fund @resvg/resvg-js@2.6.2
export NODE_PATH="$logo_env/render/node_modules"
"$logo_env/venv/bin/python" brand/scripts/export.py --work-dir "$logo_env"
"$logo_env/venv/bin/python" brand/scripts/export.py --check
"$logo_env/venv/bin/python" -m unittest discover -s brand/scripts -p 'test_*.py'
rm -rf "$logo_env"
```

超椭圆按 n=5 方程采样 4096 点。resvg 栅格化派生 SVG，Pillow 统一写 RGBA PNG 并清除元数据；过程中只在仓库外写临时文件。导出器核对读取前后的母版 SHA-256，不修改 `.pen`。如果编辑器在导出过程中保存了母版，应重新导出。

`dist/manifest.json`（schema 2）记录 21 个导出文件的 SHA-256、字节数和 PNG 尺寸，以及源文件、导出器的 SHA-256、母版和状态画板 ID、图层数据摘要、瞳孔 ID、点的尺寸与留白规范、渲染依赖版本。清单没有时间戳或本机路径；同一源、脚本与依赖下重复导出应逐字节一致。

`--check` 不写文件，检查源及导出器是否过期、文件是否缺失或多出、全部 21 个文件的哈希和尺寸、1024px 图标透明边距，以及默认/常亮 18/36px 模板的黑色与透明约束和相同边界。测试另覆盖矢量遮罩擦除、点的独立性、画板白名单、最小尺寸和同心约束。检查验证交付完整性；更新造型后仍需人工复核外观。

定稿演变与验收记录见 [FINAL-2026-10-28.md](rounds/FINAL-2026-10-28.md)。
